## Context
Milestone 3 converts throughput results into the actual facility requirements needed for production planning. The accepted model is recipe-dedicated facilities: each facility instance is assigned to one recipe, and recipe switching or sharing across recipes is out of scope because it would require explicit recipe switching, different inputs, and more complex routing semantics.

This decision intentionally favors a simple, stable wiring and layout contract over theoretical machine sharing. A shared-facility model would require scheduler semantics, recipe-change semantics, and input/output routing guarantees that are outside the current milestone.

## Why It Is Needed
Milestone 2 calculates recipe work rates but does not yet say how many facility instances are required. Wiring and layout planning need a stable facility requirement contract before they can map recipes to physical machines.

## Detailed Plan
1. Write a design document under `docs/designs/` for recipe-dedicated facility requirement calculation.
   - Define the stage as `RecipeThroughputReport -> FacilityRequirementReport`.
   - Define library-stage behavior: successful throughput reports produce facility requirement reports; failed throughput reports produce `FacilityRequirementReport { success: false }` with diagnostic code `upstream-throughput-failed`.
   - Define failure report shape: same top-level `FacilityRequirementReport`, empty requirement and summary arrays, `success: false`, and at least one error diagnostic.
   - Define output DTOs: `FacilityRequirementReport`, `RecipeFacilityRequirement`, `FacilityRequirementSummary`, and `FacilityRequirementDiagnostic`.
   - Define that facility assignment is recipe-dedicated: no facility instance can be shared across recipes in this milestone.
   - Define `required_facilities = ceil(work_seconds_per_second)`.
   - Define exact ceiling behavior: zero work rate maps to zero facilities, exact integer rates remain unchanged, and fractional positive rates round up by one.
   - Define per-recipe unused capacity as `required_facilities - work_seconds_per_second`.
   - Define `FacilityRequirementSummary.required_facilities` as the sum of recipe-dedicated `required_facilities` for each facility ID.
   - Define facility summary unused capacity as the sum of per-recipe unused capacity for that facility ID, preserving the recipe-dedicated model.
   - Define diagnostic codes: `facility-requirements-calculated`, `upstream-throughput-failed`, and `arithmetic-overflow`.
   - Define full diagnostic fields: `stage`, `severity`, `code`, `path`, `entity`, and `message`.
   - Define ordering: recipe requirements follow throughput `recipe_rates` order, facility summaries are sorted by facility ID, diagnostics are deterministic.
   - Define non-goals: no facility catalog, no recipe switching, no shared scheduling, no wiring, no layout, no optimization.
2. Add a new facility requirement stage in `aic-data`.
   - Keep it separate from recipe loading, validation, graph resolution, and throughput calculation.
   - Reuse the existing exact `Rate` DTO for work and unused-capacity values.
   - Add integer ceiling helper for positive rates.
   - Return a JSON-serializable report for both success and expected stage failures.
3. Add CLI support.
   - Add `aic recipes facilities --file <recipes.json> --request <throughput-request.json>`.
   - Reuse the existing recipe and throughput request pipeline.
   - Define CLI priority: recipe load errors remain normal CLI errors; throughput request and throughput calculation failures print the upstream `RecipeThroughputReport`; only successful throughput reports are passed to the facility stage.
   - Print the facility requirement report if facility calculation runs.
   - Map `FacilityRequirementReport { success: false }` to `CommandStatus::Failure`, matching the existing throughput command status behavior.
4. Add tests.
   - Single recipe with fractional work rate rounds up to one facility.
   - Work rate above one rounds up to multiple recipe-dedicated facilities.
   - External target produces zero facility requirements.
   - Facility summaries aggregate required counts by facility ID without sharing.
   - Direct library input with failed throughput becomes a facility-stage failure report.
   - CLI upstream throughput failure prints the upstream throughput report and does not run facility calculation.
5. Verify.
   - Run `cargo fmt --all`.
   - Run `cargo check --workspace`.
   - Run `cargo test --workspace`.
   - Run at least one CLI facility requirement command with sample JSON files.
6. Commit.
