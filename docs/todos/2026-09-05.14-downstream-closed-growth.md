# R1-order: downstream-closed construction

## Status

Complete as an opt-in experiment; not adopted as the default. Supersedes the next-step priority
of spatial direction ordering in R1a. [Measured results and next blocker](../benchmarks/constructive-downstream-order/report.md).

## Contract before implementation

The user requests human-like one-directional construction: finish the already-built side before
opening the next side. This slice tests reverse production order independently of spatial placement.
It does not implement global spatial axes or modify the official score.

- Input: original wiring, existing catalogs/budgets and an opt-in default-false request/CLI boolean
  `downstream_closed_growth` / `--downstream-closed-growth`. Existing request schema 1 is additive.
- A committed growth state must cover every internal outgoing requirement of every placed facility.
  It may have unresolved incoming requirements from unplaced suppliers. All covered requirements
  still pass the original-ID/rate audit and independent geometry/capacity validation.
- External inputs, target outputs and surplus outputs remain explicit pending boundaries; their
  physical realization stays in the existing final-boundary stage. This is internal downstream
  closure, NOT a claim that all external output wiring is already complete. Early external wiring
  would require a separate boundary relocation/extension contract and is deferred.
- For a candidate supplier, close its unplaced downstream dependencies transitively. This includes
  cycles and shared-producer branches. Prefer smaller ready groups, then existing deterministic
  pipe/upstream/ID ordering. A group is atomic at commit, not a rigid physical module.
- Grow each private group connected to the current node, adding and routing one facility at a time
  with existing placement/port/router behavior. Never place all facilities globally before routing.
  All failed/private attempts consume the same per-transaction placement/A* budgets.
- If the seed itself has internal downstream obligations, its downstream closure is a private initial
  transaction. If that transaction fails, do not expose the raw seed as a downstream-closed incumbent.
- Output: report schema 2 with additive group-attempt diagnostics (step, root, planned new members,
  variant, success), plus existing last valid node, exhausted budgets and obstruction diagnostics.
  Check the closure invariant independently of candidate-group selection before every commit.
- Local group failure retains the last valid closed prefix. No silent fallback to the old order,
  no increased budgets, no duplicate shared producers and no global infeasibility claim.

## Completion criteria

- Tests: chain, diamond, shared producer with another sink, cycle containing seed, connected group
  expansion, private group failure, defaults, determinism and per-step internal-output closure.
- Release matrix: existing versus closed order, each with coarse placement and nearby N=4, on the
  unchanged Heavy Xiranite and small cycle requests. Keep catalogs, budgets and output mode fixed.
  Record completion, covered requirements, score, transaction sizes, trials/A*, runtime and failure.
- Preserve baseline complete witness in default-false mode and the existing shared HTML. Partial
  output is never a complete quality improvement. Files hold detailed JSON; stdout stays short.
- Run fmt/check/tests, manually exercise the CLI, document the next demonstrated blocker and commit.
