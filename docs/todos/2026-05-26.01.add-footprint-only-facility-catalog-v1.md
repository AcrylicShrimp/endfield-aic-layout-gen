# TODO: Add footprint-only facility catalog v1

## Current Status
- State: Finished
- Dropped Reason:
- Last Status Update: 2026-05-26 21:04:45

## Context
Milestone 4B now produces logical facility-instance wiring, but the next facility-only layout milestone needs external facility dimensions. The project currently has recipe data but no facility catalog data or validation contract.

## Why It Is Needed
Facility-only layout can remain independent from ports and wiring, but it needs each facility footprint to place non-overlapping rectangles. A small footprint-only catalog keeps milestone 5 unblocked without forcing port schema decisions early.

## Completion Criteria
- [x] A design doc defines facility catalog v1 JSON schema, validation report schema, diagnostics, ordering, and non-goals.
- [x] Facility footprint semantics are documented as positive grid-cell dimensions in canonical, unrotated orientation.
- [x] Facility stable ID validation uses a shared crate-private helper rather than duplicated validation logic.
- [x] Diagnostic entity null serialization and diagnostic JSON pointer paths are covered by contract and tests.
- [x] `aic-data` exposes a top-level facility catalog module with `FacilityCatalog`, `FacilityDefinition`, `FacilityFootprint`, `FacilityCatalogValidationReport`, diagnostics, loader, and validator APIs.
- [x] Facility catalog JSON parsing rejects unknown fields.
- [x] Validation rejects unsupported schema versions, invalid facility IDs, duplicate facility IDs, and non-positive footprint width/height.
- [x] A CLI command loads and validates a facility catalog JSON file and prints structured validation JSON.
- [x] Example footprint-only facility catalog data is added under `data/examples`.
- [x] Tests cover valid catalogs, parse strictness, schema/version failures, duplicate IDs, invalid IDs, non-positive footprints, and loader failures where practical.
- [x] `cargo fmt --all`, `cargo check --workspace`, `cargo test --workspace`, CLI smoke checks, and `git diff --check` pass.
- [x] The verified work is committed as a focused commit.

## Detailed Plan
1. Write the facility catalog v1 design doc with footprint-only scope, diagnostic shape, CLI failure priority, shared stable ID validation, and explicit non-goals for ports, channels, and layout.
2. Add a top-level `aic-data::facilities` module for facility catalog DTOs, loader, validation report, and validation logic.
3. Re-export the new module from `aic-data` without changing recipe facility requirement APIs.
4. Add `aic facilities validate --file <FILE>` to the CLI.
5. Add example catalog JSON and focused tests.
6. Run fresh-context review before implementation and after implementation if meaningful.
7. Verify and commit the focused work unit.
