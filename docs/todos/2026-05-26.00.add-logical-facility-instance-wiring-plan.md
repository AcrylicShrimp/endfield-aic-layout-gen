## Context
Milestone 4A builds an aggregate recipe-level wiring graph, and milestone 3 calculates recipe-dedicated facility counts. The next slice should expand aggregate recipe nodes into logical facility instances without introducing facility catalog data, physical ports, belts, pipes, or layout geometry.

## Why It Is Needed
The project needs an explicit facility-instance-level wiring contract before physical placement work can start. Keeping this stage logical preserves the current milestone boundary while making recipe-level aggregate flows concrete enough for later port-aware and layout-aware stages.

## Completion Criteria
- [x] A design doc defines the logical facility instance wiring contract, input invariants, report schema, diagnostics, ordering, and non-goals.
- [x] `aic-data` exposes a `FacilityInstanceWiringReport` stage that consumes successful throughput, facility requirement, and recipe wiring graph reports.
- [x] The stage creates recipe-dedicated facility instances with deterministic IDs and per-instance recipe/facility assignment.
- [x] The stage splits aggregate recipe-level wiring edges across source/target facility instances using a documented deterministic strategy.
- [x] The stage rejects successful-but-mismatched upstream report combinations with structured diagnostics.
- [x] The stage validates recipe-level wiring edge kinds against endpoint pairs and rejects malformed successful throughput reports without targets.
- [x] External, target, and surplus endpoints remain logical non-facility endpoints.
- [x] CLI command emits the new JSON report and preserves upstream failure priority.
- [x] Tests cover multi-step chains, external targets, surplus, source-and-target multi-instance splitting, mismatched successful upstream reports, and malformed upstream report failures.
