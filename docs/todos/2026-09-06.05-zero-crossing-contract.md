# Zero-crossing block interface research

## Status

Complete as a scoped fixed-flow order/port baseline and same-item redistribution diagnostic.
The user subsequently approved explicit structural crossing modules for unavoidable different-item
crossings. The original zero-crossing rule below describes this baseline, not a new global rule.

## Stage contract

- Input: frozen chain-block placement, matching runtime items, facilities and transport catalogs.
  Preserve stable facility IDs, member geometry and all original logical requirements.
- Analyze each east-facing belt-output / west-facing belt-input interface corridor. Enumerate
  source block orders under an explicit bound and derive the necessary target precedence DAG.
  Accept only an order with zero strict inversions. A bounded failure is unknown, not infeasibility.
- For each candidate, allocate distinct facing ports in partner order with exact rational lane
  counts. Test integer-grid lane geometry, full required rate and absence of tile sharing/crossing
  or facility intrusion in the isolated corridor. This local certificate is NOT independent full
  game validation and is NOT a globally compatible placement. Never publish it as a factory.
- Preserve complete rigid chains in corridor views. A side interface inside a block envelope is
  unresolved and may require splitting; do not route through the block or silently rotate it.
- Fixed-pair same-item X shapes remain conflicts in this baseline, but changing the transportation
  matrix while preserving terminal rates may remove them without a junction at the crossing.
  A K2,2 witness proves only that four independent links cannot be ordered across two opposing
  faces. It does not prove that the commodity network, another embedding or whole factory is
  impossible. The historical `zero-crossing-explicit-junction-required` diagnostic code denotes
  a fixed-pair obstruction only; its message now explicitly allows same-item reassignment.
- A full-graph gate accounts for every internal and external requirement, return connections,
  pipes and consistency of shared block coordinates/ports across local corridors. It stays closed
  if ANY of these lacks a zero-crossing certificate. Do not call the old crossing-capable router
  as a fallback or export a normal accepted placement DTO for a blocked result.
- JSON reports carry stable failure codes, exact scope, search counts, witnesses, unresolved edge
  IDs, port assignments, geometric routes and timing. File-only artifacts, compact CLI completion.

## Completion criteria

Test order inversions, exact local certificates, budgets, K2,2 including same-item handling, rates,
port shortage, complete requirement accounting, catalog consistency and no global success from
local certificates. Render before/after order, port-level paths and the unresolved shared topology;
inspect actual images. Run workspace verification and commit the verified slice. Keep production
and all previous benchmarks unchanged.
