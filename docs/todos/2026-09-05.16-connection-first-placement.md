# R1-placement: direct-neighbor, connection-first construction

## Status

Initial interpretation implemented and measured; not adopted. User visual review exposed an overly
strict global half-plane assumption before this milestone was committed. Direct-neighbor generation
is implemented, but actual connection-face placement needs a corrected follow-up contract.

## Stage contract

- Add opt-in request/CLI `connection_first_placement` / `--connection-first-placement`, requiring
  an explicit flow direction and zero nearby-scoring candidates. Defaults preserve the old witness.
- Input: immutable validated partial node, one oriented/port-assigned fresh facility, original wiring,
  flow axis and existing transaction budgets. Use all already placed direct neighbors, never unrelated
  facilities or overall bounding-box edges as placement anchors.
- When consumers are already placed, place upstream of their upstream-most facility face. Otherwise
  place downstream of placed suppliers. In a cycle with both roles, consumer-side precedence wins;
  report supplier/back-edge requirements and route them normally. This is not monotonic routing.
- Align connection ports transversely. Enumerate small local slides and increasing clearance from
  that face; rank by summed minimum endpoint Manhattan distance across all direct requirements,
  then worst distance and deterministic local ties. This is a proposal heuristic, not route length
  or a joint capacity proof. Existing port capacity allocation and reservation semantics stay intact.
- First valid routed transaction wins. No routed area comparison, alternate rotation, unrelated
  anchor or coarse escape fallback. Reject collisions before routing; retain at most 32 local poses
  per port variant, using 1..8 empty-cell gaps and +/-16 transverse slides around port alignments
  and their median. These are explicit heuristic enumeration bounds, not game/canvas limits.
- Output: accepted independently validated node or structured local exhaustion; preserve the last
  valid state and original output-closure/capacity audits. Add per-addition diagnostics identifying
  direct neighbors, role exceptions, generated/clear candidates and attempted distance/translation.
- Keep graph growth order, final external-terminal stage, router and score priority unchanged.

## Completion criteria

- Test all axes, both growth directions, multiple neighbors, unrelated-obstacle independence of
  anchors, first-valid acceptance, deterministic repeats, invalid flags, budgets and cycles.
- Run fmt/check/workspace tests and release CLI comparisons against the fixed-orientation milestone.
  Record completeness first, then score/time/work and the next demonstrated obstruction.
- Publish separate HTML histories through the existing tailnet server, inspect them, and commit.
