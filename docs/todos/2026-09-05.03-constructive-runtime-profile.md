# Constructive runtime profiling

## Status

Complete. Instrumentation only; candidate ordering, validation and output contents are unchanged.
The next optimization slice should use the measured ranking below before introducing parallelism.

## Context

The complete Heavy Xiranite request takes about 22 seconds in construction and 31 seconds end to
end in release mode. Native sampling identifies shared-path enumeration and stdout serialization,
but inlined boundary screening and nested operations require explicit timing to rank reliably.

## Contract

- An optional `layouts construct-production --profile` writes a separate schema-1 compact JSON
  aggregate to stderr. The normal construction report and stdout remain unchanged in this slice.
- Profile input is the existing request/catalog input and one opt-in flag. The profile contains
  no layout snapshots or individual event log. Memory is bounded by operation kinds and call depth.
- Stable operation identifiers report calls, inclusive nanoseconds, exclusive nanoseconds and
  maximum invocation time. Exclusive means inclusive minus directly nested instrumented scopes;
  it still includes uninstrumented child work and instrumentation overhead.
- Timings are monotonic wall time on the calling thread, NOT CPU time. Native stack sampling is
  complementary evidence. The profile explicitly reports its calling-thread-only coverage;
  worker threads are not implicitly included. Current full-production construction is sequential.
- Nested captures on the same thread return a descriptive error. Panic unwinding restores disabled
  collection. Error-returning CLI runs still attempt to write their captured profile; stderr write
  errors are explicit. Callers can redirect the profile stream to a separate file.
- Disabled collection does not read clocks or allocate per operation. Captured spans never change
  planner choices, budgets, game semantics, validity checks or layout scoring.
- Capture timing excludes writing the profile itself. No per-cell inner-loop timer is added.

## Completion criteria

- Independently test nested accounting, recursion, disabled collection, capture isolation and panic
  cleanup. Verify the production fixture is unchanged with profiling enabled.
- Measure input loading, construction, report file serialization, stdout serialization, HTML
  generation and HTML writing separately.
- Inside construction measure candidate growth, edge closure, attachment enumeration, shared-path
  search, crossings, A*, boundary escape screening, network validation, original-wiring audit,
  port-demand analysis, capacity reporting, node copies and coordinate transformations.
- Run release baselines separately from compiler/test activity and native sampling. Compare final
  nodes and operation counts; report observational timing variability rather than speedup claims.
- Run formatting, workspace check/tests, and the profiled production CLI; record the evidence.
