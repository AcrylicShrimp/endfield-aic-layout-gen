## Next step

Read the pilot's fixed-problem environment and staged comparison. Select one inspectable request
and valid initial layout with a known useful edit within the declared envelope. Each episode
resets to that exact layout while learner state persists. No augmentation or generalization
split belongs in the first fit experiment. The belt-only 4-12-facility scope, 128-command horizon,
training budget ladder, and replication counts remain draft settings, not an executable allocation.

The current action hypothesis has seven commands. Each extension includes its anchor, and the
engine checks completion after applied edits; the model does not issue route-start/finish commands.
The remaining step is to specify the observation/decoder and validation subset needed for this
one root, then exact baseline/decoder dimensions, architecture candidates, and outcome
aggregation/uncertainty. The current size hypothesis starts around 0.1M total parameters and
increases widths toward 0.4M and 1.6M on CPU, with fresh learning per size. Actual counts and CPU
costs are unmeasured. Keep state information and action semantics comparable across encoders;
show learning curves by both interaction exposure and actual compute/time. Do not expand to
deferred features solely because the parent notebook describes them.

First keep that scope minimal. All of those candidates, including the task formulation and
model/engine split, are revisable. Stable settings within one comparison make evidence readable;
they do not constrain the next experiment's design.
Keep fixed-geometry flow verification and edit granularity as supporting decisions. The model now
specifies paths and intentional attachment targets; bridges, splitters, and convergers are
derived by the engine. The design includes a shared-trunk detour with explicit coordinates and
symbolic catalog-relative rates. It is a paper example, not a validated game fixture.

Flow is proposed as required/capacity observation features with engine-owned certification on
the fixed graph, not another model action. Pending draft loads are unknown rather than zero.
The user requests notice when their decision is actually needed; technical checker/normalization
choices should be proposed by the agent. Do not treat casual flow simplification as permission
to change terminal requirements or assume unverified splitter behavior.

The old crossing helper only proposes different-item crossings, and the constructive validator
has a stricter reachability scope than the shared semantic reference. Do not silently inherit
those restrictions or mistake the old witness probe for full original-request acceptance.
