# M2: dense boundary accessibility screening

## Status

Complete. M2 only; baseline `a7f29b4` release binary preserved before edits.
Evidence: [paired measurements and slice report](../benchmarks/constructive-boundary-screening/report.md).

## Contract

- Input: one immutable constructive candidate and validated runtime transport/component catalogs.
  Output: the same sorted, deduplicated blocked requirement IDs. No layout or search mutation.
- Preserve the existing envelope: origin (-1, -1), maxima from placement ends/network cells plus
  three, inclusive. This is a screening envelope, not a caller W/H bound. Do not expand, crop or
  change exterior reachability semantics. The root remains visited even if occupied.
- Build facility/belt/pipe occupancy once per candidate. Reuse a byte-cell flood workspace and
  dense FIFO queue for each sorted (transport, item) pair. Reset all query flags from immutable
  occupancy before the next commodity. No state survives a candidate mutation.
- Obtain crossing options from the unchanged catalog-backed crossing function for each commodity.
  Skip only consecutive crossing cells on the matching independent axis; they are transit cells,
  not visited attachment cells. Same-item occupancy and illegal crossing axes remain blocked.
- Use checked coordinate/index arithmetic and fallible reservation. A 64 MiB auxiliary dense
  workspace guard is an operational allocation limit, not geometric infeasibility. Coordinate
  overflow, resource guard exhaustion and allocation failure return distinct stable failure codes;
  reject only the current candidate, retain the previous valid factory and expose the error if
  growth exhausts candidates. Never report those errors as blocked requirements.
- Remove the old hash flood from production; retain a test-only reference. Add bounded aggregate
  `boundary-escape` counters for commodity screens, visited cells, neighbor probes, crossing hops,
  envelope cells and workspace bytes (sum and peak). Crossing option generation remains separately
  timed; `boundary-workspace` and `boundary-flood` isolate setup and traversal. No recursive
  inclusive-time summation or parallelism is introduced. Profile additions retain schema 1.

## Completion criteria

- Differential external grid fixtures cover enclosure/opening, both crossing axes, consecutive
  crossings, border and negative exterior coordinates, occupied root, and repeated workspace reuse.
- Compare complete blocked-requirement results against the original algorithm on real generated
  candidates, with multiple commodities and geometry changes. Existing game/validation tests pass.
- Check coordinate overflow/resource failure and deterministic reset behavior explicitly.
- Controlled scaling tests compare identical visited sets and report visited work/workspace size.
- Five paired unprofiled release runs and separate profiles on full Heavy Xiranite and seed-cycle,
  identical inputs/budgets/full JSON+HTML output, no concurrent compiler/tests. Preserve accepted
  node/search-choice hashes and measure latency, peak RSS and the next exclusive-time hotspot.
- Run formatting, workspace check/tests and real CLI verification; update the roadmap and commit
  only after repeatable gains and equivalent witnesses are established.
