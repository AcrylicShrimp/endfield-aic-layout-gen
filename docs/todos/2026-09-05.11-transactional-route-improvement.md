## Context and contract

Follow the [stage contract](../designs/2026-09-05.00-transactional-route-improvement.md) and accepted
constructive-planner design. Reroute one ordinary constant-flow chain at fixed endpoints, preserve
all other geometry, independently validate the complete original request and commit only a strictly
better `(area, physical transport cells, turns)` score. Retain the incumbent on every failed attempt.

The [runtime checkpoint](../benchmarks/constructive-runtime-checkpoint/report.md) shows 3.140 s
construction / 4.828 s full CLI for the unchanged Heavy Xiranite layout. More speed work is deferred;
this milestone deliberately may change geometry. A route-only pass cannot move the facilities that
already determine its width, so large area compaction is not Q1's acceptance criterion.

## Completion criteria

- Implement the minimal ordinary-chain proposal and dedicated bounded route repair, with no
  relocation, new crossing/junction, global exact dependency or caller W/H ceiling.
- Add external detour fixtures proving strict score improvement and rejection/corruption/budget
  tests proving unchanged valid incumbents. Audit the full original facility/requirement sets.
- Implement the neutral score, complete independent gate and bounded accepted-delta report.
  Do not count constructor caches or partial coverage as independent complete validation.
- Add opt-in CLI controls, explicitly migrate production report to schema 3, update HTML directly
  and retain short stdout/file-backed detailed output. Keep construction and improvement history distinct.
- Measure full/small release before/after scores, attempts, runtime and RSS. A valid no-gain full
  graph result is evidence; do not silently widen the neighborhood to force a demonstration.
- Run formatting, workspace check/tests and manual CLI verification. Commit Q1 separately and
  identify the next demonstrated quality bottleneck before defining Q2's relocation/repair contract.
