# M4: bounded parallel commodity analysis

## Status

Complete. M3 `86bd588` is the preserved unmodified release baseline. Four workers are adopted
as the default ceiling; see the [60-run matrix and decision](../benchmarks/constructive-parallel-analysis/report.md).

## Contract before implementation

- Parallelize only commodity-specific boundary accessibility of one immutable candidate. Facility
  growth, validation, routing, first-feasible selection and commits remain sequential.
- Add explicit `analysis_workers` request/CLI control. Candidate default ceiling is four, pending
  measured adoption; one selects the serial path. Reject zero or more than 16. Actual workers are
  capped by host parallelism, commodity count and the existing aggregate 64 MiB workspace guard.
- Build occupancy once; each worker receives an independent resettable scratch copy and immutable
  node/catalog references. A bounded dynamic job counter assigns each commodity exactly once.
  No speculative candidate work, unbounded task queue or persistent mutable geometry cache.
- Join all workers before returning. Merge results by original sorted commodity index, then sort
  and deduplicate blocked IDs as before. Exhausted thread creation or worker panic returns a stable
  structured screening failure; prior valid geometry remains. Do not silently commit partial work.
  Already-started work is joined on failure; no detached workers or race-selected error/result.
- Count all visited/probed work on the parent report. Add worker-local profile capture and separate
  aggregated worker operations, worker wall-duration sum, busy-worker count and max concurrency.
  Main-thread elapsed/dispatch timings remain critical-path wall time. Never subtract summed worker
  time from parent durations or claim worker wall-time sum is process elapsed time or CPU time.
- Aggregate auxiliary memory across base and worker workspaces, with bounded worker result lists.
  Report requested/effective workers and work distribution. Default adoption requires repeated
  release benefit against one worker; if overhead dominates, retain serial behavior and document it.

## Measurement and completion gate

- Differential serial/parallel blocked IDs, complete/intermediate witnesses, search counts and
  diagnostics must match, including small/corrupt cases and repeated calls after geometry changes.
- Test worker profile accounting, cancellation/join behavior, worker limit errors and memory caps.
- Compare one, two, four and eight requested workers on full and small workloads in release mode,
  with at least five unprofiled samples per configuration, rotated order and separate profiles.
  Also compare against the preserved M3 binary; full JSON/HTML and short stdout stay enabled.
- Record host, input/binary hashes, CPU/RSS, worker utilization and workspace footprint. No compiler
  or test process overlaps timings. Adopt only a repeatable end-to-end improvement.
- Run formatting, workspace check/tests and manual CLI checks. Commit M4 separately, then proceed
  automatically to the M5 runtime checkpoint and first transactional layout-improvement contract.
