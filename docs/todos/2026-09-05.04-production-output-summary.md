# Production output summary cutover

## Status

Complete.

## Context and contract

The user requests a short completion summary on stdout, not a silent command. The complete report
already has a required JSON destination; repeating it on stdout costs approximately 7.4 seconds.

- Scope: `layouts construct-production`. Other commands retain their existing output behavior.
- Stdout changes from the full production report to one compact schema-1
  `kind=constructive-production-summary` JSON record: status, success and report/HTML paths.
- Full schema-2 construction results and partial-state diagnostics remain in `--report-output`.
  Early semantic input validation failures write their native stage report to that same file and
  emit an `invalid-input` summary. I/O/parse and concise localization setup errors remain
  path-specific errors on stderr.
- A completion summary is printed only after required artifact writes succeed. It must never
  claim an HTML artifact when none was written. Profiling remains opt-in on stderr.
- Replace the shared input loader's implicit stdout writes with returned structured failures;
  each caller explicitly selects its diagnostic destination. Remove the old full-report stdout
  writer. No compatibility switch or duplicate serialization path remains in production.
- This is an explicit stdout CLI contract break, not a construction-report schema change.

## Completion criteria

- Verify success, planner failure and early validation failure use a single small stdout summary.
- Verify missing inputs and output-write errors return failure without a completion claim.
- Preserve all accepted nodes and search counters on the release Heavy Xiranite fixture.
- Measure post-cutover timing with the existing operation profiler and record the result.
- Run formatting, workspace check/tests and manual CLI checks; commit the verified slice.
