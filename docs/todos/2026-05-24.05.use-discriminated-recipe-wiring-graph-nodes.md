## Context
Recipe-level wiring graph nodes currently use one struct with `kind: String`, `recipe: Option<String>`, and `item: Option<String>`. This serializes heterogeneous node variants by leaving irrelevant fields as `null`, and it lets invalid states exist in Rust such as a recipe node without a recipe ID.

This is a breaking public JSON/CLI contract change for `recipes wiring-graph`. The cutover intentionally removes the old nullable companion fields instead of preserving them through a compatibility bridge.

## Why It Is Needed
The recipe wiring graph is a public JSON contract. Contract-first design should represent heterogeneous node variants as a tagged/discriminated union so each node kind carries only its valid payload fields.

## Completion Criteria

- [x] Recipe wiring graph JSON no longer emits irrelevant `null` node fields.
- [x] Node construction, tests, and docs are updated through a hard cutover with no compatibility bridge.
- [x] Tests cover `external`, `recipe`, `target`, and `surplus` node variants in Rust and serialized JSON form.

- [x] The verified work is committed as a focused commit.
