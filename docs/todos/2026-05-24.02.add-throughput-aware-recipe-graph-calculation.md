## Context
Milestone 2 needs a throughput-aware recipe graph stage after the validated recipe graph contract. The existing implementation can load and validate recipe JSON, promote it to `ValidatedRecipeBook`, and resolve an acyclic dependency graph. It does not yet calculate item flow rates, recipe run rates, recipe work rate, external input rates, or surplus from multi-output recipes.

Facility placement and integer facility counts are intentionally out of scope for this task. Recipe duration is still part of the throughput contract as a fractional work-rate metric, but it must not become a rounded facility-count calculation in this milestone.

Application data input and output should remain JSON. For this milestone, the target production request should be an external JSON file rather than new non-JSON data flags.

## Why It Is Needed
The current graph resolver only lists dependency recipes; it does not calculate required rates for a requested final production amount. The next milestones depend on a stable stage contract that can explain how much each item must flow, how often each recipe must run, and what external input rates are required before facility selection or layout planning begins.

## Detailed Plan
1. Write a design document under `docs/designs/` for the throughput-aware recipe graph contract.
   - Define `RecipeThroughputRequest`, `ThroughputTarget`, `Rate`, `ItemRate`, `RecipeRunRate`, `RecipeThroughputReport`, and `ThroughputDiagnostic`.
   - Include `schema_version` in `RecipeThroughputRequest` because it is an external JSON input contract.
   - Define that all rates are exact rational values normalized as units per second.
   - Define output ordering: recipe rates in dependency-first graph order; all `ItemRate` arrays, including nested recipe `input_rates` and `output_rates`, sorted by item ID; `limiting_outputs` sorted by item ID; diagnostics in deterministic calculation order.
   - Define that expected throughput-stage failures are emitted as structured JSON reports with `success: false`, not only as plain stderr errors.
   - Separate pipeline failures from throughput-stage failures: invalid recipe books remain `ValidationReport` output before the throughput stage; request-shape and throughput-domain failures use `RecipeThroughputReport`.
   - Define CLI failure priority for `recipes throughput`: load recipe file, parse request JSON, validate request schema/target/rate, validate recipe book, then calculate throughput.
   - Define non-goals: no facility catalog join, no integer facility counts, no belt/pipe throughput, no layout or wiring decisions.
2. Tighten recipe validation only where throughput needs an unambiguous contract.
   - Reject duplicate item entries within a single recipe's `inputs`.
   - Reject duplicate item entries within a single recipe's `outputs`.
   - Update the existing recipe JSON schema design document with the duplicate-side-item invariant because this changes the external recipe JSON contract.
   - Keep existing unique-producer and acyclic graph assumptions.
3. Add a new throughput stage in `aic-data`.
   - Keep the stage separate from raw loading, validation, and plain graph resolution.
   - Accept only `ValidatedRecipeBook` plus a parsed JSON request DTO.
   - Reuse `ValidatedRecipeBook::resolve_graph` for the dependency-first recipe set.
   - Calculate downstream-to-upstream demand by walking graph recipes in reverse.
   - For each recipe, calculate `runs_per_second` as the maximum of `demanded_output_rate / output_quantity` across demanded outputs.
   - Calculate surplus for every output as `produced_output_rate - demanded_output_rate`.
   - Return a `RecipeThroughputReport` for both success and expected stage failures.

+ ## Stage Contract
+ JSON RecipeBook -> ValidationReport -> ValidatedRecipeBook
+ JSON RecipeThroughputRequest -> RecipeThroughputReport
+ ## Failure Modes
+ - invalid target ID
+ - non-positive target quantity
+ - non-positive target duration
+ - unsupported throughput request schema version
+ - invalid throughput request JSON
+ - invalid recipe book is a pipeline failure reported as ValidationReport before this stage
+ - unknown target item
+ - arithmetic overflow
+ ## Multi-Output Formula
+ - required recipe runs = max(demanded output rate / output quantity)
+ - produced output rate = required recipe runs * output quantity
+ - surplus output rate = produced output rate - demanded output rate
+ ## Diagnostics
+ - stage: "recipe-throughput"
+ - severity: "info" | "warning" | "error"
+ - code: stable kebab-case code
+ - path: JSON pointer or report path
+ - entity: optional stable entity ID
+ - message: human-readable explanation
+ ## Ordering
+ - recipe_rates: dependency-first graph order
+ - every ItemRate array, including nested input_rates/output_rates: sorted by item ID
+ - limiting_outputs: sorted by item ID
+ - diagnostics: deterministic stage order

+ - request JSON parse errors emit RecipeThroughputReport before recipe validation
+ - request field errors emit RecipeThroughputReport before recipe validation
+ - recipe validation errors emit ValidationReport before throughput calculation

+ impl ValidatedRecipeBook {
+     pub fn calculate_throughput(
+         &self,
+         request: &RecipeThroughputRequest,
+     ) -> RecipeThroughputReport {
+         if let Some(diagnostic) = validate_request(request) {
+             return RecipeThroughputReport::failure(diagnostic);
+         }
+         let graph = match self.resolve_graph(&request.target.item) {
+             Ok(graph) => graph,
+             Err(error) => return RecipeThroughputReport::failure(map_graph_error(error)),
+         };
+         let target_rate = match Rate::from_quantity_per_duration_ms(
+             request.target.quantity,
+             request.target.duration_ms,
+         ) {
+             Ok(rate) => rate,
+             Err(diagnostic) => return RecipeThroughputReport::failure(diagnostic),
+         };
+
+         let mut item_demands: BTreeMap<String, Rate> = BTreeMap::new();
+         item_demands.insert(request.target.item.clone(), target_rate);
+
+         let mut recipe_rate_by_id: BTreeMap<String, RecipeRunRate> = BTreeMap::new();
+         let mut surplus_by_item: BTreeMap<String, Rate> = BTreeMap::new();
+
+         for recipe in graph.recipes.iter().rev() {
+             let (runs_per_second, limiting_outputs) = match required_runs_from_output_demands(
+                 recipe,
+                 &item_demands,
+             ) {
+                 Ok(value) => value,
+                 Err(diagnostic) => return RecipeThroughputReport::failure(diagnostic),
+             };
+             let work_seconds_per_second = match
+                 runs_per_second.checked_work_seconds_per_second(recipe.duration_ms)
+             {
+                 Ok(rate) => rate,
+                 Err(diagnostic) => return RecipeThroughputReport::failure(diagnostic),
+             };
+
+             let input_rates = match multiply_amounts(&recipe.inputs, runs_per_second) {
+                 Ok(rates) => rates,
+                 Err(diagnostic) => return RecipeThroughputReport::failure(diagnostic),
+             };
+             let output_rates = match multiply_amounts(&recipe.outputs, runs_per_second) {
+                 Ok(rates) => rates,
+                 Err(diagnostic) => return RecipeThroughputReport::failure(diagnostic),
+             };
+
+             if let Err(diagnostic) = add_input_demands(&mut item_demands, &input_rates) {
+                 return RecipeThroughputReport::failure(diagnostic);
+             }
+             if let Err(diagnostic) = add_surplus(&mut surplus_by_item, &output_rates, &item_demands) {
+                 return RecipeThroughputReport::failure(diagnostic);
+             }
+
+             recipe_rate_by_id.insert(recipe.id.clone(), RecipeRunRate {
+                 recipe: recipe.id.clone(),
+                 facility: recipe.facility.clone(),
+                 runs_per_second,
+                 work_seconds_per_second,
+                 limiting_outputs,
+                 input_rates,
+                 output_rates,
+             });
+         }
+
+         RecipeThroughputReport {
+             success: true,
+             target: Some(ItemRate { item: request.target.item.clone(), rate: target_rate }),
+             recipe_rates: graph.recipes.iter()
+                 .filter_map(|recipe| recipe_rate_by_id.remove(&recipe.id))
+                 .collect(),
+             external_input_rates: graph.external_items.iter()
+                 .filter_map(|item| item_demands.get(item).map(|rate| ItemRate {
+                     item: item.clone(),
+                     rate: *rate,
+                 }))
+                 .collect(),
+             item_demand_rates: item_demands.into_iter()
+                 .map(|(item, rate)| ItemRate { item, rate })
+                 .collect(),
+             surplus_rates: surplus_by_item.into_iter()
+                 .filter(|(_, rate)| !rate.is_zero())
+                 .map(|(item, rate)| ItemRate { item, rate })
+                 .collect(),
+             diagnostics: build_success_diagnostics(...),
+         }
+     }
+ }

+ impl Validator {
+     fn validate_item_amounts(&mut self, amounts: &[ItemAmount], path: String) {
+         let mut seen_items = HashSet::new();
+         for (amount_index, amount) in amounts.iter().enumerate() {
+             let amount_path = format!("{path}/{amount_index}");
+             self.validate_id("invalid-item-id", format!("{amount_path}/item"), &amount.item);
+             if amount.quantity <= 0 { self.push("non-positive-quantity", ...); }
+             if !seen_items.insert(&amount.item) {
+                 let code = if path.ends_with("/inputs") {
+                     "duplicate-input-item"
+                 } else {
+                     "duplicate-output-item"
+                 };
+                 self.push(code, format!("{amount_path}/item"), ...);
+             }
+         }
+     }
+ }

+ fn throughput_recipes(file: PathBuf, request: PathBuf) -> Result<CommandStatus> {
+     let recipe_book = load_recipe_book(&file)?;
+     let request = match load_throughput_request(&request) {
+         Ok(request) => request,
+         Err(parse_error) => {
+             let report = RecipeThroughputReport::failure(
+                 ThroughputDiagnostic::error(
+                     "invalid-throughput-request-json",
+                     "/",
+                     None,
+                     parse_error.to_string(),
+                 ),
+             );
+             write_throughput_report(&report)?;
+             return Ok(CommandStatus::Failure);
+         }
+     };
+     if let Some(diagnostic) = validate_throughput_request(&request) {
+         let report = RecipeThroughputReport::failure(diagnostic);
+         write_throughput_report(&report)?;
+         return Ok(CommandStatus::Failure);
+     }
+     let validated = match ValidatedRecipeBook::try_from_recipe_book(recipe_book) {
+         Ok(validated) => validated,
+         Err(report) => {
+             serde_json::to_writer_pretty(stdout, &report)?;
+             bail!("recipe validation failed");
+         }
+     };
+     let report = validated.calculate_throughput(&request);
+     write_throughput_report(&report)?;
+     if report.success {
+         Ok(CommandStatus::Success)
+     } else {
+         Ok(CommandStatus::Failure)
+     }
+ }
