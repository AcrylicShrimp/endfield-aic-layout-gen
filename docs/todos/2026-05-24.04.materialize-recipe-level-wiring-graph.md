## Context
Milestone 4A converts RecipeThroughputReport into an explicit recipe-level DAG. It materializes implicit item producer/consumer joins as graph nodes and item-rate edges. Facility instances, ports, belts, pipes, layout, and facility catalog joins are out of scope.

## Why It Is Needed
Current outputs list recipe rates and facility requirements, but they do not contain explicit source-target edges. Later facility-instance wiring and layout stages should consume an explicit logical graph instead of recalculating producer/consumer joins.

## Detailed Plan
1. Write a design document under `docs/designs/` for recipe-level wiring graph materialization.
   - Define the stage as `RecipeThroughputReport -> RecipeWiringGraphReport`.
   - Define library-stage behavior: successful throughput reports produce wiring graph reports; failed throughput reports produce `RecipeWiringGraphReport { success: false }` with diagnostic code `upstream-throughput-failed`.
   - Define failure report shape: same top-level `RecipeWiringGraphReport`, empty node and edge arrays, `success: false`, and at least one error diagnostic.
   - Define node DTO: `id`, `kind`, optional `recipe`, optional `item`.
   - Define edge DTO: `source`, `target`, `kind`, `item`, and `rate`.
   - Define node kinds: `external`, `recipe`, `target`, and `surplus`.
   - Define edge kinds: `external-input`, `recipe-flow`, `target-output`, and `surplus-output`.
   - Define deterministic node IDs: `external:<item>`, `recipe:<recipe>`, `target:<item>`, and `surplus:<item>`.
   - Define input invariants for successful throughput reports: `target` must be present, external sources are derived only from `external_input_rates`, and each produced item must have exactly one producer.
   - Define CLI priority: upstream throughput failures print the upstream `RecipeThroughputReport`; only successful throughput reports are passed to the wiring graph stage.
   - Define diagnostics: `recipe-wiring-graph-built`, `upstream-throughput-failed`, `missing-target`, `missing-producer`, and `ambiguous-producer`, including exact trigger conditions.
   - Define ordering: external nodes by item ID, recipe nodes by throughput recipe order, target node, surplus nodes by item ID; input edges by consuming recipe order and item ID, then target edge, then surplus edges by item ID.
   - Define non-goals: no facility instances, no facility catalog, no port/channel selection, no belt/pipe throughput, no wiring geometry, no layout.
2. Add a new recipe wiring graph stage in `aic-data`.
   - Keep it separate from raw recipe graph resolution, throughput calculation, and facility requirement calculation.
   - Build producer lookup from `RecipeThroughputReport.recipe_rates[].output_rates`.
   - Build consumer edges from `RecipeThroughputReport.recipe_rates[].input_rates`.
   - Build target edge from `RecipeThroughputReport.target`.
   - Build surplus edges from `RecipeThroughputReport.surplus_rates`.
   - Return a JSON-serializable report for both success and expected stage failures.
3. Add CLI support.
   - Add `aic recipes wiring-graph --file <recipes.json> --request <throughput-request.json>`.
   - Reuse the existing recipe and throughput request pipeline.
   - Print upstream `RecipeThroughputReport` when throughput fails.
   - Print `RecipeWiringGraphReport` when wiring graph calculation runs.
   - Map `RecipeWiringGraphReport { success: false }` to `CommandStatus::Failure`.
4. Add tests.
   - Multi-step recipe chain creates external, recipe-flow, and target-output edges.
   - External target creates external-to-target edge and no recipe nodes.
   - Multi-output surplus creates surplus-output edge.
   - Direct library input with failed throughput becomes a wiring-stage failure report.
   - Malformed successful throughput reports cover `missing-target`, `missing-producer`, and `ambiguous-producer`.
   - CLI upstream throughput failure prints the upstream throughput report and does not run wiring graph calculation.
5. Verify.
   - Run `cargo fmt --all`.
   - Run `cargo check --workspace`.
   - Run `cargo test --workspace`.
   - Run at least one CLI wiring graph command with sample JSON files.
6. Commit.
   - Commit the completed work as one focused work unit after verification passes.
