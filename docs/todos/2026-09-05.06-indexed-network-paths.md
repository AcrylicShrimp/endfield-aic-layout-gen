# M1: indexed existing-network path queries

## Status

Complete. M1 only; boundary screening, validation and parallelism are unchanged.
Measurements and reproduction: [slice report](../benchmarks/constructive-indexed-paths/report.md).

## Contract

- Input: an immutable borrowed segment slice from the current transport network, plus directed
  start/end coordinates. Segment order is significant for the existing BFS tie-break.
- Output: exactly the same segment-index vector or `None` as the original traversal. Equal
  endpoints return the empty path even if absent from the segment index. A missing or unreachable
  distinct endpoint returns `None`; it is not a global infeasibility claim.
- Build a sparse coordinate-to-vertex index and ordered outgoing adjacency once per eligible
  network in an attachment-enumeration call. Use dense vertex IDs for reusable per-query BFS
  state. No full-grid allocation, new bounds, root-result cache or reversed traversal.
- The index borrows its segment slice, cannot outlive it, and is not retained across candidate
  mutation. Query scratch state is reset before each search; no cached success/failure survives.
- FIFO traversal and original outgoing segment order preserve first discovery and predecessor
  selection, including duplicate segments, convergence and cycles. Capacity checks remain on the
  selected original segments and are not moved into, or removed by, this index.
- Remove the old traversal from production; retain it only as a differential test oracle.
- Add `path-index-build` timing and bounded aggregate `work` counters on profile operations:
  `vertices-indexed`, `segments-indexed`, `vertices-visited`, `edges-examined`. Empty work maps are
  omitted; this is an additive schema-1 profile extension. Counters never affect planner budgets.

## Completion criteria

- External graph fixtures cover directed chains, branch/convergence, ties, cycles, disconnected
  endpoints, self paths, duplicate segments and negative coordinates. Compare all relevant endpoint
  pairs and shuffled edge orders to the reference; test query scratch reuse and graph replacement.
- Controlled external scaling fixtures demonstrate reduced examined work; release microbenchmarks
  compare index construction plus queries with the reference, including small cases.
- Preserve all Heavy Xiranite accepted-node and search-choice hashes, 59 facilities, 96 requirements
  and 178 A* calls. Keep JSON/HTML enabled and stdout compact.
- Build baseline and candidate release binaries before measurement. Run at least five unprofiled
  runs per binary in alternating order, with separate operation profiles. Record median/range,
  RSS, binary/input hashes and toolchain. Do not overlap compilation/tests with timed runs.
- Run fmt, workspace check/tests and the real CLI. Re-profile and identify the next hotspot.
- If adjacency removes the dominant query cost, defer root-result caching; do not add it merely
  because it was listed as a possible second optimization.
