## Context and stage contract

The user permits crossings inside planned structural modules, and requests N:M support. Count
distinct recipe items, source/consumer instances and physical lanes separately. One recipe's item
degree does not bound replicated graph size or total crossing count. Split/merge and independent
crossing share an interconnect abstraction, but must not share commodity-mixing semantics.

- Census input: runtime recipes, items, facilities, transports and components. Report every recipe,
  distinct input/output counts, per-item exact full-utilization lane lower bounds, catalog port
  budgets, maxima with witnesses and provenance. Maxima describe this catalog snapshot only.
- Geometry input: ordered, capacity-feasible, typed lane terminals and a target permutation.
  Output: preplanned bridge modules, reserved rectangles, unit-grid paths and a scoped certificate.
  Each module swaps adjacent lanes. Compose any finite permitted permutation without a grid solver.
  Preserve identity, item, transport and rate. Reject same-commodity reordering in this first slice;
  same-item allocation belongs upstream, not an unvalidated self-crossing shortcut.
- Do not treat lane permutations as full N:M synthesis. A later stage must allocate exact flows,
  construct capacity-valid fanout/fanin trees and bind facility ports. Never merge different items.
- Geometry checks: every sharing cell is a preplanned catalog bridge with two perpendicular straight
  independent channels; no other overlap, jumps, loops, port direction error or capacity overflow.
  Per-channel rates are checked against both line and component capacities. Independent production
  validator acceptance is a separate future gate, not implied by this diagnostic checker.
- Limits are explicit research resource budgets, not game limits or impossibility proofs.
- CLI: explicit input/output paths, JSON file reports, concise stdout. Failures include stable code,
  severity, stage and entity context. Existing factory witnesses remain untouched.

## Completion criteria

Exhaustive small permutations, repeated-commodity stable order, negative geometry/capacity controls,
catalog census tests and a real-recipe-derived multi-lane demonstration. Render and inspect actual
geometry. Report remaining fanout/fanin, facility-boundary and independent validation gates.
Run workspace verification, compare with constructive design/AGENTS and commit the verified slice.
