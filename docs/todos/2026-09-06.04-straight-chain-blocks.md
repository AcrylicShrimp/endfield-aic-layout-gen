# Straight-chain block placement experiment

## Status

Initial experiment and interface mapping complete. Next decision: capacity-aware boundary port
subsets and approach preservation. This does not replace connected transactional construction.

## Contract

- Input: the frozen placement-only v1 proposal and its runtime-catalog provenance. Reuse stable
  facility IDs, labels, rotations, dimensions, projected ports and all logical requirements, not
  old positions. No facility duplication or catalog changes.
- Pass 1: contract a belt edge only if its source has one belt successor, its target has one belt
  predecessor, the pair has one requirement, and its east/west port geometry permits alignment.
  Count external belt relations as branches too. Exclude edges within directed cycles. Pipe side
  terminals remain explicit block boundaries. These are geometric candidates, not routed modules.
- Internal chain members have one empty column and aligned candidate connection cells. Retain
  every boundary requirement with item, rate, direction, transport and candidate ports. A block
  owns every member exactly once. Singleton blocks preserve all other topology, including shared
  producers, fan-in/out and cycles. Chains can later be split; no irreversible production cutover.
- Pass 2: grow from the target block by adjacency, using already placed neighbors' port geometry;
  no recursive hierarchy widths or duplicated subtree ownership. Search rectangle-edge and port
  alignment events in both axes. A block boundary gets a heuristic channel allowance based on
  boundary belt degree and an explicit minimum-gap parameter. The allowance is not a capacity or
  connectivity proof. Coordinate-descent relocation uses all incident edges after placement.
- Report exact extraction decisions, membership, boundary terminals, geometry, placement order,
  objective components and phase timings. Failure codes identify invalid input or candidate
  exhaustion. Never report routing/factory success from placement alone.

## Interface mapping extension

The user requested a quantitative block input/output map. Aggregate the existing logical edges
by ordered block pair, commodity and transport; retain the original endpoint facilities and rates.
Also aggregate all obligations (including internal chain and external edges) per facility,
direction, commodity and transport. Compute exact rational rate sums and lower-bound lane counts
from runtime transport capacity. Sum commodity-specific bounds when reporting a facility face;
do not merge different items or assume every group relationship is many-to-one. Same-item merged
lane bounds require physical merging/splitting and are not a port assignment or routing proof.
Report candidate ports, shared-trunk lower bounds and separate-edge lane counts distinctly.
This slice measures the interface contract; it does not change routing or allocate concrete ports.
