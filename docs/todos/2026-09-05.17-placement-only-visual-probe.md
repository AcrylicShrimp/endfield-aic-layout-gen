# Placement-only visual probe

## Status

Visual milestone complete; source-normalization defect subsequently corrected in milestone .18.
Follow-up fixed-placement routing remains pending visual review.
The user wants to inspect the complete placement before involving routing, then
mechanically route a frozen placement to identify failure patterns. Placement quality is the current
review gate; do not spend this slice changing the router or returning another route-truncated layout.

## Contract before implementation

- Separate offline diagnostic CLI under `docs/benchmarks/constructive-placement-only/`, consuming
  the original facility-instance wiring JSON and runtime facility/item catalogs on every execution.
  No production API/CLI cutover, exact solver, new dependency, game data or canvas hardcoding.
- Stage one emits all facilities, legal catalog orientations, nonoverlapping integer rectangles,
  used bounds, original logical requirements and placement decisions. No ports are assigned and no
  belt/pipe cells are created. `routing_performed` and `factory_validated` are explicitly false.
- Use eastward belt orientation as the first visual baseline. Rank required belt interface alignment
  (outputs east, inputs west) before required pipe alignment, then legal rotation angle. Report
  mixed-face exceptions. This changes only the diagnostic, not the production pipe-first policy.
- Output-first breadth-first traversal, belt neighbors before pipe neighbors, stable IDs for ties.
  Place new suppliers one empty column upstream of placed consumers; if only suppliers exist,
  place downstream. Align top edges before selecting any ports. When blocked, use the nearest
  collision-free row among obstacle-edge events, preserving one empty cell between rectangles.
  Report all direct neighbors, row shifts and mixed roles. Cycles/shared consumers can generate
  backward edges; expose them, do not hide or claim monotonic feasibility.
- An unobstructed one-to-one chain stays in a straight top-aligned row with one empty column
  between footprints, independent of port offsets. Existing positions never move. Logical edge
  overlays are optional and clearly labeled as nonphysical; default view has zero connection lines.
- JSON records source/input hashes and stable instance IDs so a later routing probe can use the exact
  same placement. Local F labels belong to this run, not to previous screenshots.
- Stage-two routing is deliberately pending visual review: load the frozen artifact, keep every
  coordinate/rotation fixed, attempt bounded mechanical wiring, and record failures separately.
  Do not confuse optional graph lines in stage one with that physical routing experiment.

## Completion criteria

- CLI produces all 59 Heavy Xiranite facilities and the small-cycle fixture with no routing calls.
- Node tests cover 1:1 rows despite port offsets, collisions, branches, cycles, mixed interfaces,
  deterministic repeats, all-facility coverage and explicit unsupported/invalid inputs.
- Inspect desktop/mobile HTML and stage controls, port and graph overlays, and selected-facility
  identity. Serve through the existing tailnet server without replacing previous artifacts.
- Commit the verified visual diagnostic, report its limitations, and request visual placement review
  before implementing the fixed-placement route probe.
