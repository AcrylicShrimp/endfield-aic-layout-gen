# Placement-ordered nearest-connection wiring

## Status

Complete. User-requested placement order, nearby connection targets first and nearby input/output
port pairs first replace the diagnostic's graph-wide straight-first sweep. Results and limitations
are recorded in `docs/benchmarks/constructive-ordered-routing/report.md`.

## Contract

- Keep all frozen rectangles and rotations, network semantics, validation and future-domain guards.
- A requirement becomes eligible at max(source placement index, target placement index). Route in
  increasing eligibility index; within it rank by minimum compatible projected connection-cell
  Manhattan distance, then belt-before-pipe on equal distance, then stable edge ID.
- Within a connection, try available port pairs by Manhattan distance then stable port IDs. Do not
  try a farther straight pair before a closer non-straight pair. Classify a clear opposed single-lane
  pair as straight; otherwise use the same existing network/A* engine. Finish its bounded attempt
  before proceeding to another connection. No global straight or transport sweep remains.
- Keep first-valid candidate acceptance in this slice; nearest-port order is not a proof of shortest
  routed path or best shared-network attachment. No relocation, rip-up or new path-preservation rule.
- Report v2 records placement index, neighbor distance and every attempted port pair/distance/result.
  A single A* limit applies per connection; remove obsolete per-stage limit semantics.
- Regress ordering against shuffled edge input, farther straight candidates and closest port pairs.
  Compare the identical frozen input, measure release routing, publish a distinct page and include
  its real browser-rendered image in the final response. Preserve the prior diagnostic artifacts.
