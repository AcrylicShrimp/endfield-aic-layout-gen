## Contract

- Input witness v1: placements with actual recipe IDs, one positive utilization at most one per
  instance, normalized commodity networks with terminals/segments, and placed logistics components.
- Runtime catalogs are loaded on every CLI invocation. Independently derive every recipe terminal
  rate and compare with routed terminal totals. Reject foreign items, wrong recipe/facility pairs,
  invalid utilization and excess or wrong-direction terminal flow. Report all missing rates.
- Validate covered physical geometry with the existing independent constructive network validator;
  do not alter or bypass its rules to accept the new fixture. No search or routing runs in validation.
- Output v1: covered geometry acceptance, recipe terminal ledger, pending obligations, diagnostics,
  measured bounds and validation time. Always `factory_validated: false`: this diagnostic is not the
  normal complete-factory acceptance path. Invalid witnesses still produce structured JSON.
- Protect validator arithmetic/materialization with explicit diagnostic coordinate/count/rate guards.
  These are research resource limits, not game constraints or global infeasibility proofs.
- First fixture: two different actual powder commodities, real suppliers and two real consumers,
  preplanned splitters and crossing module. Then exercise convergers and larger interfaces. Use
  external fixture data and derive all game rates/geometry from catalogs. Ports remain explicit.
- Keep full JSON on disk and concise stdout. Output files must be new. Record catalog/witness hashes.

## Completion criteria

Positive bound fixture accepted by the unchanged physical validator; negative controls for missing
bridge/splitter/converger, wrong port, wrong commodity, rate overflow and dropped recipe obligations.
Inspect actual rendered geometry and failed-state images if any. Run fmt, workspace check/tests,
release CLI verification; report builds separately from execution. Commit each verified milestone.
