# Entity observation schema 2

Status: isolated implementation; merge and learned acceptance remain gated on stage 3.
This contract implements the bounded representation scope from preparation note 18.
It does not change candidate generation, accepted belt-path semantics or rewards.

## Native observation DTO

All arrays are owned. `schema_version` is scalar 2. Let `S = F + N + T` and
`E = 2*S`; entity order is facilities, networks, terminals for draft, then base.
Entity order is an index convention only, not a categorical model input.

| Field | Shape | Type | Meaning |
|---|---|---|---|
| raster | 23,H,W | float32 | Ten geometry channels per snapshot, x/y and valid-cell mask |
| entity_maps | 6,H,W | int64 | Facility/network/terminal entity at each snapshot cell; -1 is empty |
| entities | E,42 | float32 | Fixed semantic entity fields below |
| edges | L,2 | int64 | Sender and receiver entity references |
| edge_types | L | int64 | Typed ownership/incidence/correspondence relation |
| candidates | K,15 | float32 | Seven operations, direction(4), growth(2), log length and assignment count |
| operands | K,2,15 | float32 | Role(5), absolute x/y, rotation(4), arm direction(4) |
| operand_entities | K,2 | int64 | Draft entity reference, -1 for absent operand |
| operand_mask | K,2 | bool | Real semantic operands |
| points | K,2,2 | int64 | Operand spatial points relative to raster origin |
| stats | 8 | float32 | Existing budget/score/unbound statistics |

Ten geometry channels are facility occupancy, transport occupancy, four incoming
arms and four outgoing arms. Raster maps preserve network identity through gathered
entity embeddings. They cover only the existing non-overlapping belt-path scope.
Missing or off-raster operand points contribute zero spatial features, rather than
borrowing a clamped edge cell. Coordinates and widths use the existing square-root
initial-area scale. Width/height are measured geometry, not feasibility inputs.

Entity columns, in order: type facility/network/terminal (3), draft/base (2), x/y (2),
width/height (2), rotation (4), allowed rotations (4), source/target/external/bound (4),
arm direction (4), rate/capacity ratio (1), log capacity (1), utilization (1), log
input/output terminal counts (2), log input/output belt ports and input/output pipe
ports (4), belt/pipe transport kind (2), log occupied-cell count (1), bound-terminal
fraction (1), source x/y and target x/y (4). Non-applicable fields are zero. Network
x/y and size describe its occupied bounds; an empty network has zero bounds. Facility
bound fraction counts incident terminals; network bound fraction counts its two
terminals. Terminal binding status and direction remain explicit. Facility/port,
recipe and rate values come only from loaded catalogs and request data.

Relations are facility->terminal, terminal->facility, source-terminal->network,
network->source-terminal, target-terminal->network, network->target-terminal,
draft->base counterpart and base->draft counterpart. Directed role names determine
meaning independently of instance IDs. Add no graph-based pruning.

Operand roles are assignment, directed source/anchor, directed target/endpoint,
removal cell and terminal binding. Pair swaps contain two assignment operands and
preserve both current rotations. Erase endpoints share the removal role. Bind/unbind
has one terminal operand with proposed/current location and arm; discard has none.
No current action gains new powers. Length uses log(1+length); assignment count is
explicit. Mask absent operands in all normalization and pooling.

## Policy and batching contract

Use 32*width entity features and four shared typed message-passing steps. Project
entities to 8*width spatial features before raster gather. Apply the existing three
masked-BN spatial convolutions. Global context pools spatial features and masked
entity mean/max. Each candidate operand combines its entity embedding, spatial
feature and semantic operand fields using one shared MLP; masked mean pooling makes
same-role unordered operands independent of instance sorting. Directed roles remain
distinct. Score candidates with the pooled operand/context and fixed operation fields.
These are initial experimental dimensions, not an optimality claim.

Batching pads raster, entity, edge and candidate axes, with explicit masks. Prepared
CUDA rollouts account for and crop every padded axis. Parameter dimensions must not
contain F/N/T. A mixed-count forward/update must work without recreating the policy.
Normal floating tolerances suffice for equivalent inputs; do not demand identical
sampled trajectories after candidate reordering or parallel floating reduction.

Old object tables, identity one-hots and flattened fusion are removed. Legacy policy
weights are rejected with an explicit checkpoint-schema diagnostic. Mechanical
snapshot version stays unchanged because transitions and serialized layout semantics
are unchanged; observation schema and checkpoint model dimensions change explicitly.
Study compatibility compares schema/feature meaning and runtime catalog identity,
not equal production signatures or instance counts.

## Acceptance and failures

Required checks: native/reference array parity and unchanged domains/transitions;
ragged-count batch/update and BN padding invariance; entity renaming/reordering with
command-mapped logit equivalence; pair operand permutation; retained best-valid
semantics; stale build/checkpoint diagnostics; workspace verification and an actual
small CLI training smoke. New chain learning is a separately declared experiment
following mechanical cutover acceptance. A changed input, stale handle, unsupported
schema, invalid entity reference or resource guard must identify its stage and input.
No raster byte/work guard is a claim that the requested factory is infeasible.

## Mechanical verification

The isolated implementation passes 81 Python tests (78 pass, three platform/CUDA
skips), release native/reference observation parity, mixed two-/four-facility forward
and PPO update, entity-ID/operand permutation, BN padding and exact prepared-rollout
byte accounting. `cargo fmt --all`, `cargo check --workspace` and
`RUST_MIN_STACK=16777216 cargo test --workspace` complete successfully. The larger
stack accommodates the existing workspace CLI-test stack requirement.

An actual CPU `run.py train` smoke uses `case-relocation.json`, masked BN, 32 commands,
two 16-command PPO rollouts and two evaluation episodes. It completes, saves a
checkpoint and retains the valid initial score [133,14,1]. Its 70314 trainable
parameters are independent of entity count. This tiny smoke establishes executable
integration only; it reports no learned improvement and no generalization result.
The temporary config/logs/checkpoints are under ignored `target/entity-cli-smoke*`.

The cutover removes cardinality-sized input layers and same-production batching
restrictions. One shared entity/operand encoder replaces identity one-hots and
flattened object fusion. Native and independent reference observations each have
separate entity/candidate modules; mechanical transitions and production commands
remain unchanged. Learning comparisons and stage-3-gated integration are outstanding.
