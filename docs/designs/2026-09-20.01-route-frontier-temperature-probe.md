# Route frontier temperature probe

## Status and question

This is a bounded diagnostic contract, authorized on 2026-09-20. It does not
change production construction or train a new policy.

The falsifiable question is: **given a valid crossed depth-zero route generated
by the retained route policy itself, can the same frozen policy produce any
valid depth-one continuation when only its sampling temperature changes?**

The retained replay seed-303 checkpoint is the subject because its held-out
greedy evaluation already completes the single crossed route. The checkpoint,
model, native session, action domain, route budget, geometry, rewards and
catalogs remain fixed. Sampling temperature is the sole matrix axis.

## Prefix and policy contract

The probe builds two-connection crossed tasks through the existing external-data
task builder. It samples the first option from the frozen checkpoint and retains
up to eight semantically unique successful command sequences. Each retained
sequence is replayed through the normal native `Session::step` API from the same
task specification. Every command must be accepted and the reconstructed state
must contain exactly one completed route and no active provisional route.

These prefixes are policy-generated research states, not demonstrations, solver
paths or training labels. Prefix discovery is bounded at 4,096 attempts. The
probe stores their exact task specifications, commands and semantic digests so
the state distribution is visible and reproducible.

For the second option, the policy parameters stay frozen. For each conditional
factor with base probabilities `p`, temperature `T` uses the exact behavior
distribution

```text
q_T(a) = exp(log(p(a)) / T) / sum_b exp(log(p(b)) / T)
```

and records likelihood and entropy from `q_T`. No PPO or SIL update occurs.

## Controlled matrix and budget

The temperatures are `0.5`, `1.0`, `1.5` and `2.0`. Every retained prefix gets
64 independent depth-one attempts at every temperature. Therefore all matrix
cells have equal attempts and identical prefix composition. Random streams are
derived from the configured probe seed, prefix index and temperature index.

Each attempt ends on a successful commit, accepted abort, active dead end or the
existing 24-command route bound. A blocked start is recorded separately. The
probe reports for every temperature:

- attempts, successful depth-one commits and unique successful command paths;
- blocked starts, active dead ends and route-budget failures;
- accepted commands, mean commands per attempt and mean factor entropy;
- the empirical success rate and a 95% Wilson interval.

The output contains machine-readable JSON, a self-contained HTML rendering and
the reconstructed prefix manifest. Checkpoint, config, catalogs and output files
receive SHA-256 identities.

## Decision boundary

If any temperature produces a depth-one success, the next experiment may train
with frontier oversampling and a success-responsive temperature controller. Its
training rollout must keep one temperature fixed through collection and its PPO
epochs and use the matching behavior likelihood.

If all temperatures produce zero successes after at least four distinct
prefixes are found, increased exploration alone is not supported as the next
training change. The 95% upper bound will quantify the remaining success
probability, and the next controlled contrast should test the route-local
representation on these same prefixes.

If fewer than four unique prefixes are discovered, the result is
`insufficient_prefixes`; it does not decide the depth-one question. Stop after
reporting this slice and do not silently continue into training or a
representation change.

## Continuity checklist

| Existing benefit | Probe treatment | Check |
| --- | --- | --- |
| Native legality and exact occupancy | Rebuild with the existing task builder and replay through `Session::step` | Every command accepted; exactly one committed route before probing |
| Conditional policy distribution | Reuse the existing model and masks, changing only factor temperature | Behavior log-probabilities normalize and temperature one matches the existing sampler |
| Router-free ownership | Retain only commands sampled from the frozen policy | Prefix manifest contains policy commands and no generated path |
| Bounded GPU batching | Batch active attempts through the existing model | Fixed prefixes and attempts per temperature; route-turn bound unchanged |
| Evaluation separation | Load a completed checkpoint and perform no optimizer step | Output identifies the immutable checkpoint and reports zero training updates |
