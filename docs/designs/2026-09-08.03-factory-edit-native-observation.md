# Native Observation Geometry Experiment

Status: implementation authorized as a bounded Rust adoption trial, 2026-09-08.

Profile evidence identifies Python geometry traversal and raster/object construction as one
large observation cost. This slice moves that complete block to one native call and measures
input conversion and array return costs. It does not port the whole mutable environment.

## Interface and invariants

An isolated `aic-pilot-native` crate exposes a PyO3 observation encoder. Its constructor takes
runtime-derived facility sizes, terminal metadata, rotated port offsets, scale, and immutable
object feature rows from the loaded catalog. No game data lives in Rust source. A call takes
the draft/base snapshots, halo and raster cell guard. State ownership remains with Python;
Rust copies the needed geometry into owned typed values during that call. No JSON serialization,
subprocess, or per-cell Python callback occurs inside the encoder.

Output contains fresh, owned float32 raster and object arrays plus their world origin. It must
match the existing Python array shape, channel order and every byte. Coordinate feature division
stays in the existing NumPy coordinate-channel operations, including large-coordinate
`arange` behavior, while object features preserve Python float64 division
followed by float32 storage. Rotation, directed-arm channels, unbound terminals, draft/base union
and halo semantics remain unchanged. Returned arrays must not alias later calls or static tables.

The experimental Python environment subclass retains candidate generation/order, feature
encoding, command application, mechanical checks, independent acceptance, rewards and stats.
Only observation geometry construction changes. Existing training commands use Python unless
a later measured cutover is explicitly implemented. The benchmark selects the extension by an
explicit build directory and fails if missing; it never silently falls back.

Rust uses checked coordinate/dimension arithmetic and rejects semantic geometry or resource-guard
failures with stable `native.input` / `observation.resource_guard` diagnostics. An arithmetic
range failure is a diagnostic of this experimental representation, not factory infeasibility.
Python stale-candidate checks remain at the wrapper boundary. No additional raster guard is
invented; allocation is bounded by the supplied guard and checked channel/dimension products.

## Evidence and acceptance

Compile release mode separately for the local and server Python interpreters. Record the native
library hash, Rust source hashes, Cargo lockfile and build settings alongside existing runtime
and retained-input provenance. Build outputs belong in ignored `target/`.

Check initial, later and elongated retained streams, plus rotations, negative coordinates,
unbound terminals, stale candidates, resource guards and array ownership. Compare every candidate,
observation byte, transition and final draft/base/best state. Alternate baseline/native order
after warm-up and report complete environment replay time, observation time and setup separately.
Also measure the same replay interleaved with policy inference to show the practical limit of
an observation-only optimization. Do not claim a sampled training quality change from a replay.

Retain the experiment only with a reproducible result, including a negative result if conversion
cost erases the benefit. Broader Rust state ownership is a separate contract; no native speedup
can justify changing candidate or acceptance semantics.

Measured result: [native observation trial](../reports/2026-09-08.06-factory-edit-native-observation.md).
Prior-trial garbage collection is an explicit benchmark setup option; automatic collection
remains enabled in replay. Python binding type errors retain their standard exception types.
