# Full-factory edit acceptance

Status: implementation contract for the next stage-four slice. The broad learning
screen already permits moving beyond small-path reliability. This slice connects
full physical witnesses to the production validator; it does not certify a learned
policy or resume historical training.

## Boundary

Use the existing production `WitnessProbeInput` physical DTO: arbitrary facility
count within explicit materialization guards, commodity networks with multiple
terminals, rate-carrying segments, belt and pipe layers, and logistics components.
The production geometry validator remains authoritative. Do not duplicate its
junction, capacity, port, crossing or reachability rules in the learning backend.

A schema-one `FactoryEditRequest` separately fixes instance IDs, recipes,
utilizations and exact terminal obligations keyed by facility/external endpoint,
direction and item. Import these from the original production request, never from
a proposed witness. Terminal obligations aggregate compatible original wiring;
physical lane splitting and commodity sharing may change. Validate request facility
margins against loaded recipes before accepting a root. Every candidate must contain
exactly the requested inventory and satisfy every original terminal obligation,
including the original external node, commodity, direction and rate. An internal
input cannot be converted to an external purchase. Surplus exports remain explicit.

The physical DTO's generated requirement labels do not replace the original request
ledger. No pending margin, extra facility, changed recipe/utilization, invented
external endpoint or missing network can make an edit valid. Connected production
cycles are allowed; reachability still rejects transport-only disconnected circulation.
This is steady-state physical/material acceptance, not power or startup certification.

## Session

A `FactoryEditSession` owns its immutable request and catalog bundle, validated root,
current complete layout, and best complete layout. It accepts whole physical proposals
as closed transactions. The policy/executor builds proposals privately; this API does
not select a destination, reroute, construct a factory, or invoke an exact solver.
A valid temporary deterioration may become the exploratory current state. The best
layout changes only on lexicographic improvement: used area, physical layer tiles,
then directed perpendicular input/output arm pairs, including facility and external
arms. Version this metric explicitly because old research scorers differ on endpoint
arms. Report XY occupancy separately from physical layer tile cost.

Requests and physical schemas are explicit. Numeric/count/span guards are operational
validation limits, not game W/H limits. Canonicalize translation to the actual used
minimum before checking geometry; unused positive or negative coordinate capacity
never changes score. Reject arithmetic overflow and unsupported component footprints
before invoking the existing geometry materializer.

Every selected proposal consumes a proposal slot, including malformed physical
geometry and unchanged results. Check the elapsed budget before and after validation;
a late result cannot update current or best. These checks prevent late commits, not
preemptive interruption of the validator. Root initialization is measured separately.
A bounded caller may stop earlier; retained output always includes a validated root.
Reports expose stable status, diagnostics, proposal number, candidate/current/best
metrics, validation time and deadline termination. They must not label an exhausted
budget as global infeasibility. A JSON Python binding loads explicit catalog paths
and exposes reset-by-construction, proposal checking and retained witnesses; it does
not claim observation/model compatibility with historical single-path checkpoints.
