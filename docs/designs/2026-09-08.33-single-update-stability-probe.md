# Single-update stability probe

Status: declared before outcomes. Diagnostic private updates only, outside the
capacity protocol and production planner. No training continuation is selected.

The weight/buffer intervention identifies a 32-update regression without locating
its mechanism. Measure one controlled fresh-data update at the old width-one
seed-43 checkpoint, including policy movement outside the optimizer's reported KL.
This is not a replay of the historical CUDA training update or proof of its cause.

## Contract

Inputs: the audited 1179648-command checkpoint, including Adam state; the same
sixteen admitted training roots; frozen native and policy sources; and
`tools/factory-edit-pilot/update-stability.json`. Verify checkpoint/audit hashes
and save the unchanged anchor before collecting outcomes. CPU, one thread.

Collect 1024 fresh commands: four rounds of sixteen parallel root episodes, each
sixteen commands. Use independent CPU generators from base seed 1026000 with the
collector's declared stream offsets and continuous states across rounds. Use the
corrected candidate-count sampler. No curriculum prefix or free repair. Replay all
64 collection episodes independently and retain the rollout and its provenance.

Clone identical policy and saved Adam state for learning-rate multipliers
0, 0.1, 0.3 and 1. Each branch performs exactly one standard update: four epochs,
64-sized minibatches, identical shuffle seed 1027000, and the existing single
normalization-calibration pass. Zero learning rate isolates calibration while
still exercising identical optimizer machinery. Do not save any branch as a
production actor, retention choice, or resumed training run.

Measure exact categorical KL(reference || candidate), total variation, sampled
log-probability movement and value RMS movement over every collected observation.
Exclude padded candidates. Capture three pairs: anchor to post-optimizer,
anchor to post-calibration, and post-optimizer to post-calibration. Keep the
existing sampled minibatch `approx_kl` separately named. Instrumentation must not
alter model, optimizer or RNG outcomes relative to the ordinary update.

Freeze all five actors before root evaluation, including the unchanged anchor.
Evaluate each on all sixteen training cases, sixteen paired fresh seeds starting
at 1028000, horizon 128, batches of sixteen. All 1280 incumbents require native and
independent reference acceptance; replay best and median per cell. Preserve score
priority and account for all 163840 evaluation commands plus 1024 collection
commands. Retain complete episode scores, selected traces, actor and input hashes.

Output: schema-one `stability.json` with status, protocol/provenance, rollout hash,
per-branch optimizer metrics and policy distances, per-case scores and paired
comparisons, timings, and validation. Reject changed inputs, missing Adam state,
nonfinite distances, altered frozen actors or existing output paths. On failure,
write a structured `update_stability.interrupted` diagnostic with error severity,
`single_update_stability` stage and active condition/case when available.

## Interpretation and verification

Learning-rate comparisons are coupled on the same collected observations and
Adam state. A smaller step with smaller policy movement supports bounded update
control as a follow-up; it does not establish long-run retention or generalization.
One update may show no measurable root-quality effect. This is still useful when
it quantifies the otherwise unmeasured calibration contribution. Preserve the
ongoing six-stream server study and all held-out gates unchanged.

Test categorical distances against hand-computed distributions, padded-domain
exclusion, zero identical-policy distance, and instrumented versus ordinary update
state/RNG equality. Run the full Python suite, workspace checks/tests, CLI help,
full diagnostic, and artifact checks. No new dependency or production API change.
