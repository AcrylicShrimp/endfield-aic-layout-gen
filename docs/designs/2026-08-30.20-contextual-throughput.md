# Contextual Throughput

## Scope

Contextual throughput calculates fixed recipe-occurrence run rates and material-edge flow rates from a contextual production graph. It preserves every hierarchy-path occurrence through the rate report instead of aggregating by recipe or item ID.

This stage does not select sources, merge co-product occurrences, round continuous work into facility counts, place facilities, select ports, or route transport.

## Input And Output

`aic recipes contextual-throughput --file <recipes.json> --request <source-plan.json>` accepts a validated recipe book and a source-plan request. Source checking and contextual graph projection must both succeed before rate calculation begins.

The report contains:

- the target item rate;
- recipe run and work rates keyed by recipe-occurrence node ID and hierarchy path;
- material flow rates keyed by contextual graph edge ID and demand path;
- external input rates per external-input occurrence;
- surplus output rates per recipe occurrence;
- bootstrap material options for cyclic components;
- unresolved source paths on upstream failure;
- structured diagnostics owned by `contextual-throughput`.

## Linear Model

The model creates one nonnegative continuous run-rate variable for every recipe occurrence and one nonnegative flow variable for every material edge.

For every recipe input, its single incoming contextual edge satisfies:

```text
edge flow = recipe input quantity * recipe occurrence run rate
```

For every recipe output:

```text
sum(outgoing edge flows for this item)
    <= recipe output quantity * recipe occurrence run rate
```

The root target edge equals the requested target rate. The objective minimizes total recipe work seconds per second. Unused recipe outputs become occurrence-owned surplus. External-input occurrence rates are determined by the consuming recipe constraints rather than by free global item balances.

## Cycles

The same equations operate on acyclic and cyclic contextual graphs. A cycle back-edge consumes output capacity from its referenced ancestor occurrence and supplies an input of another occurrence. An infeasible steady-state circulation returns `contextual-throughput-infeasible`.

Bootstrap options are the item IDs carried by recipe-to-recipe edges inside a directed cycle. They describe possible one-time initialization materials, not continuous external input rates or a startup schedule.

## Exact Report Verification

The LP backend returns floating-point values. Recipe occurrence rates are converted to bounded rational `Rate` values. Edge rates are then derived exactly from the target rate or the consuming occurrence input equation. The stage verifies every source output capacity with rational arithmetic before returning success. A rationalized result that violates the contextual graph returns `contextual-rate-rounding-error`.

## Follow-on

Facility requirements must next round each occurrence work rate independently and retain occurrence IDs. Instance wiring can then consume the contextual edge rates directly without rediscovering producers by global item ID.
