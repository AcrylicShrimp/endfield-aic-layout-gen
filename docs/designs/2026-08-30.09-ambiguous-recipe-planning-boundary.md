# Ambiguous Recipe Planning Boundary

## Decision

Multiple recipes may legitimately produce the same item in the game data. That is not a structural recipe-catalog error and it is not a spatial solver decision.

The validated recipe book therefore indexes every producer for an item. Graph resolution proceeds automatically when exactly one producer exists and returns `ambiguous-recipe-producer` with a stable sorted recipe list when more than one producer is encountered.

An external input cutoff takes precedence over producer resolution. A user can stop at an ambiguous intermediate item by declaring it external without selecting any producer.

## Solver Boundary

The layout solver receives only a successfully resolved, fixed facility-instance graph. It never chooses recipes, facility modes, or graph depth.

The current CLI reports ambiguity as an error. A later interactive frontend may present the same recipe list to the user and resubmit an explicit planning choice without changing the spatial solver contract.

Recipe cycles follow the same boundary. Cyclic recipes may exist in the catalog, but graph resolution returns `recipe-cycle` when a requested plan traverses one. The user can cut the loop at a supplied external input. Cycles are never passed to the spatial solver.
