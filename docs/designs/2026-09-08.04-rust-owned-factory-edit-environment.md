# Rust-Owned Factory Edit Environment

Status: architecture direction selected by the user, 2026-09-08. Interface contract defined;
full native environment implementation is the next work unit. The observation-only trial
remains the completed evidence baseline, not the final architecture.

## Ownership boundary

Rust owns runtime catalogs, request validation, root/draft/working-base/episode-best layouts,
geometry and adjacency indexes, terminal assignments, candidates and their feature encoding,
edit application, mechanical checks, independent factory acceptance, scores, rewards, horizon
accounting, traces, and observation arrays. It retains this state across calls. Python must not
reconstruct the entire factory or run duplicate rule logic on each action.

Python owns PyTorch parameters, inference, action sampling RNG, PPO/GAE/Adam, rollout assembly,
evaluation scheduling, metrics/plots, and top-level training checkpoints. Training and evaluation
both drive the same Rust engine. Evaluation is not a separate Python implementation of factory
rules. Python's independent acceptance/environment code survives only as isolated migration
verification and historical research reference after the cutover.

The hot boundary is observation arrays outward and an action index inward. Full state export
is available explicitly for interruption, checkpoints, independent audit and visualization.
Catalogs load from their external files on each execution; native code contains schema/rule
logic, not facility, recipe, item or balance tables. No global exact solver is involved.

## Input and output contract

`Engine.open(root, case_path, environment_config)` loads the runtime inputs and returns an
owned engine. Admission errors identify the input path and stable diagnostic code. Metadata
exposes environment/schema versions, catalog/request/source hashes, category ordering and
dimensions, resource guards, and initial score. Model/PPO settings are not environment inputs.

`reset()` restores root/draft/base/best, episode counters and traces with existing semantics.
It invalidates previous candidate handles. Global performance counters remain cumulative.

`observe()` produces an owned observation bundle: float32 raster/object/candidate/stats arrays,
int64 candidate point arrays, and a separate opaque candidate handle containing an episode
generation and revision. The handle is execution metadata and never a neural input. Arrays
retain their values after later steps and resets, and have explicit shapes/dtypes/channel order.
The engine keeps the matching ordered command domain; Python does not materialize every command.

`step(handle, action_index)` selects the exact native command. Invalid index/foreign-generation
handles are API errors with unchanged state; these are not sampled edit attempts. For valid
handles, native edit application, command charging, rejection, completion, base promotion,
best-score update, reward and horizon termination preserve the existing environment contract.
Return reward, done, applied/complete/new-completion/improved flags, structured diagnostics,
and relevant scores/counters. Materialize the selected command for trace/report use only.

`export_state()` produces a versioned snapshot containing root identity, draft/base/best,
scores, steps/revision/generation, traces and counters needed to reconstruct every partial
episode. `restore_state(snapshot)` validates versions and provenance before restoring. Rebuild
derived indexes; never trust cached validation conclusions from the serialized input. The
snapshot contains all mutable engine state, not only a seed. Reconstructed candidate handles
must prevent use of observations from another live engine or pre-restore generation.

`export_layout(which)` and explicit diagnostic candidate export preserve independently
auditable external DTOs. These exports are outside the ordinary per-action boundary.

## Semantic preservation

Keep all seven edit operations, exact candidate membership and existing canonical JSON-derived
order. A native comparison key may replace JSON serialization only after proving equivalent
ordering, including negative/multi-digit coordinates, field ordering and identifier escaping.
Do not change the policy distribution by presenting candidates in a different order.

Preserve draft/base separation, automatic complete-factory checks after applied edits,
lexicographic score `(used area, physical transport tiles, turns)`, and reward from improvement
in best validated area. Incomplete drafts remain editable; they never become accepted factories.
`DISCARD_EDIT` restores the latest valid base, which may differ from the root or episode best.
Keep the existing directed-path pilot scope; a language migration does not add crossings,
junctions, repair heuristics, route search or relaxed external-boundary rules.

Preserve observation values, including arithmetic evaluation order and NumPy coordinate-channel
behavior. If an external DTO/arithmetic range cannot be represented exactly, reject it with an
explicit diagnostic rather than overflow, truncate or silently reinterpret it. Existing raster
guards are resource controls, not game dimensions or feasibility bounds.

Learning parameters, rollout/horizon exposure, episode boundaries, GAE ordering, sampling RNG
consumption and update count remain fixed. GPU batched collection is an independent execution
change and must not be mixed into the parity comparison for this migration.

## Milestones and completion criteria

1. Implement typed native catalog/state ownership and versioned snapshots. Verify load/reset/
   export/restore, rotations, bindings and exact request rates against the Python reference.
2. Implement native candidates, all edits and independent acceptance as one coherent transition
   path. Replay retained and adversarial commands; compare domain order, outcomes, diagnostics,
   draft/base/best states, rewards and counters after every step.
3. Complete native observations and candidate features on the retained state. Compare every
   array byte, stale-handle behavior, ownership, guard failure and interruption snapshot.
4. Cut training and evaluation over together. Remove the obsolete production Python environment
   and partial observation bridge; keep reference code outside normal execution. Version native
   checkpoints explicitly and reject incompatible legacy continuation with a clear diagnostic.
   Measure release-mode replay and a full equal-exposure training run; audit layouts and traces.

Each milestone is independently verifiable and does not expose an unfinished fallback in normal
training. Do not claim the full migration complete before the final cutover passes normal checks.
Reports must distinguish native compute, boundary/array transfer, inference and PPO costs, and
account for setup and GC measurement effects. The current observation-only 5–6% CUDA replay gain
is evidence for the boundary direction, not a prediction for a complete Rust environment.
