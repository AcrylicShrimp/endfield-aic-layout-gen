# Curriculum and parallel PPO experiment

Status: implemented and evaluated; see [results](../reports/2026-09-08.13-curriculum-parallel-ppo-results.md). This is isolated learned-edit research, not a
production constructor change. Behavior cloning and supervised action targets are excluded.

## Frozen question and protocol

Does success-near-start training increase original-root improvement, and does concurrent
native environment execution with batched GPU inference improve collection throughput?
Compare root-serial, curriculum-serial, root-parallel and curriculum-parallel on the same
A/B cases and seeds 17, 29 and 43. Each run gets 65,536 sampled edits, alternating A/B
by episode, 128 edits per episode and 1,024 samples per PPO update. Four PPO epochs and
64-example minibatches give 64 optimizer steps per update. The previous 256-sample
study is historical context, not the matched control. All four conditions use unchanged
policy architecture, candidate semantics, reward, optimizer parameters and catalogs.

Serial collection completes eight episodes in order using CPU inference. Parallel
collection uses eight independent native engines, one persistent Python thread pool,
and a batched CUDA forward pass. Native observation and transition work releases the
GIL; Python owns no environment rules. Both collectors flatten complete episodes in
stream order before GAE. Done masks end every episode; no return crosses streams and
no unfinished trajectory is bootstrapped with zero. The policy stays fixed during each
collection round. CPU sampling of batched GPU probabilities uses independent per-stream generators. Numerical
and sampling trajectories can differ; throughput and learning are measured separately.
A bounded replay benchmark also compares batched inference with sequential versus
concurrent native work, so threading is not credited for GPU batching's contribution.

## Curriculum start contract

Input: an ordered JSON array of existing candidate commands, selected from the prefix
before the first positive reward of each case's already validated witness. A requires
six commands and B three. Remaining lengths 1, 2 and 3 use prefixes of lengths 5/4/3
for A and 2/1/0 for B. These are known sufficient suffix lengths, not shortest-path
proofs. B's third level already equals its original root. This is privileged starting
state selection; it supplies neither action labels nor a supervised loss.

The native reset API replays each prefix command through its actual candidate domain.
It rejects absent/rejected commands, positive reward, changed retained best/base, or
prefix exhaustion of the horizon. Admission is transactional. Successful setup keeps
the mechanically valid draft, original valid base/best, original reward denominator,
and original observation feature meanings. It resets episode steps, revision, trace
and episode counts to zero and invalidates old handles. Snapshots remain restorable;
external run evidence stores the prefix separately from the policy's 128-edit trace.
Malformed prefixes produce structured errors and leave the previous state intact.

Fixed curriculum schedule by sampled-command count: remaining-one until 8,192,
remaining-two until 16,384, remaining-three until 24,576, then original-root training
through 65,536. Each block splits exposure equally between A and B. Advancement is
fixed rather than based on evaluation outcomes, to avoid tuning on held-out seeds.
Every preparation action is counted separately and its wall time is included in
training time. Prefix rewards cannot enter PPO or training returns. No shaping,
demonstration replay, imitation loss, search hints or initial policy warm-start is used.

## Outputs, failures and acceptance

Checkpoints at 0, 8,192, 16,384, 24,576, 32,768 and 65,536 include model, optimizer,
all sampling/minibatch RNGs, environment snapshots and scheduler state. Interrupted
runs retain partial rollout and per-stream states; automatic resume is not promised.
Metadata records source/native/input hashes, stage exposure, preparation count,
sampled edits, episodes, optimizer steps, training and collection/update/evaluation
seconds, per-case champions and status. Errors include stable code, severity, stage,
message and entity. Fresh output directories prevent overwriting evidence.

All frozen evaluations start from original roots: 32 fixed sampling seeds per case,
128 edits, CPU inference, unchanged acceptance. Report mean/median/max area reduction,
success frequency, multiple-improvement frequency, and actual selected geometry.
Curriculum episode gains are separate from original-root performance. A selected
curriculum layout's replay includes its recorded setup prefix, without counting that
prefix as policy behavior. Three training seeds are the independent replicates.

Verify start admission/rollback/handle invalidation, unchanged root behavior, threaded
versus serial native parity, per-stream GAE and padded batch logits, fixed evaluation
isolation, interruption evidence and exposure audits. Run workspace checks/tests,
Python tests, small actual CLI runs and the complete frozen 12-run matrix before
reporting an outcome. A negative or slower result is valid; do not retune this study
silently. Preserve full checkpoints under ignored artifacts, commit concise findings
and compact provenance. No global optimality or unseen-case generalization claim.
