# Exact Observation Construction Cost Reduction

Status: bounded implementation experiment, 2026-09-07.

The user prioritizes elapsed time and requested further optimization before expanding training.
The completed CUDA run spent 72.402 s in candidate and observation construction. A local profile
of the retained 256-command elongated-state sequence attributes 0.459 s of 1.172 profiled seconds
to observation construction's own Python work, plus 0.065 s to array conversion. These profiling
clocks guide implementation; they are not benchmark speedup measurements.

## Contract

Keep the same command set and exact canonical ordering, all candidate mechanical checks,
observation feature ordering/dtypes/numeric values, transitions, acceptance, and rewards.
The first change directly populates sparse one-hot candidate features in an allocated NumPy
array instead of constructing and converting dense Python float lists. Immutable category
indexes and lazily constructed one-hot templates derive from runtime catalog identifiers.
Template keys contain only finite action/catalog categories, never coordinates or mutable state;
returned observation arrays own their copies. Reuse an unchanged standard JSON encoder for
sorting rather than reinitializing it for every command. Do not cache mutable state or alter
network inference, optimizer, model size, learning budget, or numerical precision.

## Evidence

An explicit diagnostic loads the trusted pre-change environment source from a named Git commit.
On identical recorded actions, compare every candidate dictionary in order, every observation
array bit for bit, every step outcome/reward, and final serialized draft/base/best states.
Time old/new environment work in alternating rounds after warm-up. Retain input hashes, source
hashes, sample counts, timings, and parity results under ignored artifacts. Production imports
only the new implementation; the old source remains isolated to the Git-backed diagnostic.

Run the existing behavior tests and repeat a complete server CUDA training allocation against
its prior same-seed run. Report elapsed time and actual learned outcomes separately, checking
whether final model tensors and raw episode outcomes stay equal. Exact observation preservation
does not by itself promise equal timing-dependent backend behavior. Continue longer training
on its unchanged-source server snapshot to avoid mixing learning-duration and runtime changes.
