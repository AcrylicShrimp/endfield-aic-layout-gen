## Cells and arithmetic

First compare optimized CPU FP32 with optimized CUDA FP32 at bounded
microbatch sizes, including the measured CPU choice of eight. Each cell uses
the complete same shuffled 64-selection minibatch, accumulating microbatch
contributions before exactly one actor and one critic optimizer step. Exact-
shape raster buckets preserve GroupNorm and graph boundaries.

Measure CPU preparation plus device transfer, resident learner computation,
and combined preparation/transfer/computation separately. A resident-only
speedup is not the end-to-end result. Prepare fixed metadata on CPU before
moving complete prepared tensors to the selected device. Record preparation
and transfer costs without per-observation device synchronization hidden inside
candidate filtering. Reset model and Adam state outside every timing interval.

After the device comparison, compare CUDA FP32, BF16 autocast and FP16 autocast
with GradScaler on the selected GPU microbatch configuration. Keep parameters,
Adam state, categorical normalization, probabilities, ratios, advantages,
targets, loss reductions, graph accumulation and normalization in FP32; allow
linear and convolution work under autocast with explicit FP32 output boundaries.
Disable TF32 for FP32 cells and record deterministic settings and the actual
Torch/CUDA/device build. Do not run AMP before the FP32 device comparison.

Compute categorical entropy with masked log terms set to zero before
multiplication by probability. The library entropy's finite minimum sentinel
for masked logits produces nonfinite gradients under loss scaling, including
with otherwise FP32 arithmetic; this was reproduced locally. The masked terms
have exactly zero probability. Apply this algebraic rewrite in every cell and
verify it against the frozen update with nonempty Adam state, both with and
without gradient scaling. This rewrite is already verified in the optimized CPU path and preserves
the unscaled reference update.

For FP16, scale each minibatch contribution, unscale both optimizers before
separate gradient clipping, step both optimizers and update the shared scaler
once. Record actual optimizer step calls, scaling changes and nonfinite
gradients. An overflow-skipped update is not a completed equivalent update.

## Output and interpretation

Write a structured report containing input identities, sample order, cell
status, warmup/timing results, peak CUDA allocation, actual optimizer steps,
losses, old-log-probability drift, critic-value drift, gradient norms,
gradient cosine/relative L2, and parameter drift after one update against the
CPU FP32 reference. Preserve full per-cell numeric vectors only in ignored
artifacts if needed; concise statistics suffice for tracked findings.

Expected cross-device floating-point differences are measured rather than
required to match CPU behavior hashes. The stored behavior denominator stays
the actual CPU behavior log probability. Do not silently recompute a different
old policy. Any future GPU collector needs its own declared precision and
replay contract. Finite or close gradients alone do not prove unchanged learned
performance. Faster update kernels alone do not prove faster complete training.

Failures carry stable `ppo-precision.*` codes, cell identity and the offending
input path or operation. Missing prerequisites and invalid reference identities abort before timing.
These reference-input checks are probe work, not recurring training validation. Cell-specific device/dtype limitations produce
explicit failed cells; never substitute another precision under the same name.
