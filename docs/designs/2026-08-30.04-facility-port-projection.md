# Facility Port Projection Contract

## Purpose

Facility port projection converts canonical facility catalog ports into world-grid routing endpoints after facility placement has selected a position and rotation. It is a deterministic geometry stage; it does not choose routes or alter placement.

## Inputs

The stage consumes:

- a successful `FacilityPlacementReport`;
- a `ValidatedFacilityCatalog` using schema version 3;
- the validated `FacilityPlacementRequest` that defines the hard layout width and height.

The placement request is an explicit input because an outward-facing port needs one connection cell beyond the facility footprint, and that cell must remain inside the system layout bounds.

## Output DTO

```json
{
  "success": true,
  "ports": [
    {
      "instance": "facility-instance:grind:0",
      "facility": "grinding-unit",
      "port": "solid-input",
      "direction": "input",
      "transport": "belt",
      "position": { "x": 7, "y": 4 },
      "edge": "south",
      "connection": { "x": 7, "y": 5 }
    }
  ],
  "diagnostics": []
}
```

`position` is the occupied facility cell containing the port. `connection` is the adjacent world-grid cell immediately outside `edge`; it is the first cell available to a later belt or pipe route.

Ports are sorted by facility instance ID and then port ID so equivalent inputs produce deterministic reports.

## Invariants

- The upstream placement report is successful.
- Every placed instance ID appears once.
- Every placement references a catalog facility.
- The selected rotation is allowed by that facility.
- Placed width and height match the rotated catalog footprint.
- The placed footprint is inside the placement request bounds.
- Every projected connection cell is inside the placement request bounds.

The last invariant intentionally exposes placements that use all available rectangle space but leave an outward-facing port unusable. A later integrated placement-and-routing model must reserve those endpoint cells while solving.

## Failure Report

Any validation failure returns `success: false`, an empty `ports` array, and one or more structured diagnostics. Diagnostic codes are:

- `upstream-facility-placement-failed`
- `invalid-facility-placement-request`
- `duplicate-placed-facility-instance`
- `missing-facility-definition`
- `disallowed-facility-rotation`
- `unsupported-facility-rotation`
- `placed-facility-dimensions-mismatch`
- `placed-facility-out-of-bounds`
- `facility-port-connection-out-of-bounds`

## Deferred Work

- Assigning logical item-flow edges to compatible physical ports.
- Reserving projected connection cells in the placement constraint model.
- Routing belts and pipes through free cells.
- Enforcing transport capacity and bridge rules.
