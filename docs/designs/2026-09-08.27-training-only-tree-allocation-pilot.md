# Training-only tree-allocation pilot

Status: declared before tree-search outcomes. Implements the next bounded slice of
[the search contract](2026-09-08.26-factory-edit-tree-search-probe.md); no production cutover.

## Fixed inputs and question

Use all sixteen frozen entity training cases and sampling seeds 1000000, 1000001 and
1000002. Compare random independent rollouts, frozen-policy independent rollouts,
UCT with random rollout, and PUCT with frozen-policy rollout at 128, 1024 and 8192
native-transition allowances. All rollouts begin at the original valid root and have
at most 32 commands. Every tree-path replay is charged as a transition; restoration
does not erase external accounting. There are no executed production edits. Every
retained completion is explicitly labeled as discovered by hypothetical exploration.

The learned arms use the final 3145728-command checkpoint of width one, training seed
17, from the ongoing declared capacity matrix, after that stream's complete independent
audit. This choice is fixed before the stream completes; it does not use development
results, root eligibility or a quality-based checkpoint choice. Freeze source and
checkpoint hashes before the first comparison cell. Keep the other training streams
running on their frozen source. A weak final policy is a valid training-only result.

This asks whether tree allocation helps beyond independent trials under a common
transition allowance on already trained geometry. Three sampling seeds do not establish
generalization or architectural superiority. All current development and held-out
outcomes remain reserved for capacity confirmation. Search parameter selection and
fresh outcome confirmation require a later declared study.

## Search semantics

Maintain a tree of complete action histories; no transposition table or permanent
candidate pruning. Restore the original full snapshot for each simulation, regenerate
handles and replay the selected tree path. Add at most one child per simulation, then
roll out to the remaining horizon. A fixed array pool bounds retained nodes and stores
child/sibling/action indices, visits and value sums; it does not retain per-node native
snapshots or observations. The measured restore cost supports this simple initial form.

UCT visits unexpanded actions in seeded random order before using
`mean_return + sqrt(2) * sqrt(log(parent_visits) / child_visits)`.
PUCT considers every legal action, including unexpanded actions with zero visits/value,
using `mean_return + 1.25 * policy_prior * sqrt(max(1,parent_visits)) / (1+child_visits)`.
Ties are resolved by the declared local sampling generator. No root Dirichlet noise,
temperature tuning or top-k filtering. PUCT and its rollout use the identical frozen
policy. Independent policy rollout uses the same action distribution and horizon.

Back up the actually observed retained area reduction relative to the original root,
with discount one. The value head is not used: its longer-horizon calibration has not
been established. This pilot tests policy-guided MCTS, not the full AlphaZero learning
loop or a value-guided leaf evaluator. A later value experiment must validate that
additional assumption. Final result selection remains lexicographic area, tiles, turns.

## Bounds, evidence and failures

Each cell has a 60-second exploration allowance, 16384 retained nodes and a 1 MiB
tree-array memory allowance. Check time between operations, report any overrun, and
include final validation/replay in total elapsed time. The tree limit covers allocated
array storage and headers; it is not a process-RSS promise. Report process peak RSS
separately, along with native operations, model calls, tree nodes, restores, rollout
count, first improvement and branching counts. Stop at the first exhausted bound and
keep the validated incumbent. If one method stops early, do not treat its result as
a completed matched-transition comparison.

Independently validate every final selected layout and replay its complete retained
trace from the original root. Keep the original if no valid better layout was found.
No witness prefix, free repair, environment change, or tree-supplied fake score is
allowed. Validate policy tensors/BN unchanged. Record training cost separately.
Malformed inputs, provenance mismatches or replay disagreement are explicit errors.

Publish every case/method/seed/budget result, including zero gains. Compare original
area, retained score, translation, success frequency and paired score differences,
alongside actual charged work and elapsed cost. Do not interpret transition matching
as wall-time matching. After this initial cost/quality curve, declare any dedicated
wall-budget comparison before running it; do not retrofit such a claim onto these cells.

## Executable pilot

`tree_search_pilot.py --source <matrix-directory> --protocol
tools/factory-edit-pilot/tree-search-pilot.json --native-library <path> --output
<fresh-directory>` requires the designated stream's matching audit even if other
matrix streams are still running. It uses CPU inference with one Torch thread for
every learned arm, allowing this pilot to run locally without perturbing the server
capacity study. This is a separately reported hardware condition, not a comparison
to the server's batched CUDA throughput. Rotate the four method execution positions
by sampling-seed index. The file freezes all other budgets and ordering.

The result contains 576 cells when complete, each with native validation, independent
acceptance and full representative replay, hypothetical-work accounting and retained
layout/trace hashes. The selected source records the current matrix snapshot hash;
later completion of other streams need not change this already audited policy.

`tree_search_summary.py --source <completed-pilot> --output <fresh-json>` verifies
the full declared cell matrix and retained artifact hashes, then reports every case's
actual median/best score and translated success count. It gives cases equal weight
through their median-area ratios. Paired UCT/random and PUCT/policy comparisons use
the full lexicographic score and exclude pairs where either transition allowance was
not completed. They explicitly make no wall-time-matching claim. Recorded RSS is the
process-lifetime high-water mark, not an isolated per-method peak allocation.
