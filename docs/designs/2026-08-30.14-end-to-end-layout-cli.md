# End-to-End Layout CLI

## Command Contract

`aic layouts solve` is the first user-facing command that executes the complete implemented pipeline:

1. load and validate the recipe book and throughput request;
2. calculate recipe throughput;
3. calculate dedicated facility counts;
4. build recipe and facility-instance wiring;
5. load and validate facility and item transport catalogs;
6. load hard maximum width and height;
7. jointly solve placement, rotation, port selection, boundary terminals, and routes;
8. write the integrated layout report as JSON.

The command requires explicit paths for every runtime data contract. It does not compile game data into the executable or guess which catalog file to use.

## Time Limit

`--time-limit-seconds` is a required-positive CLI value with a default of 10 seconds. When the limit expires after an incumbent is found, the report is successful with status `feasible`. When the solver proves the minimum total route length, status is `optimal`. Expiration before any incumbent or proof returns `unknown` and a failing exit status.

The library keeps both an unlimited proof-oriented entry point and an explicit timed entry point. Tests use the unlimited entry point only for small bounded models.

## Diagnostic Boundary

Each upstream stage writes its own structured failure report and stops the pipeline. Invalid placement-request JSON is represented as an integrated-layout diagnostic. Catalog file open and parse failures include the offending path.

## Current Scale Boundary

The command proves the full contract on the repository's three-recipe, four-route example and returns a feasible result within a two-second manual run. The current fully enumerated multi-commodity grid model is not yet expected to solve the larger official seed-loop instance graph efficiently. Candidate and route-domain reduction is the next solver-engineering stage; the CLI exposes the limitation through bounded `feasible` or `unknown` statuses rather than hanging indefinitely.
