# End-to-End Layout CLI

## Command Contract

`aic layouts solve` is the first user-facing command that executes the complete implemented pipeline:

1. load and validate the recipe book and throughput request;
2. calculate recipe throughput;
3. calculate dedicated facility counts;
4. build recipe and facility-instance wiring;
5. load and validate facility, item transport-kind, and transport-capacity catalogs;
6. load hard maximum width and height;
7. jointly solve placement, rotation, port selection, boundary terminals, and routes;
8. write the layout solve report as JSON.

The command requires explicit paths for every runtime data contract, including `--transport-catalog`. It does not compile game data into the executable or guess which catalog file to use.

The top-level success report preserves `bootstrap_item_options` from throughput planning next to the spatial `layout` report. This keeps one-time cycle startup inputs visible without making bootstrap inventory a spatial solver decision.

## Time Limit

This time-limit flag was superseded by the versioned `--optimization-config FILE` contract in `2026-08-30.31-incremental-scc-optimization-plan.md`. The configuration's `total_time_limit_ms` is the single caller-supplied strategy budget.

The library keeps both an unlimited proof-oriented entry point and an explicit timed entry point. Tests use the unlimited entry point only for small bounded models.

## Diagnostic Boundary

Each upstream stage writes its own structured failure report and stops the pipeline. Invalid placement-request JSON is represented as an integrated-layout diagnostic. Catalog file open and parse failures include the offending path.

## Current Scale Boundary

The command proves the full contract on the repository's three-recipe, four-route example and returns a feasible result within a two-second manual run. It also solves the official normalized moss seed loop at one item per four seconds: one planter, one seed collector, two feedback routes, and one target route fit within the 12 by 8 example bounds, while crop and seed remain visible as bootstrap alternatives.

The current fully enumerated multi-commodity grid model is not yet expected to solve higher-rate official instance graphs efficiently. Candidate and route-domain reduction is the next solver-engineering stage; the CLI exposes the limitation through bounded `feasible` or `unknown` statuses rather than hanging indefinitely.
