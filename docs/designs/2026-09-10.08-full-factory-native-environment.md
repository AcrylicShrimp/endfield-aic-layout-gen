# Full-factory native environment contract

Status: implementation contract, written after the completed baseline profile
and historical comparison, before the full-factory cutover. The user authorized
profile → historical comparison → contract redesign → implementation → second
profile. The selected training input is `current-history-16`; existing registered
input contracts remain explicit and preserve their meaning.

## Evidence and scope

The [baseline profile](../reports/2026-09-10.07-full-factory-ownership-profile.md)
identifies repeated state canonicalization during fresh initial randomization,
Python observation construction, Node candidate preflights and complete-state JSON
transfers. Native physical acceptance itself is inexpensive on these inputs.
The redesign must remove those ownership and repeated-work defects, not merely
move JSON strings to a different subprocess.

This replaces the current full-factory environment used by PPO collection and
held-out evaluation. It also replaces the setup-edit environment used to generate
fresh starts. Preserve the current complete-factory physical domain: multiple
commodity networks, shared trunks/components, belts/pipes, branches, cycles,
port assignments, explicit boundary endpoints and exact rates. The older restricted
directed-path engine is historical evidence and is not a fallback or substitute.
The production constructor and its budgets/pipe-first connected growth semantics
are unchanged. No global exact solver is involved.

## Ownership

A Rust runtime loads external catalogs once per execution and owns validated typed
catalogs and immutable lookup indexes. New requests and rates still arrive from
external source files on each execution. No facility, recipe, item or balance data
moves into code. A runtime is local to one collection worker.

Each Rust episode owns the immutable original request, initial/current/retained-best
complete layouts and scores; candidate commands and their order; geometry, port,
chain and movement indexes; seen/failed-action memory; bounded action/outcome history;
selected/proposed counts; deadline/work budgets; rewards; traces and observation
buffers. Physical identities are computed once per distinct retained state revision
and reused across candidate keys and setup choices. Native validation continues to
accept only complete transactions against the original request.

Python owns actor/critic parameters, inference, action sampling RNG, actual sampled
log probabilities, entropy, rollout assembly/storage, GAE/PPO/Adam, evaluation
schedules and run-level checkpoints/monitoring. It does not reconstruct geometry,
make candidate/movement decisions, route, normalize complete layouts or compute
physical-state identities on each action. Node is removed from ordinary full-factory
collection and setup execution. Historical prototypes/oracles may remain only as
explicit verification/research tools outside the normal call graph.

## Native inputs and lifecycle

Use a versioned `FullFactoryRuntime`/`FullFactoryEpisode` PyO3 boundary rather than
an adapter that emulates the obsolete describe/execute/full-snapshot loop.
Runtime metadata includes schema/build/source/catalog hashes and supported input
contracts. Episode configuration names the observation contract, selected-action
horizon, elapsed allowance, route-expansion allowance and selection-memory setting.
Those are operational/episode bounds; factory width and height remain measured
outputs, never new caller-supplied feasibility limits.

An episode opens an original `FactoryEditRequest` and `WitnessProbeInput`, validates
them once at the external boundary, and retains native current/best state. Catalogs
are shared immutably within the worker. Admission errors identify the input path
and stable diagnostic. A malformed request never produces a usable episode.

Fresh generation preserves the existing product/rate/setup RNG schedule and
production constructor choices. Python may orchestrate the Rust constructor CLI
and choose among compact native setup action indices using its existing RNG.
The original request ledger comes from production wiring/recipes, never from a
proposed layout. The native engine performs the same basic/local setup edit domain
and charged steps. The randomized current state, not its setup best, becomes the
training start. Input persistence at this episode boundary is allowed; per-action
whole-state serialization is not. Constructor source files and exact rates remain
external. Generation rejections consume attempts without replacement.

## Hot observation/action contract

`observe(include_critic)` returns an owned array bundle, a mask, action-kind IDs and
an opaque candidate handle. The actor and critic array schemas preserve the current
`factory-input-contract-screen-v1` numerical meanings. The critic retains its current
and best-world inputs. Actor branches remain absent where the selected contract
omits them. Current/best world buffers may share an exported object when equal;
previously returned arrays remain unchanged after later steps, resets or restores.
The neural input does not contain the handle, revision, raw string identifiers,
routing outcomes or hidden state from an omitted branch.

The engine retains the exact ordered command list. Handles bind to an engine
identity, episode generation and revision. `step(handle, index)` rejects stale,
foreign or out-of-range selections before any mutation or charge. An ordinary valid
selection consumes one selected-action unit, even if execution rejects or geometry
is unchanged. Executor rejection leaves the accepted physical state intact. Native
proposal count remains distinct from selected count.

A step returns only selected-action metadata, reward, done/status flags, scores,
counts and structured diagnostics needed for logging; it never returns full
initial/current/best geometry. The selected action may be materialized for its trace;
the full candidate domain is an explicit diagnostic export, not a neural input.

Setup may request the same handle/mask/kind domain without constructing model arrays.
Its Python RNG first chooses an allowed configured kind, then one allowed index,
exactly as before. This prevents a full physical-key computation per candidate.

## Semantic preservation

Preserve the ordered unranked pose, port, reroute, component, bridge-release, strip
insert/contract and restore-best domains. Preserve local/distant/group translation,
terminal closure, production SCC/edge groups, rigid compound rotations, static
preflight rejections, enumeration/stream budgets and tie order. A language cutover
must not shrink or pre-rank the domain to obtain faster demonstrations.

Selected edits use the same dedicated bounded A* semantics: pipe-first route
priority, length before turns, retained arms, terminal detachment/rejoining,
component/crossing rules, work charging and deterministic heap/neighbor tie order.
Preserve valid temporary worsening, explicit external-boundary obligations and
closed proposal acceptance. Preserve original exact rate arithmetic and the score
priority of used area, physical layer tiles and turns. The best witness changes
only on lexicographic improvement; reward is only newly improved retained-best
area divided by initial area, so restore/recovery earns no duplicate reward.

Seen-state/failed-action masking preserves physical equivalence independent of
set-like DTO array order while keeping directed chain order meaningful in action
keys. Restore remains the existing exhausted-memory escape; no-restore exhaustion
is explicit. History keeps the same selected-action feature token, recency and
optional outcome encoding. Preserve original float32 casts, coordinate normalization,
rate signals, graph order, masked kind balancing, probabilities and RNG consumption.
An external checkpoint schema changes only when its boundary/state contract changes;
model parameter names/shapes and PPO credit/update semantics remain unchanged.

Do not reintroduce full observation/reward/behavior replay or duplicate optimizer
execution into ordinary training. Those checks belong in standalone parity/readiness
tests. Retain the existing essential batch envelope controls and finite gradient-norm
guard before optimizer steps. Native acceptance of each proposed factory is required.

## Snapshots and diagnostics

`export_state()` is a cold, versioned interruption/checkpoint operation. It contains
request/catalog identities, full initial/current/best geometry, scores, selected and
proposed counters, consumed elapsed allowance, selection memory, bounded history,
trace and RNG-independent episode configuration. Python saves its own sampling and
learner RNGs with the corresponding rollout. A seed alone does not reconstruct an
interrupted stream.

Restore validates schema, provenance and all accepted layouts/scores before replacing
state. It rebuilds derived indexes and invalidates every prior candidate handle.
Restored execution preserves the remaining episode allowance and cannot grant free
selected actions or reset failed-action memory. Failure is atomic. JSON is permitted
for this cold boundary and selected artifact exports, not normal observe/step calls.

Diagnostics have stable code, severity, stage, message and relevant entity. Distinguish
input/schema errors, invalid handles, candidate-domain exhaustion, executor rejection,
physical rejection, routing work exhaustion, late results and episode resource stops.
No local failure is reported as global factory infeasibility. Expired work cannot
replace accepted current/best state. Interruption preserves the last accepted state
and actual partial trajectory rather than inventing a complete episode.

Performance output separates catalog/admission, candidate/index construction, physical
identities, observation construction, routing, native acceptance, array export and
cold state exports. Include calls, candidate counts, route expansions, cache/revision
counts and bytes where meaningful. Timings must identify nested regions. Reports
also measure Python inference, persistence and end-to-end parallel collection.

## Cutover and verification

Implement typed native geometry/candidates/execution/observations, then switch current
PPO training, evaluation and fresh setup together. Remove the obsolete normal Node
executor and Python geometry/observation paths; keep historical oracle dependencies
explicitly isolated. Do not keep old `describe/execute/snapshot` interfaces through
compatibility shims in the new normal path. Historical retained runs use their frozen
runtime. Breaking episode/checkpoint contracts have explicit schema diagnostics.

Compare against the frozen baseline using all selected 32-action trajectories and
additional controls for rotations, grouped movement, branches, cycles, pipes, shared
terminals and crossings. Check candidate order, selected proposals/statuses, scores,
rewards, current/best geometry, masks, history and all actor/critic arrays. Verify
owned arrays, stale/foreign handles, failed restore, late/rejected edits and exact
nonempty episode/checkpoint continuation. Run actual native PPO collection/update
and reviewed harness stop/resume behavior; preserve actual behavior probabilities.

The second profile repeats the five retained cases and 24-worker batch on the same
server and inputs. Separate uninstrumented timings from instrumentation and report
all cases, including regressions. No fixed target speedup or long-run learning claim
is an acceptance shortcut. Pass Rust format/check/tests, relevant Python/native tests,
manual CLI checks and tracked-file worktree/index checks. Retain compact findings
and source/hash manifests in Git, with raw profiles/checkpoints outside tracked
source directories. Commit completed, verified implementation slices.
