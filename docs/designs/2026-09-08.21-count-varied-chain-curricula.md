# Count-varied chain curriculum admission

Status: generator contract, before training or policy outcomes.

Accept an external specification of existing case paths or serial recipe lists,
requested rates, gap/rotation splits, runtime config and explicit native library.
A template defines a new independent factory request; it never changes obligations
of an existing improvement episode or the original 59-facility target. Derive all
facility shapes, permitted ports, material quantities, timing and transport capacity
from runtime catalogs. Never admit an intermediate import unless the runtime catalog
explicitly declares that item external. In particular, removing the battery grinder
and importing its powder is not an admissible way to manufacture a three-facility case.

For the bounded serial constructor, require at least two distinct recipe steps with
one belt input and one belt output each, contiguous commodities and an admitted raw
input. Compute exact upstream rates/utilizations backward from the requested final
rate. Require legal north-output/south-input ports at rotation zero, then place the
chain incrementally with straight aligned corridors. The initial first-producer gap
allows a two-cell move toward its consumer. Construct the explicit unbind/erase/move/
bind witness from actual port geometry. Reject unsupported contracts instead of
silently changing game rules. Existing validated cases remain admissible templates.

The initial matrix trains on a two-facility glass-component chain and the existing
four-facility battery case, gaps 0/4 and all rotations (16 cases). Development uses
those templates at gap 2 plus a two-facility originium/crystal-powder chain at gap 2
(12 cases). Held-out uses the three-facility originium/crystal-powder/crystal-shell
chain at gaps 0/4 and all rotations (8 cases). That outcome jointly probes unseen
count and an extended recipe chain; do not describe it as an isolated causal count
comparison or arbitrary recipe generalization. Freeze identities before learning.

Validate the initial factory and every witness prefix in native and independent
reference engines: domain membership, reward/best-layout agreement and strict area
improvement with actual translation. Generate each case curriculum from validated
prefixes and apply the existing gap/rotation transformer. Reject empty splits,
duplicate geometry identities, unknown recipes, inconsistent commodity chains,
unavailable ports, excessive rates and stale native libraries with stable
`chain_augmentation.*` diagnostics identifying the input/template.

Publish generated cases and manifest only after every case validates. Record hashes
of inputs and outputs, facility/network/terminal counts, split/template/gap/rotation,
initial/witness scores and first reward distance. Generated payloads live under
ignored artifacts; source specifications and concise admission findings are tracked.
Learning remains a separate multi-seed capacity/budget study with full success,
quality and cost curves. The initial count milestone does not cover shared commodity
junctions, pipes or production cycles; those remain required later stages.
