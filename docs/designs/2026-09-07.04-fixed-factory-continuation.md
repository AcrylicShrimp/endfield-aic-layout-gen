# Fixed-Factory Training Continuation

Status: accepted bounded experiment, 2026-09-07.

The user asked whether more training improves the fixed-instance policy. Continue the successful
server CPU run from 65,536 to 131,072 cumulative commands before changing the starting factory.
The user's proposed deliberately inefficient valid factory is a separate difficulty experiment;
it must not be mixed into this learning-duration comparison.

## Input and invariants

`run.py train --resume <trusted-final-checkpoint.pt>` accepts only a completed CPU run's final
checkpoint. Parent metadata must report complete and agree on command and optimizer counts.
Only total commands and evaluation checkpoints may differ in configuration. Model architecture,
environment semantics, catalogs, case, runtime versions, host, and thread count remain fixed.
The semantic source files `policy.py`, `environment.py`, and `acceptance.py` and catalog/case
hashes must match. Runner orchestration can change to add continuation support.

Load policy, Adam state, cumulative command/episode/update counts, champion score, all training
RNG states, and retained best layout/trace. Reset every new episode to the original factory.
The champion never becomes the new root. Restore RNG state after fresh object construction;
frozen evaluation uses its separate generators. Resume only at complete rollout/episode
boundaries. Interrupted and intermediate checkpoints are intentionally unsupported.

The new allowance is 65,536 additional commands, 512 additional episodes, and 4,096 additional
Adam steps. Evaluate at cumulative 65,536, 98,304, and 131,072 with the same 32 evaluation seeds.
No learning-rate, reward, action, model-size, or precision change accompanies continuation.

## Outputs and failures

Use a fresh output directory. Raw episode/update counters are cumulative but rows contain only
this segment. Timing fields measure this invocation only; metadata explicitly records resumed
commands, segment commands, parent checkpoint/metadata hashes, and inherited cumulative training
time. Parent results remain immutable. New checkpoints retain full continuation state.

Invalid parent status, nonfinal checkpoint, altered configuration/semantics/runtime, invalid
champion, or an insufficient new command allowance raises a path-specific `resume.invalid`
diagnostic before training. No silent restart or partial-state approximation is allowed.
Interrupted continuation preserves the usual partial rollout but is not advertised as resumable.

## Verification and interpretation

A bounded CPU test compares uninterrupted training with two joined segments, checking exact
final policy/Adam tensors, RNG states, counters, and episode outcomes. Negative tests reject
changed semantics/configuration and nonfinal parent checkpoints. A manual server continuation
must repeat the inherited frozen evaluation before more updates and independently audit selected
layouts/traces. Report additional time separately from cumulative learning exposure.

Flat or declining held-out action-sampling outcomes remain valid results. Increased training
is not assumed to monotonically improve PPO. This still measures one fixed instance and one
training seed; no generalization or global optimum claim follows.
