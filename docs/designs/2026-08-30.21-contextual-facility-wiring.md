# Contextual Facility Expansion And Wiring

## Scope

This stage rounds contextual recipe-occurrence work rates into dedicated facility instances and expands each contextual material flow across those instances. Its output is the existing solver-facing `FacilityInstanceWiringReport`, so placement, port selection, belt routing, and pipe routing can consume it without resolving producers again.

## Facility Requirements

Each contextual recipe occurrence owns a separate facility requirement:

```text
required facilities = ceil(work seconds per second)
unused capacity = required facilities - work seconds per second
```

The occurrence requirement preserves occurrence ID, hierarchy path, recipe ID, facility ID, exact work rate, instance count, and unused capacity. Facility summaries aggregate counts only for diagnostics and presentation; they do not merge occurrence ownership.

## Instance Identity

Facility instance IDs are deterministic:

```text
facility-instance:<recipe-occurrence-id>:<zero-based-index>
```

The final numeric suffix can be separated with `rsplit_once(':')`; the remaining prefix contains the complete occurrence ID. External and target nodes keep their contextual production graph IDs. Surplus endpoints include both occurrence ID and item ID.

## Flow Expansion

Every contextual material flow already names its exact source and consumer occurrences. Expansion replaces a recipe occurrence endpoint with its ordered facility instance IDs and splits the total rate evenly and deterministically:

- one source to many consumers: equal consumer shares;
- many sources to one consumer: equal source shares;
- many sources to many consumers: a balanced linear split preserving equal per-instance source and consumer totals.

The same rule expands occurrence-owned surplus output. No step searches for a producer by item ID, so identical materials and recipes on different hierarchy paths remain independent.

## Invariants

- every nonzero recipe occurrence has at least one facility instance;
- every contextual flow rate is conserved exactly after expansion;
- every expanded edge connects known instance or boundary nodes;
- occurrence IDs remain recoverable from facility instance IDs;
- facility summaries never affect wiring ownership;
- cycle edges are expanded like any other directed recipe flow.

## Follow-on

The integrated spatial solver can now consume contextual instance wiring. The remaining cutover work is a source-plan-based end-to-end layout CLI that replaces the flat throughput v3 pipeline and preserves contextual bootstrap diagnostics.
