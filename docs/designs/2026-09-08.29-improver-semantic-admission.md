## Evidence and scope

The next stage must represent the game rules before training can demonstrate them.
The current pilot is a restricted belt-path environment, not a general factory
validator. This inventory comes from local code inspection at `569ccec`:

| Concern | Current implementation | Required next evidence |
| --- | --- | --- |
| Facility count | Variable instance and entity tables | Pending frozen count/chain outcomes |
| Commodity networks | `NetworkSpec` has one source, one target and one rate; terminal indexes use `2 * network` | Arbitrary terminal sets and exact flow balance |
| Shared trunks, splits and merges | Acceptance requires one incoming and one outgoing arm at every cell; networks cannot overlap | One physical network per compatible commodity/layer, catalog components and per-arc flow |
| Pipes | Catalog loads belt capacity only; port validation requires belt; occupancy uses one combined set | Item-derived transport, layer-specific capacities and collision checks |
| Production cycles | Admission compares recipe obligations without imposing a facility DAG | A real cyclic recipe fixture and validated relocation/reconnection witness |
| Route circulation | Path degree and source reachability restrict acceptance | Positive balanced circulation must not be rejected as a game-rule violation |
| External obligations | One target item/rate and no other exports | Explicit target and surplus obligations from the complete production request |

Sources: `crates/aic-pilot-native/src/{catalog,state,acceptance}.rs` and
`tools/factory-edit-pilot/reference/{acceptance,environment}.py`. Native and Python
currently share these restrictions; agreement between them does not establish
coverage of the general game rules. Neither observation schema 2 nor a larger
policy removes restrictions in the case/layout contract.

Use [the mathematical model](aic-game-rules-mathematical-model.md), especially
transport layers, selected terminals, branch topology and cycles, as the semantic
reference. Production cycles and route circulation are distinct. Do not impose a
DAG on facilities or require every occupied transport cell to be terminal-reachable.
Disconnected, locally balanced commodity components are permitted by that model.
Equal splitter output rates remain an unresolved domain ambiguity, not a pruning
premise. Catalog component topology and total capacity remain mandatory.

## First implementation slice: transport-aware path admission

This slice makes the existing single-path limitation explicit while introducing
correct belt/pipe behavior. It does not claim shared-network completeness.

Input DTO: a versioned case with the existing fixed production obligations and
complete initial geometry, plus runtime item and transport catalogs. Resolve each
network's transport from its item. Reject missing/unknown items and inconsistent
transport declarations. Do not infer transport from a selected port or hardcode
game capacities. A scoped admission profile declares `single_path`; unsupported
junctions receive a capability diagnostic rather than a global invalidity claim.

The first cutover uses case schema 2 with required `admission_profile: "single_path"`,
`imports` and `surplus` arrays of exact item/rate obligations, plus the existing
target. Aggregate external source rates must exactly equal `imports`; external demand
rates must exactly equal target plus `surplus`. Every network must touch a facility.
No import is inferred or added by the improver. Preserve the upstream request's
explicit boundary contract, including water/sewage and required surplus exports.

This distinction is necessary: `tools/normalize_game_data.py` computes
`external_items` as consumed minus produced recipe items. It is not a whitelist of
all permitted explicit source selections. The accepted
`data/examples/source-plan.game-heavy-xiranite-forge.request.json` explicitly imports
water and sewage, and the original 59-facility benchmark requires those inputs and
its low-polymer surplus. Restricting imports to that derived leaf list would prevent
the pilot from representing the existing production request. Do not modify the
normalized catalog to bypass that mismatch.

Layout schema 2 binds transport meaning to the admitted item catalog. Observation
schema 3 separates network and terminal maps and arm rasters by transport layer;
existing entity transport flags carry the resolved belt/pipe identity. Reject older
case/layout/observation/checkpoint contracts explicitly. Preserve historical runs in
their frozen source checkouts instead of adding compatibility adapters.

Output DTO: versioned owned layout, admission profile, provenance hashes, independent
acceptance, used bounds and score. The observation/checkpoint identity must change
when transport features change. Reject incompatible checkpoints before inference;
do not reinterpret old feature channels. The future CLI accepts an already complete
validated incumbent and returns it unchanged if the configured edit budget produces
no validated improvement.

Invariants: facilities block both layers; belt and pipe can share XY coordinates;
same-layer conflicts still fail in this restricted path profile. A port must match
the item's transport and direction, and each physical port remains exclusive.
Capacity is exact rational arithmetic for the selected transport. Used area counts
the XY union; transport cost counts physical occupancy separately per layer.
External terminals stay on actual used bounds. Mechanical edits may temporarily
break connectivity in private; only complete independent acceptance can replace
the incumbent. Preserve lexicographic area, tile, then turn priority.

Diagnostics retain `code`, `severity`, `stage`, `message` and an entity reference.
Add stable admission codes `capability.network_topology`, `input.item_transport`
and `policy.schema_mismatch`; keep geometry collisions and capacity violations
distinct. Reports include resolved layers, per-layer tile totals, input/incumbent
scores, candidate rejection counts and termination reason. Unsupported topology is
not proof that a factory is infeasible.

Before learning: independently replay a real pipe-bearing recipe case; accept
cross-layer coexistence and reject same-layer overlap, wrong-layer ports, missing
items and over-capacity flow. Test score accounting when two layers share a cell.
Demonstrate a reversible relocation/reconnection witness, including a failed edit
that preserves the incumbent. Native and reference validators must rebuild from
owned geometry. No synthetic recipe rates or game constants in application code.

## Subsequent slices and cutover conditions

1. Replace pairwise network endpoints with explicit terminal IDs, signed rational
   terminal obligations, directed arc flows, and catalog component placements.
   Group compatible terminals by item and transport; remove `2 * network` indexing.
   Validate per-cell conservation, arm/item compatibility, line/component capacity,
   ports and external boundaries. Shared physical tiles count once per layer.
   Freeze the detailed DTO and diagnostics before implementation; do not bolt a
   second authoritative pairwise-routing contract onto the new one.
2. Admit split and merge fixtures with real recipes and independent flow witnesses.
   Include balanced disconnected components and positive circulation in validator
   coverage. Unsupported bridges need explicit capability rejection until their
   independent-channel representation is implemented; never silently flatten them.
3. Admit required production cycles using fixed steady-state obligations from the
   production planner. Keep bootstrap scheduling outside this spatial contract.
   Prove the curriculum reconnects all cycle obligations; a removed edge or added
   external substitute is not an acceptable witness.
4. For each admitted slice, freeze training/development/held-out geometry and budgets
   before outcomes. Geometry admission and a hand-authored edit witness are only
   prerequisites; measured learned transfer is a separate milestone.

Complete the current six runs and audits before altering their policy, native
environment, reference validator or training catalogs. Preserve their outputs and
source identity for replay. Runtime changes then make an explicit hard cutover;
historical experiments use their frozen source, not compatibility adapters.

A separate development checkout may implement this next contract while the original
training and confirmation checkouts remain frozen. Its native build has a separate
output directory. Capability verification is independent work; it does not advance
the pending count/chain learning gate or authorize new training on opened outcomes.

This order follows [the constructive planner design](2026-09-02.00-constructive-layout-planner.md):
improvement starts from a complete valid factory, commits transactionally and never
calls the global exact solver. This admission work does not alter construction
order or production pipe-first routing. Stage 4 remains open until semantic and
held-out learning evidence passes; stage 5 still includes the original 59-facility
Heavy Xiranite target, at most 1% empty XY area, and visual acceptance.
