# Transport Capacity Catalog

## Source Mapping

Transport capacities are runtime game data. `FactoryGridBeltTable.grid_belt_01.beltData.msPerRound` defines one belt transfer round every 2000 milliseconds. `FactoryLiquidPipeTable.log_pipe_01.pipeData` defines volume 1 every 500 milliseconds.

The normalizer writes these values without converting them to floating point:

```text
belt: quantity 1 per 2000 ms
pipe: quantity 1 per 500 ms
```

## Catalog Contract

Transport catalog schema version 1 contains exactly one definition for every `TransportKind`. Each definition has a positive integer `quantity` and `duration_ms` capacity ratio. Unknown JSON fields, duplicate kinds, missing kinds, nonpositive values, and unsupported schema versions are validation errors.

The catalog is loaded on every command execution. No capacity is compiled into application code.

## Independent Route Constraint

The current integrated model assigns each logical edge an exclusive route. Before solver construction, the edge's exact rational rate must be less than or equal to its transport capacity:

```text
edge_rate <= transport.quantity * 1000 / transport.duration_ms
```

The comparison uses integer cross multiplication. An exceeded capacity returns `route-capacity-exceeded` and identifies the edge item.

This slice does not sum multiple logical edges because they cannot share a route cell yet. When shared trunks are introduced, every shared segment must constrain the sum of assigned edge rates and require explicit splitter or converger components at topology changes.
