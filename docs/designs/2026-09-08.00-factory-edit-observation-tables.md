# Runtime-Derived Observation Tables

Status: implementation experiment, 2026-09-08.

Input remains the execution-loaded catalog, current draft/base, and revision-bound candidate
set. Output remains five owned arrays with identical dtype, shape, and bytes, plus unchanged
candidate/transition/validation behavior. No model or collection settings change.

Precompute immutable terminal metadata, capacity/rate and footprint features, and facility
port rotation offsets from the catalog. Build observation object rows by copying a read-only
constant template and filling binding, absolute position, direction, placement, and rotation
fields from the current state. Cache neither state indexes nor validation results across edits.
A catalog is fixed for an Environment's lifetime; new executions load external data again.

Array ownership must survive caller mutation. Preserve Python division followed by float32
conversion, external-boundary directions, catalog ordering, and unbound terminal zero position.
Existing mechanical and resource-guard errors remain unchanged. No new pruning is allowed.

Compare three retained 256-command replays byte-for-byte against `3b60753`, including all
ordered candidates and transitions. Measure total replay and observation cost in alternating
rounds. Inspect additional profile costs before deciding whether to retain further changes.
Run normal verification, then a full CUDA run if controlled measurements justify adoption.
