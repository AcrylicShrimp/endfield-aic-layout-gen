# Facility Placement V1

## Design Goal

Place recipe-dedicated facility instances as non-overlapping, axis-aligned grid rectangles within a requested maximum width while selecting only rotations allowed by facility catalog v2.

V1 establishes the placement-stage DTO and diagnostic boundary. Its deterministic solver produces a feasible layout but does not claim optimality. A later CP-SAT backend may return an optimal layout without changing the input or placement DTOs.

## Pipeline

```text
FacilityInstanceWiringReport
  + ValidatedFacilityCatalog
  + FacilityPlacementRequest
  -> FacilityPlacementReport
```

The placement stage does not load recipe, throughput, or catalog files. The CLI composes and reports failures from the earlier owning stages before placement runs.

## Request DTO

```json
{
  "schema_version": 1,
  "max_width": 12
}
```

- `schema_version` must be `1`.
- `max_width` is a positive integer number of grid cells.
- Height is unbounded. The solver reports the height used by its feasible solution.
- Unknown fields are rejected during JSON parsing.

## Output DTO

```json
{
  "success": true,
  "status": "feasible",
  "bounds": { "width": 5, "height": 4 },
  "placements": [
    {
      "instance": "facility-instance:assemble-casing:0",
      "recipe": "assemble-casing",
      "facility": "assembler",
      "x": 0,
      "y": 0,
      "width": 5,
      "height": 4,
      "rotation": 0
    }
  ],
  "diagnostics": [
    {
      "stage": "facility-placement",
      "severity": "info",
      "code": "facility-placement-feasible",
      "path": "/",
      "entity": null,
      "message": "facility placement is feasible but not proven optimal"
    }
  ]
}
```

`status` is one of `optimal`, `feasible`, `infeasible`, `invalid-input`, or `unknown`. V1's deterministic solver returns `feasible`; `optimal` is reserved for a backend that proves the objective bound.

`bounds` is the smallest origin-anchored rectangle containing every placement. It is `{ "width": 0, "height": 0 }` when no facility instances are required. Failure reports use `bounds: null` and an empty placement list.

Every placement preserves the logical facility instance ID, recipe ID, and facility ID. `rotation` is a clockwise degree value selected from that facility's `allowed_rotations`. Rotations `90` and `270` exchange canonical width and height.

Placements are sorted by instance ID in the report.

## V1 Solver

V1 uses deterministic first-fit decreasing shelves:

1. Build one rectangle candidate set per facility instance from its allowed rotations.
2. Order instances by descending largest canonical side, descending area, then instance ID.
3. Try existing shelves in creation order. On a shelf, choose a fitting orientation by least remaining horizontal space, then lower height, then lower rotation value.
4. If no shelf fits, create a shelf using the fitting orientation with the lowest height, then lowest width, then lowest rotation value.
5. Place rectangles left to right. Stack shelves from `y = 0` upward.

This solver guarantees width compliance and non-overlap for successful reports. It is an initial feasible-solution backend and does not minimize height globally.

## Diagnostics

Every diagnostic has stable `stage`, `severity`, `code`, `path`, `entity`, and `message` fields. `stage` is `facility-placement`.

Expected failures include:

- `upstream-instance-wiring-failed`
- `unsupported-facility-placement-schema-version`
- `non-positive-layout-max-width`
- `duplicate-facility-instance`
- `missing-facility-definition`
- `facility-does-not-fit-layout-width`
- `placement-arithmetic-overflow`

Successful V1 output includes an informational `facility-placement-feasible` diagnostic so callers can observe that the result is feasible but not proven optimal.

`facility-does-not-fit-layout-width` returns status `infeasible`. Request, upstream-contract, catalog-reference, and arithmetic failures return `invalid-input`.

## Non-Goals

- No map-height limit or blocked map cells.
- No facility spacing or access clearance.
- No ports, belt/pipe routing, or wire-length objective.
- No global optimality claim.
- No time limit or partial CP-SAT solution handling.
