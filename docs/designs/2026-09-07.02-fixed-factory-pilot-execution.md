## First executable scope

One fresh CPU CNN+MLP policy, one training seed, 65,536 submitted editing commands, 128 commands
per episode. Frozen evaluation at initialization and 8,192, 16,384, 32,768, and 65,536 commands,
with 32 rollout seeds and the same horizon. Intermediate checkpoints expose the first curve;
65,536 is the first diagnostic endpoint, not completion of the proposed longer learning ladder.
No generalization or architecture ranking is claimed from this first seed.

The selected request produces `item-proc-battery-1` at 1/20 per second from catalog-external
quartz sand and originium ore. Four facilities use the catalog recipes for quartz glass,
glass components, originium powder, and the battery. Exact recipe quantities, footprints,
ports, and transport capacities are read from the normalized runtime catalogs. Three machines
are 3x3 and the assembler is 6x4 in that snapshot; these values are evidence, not application
constants. Proposed utilization is 1/2, 1/2, 1, and 1/2 respectively.

The root fixture is human-authored input with all external input/output belts and bindings,
not an inherited successful training result. Its layout and a known improvement witness must
pass an independent complete-factory checker before training. The witness is never supplied as
training data or candidate ordering hints. Initial proposed used bounds are 7x22, area 154;
shortening two external input tails can reach area 140. Neither is claimed valid until checked.

The first executor supports six distinct single-source/single-demand belt networks as directed
paths and editable path fragments. No pipes, physical junctions, crossings, or transport cycles
are admitted in this first action domain. The production dependency graph has two inputs joining
at the assembler, but no belt merger is needed. This restriction narrows the experimental question;
it is not a game rule, a complete routing formulation, or an optimality claim. Flow on a completed
path is the immutable exact network rate; this scope needs no allocation solver. Any broader
flow/topology claim is deferred rather than inferred from this checker.

## Stage contract

Input: versioned JSON fixture and run configuration, external catalog paths, immutable facility
recipe/utilization records, network terminal obligations, initial placements/bindings/cells/edges.
Output: validated episode-best layouts, exact score tuples, episode returns, frozen evaluation
records, checkpoints with optimizer/RNG state, provenance hashes, and standalone plotted figures.

State: private draft, last complete working base, and best valid layout, plus remaining horizon.
Every episode resets these layouts to the same root. Learner state persists. Valid worse edits
can become working base; episode best retains the lexicographic area/tile/turn optimum observed.
Every applied edit triggers complete checking; incomplete drafts remain editable. Mechanically
invalid commands do not mutate geometry. Every submitted command consumes one step, including
discard; actual candidate generation and validation costs are reported separately.

Commands remain the seven parent operations. For this first decoder, enumerate a declared local
domain of explicit typed commands and let the policy score/select them. Enumeration may filter
mechanical illegality but must not run lookahead, rank by outcome, repair routes, or provide a
known improving script. It is a different decoder implementation hypothesis from autoregressive
parameter decoding, recorded before results. Candidate order is canonical and not score-sorted.

- Placement: move one unbound facility by one or two cells along one cardinal axis, rotate it
  to another allowed orientation, or swap the origins of two unbound facilities atomically.
- Unbinding/binding: select one terminal and an explicit compatible facility port or network
  endpoint on the current used boundary. Creating an isolated bound port cell is allowed.
- Erasure: select one or two consecutive cells of one network; never erase a bound terminal cell.
- Extension: select one channel endpoint, forward/backward directed growth, cardinal direction,
  and length one or two. Existing geometry is not silently connected or rerouted.
- Connection: add exactly one directed edge between adjacent compatible endpoints of a network.
- Discard: restore the last complete working base without refunding the command.

There is no fixed canvas limit. A whole raster covers draft and working-base geometry plus a
small observation halo. Relative local commands permit repeated expansion. A run-level spatial
work guard, if triggered, is a structured resource interruption, not an infeasibility result.

The model reads separate draft/base rasters with facility/network identity and directed arm
features, exact terminal identities/bindings as object rows, and remaining budget/score context.
A shared per-object MLP processes rows; no GNN or learned neighbor aggregation. A small CNN keeps
cell features, combined with global and selected-command features for a shared candidate scorer.
Exact trainable parameters and dimensions are reported; approximately 0.1M is a target, not an
assertion about an unbuilt network. Action probabilities include all enumerated candidates; no
expert-only actions or hidden completion macro is supplied.

PPO proposal for this first run: CPU, one tensor-library thread, fresh weights, Adam learning
rate 0.0003, clipping 0.2, four update epochs per 256 commands, minibatches 64, gamma 1,
GAE lambda 0.95, value-loss coefficient 0.5, entropy coefficient 0.01, gradient norm cap 0.5.
Remaining horizon is observed; completed episodes have zero terminal bootstrap. Evaluation uses
separate RNG streams with frozen weights and fixed sampling. Record actual values in run JSON
before training. This is one untuned optimizer configuration, not evidence of its adequacy.

The user subsequently prioritized elapsed time and authorized more CPU use. The
[CPU timing follow-up](../reports/2026-09-07.01-factory-edit-cpu-speed.md) changes the local
default to four intra-operation threads after a fixed-input comparison. The original one-thread
record remains historical evidence. Model, environment, optimizer exposure, and evaluation
allowances remain the same; CPU thread count is an execution setting rather than a game rule.

Reward is the raw relative decrease in best complete area; episode return equals final relative
area reduction. Show training episode returns, their declared 32-episode moving mean, and frozen
evaluation outcome/return distributions. Keep the cumulative training champion separate. Report
unchanged initial returns and zero rewards without suppressing them. Initial validation failures,
unsupported scope, stale references, mechanical rejection, incomplete topology, and runtime
interruptions have structured codes, severity, stage, message, and entity fields.

## Acceptance and verification

The complete checker independently reconstructs rotated footprints, terminal cells/directions,
recipe margins and exact rates from catalogs and the serialized layout. It checks every facility,
external obligation, network cell/edge, direction, conservation, path reachability, capacity, used
boundary, and complete score. It must not trust environment completion flags or cached rewards.
Draft mechanical checks and final acceptance have distinct roles. No historical solver/validator
is assumed to certify this new executor.

Before learning, test root/witness acceptance and negative mutations: lost recipe obligation,
wrong port direction, internal external endpoint, disconnected transport, overcapacity, and a
facility collision. Check discard, fixed-root reset, reward telescoping, non-mutating rejection,
candidate replay, CPU device, and finite gradients with this actual command interface. Run the
relevant CLI manually and repository-required checks. Generated outputs live under ignored
`artifacts/factory-edit-pilot/`; retain source/configuration and concise findings in Git.

The first report must include the actual run status, exposure, parameter count, CPU runtime,
all observed improvements or lack thereof, raw curves, before/after layouts, and limitations.
An unchanged root is valid output but no observed learning success. If the first run is flat,
show it before extending training or enlarging the model.
