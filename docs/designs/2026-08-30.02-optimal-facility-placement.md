# Optimal Facility Placement Backend

## Design Goal

Replace the feasible shelf backend behind `solve_facility_placement` with a pure Rust constraint-programming model that proves minimum used height under the existing placement request.

The placement, status, and diagnostic output DTOs remain unchanged. This is a hard backend cutover: successful bounded solves return `status: optimal`; the old shelf result is not exposed as a compatibility path.

The placement request becomes schema version 2 in this slice because the game system supplies both hard layout dimensions:

```json
{
  "schema_version": 2,
  "max_width": 12,
  "max_height": 8
}
```

Both dimensions are positive grid-cell counts. This is a hard cutover from request v1, which had only `max_width` and treated height as unbounded.

## Solver Choice

Use `pumpkin-solver` 0.5, a pure Rust Lazy Clause Generation constraint-programming solver. It supports finite-domain integers, clauses, reified linear constraints, and objective optimization without a Python runtime, C++ library installation, or FFI boundary.

Pumpkin 0.5's dependency graph requires Rust 1.95, so this slice explicitly raises the workspace `rust-version` from 1.85 to 1.95. The repository remains on stable Rust and does not preserve a compatibility shim for the old minimum toolchain.

Google OR-Tools does not provide an official Rust wrapper. The public `cp_sat` Rust binding requires a separately installed OR-Tools C++ library and protobuf linkage, so it is not selected for this workspace.

## Model

For every facility instance `i`:

- integer `x_i` and `y_i` variables represent its lower-left grid coordinate;
- one Boolean literal is created for every allowed rotation;
- exactly one rotation literal must be true;
- a selected rotation implies `x_i + width(i, rotation) <= max_width`;
- a selected rotation implies `y_i + height(i, rotation) <= used_height`;
- `used_height <= max_height`.

For every pair of distinct facility instances `i` and `j`, and every pair of their rotation choices, at least one separation literal must hold when those rotations are selected:

```text
i is left of j
or j is left of i
or i is below j
or j is below i
```

Each separation literal is reified to its corresponding integer inequality. Together these clauses encode exact rectangle non-overlap.

`used_height` is minimized within the hard system bounds. A layout that cannot fit inside both `max_width` and `max_height` is proven infeasible.

Facility catalog version 3 makes rotations with identical rectangle geometry semantically distinct because their ports can face different boundaries. The solver therefore retains every allowed rotation and applies rotation-specific port boundary clearance. Full route selection remains deferred to the integrated routing model.

## Outcomes

- Proven optimum: success with `status: optimal` and diagnostic `facility-placement-optimal`.
- Proven infeasible: failure with `status: infeasible` and diagnostic `facility-placement-infeasible`.
- Model construction or integer-domain failure: failure with `status: invalid-input` and a stable diagnostic.
- Solver termination without proof: failure with `status: unknown` and diagnostic `facility-placement-unknown`.

The current request has no time limit, so the backend uses indefinite termination. A later request schema may add time and worker limits together with partial feasible-solution reporting.

## Integer Domain

Pumpkin uses 32-bit finite-domain integers. Both placement request bounds and facility dimensions must fit `i32`. Values outside this solver domain produce `solver-domain-out-of-range` rather than truncating.

## Verification

Tests must demonstrate:

- a case where the optimal height is lower than the previous shelf heuristic;
- allowed rotation selection;
- non-overlap and width compliance;
- proven infeasibility;
- stable output ordering;
- unchanged full-pipeline CLI JSON with `status: optimal`.
