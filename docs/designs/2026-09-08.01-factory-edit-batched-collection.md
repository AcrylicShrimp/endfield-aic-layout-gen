# Batched On-Policy Factory Edit Collection

Status: controlled throughput experiment, 2026-09-08.

The remaining largest cost is CPU action inference. Fixed elongated-input probes show no
benefit from moving one action at a time to CUDA, while batching two independent episodes
reduces actor cost. Compiled CPU inference also improves steady-state cost but requires a
separate cold compilation allowance. This experiment measures complete collection before
choosing a production execution setting.

## Contract

Input is a fixed policy snapshot, catalog, environment configuration, explicit actor device
and batch size, and a CPU sampling generator. Every actor batch contains one current observation
from each independent environment. The policy is unchanged during the entire PPO rollout.
Each environment begins at the same existing root, owns its draft/base/best and caches, and
receives exactly the same horizon and full candidate domain as the serial collector.

Run the existing CNN/MLP on padded observations, preserving per-layer raster masking and
candidate masking. Transfer completed log probabilities and values to CPU and sample each
row independently in environment order. Numerical differences from batching/device execution
are allowed; model structure, parameters, precision, reward, candidate/validation semantics,
episode count, rollout command count, minibatch size, and Adam step count are unchanged.
Do not share accepted layouts, rewards, actions, or validation outcomes between environments.

Output comprises per-environment episode streams. Flatten streams in episode-major order
before GAE so adjacent timesteps belong to the same episode. Every episode ends with `done`;
no credit crosses an episode boundary. Candidate generation, observation, device transfers,
completed inference, sampling, stepping, and validation are included in collection clocks.
The test must reject invalid batch/rollout/horizon combinations explicitly.

Interleaved sampling changes the sequence assigned to each episode. A seed therefore does not
promise an identical serial trajectory. This is an explicit execution-contract change, not
an assertion of bit-exact learning. Equal exposure and independent on-policy episodes remain
required. CPU serial continuation remains supported under its existing strict contract.

## Decision gate

First compare a standalone collector on fixed model weights for a complete 256-command
rollout, alternating CPU batch one, CPU batch two, and CUDA batch two. Reset sampling state
for each repetition; retain exact chosen actions, per-episode streams, final layouts,
component costs, peak memory, and numerical actor comparison on fixed observations.
Audit every final best layout and replay selected traces independently. Since sampled paths
can diverge, pair this with the fixed-observation actor probe and report work counts.

Install a runner cutover only if complete collection shows a useful improvement. If retained,
checkpoint metadata must identify actor device, batch size and episode-major PPO order;
interruption evidence must retain every partial stream, environment, RNG, and policy snapshot.
Keep CPU frozen evaluation explicit and unchanged for comparable assessment. Run the full
same-allowance CUDA experiment and all verification before committing the runner change.
