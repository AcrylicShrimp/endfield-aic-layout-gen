# Iterative SCC Layout

## Status

Implemented MVP. SCC growth planning, cumulative wiring projection, bounded coordinate anchors, radius escalation, global rescue, per-phase routing validation, and phase history reports are implemented. Routing-failure neighborhood extraction remains deferred.

## Problem

Solving every facility and every route in one search creates a large search space before the solver has established any useful local structure. The layout stage needs a way to grow a complete solution from a smaller solved subgraph while preserving the ability to repair earlier choices.

Recipe graphs may contain material cycles. An incremental solver must not split a cycle into individually ordered facilities because no member of the cycle is strictly upstream of every other member.

## Growth Unit

The planner builds the directed facility-to-facility graph from successful facility instance wiring and condenses it into strongly connected components (SCCs).

- Every facility instance belongs to exactly one SCC.
- Every SCC is added atomically.
- External, target, and surplus nodes remain boundary terminals and are not placement units.
- Edges between SCCs form a directed acyclic graph.
- Component identifiers and member ordering are deterministic for identical input.

## Growth Order

Growth starts at the output-facing end of each connected facility subgraph and proceeds toward its inputs.

For each SCC, its phase index is the longest directed distance from that SCC to any sink SCC in the condensation graph. Sink SCCs are phase zero. Therefore, for every edge from component `A` to a different component `B`, `phase(A) > phase(B)`.

All components at the same phase may be added together. A phase is cumulative during execution: phase `n` solves its new components plus all components from phases `0..n-1`.

## Stage Contract

### Input

A successful `FacilityInstanceWiringReport` with unique node identifiers and edges whose endpoints reference declared nodes.

### Output

`FacilityGrowthPlanReport` contains:

- all SCCs with deterministic identifiers, member facility IDs, and downstream component IDs;
- output-first phases referencing the SCCs and facilities introduced in each phase;
- structured diagnostics describing the plan or failure.

An input with no facilities produces a successful empty plan.

### Failure Modes

- failed upstream instance wiring;
- duplicate wiring node identifiers;
- wiring edges with missing endpoints.

Diagnostics use stable code, severity, stage, path, entity, and message fields.

## Incremental Placement Contract

Each cumulative phase is solved with these rules:

- newly introduced SCCs have free coordinates within the hard factory bounds;
- previously placed facilities receive their prior placement as an anchor;
- an attempt constrains anchored facilities to a bounded movement radius;
- rotation changes and Manhattan displacement are scored after feasibility;
- failure expands the movement radius instead of permanently freezing old choices;
- the final rescue attempt removes all anchors and solves the cumulative graph globally.

The hard factory width and height always apply. The used layout bounds remain a candidate-quality objective, not a blueprint limit.

The coordinate placement API now accepts a prior validated placement set and a non-negative movement radius. Each anchored facility's `x` and `y` coordinates are constrained independently to the closed anchor-radius interval. Unanchored facilities remain free. Radius escalation and displacement scoring belong to the cumulative phase executor.

The MVP attempts movement radii `0`, `4`, and `12` in that order, followed by an unanchored global rescue. Phase zero is solved globally because it has no prior anchors. Missing upstream facilities are projected as synthetic external boundary inputs until their SCC is introduced. The final cumulative phase preserves the original wiring report exactly.

## Routing And Repair Contract

Each cumulative placement must be routed and independently validated before it becomes the anchor state for the next phase.

`IntegratedLayoutReport.phases` preserves every successful cumulative witness. Each phase records introduced SCCs and facilities, cumulative facility count, selected movement radius, used bounds, placements, logistics components, routes, route turns, route cells, bridge count, and every attempted radius with its status and diagnostic code. The final report remains the authoritative full-graph witness.

The MVP widens every existing anchor together when routing fails. A later locality-aware repair may instead widen the neighborhood around:

- the newly introduced SCCs;
- SCCs incident to the failed routing network;
- facilities occupying the failed route corridor.

Repeated failure expands to a global cumulative solve. No phase is considered complete from placement feasibility alone.

## Portfolio Contract

Independent workers may search different combinations of placement width cap and anchor radius. A validated witness is selected using the existing layout candidate score. At least one worker must retain the caller's full hard width, and at least one rescue attempt must permit global movement.

## Heavy Xiranite MVP Benchmark

With a two-second placement limit per attempt, the iterative strategy solved 59 facilities and 102 routes through nine cumulative phases in 17.4 seconds on the development host. The final witness used `484x40`, 10,031 route cells, 263 turns, and 486 bridges. The preceding coordinate portfolio witness used `364x53`, 11,953 route cells, 293 turns, and 659 bridges. The iterative witness has nearly identical area, is more elongated, and reduces route length, turns, and crossings.

Phases six and eight exhausted radii `0`, `4`, and `12` within their placement time limits and succeeded through the unanchored global rescue. This confirms that bounded anchors are useful but cannot be treated as permanent placement commitments.
