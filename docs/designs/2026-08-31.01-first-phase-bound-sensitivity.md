# First-Phase Bound-Sensitivity Experiment Contract

## Purpose

The `research solve-first-phase` command isolates cumulative SCC phase 0 so the exact joint model
can be compared across caller-supplied layout ceilings. It is a research observation path, not a
production feasibility command and not an alternative solver architecture.

## Inputs

The command requires:

- a validated contextual benchmark workload manifest;
- a workspace root used to resolve the manifest's data files;
- one explicit facility-placement request containing `max_width` and `max_height`;
- one positive exact-search budget in milliseconds;
- one JSON output path;
- an optional self-contained HTML output path.

The workload identity does not contain a layout bound or search budget. Every experiment case must
provide both explicitly.

## Phase Selection

The command runs the same current one-ready-SCC growth planner as `iterative-scc`, selects its first
cumulative phase, and projects the logical wiring with the existing frontier-external semantics.
The selected phase is then solved as a complete joint placement, port-selection, component, and
routing model.

The production solver's full-graph facility-area preflight is intentionally not applied because it
would prevent observation of a valid partial model when the final 59-facility graph cannot fit the
same small experimental ceiling. The projected phase still passes the normal exact-model
validation and its own facility-area feasibility check. The production solve path remains
unchanged.

## Output

The JSON wrapper has schema version 1 and contains:

- workload ID;
- explicit request bounds;
- explicit search budget;
- the complete integrated-layout report for phase 0, including exact model-complexity metrics and
  structured diagnostics.

Success and failure may both produce HTML. `unknown` remains distinct from infeasible, and any
complete incumbent must pass the normal independent witness validator.

## Invariants

- No placement candidate, port option, routing cell, routing arc, flow, or logistics component is
  removed from the selected phase.
- No coordinate, route, or component choice is fixed outside the solver.
- No heuristic fallback runs after timeout or `unknown`.
- The exact objective order remains used area, physical transport tiles, route turns, maximum side,
  and component count.
- This research command cannot be used to infer production feasibility of the complete graph.

## Failure Modes

The command reports workload, catalog, source-plan, growth-projection, phase-model, solve, and
visualization failures with the existing structured diagnostics where available. A non-successful
layout produces a non-zero process exit after its JSON and requested HTML artifacts are written.
