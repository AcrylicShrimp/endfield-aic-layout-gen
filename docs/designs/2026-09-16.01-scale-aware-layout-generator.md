# Scale-aware procedural layout generator

Status: implemented and release-verified as an experimental physical-layout
baseline. It is not accepted as the production random-factory architecture; see
the [prior-art review](../reports/2026-09-16-random-factory-generation-prior-art.md)
and replacement [dataset-generator
design](2026-09-16.02-recipe-sized-layout-dataset-generator.md).

## Goal

Make the public generator configuration describe the requested layout rather
than the generator's internal loop limits. The same configuration language must
remain meaningful from 2 through 100 facilities without manual retuning of pair
trials, canvas cells, margins or routing expansions.

The current `aic-layout-generator-v1` object becomes an internal
`MechanismConfig`. Existing workspace consumers may use it while they migrate,
but the CLI, examples and Monte Carlo survey use the new semantic contract.

## Public model

`aic-layout-generator-v2` contains:

- an inclusive facility-count range;
- one or more topology profiles: `tree`, `light-cycles`, `branching`;
- one or more packing profiles: `compact`, `balanced`, `spacious`;
- a dimensionless long-connection preference range;
- `fast`, `standard` or `thorough` effort;
- transport choices, facility filters, explicit transport minima, crossing
  permission and the acyclic-graph requirement.

The public object does not expose attempt count, pair trials, port-pair trials,
route expansions, canvas cells, margin, bridge count or degree limit. These are
resolved by the named `scale-policy-v1` and recorded with every result.

For `n` facilities, topology profiles request a weakly connected backbone and
scale only the connections beyond it:

| Profile | Target connections | Shape requirement |
| --- | --- | --- |
| `tree` | `n - 1` | none |
| `light-cycles` | `n - 1 + ceil(n / 4)` | none |
| `branching` | `n - 1 + ceil(n / 2)` | for `n>=3`, at least `max(1, n / 10)` branch and merge blocks |

Packing profiles initially reuse the established and measured gap ranges:
`compact=1`, `balanced=1..5`, and `spacious=5..10`. They are semantic profile
names rather than user-maintained cell knobs. Final spatial occupancy remains a
measured result; the generator does not claim that a packing profile is an exact
occupancy target.

`scale-policy-v1` derives a margin of `6 + floor(sqrt(n) / 2)` and a canvas guard
of `max(65,536, 16*n*n)`, capped at 250,000 cells. It derives pair trials from
target connections and routing work from facility count, connection count and
packing profile. Standard per-call work is `max(12,000, c*n*n)`, where `c` is 12
for compact, 20 for balanced and 40 for spacious. Total work is at least one call
and otherwise twice the per-call work per target connection. Standard pair trials
are `clamp(64*target, 512, 8192)`, eight port pairs are tried and four production
attempts are permitted. Fast halves per-call work, uses a factor of 32, four port
pairs and one attempt. Thorough doubles per-call work, uses a factor of 96 capped
at 8192, tries sixteen port pairs and permits eight attempts. All arithmetic is
checked and bounded.

The preference selects the distant-only candidate branch at each pair trial;
distant means the upper quartile of pairwise block-origin Manhattan distance.
The ordinary branch is restricted to the other three quartiles. Route feasibility
still determines which trials become accepted edges, so this is explicitly a
construction preference rather than a promised output fraction. Attempts record
the threshold and accepted long-connection count.

These coefficients are an explicit versioned generator policy, not game data or
training-distribution decisions. Changing them requires a new scale-policy
version and comparable generator evidence.

## Request and retry boundary

A generation request samples facility count, topology profile, packing profile
and long-connection preference exactly once. Production retries preserve all four
values and vary only construction randomness. A failure cannot silently move to
an easier size or profile.

The resolved record includes the semantic request, policy version, target
connections and every derived mechanism limit. This makes automatic scaling
inspectable and reproducible without asking callers to calculate it.

## Survey model

`aic-layout-generation-survey-v2` gives every facility bucket the same number of
raw slots. Each slot samples and then fixes an exact facility count, topology
profile, packing profile and long-connection preference. It invokes exactly one
construction attempt. Failures are rows rather than triggers for resampling.

Bucket work remains round-robin under the wall deadline. Rows retain the complete
semantic request and resolved policy. Summaries report both facility-bucket
results and topology/packing profile cells. This separates generator support
from retry policy and exposes which semantic profile caused a failure.

## Invariants

- Public parameters keep the same meaning at every supported facility count.
- Every requested topology begins with enough target connections for weak
  connectivity; no 2-facility special case constrains larger graphs.
- Production retries never change the semantic request.
- Survey slots contain one raw construction attempt and are never substituted.
- Derived resource limits grow monotonically with relevant request size inside
  one effort tier and stay within checked hard guards.
- Reports preserve requested and resolved values; automatic scaling is not hidden.
- Timeouts and exhausted work remain bounded failures, never infeasibility claims.
- Catalogs remain external, loaded and validated once at the command boundary.

## Rejected alternatives

- Keeping `edges_per_block` and asking users to special-case small factories.
- Making callers scale route work, pair trials, margins or canvas cells.
- Resampling facility count or topology inside a retry.
- Calling one arbitrary gap range the generator's attainable occupancy range.
- Silently clamping infeasible semantic requests without reporting the resolved
  target and reason.
- Removing the low-level mechanism immediately while active internal learning
  configurations still depend on it.

## Scale-policy-v4 upper-scale repair (2026-09-27)

The generator now admits the declared 2–256 facility range. The original
`scale-policy-v1` remains the historical measured baseline above; its
250,000-cell canvas ceiling, 8,192 pair-trial ceiling and 250-million total
route-work ceiling prevented some upper-scale requests from completing. Version
`aic-layout-generator-scale-policy-v4` preserves the same semantic topology,
packing and retry rules while resolving `max(65,536, 16*n*n)` without the
250,000-cell truncation. Thorough keeps twice the Standard per-call work. Pair
trials use `max(512, factor*target_connections)` without the 8,192 truncation.
The Fast factor stays 32; Standard and Thorough use 192 and 288. A controlled
256-facility branching Compact probe completed a seed only after allowing more
than the previous 64-times-target Standard budget. The low-level validator
allows up to 131,072 pair trials, above the policy's 110,304-trial declared
maximum for Thorough branching at 256 facilities.
The total per-attempt route work uses the original checked size-dependent
formula, `max(per_call, 2*per_call*target_connections)`, without another
truncation. The low-level validator bounds it to a portable 32-bit unsigned
count; the declared 256-facility maximum remains below that bound even for
Thorough branching Spacious. These finite work counts and separate survey
deadlines are stop budgets, not feasibility proofs. An intermediate v2 probe
used one-billion/two-billion ceilings, but a 256-facility branching Spacious
sweep reached the Standard ceiling in all three additional seeds. An
intermediate v3 probe restored the full work formula while retaining the old
pair factor. Neither was adopted as the final policy. The exact resolved
policy is recorded with each attempt.

Batch and survey commands keep their conservative two-GiB aggregate workspace
admission by default. `--workspace-budget-gib` explicitly sets the admission
budget for a machine with more memory; the report records the chosen value.
This is a run resource setting rather than a change to the requested factory.
The measured 256-facility outcomes and remaining limitations are recorded in
[the upper-scale repair report](../reports/2026-09-27-generator-scale-budget-contract.md).

## First implementation slice

Add the semantic configuration, request sampler and `scale-policy-v1` resolver;
switch the standalone CLI, examples and survey to it; keep the mechanism config
as an explicitly named internal boundary; record resolved values; and repeat a
bounded equal-slot release survey with one attempt per slot. Do not select final
facility or occupancy training distributions and do not start pretraining.
