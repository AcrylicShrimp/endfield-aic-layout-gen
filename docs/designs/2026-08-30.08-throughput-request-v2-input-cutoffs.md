# Throughput Request V2 Input Cutoffs

## Scope

The user-facing planning request starts from a final item and rate. It may also declare produced items that should be supplied externally, cutting recipe expansion at those items.

This is a hard cutover from throughput request schema version 1 to version 2. Version 2 requires an explicit `external_inputs` array, which may be empty.

## Schema

```json
{
  "schema_version": 2,
  "target": {
    "item": "originium-casing",
    "quantity": 1,
    "duration_ms": 10000
  },
  "external_inputs": ["originium-ingot"]
}
```

- Every external input must be a stable item ID.
- Duplicate external inputs are rejected.
- Every external input must be a known raw external item or recipe-produced item.
- When graph traversal reaches an external input, it records an external source and does not include that item's producer recipe or its dependencies.
- An empty list preserves full expansion to the recipe book's raw external items.

## Planning and Solver Boundary

The planning pipeline resolves recipes, computes rates, determines facility counts, and expands a fixed facility-instance wiring graph. A recipe is selected automatically only because the validated recipe book guarantees a unique producer for every item. Ambiguous producers remain a validation error rather than a solver choice.

The spatial solver receives the fixed graph. It does not select recipes or decide how deep the production graph should expand.
