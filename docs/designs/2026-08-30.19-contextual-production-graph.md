# Contextual Production Graph

## Scope

The contextual production graph is the hard boundary between hierarchical material-source selection and rate calculation. It projects one ready source plan into explicit recipe occurrences, external-input occurrences, a target endpoint, and directed material-demand edges.

This stage does not calculate rates, share co-products between otherwise independent source paths, count facilities, select ports, place facilities, or route belts and pipes.

## Input Contract

The stage receives the same validated recipe book and recipe source-plan request used by `recipes check-sources`. It runs the source check before projection and requires `ready` status.

`selection-required` and `invalid-input` source plans produce a failed graph report. The report preserves every required selection path so a web caller does not need to parse a message.

## Output Contract

`aic recipes production-graph --file <recipes.json> --request <source-plan.json>` returns:

- `success`;
- `source_status`, preserving `ready`, `selection-required`, or `invalid-input` as machine-readable state;
- the target quantity and duration when projection succeeds;
- `nodes` as a tagged union of `recipe-occurrence`, `external-input`, and `target`;
- directed `edges`, one for every active material-demand context;
- `required_selection_paths` when source choices remain unresolved;
- structured diagnostics owned by `contextual-production-graph`.

Recipe occurrence and external-input node IDs derive from their full hierarchy paths. The same item or recipe selected at two paths therefore produces two distinct nodes. Each recipe occurrence embeds the complete selected recipe DTO so later stages can calculate exact input, output, duration, and facility requirements without collapsing occurrences by recipe ID.

Each edge contains its demand path, item, source and target node IDs, flow kind, and optional cycle reference. The root demand terminates at the target node. Child demands terminate at the recipe occurrence that consumes them.

## Cycles

When a source hierarchy node references an ancestor through `cycle_to_path`, graph projection reuses that ancestor recipe occurrence as the edge source. It does not add a duplicate recipe node. The resulting directed graph is finite and cyclic, which is the shape required by steady-state throughput calculation.

## Invariants

- every successful graph has exactly one target node;
- every active hierarchy material node becomes exactly one graph edge;
- every non-cycle selected recipe context becomes exactly one recipe occurrence node;
- every external-input context becomes exactly one external-input node;
- a cycle reference must resolve to an already visited ancestor recipe occurrence;
- graph projection never selects a source or changes a source choice.

## Follow-on

The next throughput contract must index recipe run rates by occurrence node ID rather than recipe ID. Its balance equations operate on this directed multigraph, preserving contextual external cutoffs and feedback edges through facility expansion and spatial routing.
