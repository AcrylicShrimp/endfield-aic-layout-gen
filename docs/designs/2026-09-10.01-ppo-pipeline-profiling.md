# Profile and optimize the PPO pipeline before long training

Status: authorized follow-up; profiling contract precedes optimization.

The user-approved execution order is: profile, optimize measured bottlenecks,
compare CPU/GPU throughput on that optimized pipeline, compare AMP precision,
then finalize the setup and complete the production training/monitoring readiness
stage before long training. Device/precision measurements must not delay the initial
removal of measured orchestration and duplicate-computation bottlenecks.

## Objective

The user requested profiling and optimization before long training because the
current comparison is slow. Complete the running stage-43 comparison, then
identify and improve measured bottlenecks before launching a longer training
run. This extends the [device/precision probe](2026-09-10.00-ppo-device-precision-probe.md)
beyond an AMP timing comparison.

The current runner collects a complete batch using 24 CPU workers, waits for
collection, and runs optimization and its full reconstruction on one CPU thread.
Workers wait during that update. GPU is unused. These phases are sequential;
their costs should not be explained as continuous competition between active
collection workers and the learner.

## Measurement inputs and outputs

Use the user-shortened confirmation and its recorded online validation as
immutable inputs. The cancelled additional full offline audit is not required.
Preserve original phase timings for all batches and factory admission outcomes.
Distinguish constructor/generation work, observation building, policy/value
forward passes, native edit/validation work, experience serialization/loading,
tensor preparation/transfer, backward/Adam, update diagnostics, full transition
reconstruction and checkpoint verification. Label unavailable subdivisions;
do not invent them by subtracting overlapping cumulative timings.

Use the same seed-17 batch-8 inputs and selected minibatch as the precision
probe. A separate instrumented replay profiles the first admitted training
episode in that batch and verifies that its actions, physics and observations
match the retained episode. Profile the stored minibatch separately. Python
profiling identifies orchestration/serialization work; Torch operator profiling
identifies model costs. Retain instrumentation traces in ignored artifacts.
Instrumented durations are diagnostic and are not throughput measurements.

Record stable `ppo-profile.*` diagnostics, input/source hashes, profile scope,
top exclusive and cumulative costs, uninstrumented timings, memory, and an
explicit bottleneck decision. Keep the isolated profile bounded to ten minutes.
Prefer existing native timing fields to invasive instrumentation of live code.

## Optimization boundary

Choose the first optimization from measurements. Candidate changes include
device placement, precomputing fixed metadata, batching independent model
evaluations, removing redundant observation conversion, and changing when
verification is scheduled. Do not assume AMP is the dominant improvement.

The user specifically questioned full update reconstruction. It is a development
check, not a PPO requirement. Remove duplicate training from the normal long-run
loop; verify optimizer and RNG continuation in short regression/checkpoint
tests instead. This does not remove native factory validity checks or finite
gradient checks. Attribute any throughput improvement from omitting the duplicate
update separately from improvements to actual learning computation.

Preserve the action vocabulary, observation information, mask/kind balancing,
behavior probability denominator, reward, finite-horizon GAE, target freezing,
minibatch membership, optimizer-step boundaries and score acceptance. Preserve
temporary valid worsening and the best witness. Do not change factory or
selection budgets to make throughput look better. A faster path must still
report validation and audit work; excluding it from a learner-only timer does
not remove its total cost.

True minibatch evaluation must preserve per-example normalization and graph
boundaries. In particular, simply padding variable-sized rasters changes
GroupNorm statistics. Group equal raster shapes or use a formulation that
preserves the original per-example statistics. Concatenated graphs must offset
indices and aggregate only within their own examples. Sum/mean reductions and
action softmax must retain their original example membership.

Use an explicit new execution/checkpoint contract if device, precision or
experience serialization changes. Keep a bounded reference implementation for
the diagnostic equivalence comparison, then complete the chosen internal
cutover without an automatic slow-path fallback. The frozen historical study
remains separately reproducible.

## Acceptance before long training

Measure the same workload before and after, separating transfer, learner-only
time, full update with diagnostics, and complete collection/update throughput.
Verify probability/value/gradient/update drift against the reference. GPU/AMP
roundoff must be measured under declared tolerances; do not require cross-device
byte identity or silently replace the recorded behavior denominator.

Run a bounded real-native collection/update/checkpoint-continuation check under
the optimized execution contract. Verify native factory validity, finite
gradients, actual optimizer steps and replayability. Preserve comparable
evaluation budgets and report any performance or numerical regression. Record
measured throughput and remaining bottlenecks, run required repository checks,
and commit the completed optimization slice before any longer training run.

The user added a further prerequisite: after the experimental setup is finalized,
define and implement a production-grade training harness and monitoring system,
obtain independent reviews, address confirmed findings, and complete thorough
tests plus a representative real execution check. Develop the detailed
requirements at that stage. Successful optimization alone does not authorize
skipping this readiness gate and starting the long run.
