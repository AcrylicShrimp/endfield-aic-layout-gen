# Post-pose recovery diagnosis

Registered before running the counterfactual probes. The user requested checking
actual policy-created drafts to distinguish physical recovery difficulty from
policy sequencing or abandonment. This is read-only research on the completed
persistent PPO screen, not a new learner or production fallback.

## Population and source identity

Census every training pose in the two registered seeds; probe every accepted
pose, including repeats and late-episode actions. Report rejected poses
separately. Retain stream/episode/update/action/start identity and authenticated
chunk references. Do not select only successful trajectories. Evaluation traces
are outside this first population because their time budgets differ.

Reconstruct the post-action native checkpoint from the retained chunk-start
checkpoint plus authenticated successor observations. Update the retained best
only at recorded improving commits. Restore through the strict native checkpoint
API and require full semantic equality with the recorded successor before any
counterfactual intervention. Never regenerate observations from a sampling seed.

## Probe contract

Inputs: completed run protocol/state/audit, frozen native library and external
probe configuration. Outputs: source-bound probe protocol, checkpoint/case
records, structured summary and selected independently validated witnesses.

Classify existing facility/component overlap and pending endpoints inside
facility bodies. Such geometry needs further facility movement for complete
physical validity; do not count it as an unexplained routing-engine failure.
For conflict-free post-pose drafts, preserve every facility pose, original
endpoint, network identity, rate and still-routed path. Try canonical repair-all
and commit using the original 100,000-expansion / padding-4 routing bounds.

On failures, restart the same physical draft for this registered cascade:
1. Canonical repair-all, 1,000,000 expansions, original padding.
2. Canonical repair-all, 1,000,000 expansions, padding 16.
3. Individual pending repairs in three orders: reverse edge ID, decreasing
   endpoint Manhattan distance, and increasing distance. Each keeps pipes first,
   uses padding 16, and has a **total** 1,000,000-expansion branch allowance.

Every branch gets a fresh 5-second diagnostic clock and 64-action allowance.
Those are counterfactual resources, not the source episode's remaining budget.
Within an ordered branch, only the remaining expansion allowance is supplied to
the next native call; no failure silently refreshes it. One failed edge ends the
branch. Do not remove unrelated retained paths or introduce a global router.
A successful branch proves recoverability of that exact geometry under its
recorded actions. An unsuccessful cascade is bounded unresolved recovery, not
an infeasibility proof. Higher tiers are conditional probes, not independent
factorial treatment estimates.

Compare recovered score against the best retained at the sampled pose. Separate
valid recovery, full-score improvement, and positive area improvement. Every
successful witness must preserve original directed topology and pass independent
complete-factory native admission. Retain each source pose and all failed-stage
edge/route diagnostics, expansion counts and termination reasons.

## Actual continuation

Follow each source pose within its real 256-action episode, crossing chunk
boundaries. Record the next pose, restore-best, successful commit or terminal;
repairs of pending versus already-routed edges; actual repair progress; and
later overlap resolution. A new pose is further editing, not automatically
abandonment. Restore-best explicitly discards the current draft. A recoverable
but non-improving draft is not evidence of missed positive reward.

Use counts by seed/start and geometry class. Show representative actual pose,
remaining original connections and counterfactual repaired geometry. Preserve
all source experience. Put generated evidence under ignored `artifacts/` and
commit the scripts, compact findings and provenance only.
