# Matched update-size continuation comparison

Status: declared before outcomes. Bounded diagnosis of update stability from one
trained anchor; not a new capacity study or independently trained seed result.

## Contract

Restore the audited width-one seed-43 checkpoint at 1179648 commands, its Adam
moments, episode count and curriculum state. Compare learning rates 0.0003 and
0.00003 over exactly 32 further updates of 1024 commands each. Use three paired
continuation seeds 1030000, 1040000 and 1050000, with the explicit alternating
branch order in `tools/factory-edit-pilot/update-size-comparison.json`.

Every branch starts from identical parameters/buffers and Adam state except the
learning rate. Each owns fresh on-policy collection; do not train one branch on
another branch's samples. Its sixteen generators use the collector's base-seed
and 1009 stream offsets, and NumPy shuffle uses seed+100000. Restore the historical
episode ordinal so the four-round, sixteen-command rehearsal schedule remains
identical across branches. Keep current curriculum levels fixed for this interval;
observational assessments do not advance them. Preserve four epochs, 64-sized
minibatches, clipping, reward, normalization calibration and all other settings.

Use the corrected candidate-count sampler and duplicate-length admission on the
original CUDA host, in a clean separate checkout with its own native build. This
is a prospective comparison, not historical replay. Verify the checkpoint/audit,
unchanged policy source and native runtime data. Explicitly verify that the sole
native source difference from training is `engine.rs`'s admission correction and
that both length lists are unique. Record old/new source and runtime provenance.
The original six-stream source, native binary, results and gates remain untouched.

Run one common initial current-level assessment, then assess each branch after
8/16/24/32 updates, using sixteen commands, 64 seeds per case beginning at 1060000.
At the shared anchor and every branch endpoint, run original-root evaluation with
128 commands and sixteen paired seeds per case beginning at 1070000. Freeze each
actor before evaluation. Report area, physical tiles and turns with their existing
priority, translated successes, weakest cases, paired endpoint scores, and all
per-update optimizer/calibration distances relative to that update's incoming policy.
These are training-case diagnostics; no development or held-out outcome is opened.

Retain all 192 update states, endpoint actors, collected commands/sampling records,
25 complete assessments, and selected best/median root traces. Every collected
training episode and current-level assessment must replay independently. Every
root incumbent must pass native/reference acceptance; replay both selected traces
per root/actor. Account for 196608 training commands, 409600 assessment commands,
229376 root-evaluation commands and all separately counted curriculum setup work.
All 12288 Adam steps are charged. No free repair, checkpoint reselection, extra
training branch, or post-outcome seed/budget change is allowed.

## Outputs and decision

Write schema-one `comparison.json` with protocol/input hashes, source/runtime
provenance, anchor results, all six branch records, fixed-order completion status,
checkpoint and evidence hashes, timings, validation and the following decision.
For each seed compare the minimum total assessment successes over updates
8/16/24/32. The lower rate is a candidate for a larger stability test only if:

1. Its minimum is no lower in any pair and strictly higher in at least two pairs.
2. Final original-root translated successes are no lower in every pair.
3. Its pooled mean median root area ratio is no worse, computed exactly as equally
   weighted case/seed fractions. If equal, physical tiles and turns retain priority.

Report all tradeoffs even if the criterion fails. A pass supports a subsequent
larger test; it does not certify independent-seed training, generalization, required
semantic coverage, production readiness, or the 59-facility target. No permanent
learning-policy change is made by this diagnostic.

Reject changed/unaudited inputs, unexpected native source migration, dirty source,
unsupported protocol, nonfinite measurements and existing outputs. On interruption,
write an error diagnostic with stable `update_size.interrupted` code,
`update_size_comparison` stage, active branch/update reference, and preserve state.

Verify decision logic against reliability/quality tradeoffs and ties, paired branch
initialization, the full Python suite and workspace checks/tests. Run CLI help,
source/native checks, the complete comparison and artifact checks before reporting.
