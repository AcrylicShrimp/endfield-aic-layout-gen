# Korean Game Data Localization

## Scope

The repository stores Korean display data for every normalized factory item, every flattened recipe facility, every machine mode, and every machine recipe description. Localization remains external runtime data; solver domain objects continue to use stable IDs.

Recipes do not have independent names in the source tables. Their localized presentation uses the official `FactoryMachineCraftTable.formulaDesc` text as a description, while the stable recipe ID remains the identifier.

## Source Snapshot

The item and relationship tables come from the same pinned extracted game-data commit as the existing factory snapshot:

- `ItemTable.json` supplies item name text IDs.
- Existing `FactoryBuildingTable.json` supplies facility name text IDs.
- Existing `FactoryMachineCraftModeTable.json` supplies mode name text IDs.
- Existing `FactoryMachineCraftTable.json` supplies recipe description text IDs.

Korean strings are stored as table-specific text-ID dictionaries obtained from the extracted official KR text map. The source manifest records the retrieval endpoint, retrieval date, and committed checksums. Normalization never performs network access.

## Normalized Catalog Contract

`localization.ko-KR.json` has schema version 1 and contains:

- `locale`: `ko-KR`.
- `items`: stable item ID, display name, and display-name source.
- `facilities`: flattened facility ID, base facility ID, facility display name and source, mode ID, and mode display name and source.
- `modes`: stable mode ID, display name, and display-name source.
- `recipe_descriptions`: stable recipe ID, official Korean formula description, and description source.

Collections are sorted by stable ID. IDs are unique within each collection, names are non-empty, and every normalized item, facility, and recipe has exactly one localization record.

## Missing Official Strings

Eight records in `FactoryItemTable` are internal building placement items and have no matching `ItemTable` record. They are not consumed or produced by machine recipes.

When an entity has an official Korean string, its `name_source` is `official`. When no official Korean string exists, the display name is the unchanged stable ID and `name_source` is `id-fallback`. The generator never invents, derives, or transliterates a missing localization. This fallback rule applies consistently to every localized entity kind.

## Recipe Source Diagnostics

`recipes check-sources` requires a localization catalog and always returns the localized report contract. This is an explicit CLI output cutover; the underlying planning stage remains ID-based. Every source group includes its localized material name, and every recipe option includes:

- the unchanged stable recipe record;
- the official Korean formula description;
- the localized facility and mode names;
- localized names for every input and output material.

The standalone localization validation command detects incomplete or mismatched catalogs before a web process begins serving requests. Presentation lookup still applies the global ID fallback rule defensively if a referenced record is absent.

## Failure Modes

The localization catalog validator emits structured diagnostics for unsupported schema versions, invalid locale, invalid or duplicate stable IDs, blank display names, invalid name sources, inconsistent ID fallbacks, and cross-catalog coverage failures. CLI file-read and JSON-parse failures identify the input path.
