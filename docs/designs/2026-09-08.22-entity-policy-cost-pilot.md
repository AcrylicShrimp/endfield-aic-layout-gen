Status: declared before pilot training.

Run schema-2 masked-BN widths one/two (70314/264530 parameters) on the sixteen frozen
count-varied training cases, seed 17, 16384 edits each, sixteen native collectors,
1024-command rollouts and the existing nine-level curriculum/rehearsal rules. Use the
external `entity-cost-width{1,2}-study.json` protocols and fresh full checkpoints.
Do not evaluate development or held-out cases. Original-root evaluations attached
to this short run are diagnostic only; this is not enough training to judge capacity.

Measure collection, PPO update, assessment, evaluation, whole-run and CUDA allocator
peak bytes separately. Retain update/preparation details already produced by the
runner. Audit each completed stream on its frozen source. Compare basic executable
correctness and budget feasibility, not winner quality or convergence. A CPU smoke
cannot stand in for actual CUDA ragged-count execution.

Use measured costs to declare the subsequent matched multi-seed learning allowance
and checkpoint schedule before further training. That study must publish success,
area/tiles/turns and elapsed-cost curves at equal edit counts, as well as observed
checkpoint quality at matched time budgets. Never infer that a wider model is worse
from one seed or that one reliability threshold proves adequate training. If throughput
exposes a material implementation bottleneck, measure and correct it without changing
accepted actions, rewards, training sampling or the intended model's computation.
