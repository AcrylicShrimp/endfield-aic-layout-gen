# Fresh on-policy comparison of learning rate and flat-group skipping

## Status and question

Contract specified before implementation or fresh training. Reports 34/35 identify
large warm-policy movement without current task-reward gradients. Report 33's
concurrency matrix is running to select an execution mode and resource bounds.
Freeze the concrete JSON configuration and complete verification before training.

Determine whether a smaller learning rate and skipping flat-return groups improve
sustained learned factory outcomes under equal experience. This comparison does
not test longer horizons, more samples per group, architecture changes, imitation
targets or a replacement task reward. Those would confound the two controls.

## Experimental inputs

Use the same frozen imitation-warm policy as report 30, with empty Adam state in
every arm. Cross learning rates 0.0003 and 0.00003 with ordinary and skipped
flat-return updates, yielding four arms. Keep entropy coefficient 0.001, gradient
clip 0.5, the existing Adam defaults, temperature 1, balanced action-kind sampling,
history masks and all original factory/port/routing semantics.

Retain all ten training resets: five complete original factories and their five
contraction-exhausted versions. Fifty four-episode groups of 32 actions give five
complete reset cycles, 200 episodes and 6400 selected actions per arm. Each reset
receives 20 episodes per arm. Fifty groups exceed the previously observed group-38
reversal while keeping this a matched stability comparison, not a sample-scaling
claim. The full matrix requests 800 episodes and 25600 actions.

Shuffle the ten-case cycle using the original schedule seed 17, but start a new
training sample-seed namespace at 3100000. Group/attempt seeds are equal across
arms and explicit in the frozen protocol; trajectories may differ after policies
diverge. Generate every episode anew using its arm's current policy. Do not treat
retained old trajectories as fresh on-policy data or replace failed draws.

Choose the collector worker count from the completed report-33 execution-time and
memory comparison. The selected mode and report hash enter the new protocol.
Declare episode, group, arm, study and sampled-process-RSS bounds before running;
charge worker startup, routing, validation, snapshot recording, gradient replay,
checkpoint writes and monitoring. Bounds are operational guards, not factory
feasibility constraints. Preserve the original route-work and observation/state
byte limits. Do not silently extend a bound after seeing results.

## Group transaction and checkpoint contract

Collect exactly four episodes at frozen behavior weights, retain every trace and
snapshot, order results by attempt, and compute the original lexicographic relative
terminal returns. Never update from a partial group. All-equal terminal scores
give an exactly zero return vector and define a flat group.

For ordinary arms, use the existing exact-distribution gradient recomputation,
gradient clipping and one Adam step. For skip-flat arms, skip the entire gradient
replay and optimizer step only on flat groups. Policy, optimizer moments and Adam
step counters must remain unchanged. An explicit zero-gradient Adam step is not
an acceptable implementation. Entropy-gradient statistics are null when not
computed, not falsely reported as measured zero. Nonflat groups follow the same
gradient and clipping path in all arms; only the configured learning rate differs.

Every checkpoint identifies its policy schema and new learning-contract version,
arm, completed collection groups, applied optimizer updates, policy hash, model,
Adam and RNG states and protocol hash. Collection-group and optimizer-update counts
are separate because skipping changes only the latter. Do not interpret an old
single-counter terminal-result contract as proof of these new semantics.

Each arm's collection and update stay sequential. Interleaving complete groups
across arms is allowed if every arm's model/optimizer/RNG state remains isolated
and all costs are attributed explicitly. Save the preceding checkpoint before
dispatch and retain it on any group failure. No branch may become an unvalidated
production fallback; every rollout preserves its valid best factory incumbent.

## Outputs, monitoring and evaluation

Versioned protocol/progress/group/checkpoint/result records must expose requested
and actual episodes/actions, groups collected, updates applied/skipped, flatness,
returns, separately measured reward/entropy gradients, clipping, parameter identity,
timing/memory, action kinds/statuses and actual physical pose/reroute improvements.
Failures include stable code, severity, stage, arm/group/attempt and underlying
cause. A resource-ended result is incomplete and reports the actual prefix; do not
claim all four arms completed the planned matched comparison.

Monitor original/prepared training outcomes by case and balanced complete reset
cycles. Probe the same ten unchanged initial observations after each group to
track probability movement and kind mass. These probes select no actions, change
no training decisions and cannot identify a favorable checkpoint for evaluation.

Freeze evaluation membership and method/seed budgets before training. Use the
previously evaluated 35 complete factories as a disclosed development benchmark,
with new paired sample banks 3200000 and 3200001. Compare the shared initial policy
and all four terminal policies with the same action/work limits; this requests
350 episodes and 11200 actions if all training arms complete. No intermediate
checkpoint substitution or winner-only evaluation is allowed. Previously evaluated
factories are not a new untouched transfer set. Future transfer requires another
prospectively frozen, unopened case set after this comparison.

Report paired score wins/ties/losses, per-case score and area reduction, original
versus prepared results, physical relocation/rerouting and original 59-facility
Heavy Xiranite geometry/empty fraction. Inspect representative full-factory views,
including Heavy. Smaller policy movement or nonzero gradients alone are not
success. Preserve the at-most-1% empty-XY and visual-quality objective as unfinished
unless direct final-layout evidence satisfies it.

## Verification and decision boundary

Test full policy/Adam identity across skip-flat groups, distinct counters, ordinary
flat-group entropy updates, nonflat reward updates, branch isolation and incomplete
group rejection. Audit retained checkpoints and physically replay selected actions
against the complete request and independent history masks, including skipped and
unapplied groups. Verify sampling distributions against the correct behavior
checkpoint and bind every consumed artifact. Run normal repository checks and
the actual CLI on a bounded native test before freezing the real study.

After complete evaluation, compare the four arms rather than merely confirming
that the proposed fix reduces TV. A useful result must show factory-score and
physical rearrangement evidence against initialization and the ordinary-rate
baseline. Report case/bank variation and the limitation of one training stream.
Use the result to decide between larger experience budgets, horizon/credit tests
or further stability work; do not advance to production readiness on a diagnostic
win or declare RL impossible from this bounded comparison.
