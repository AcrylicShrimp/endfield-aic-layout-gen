# Local generator spatial-diversity probe

Status: complete. All twelve paired setups passed native admission while the
isolated server learner ran. See the matching report for results and limits.

The user wants more diverse spatial starts than spaced regular grids and
requested local experimentation during server training. The first slice compares
existing validated setup vocabularies before changing constructor semantics.
It does not claim uniform sampling of every valid factory or adopt a new normal
training distribution.

## Contract and continuity

Input: the existing external four-product/rate generator, release CLI/native
runtime, four newly drawn requests (first seed per product from a fixed seed
interval), and explicit setup-arm configuration. Construct each actual request
once; all arms start from that same complete admitted constructor witness.
Arm selection is independent of setup success or geometry quality.

Compare original 2–6 local edits, sixteen distant edits and sixteen group edits.
All choose uniformly among available configured kinds, then allowed candidates
of the chosen kind, using the same recorded per-request setup seed. This is not
uniform sampling over geometry or a policy-trained edit sequence. Each setup has
a 30-second native deadline; the whole diagnostic has a 600-second ceiling.
Retain failures instead of replacing difficult factories or extending budgets.

| Established requirement | Preservation and evidence |
| --- | --- |
| Fresh requests, external game data, bounded generation failures | Existing draw/admit code and actual recorded requests; no training fixtures |
| Construct complete factories incrementally, route before committing growth | Existing unchanged constructor and source-bound release native library |
| Exact request and complete valid initial geometry | Native admission of each final current witness; compare exported identity |
| Randomized starts can be worse than constructor | Export current, not retained best; never select by score improvement |
| Main training stays bound to actual inputs and launch sources | Separate local process/output; no server source, input or learner mutation |
| Time/routing/resource controls and honest failures | Explicit setup and total deadlines; per-arm completed-step/failure reports |
| Variation beyond rate or global translation | Compare normalized pair offsets, changed rotations, pairwise axis alignment and area |
| Generated artifact hygiene | Raw inputs/output/plots under ignored artifacts; compact report/config/source tracked |

Outputs: structured per-arm status/diagnostics, action counts, native admission,
geometry hashes, footprint and spatial metrics, paired comparison and a selected
visual example. A successful JSON hash change alone does not establish useful
spatial variety. The four requests form a diagnostic sample, not a distribution
estimate. Any constructor-randomization follow-up needs a separate bounded slice
if existing valid edits leave the regular-grid structure mostly intact.


## User decision after inspection

The user found that these perturbed layouts still lack human-like dense related
facility groups connected across regions. Coordinate displacement is not an
adequate proxy for that preference. The user then reconsidered the deployment
contract: real inputs are the current constructor's outputs plus the model's own
edits, because the product first constructs a factory and then compresses it.
That distribution is sufficient for the present goal. Keep the current generator
and restored 80/10/10 curriculum. Close this diagnostic without adopting its arms
or proceeding with the proposed human-like/constructor-randomization follow-up.
