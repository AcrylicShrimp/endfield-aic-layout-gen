# Layout Boundary Terminals

## Purpose

The facility-instance wiring graph contains non-facility nodes for continuous external inputs, requested target output, and recipe surplus. The integrated solver must route these edges without inventing facilities or requiring callers to remove them.

## Endpoint Contract

An external-input node is valid only as a route source. A target or surplus node is valid only as a route target. A facility remains valid in either position when it exposes a port with the required direction and transport kind.

Every boundary node must carry the same item as its logical edge. A mismatch returns `boundary-item-mismatch` before solver construction.

The route output uses a discriminated endpoint:

```text
facility { instance, port }
boundary { node, side }
```

`side` is one of north, east, south, or west.

## Constraint Model

For each boundary endpoint, the model enumerates every `(perimeter cell, outward side)` candidate and selects exactly one. That selected cell participates in the same flow-conservation equation as a facility port connection cell.

The boundary cell is a route cell. It therefore cannot overlap a facility, another route, or the opposite endpoint of the same route under the current independent-path contract. Corner cells have two distinct side candidates but only one can be selected for an endpoint.

Boundary terminal selection is solved jointly with facility placement and all other routes. It is not assigned after solving.

## Deferred Work

This contract identifies where a route reaches the layout boundary. It does not model an outside storage building, depot geometry, startup bootstrap injection schedule, or shared boundary manifold.
