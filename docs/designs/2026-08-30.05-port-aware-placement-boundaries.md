# Port-Aware Placement Boundary Constraints

## Scope

The exact facility placement model must leave the first logistics connection cell of every directional facility port inside the hard layout width and height. This slice adds that boundary condition before full routing variables are introduced.

This is part of the integrated constraint model, not a post-placement repair step. The full solver will jointly decide placement, rotation, port assignment, and routing. `FacilityPortProjectionReport` remains the observable projection of a solver result.

## Rotation-Specific Clearance

For each facility orientation, the model derives four binary constants from its rotated ports:

- `top_clearance = 1` when any port faces north;
- `right_clearance = 1` when any port faces east;
- `bottom_clearance = 1` when any port faces south;
- `left_clearance = 1` when any port faces west.

For selected orientation `o`, facility position `(x, y)`, oriented dimensions `(w, h)`, and layout bounds `(W, H)`, the model posts:

```text
x >= left_clearance[o]
x + w + right_clearance[o] <= W
y >= top_clearance[o]
y + h + bottom_clearance[o] <= H
```

These constraints guarantee that projection cannot place an outward endpoint beyond the system bounds.

## Rotation Identity

The footprint-only solver previously collapsed rotations with equal rectangle geometry. That is no longer valid. A square facility's `0` and `180` rotations have identical dimensions but can expose ports on opposite boundaries, so every allowed rotation remains a distinct solver orientation.

## Deferred Integrated Routing Constraints

- Connection cells must not overlap unrelated facility footprints.
- Logical item-flow edges must select compatible input and output ports.
- Belt and pipe routes must satisfy per-cell flow conservation.
- Transport occupancy, capacity, split/merge, crossing, and bridge rules must be enforced in the same solve.
- Route cost must participate in the optimization objective.
