# Contextual End-To-End Layout CLI

## Command

`aic layouts solve-contextual` runs the production pipeline directly from a hierarchical source-plan request:

```text
source check
  -> contextual production graph
  -> contextual throughput
  -> occurrence facility requirements
  -> facility instance wiring
  -> integrated placement, port selection, and routing
```

The command requires recipe, facility, item, transport, source-plan, and placement-request JSON files. The placement request supplies hard `max_width` and `max_height` bounds. Every facility footprint and every belt or pipe route cell must remain inside both bounds.

## Output

On a successful spatial solve, one JSON report contains:

- `success`;
- the complete contextual throughput report;
- occurrence-owned facility requirements;
- solver-facing facility instance wiring;
- the integrated layout report with placements, selected ports, belt routes, and pipe routes.

The embedded throughput report preserves cycle bootstrap options. Upstream failures emit the earliest failed stage report, including required source-selection paths when the source plan is unresolved. A spatial failure still emits the contextual reports and the failed layout diagnostics.

## Verified Examples

The synthetic single-facility source plan proves a bounded end-to-end belt route through `data/examples/source-plan.request.json`.

The official normalized moss production loop is represented by `data/examples/source-plan.game-seed-cycle-small.request.json`. Its unique planter and seed collector recipes form a finite contextual cycle automatically. The integrated solver must place both facility occurrences and route the two feedback flows plus the target output without treating bootstrap inventory as a continuous external input.

## Remaining Cutover

The flat throughput-request v3 commands remain available only while existing examples and callers are migrated. The contextual pipeline is now complete through the spatial solver. A future hard cut removes global `external_inputs` and `producer_selections` after the web boundary and remaining fixtures use source-plan schema version 1.
