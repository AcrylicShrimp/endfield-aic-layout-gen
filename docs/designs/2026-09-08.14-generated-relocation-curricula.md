# Generated relocation curricula

Status: implementation contract for stage 3, before generated-layout training.

Input: a schema-1 accepted pilot case with one cardinal translating placement edit,
its verified witness, runtime catalogs, run configuration, and a schema-1 split spec.
The spec lists unique variant IDs, split (`train`, `development`, `heldout`),
nonnegative outward gap extensions and clockwise quarter turns. Outputs are ordinary
schema-1 cases and a schema-1 manifest with source hashes, geometry hashes, initial
and witness scores, first reward distance and split membership. Outputs belong under
ignored `artifacts/` or `target/`.

Supported transformation: extend the one moved facility away from its witness target.
Translate incident external networks with it; extend the moved endpoint of a straight
internal corridor. Translate the corresponding witness erase cells and external
bindings, preserving the witness displacement. Rotate every facility footprint,
network corner and absolute binding together. Derive IDs and displacement from the
input, never from game identifiers in application code. Unsupported witness or
corridor shapes fail explicitly. This is augmentation of an existing verified
witness, not witness discovery for arbitrary factories.

Admission requires unchanged request obligations, a valid initial layout, every
witness action in the native action domain, native/reference step agreement, a valid
best layout throughout, positive area gain and actual facility translation. Derive
all curriculum prefixes through the first positive reward using the existing native
prefix validator. Duplicate canonical geometry across splits is an error. The
manifest records all transformations before training; held-out layouts may be
validated structurally but must not be used for policy selection or learning.

Initial split: train gap extensions 0 and 4, development 2, held-out 6 and 8; each
uses all four rotations. This tests unseen relative spacing on one production chain,
not new facility counts or production chains. Stage 3 additionally requires a
separately declared learning/selection/evaluation protocol and measured held-out
policy benefit; generator correctness alone does not complete it.

Failures carry stable `augmentation.*` codes, stage `augmentation`, severity `error`,
message and relevant variant/input path. No invalid case is admitted to the manifest.
File publication is last, after all variants pass admission. Generated case paths
are explicit hash-checked external audit inputs; tracked source files still verify
against their recorded Git revision.
