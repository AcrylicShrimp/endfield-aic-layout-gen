# Completion-First Facility Construction

Status: Implementation slice approved through the construction-first research decision.

## Contract

Replace automatic compact-module discovery/composition with `layouts construct-production` and
`construct_production`. Remove the old automatic module API/command, not reroute it through an
adapter. Explicit, manually selected module diagnostics remain isolated experimental tools.

Input: validated wiring, facility, item, transport and component catalogs; request schema 1 with
seed instance, maximum growth transactions, placement-attempt limit and A* call limit per transaction.
No W/H input. Every runtime quantity and port comes from those catalogs.
The report echoes the request and the operational limits: at most 64 A* calls per fixed connection
attempt and 1,000,000 dense routing-workspace cells. Recursive lane depth is bounded by the A* budget.
These are implementation resource guards, not game rules or infeasibility proofs.

Output: production report schema 1 with status, full-completion flag, required/constructed facility
and internal-requirement counts, accepted transactional history, last validated node, unresolved
external requirements, per-step attempts and routing counters, elapsed time, and structured failures.
At growth failure, include the attempted facility groups and the last geometrically valid but
boundary-obstructing candidate, its triggering connection and blocked requirement identities.
That candidate is diagnostic evidence only, never the committed final node.
`success` means a complete factory, not simply a valid partial state. A budget stop retains the
last validated node. External connection realization remains an explicitly reported subsequent
stage in this first cutover; internal completion alone must not set full completion.

## Construction

- Grow one frontier facility or strongly connected facility group. Within a cycle transaction,
  connect each newly added facility before adding another and close all newly internal edges.
- Reuse facility identities already in the current node. Never instantiate them twice or discard
  a useful frontier because a predefined module overlaps them.
- Allocate compatible port domains for all incident commodity demands on the new facility, using
  capacity-grouped totals. Reserve their immediate escape cells while routing other connections.
- Try deterministic separated positions near the connected facility, then the current layout's
  exterior, with allowed rotations. Clearance derives from the new facility footprint. This is a
  placement heuristic, not a blueprint size restriction. The portfolio has four port/rotation
  variants and 32 positions per addition, all subject to the transaction's operation budgets.
- Accept the first independently validated connected candidate with remaining boundary support.
  Do not enumerate candidates for area improvement, share an area incumbent, or freeze a compact
  process module before its outgoing connection is known.
- Route pipes before belts within a growth transaction. Extend normalized commodity networks with
  real catalog components and segment-local residuals. Split a remaining rate over available
  attachment capacity, not only over initially unused ports.
- Preserve the current node when any local attempt fails. Retry an uncommitted addition; this slice
  does not roll back accepted history, place bridges, or implement an improvement optimizer.
- Measure area/tiles/turns for reporting only. The later improvement priority remains unchanged.

## Invariants and failure modes

Every accepted node has unique facilities, independently valid geometry and flow, and all wiring
edges between its placed facilities routed. Boundary ports must retain capacity and an escape to
free exterior space under the current bridge-free routing model. This is a constructive screen,
not a proof of global extendability. In particular, the exterior screen checks that each remaining
boundary has at least one accessible attachment; it does not prove that all remaining rates can
simultaneously reach the exterior. Cycles are committed atomically.

Failures use stage `constructive-planner` and stable codes: `production-input-invalid`,
`production-port-allocation-failed`, `production-growth-exhausted`, `production-route-budget-exhausted`,
`production-placement-budget-exhausted`, `production-routing-workspace-budget-exhausted`,
`production-step-limit`, `production-external-connections-pending`, and independent geometry codes.
Record the facility group, requirement, attempt counts and rejection reasons. No failure is global
infeasibility. Hard operation limits are diagnostic controls, not game limits.

## Verification and research gate

Regress a separated moss-style fan-in/fan-out, existing-producer reuse/cycle closure, pipe priority,
shared capacity, first-feasible selection, transactional exhaustion, and honest completion status.
Run the real Heavy Xiranite source plan with a full-graph growth budget. Measure coverage, elapsed
time, A* calls, actual footprint and next failing stage. Keep the unoptimized layout and inspect its
history. Do not weaken capacity or geometry rules to claim completion.
