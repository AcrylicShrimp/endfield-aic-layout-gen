# Logistics-Component Routing

## Problem

Facility-instance wiring edges are material-flow requirements, not one-to-one physical transport lines. The current integrated solver incorrectly turns every capacity-split wiring edge into a cell-disjoint route. Endfield represents branching, convergence, and same-layer crossings with explicit logistics components, so valid layouts require transport networks containing those components.

The pinned source snapshot contains the required component records:

- `FactoryGridRouterTable`: belt splitter and converger;
- `FactoryGridConnecterTable`: belt logistics bridge;
- `FactoryLiquidRouterTable`: pipe splitter and converger;
- `FactoryLiquidConnectorTable`: pipe logistics bridge.

The official Korean item names confirm that the source IDs called `connector` are the belt and pipe logistics bridges.

## Runtime Data Contract

`logistics-components.json` schema version 1 contains one normalized record per component. Each record has a stable ID, transport kind, component kind, one-by-one horizontal footprint, input directions, output directions, and line capacity.

Component kinds are:

- `splitter`: one input and up to three outputs;
- `converger`: up to three inputs and one output;
- `bridge`: up to two independent crossing channels on the same transport layer.

Directions are normalized from the source Y-axis rotations and remain relative to component rotation. Actual game data stays external; application code contains only schemas and validation rules.

## Network Contract

The routing stage groups material-flow requirements into directed commodity networks by item and transport layer. A network carries exact flow on directed line segments and component channels.

- Plain belt or pipe cells carry at most one directed channel and enforce line capacity.
- A splitter divides one incoming commodity flow among two or three outgoing channels without creating material.
- A converger combines two or three incoming flows of the same item into one outgoing channel without losing material.
- A bridge permits two independent channels of the same transport kind to cross without merging their items or flows.
- Belt and pipe layers remain independent and may overlap without a bridge.
- Different items may never merge through a splitter or converger.
- Facility ports retain their fixed direction and transport kind.

Logical wiring edges remain visible in diagnostics, but physical route output must also identify placed logistics components and the network segments connected through them.

## Solver Decomposition

The placement solver chooses production-facility coordinates and rotations using coordinate variables, rectangle non-overlap, symmetry breaking for interchangeable instances, and an approximate connection objective. It does not enumerate every legal origin as a Boolean candidate.

The routing solver places transport networks and logistics components separately for belt and pipe layers. A failed route returns a structured conflict over facility positions, port assignments, corridor capacity, or missing component capability. The placement stage consumes that conflict as a cut and retries. A feasible witness becomes a warm start for local joint refinement.

This feedback loop preserves placement-routing coupling without constructing every route arc on every grid cell in one monolithic model.

## First-Feasible Execution Path

The default `coordinate-feasibility` strategy stops coordinate CP search at the first feasible production-facility placement. A deterministic shelf arrangement is supplied only as a warm-start branch order; the CP model still enforces rotation, hard bounds, routing clearance, and rectangle non-overlap. The initial routing clearance is ten cells.

The current routing pass assigns compatible fixed ports, constructs capacity-split belt and pipe routes, inserts bridge records at valid perpendicular same-layer crossings, and independently validates the complete witness before reporting success. A placement or routing timeout/failure remains `unknown`, because this execution path does not prove global infeasibility. Splitter and converger network sharing remains the next routing-model cutover; capacity-split routes are retained until that cutover is complete.

Before spatial component placement, a topology pass groups terminal branches only when their exact combined rate fits one component line. Deterministic first-fit-decreasing capacity bundles prevent a splitter or converger trunk from exceeding catalog capacity. A component with branch arity `A` requires `ceil((branches - 1) / (A - 1))` tree nodes. The `routing-network-topology-planned` diagnostic reports the network, shared-bundle, terminal, splitter, converger, and maximum-branch counts while those requirements are still unplaced.

Sparse path search starts in an active-height corridor around the placed facilities and retries with progressively larger corridors. The final retry uses the full hard height, so corridor pruning changes search order and runtime but does not remove the existing full-grid fallback. Boundary candidates on an omitted south region are not mislabeled as hard-boundary terminals.

## Parallel Feasibility Portfolio

Coordinate feasibility uses up to four independent workers, bounded by available hardware parallelism. Workers preserve the caller's hard width and height for final routing validation but solve placement with distinct width caps: the full width, nine tenths, four fifths, and three quarters. These conservative first portfolio steps keep enough routing corridor to produce useful incumbents; later rounds can shrink from the best validated cap. Each worker owns its Pumpkin solver and routing state; no mutable solver state is shared across threads.

Only complete independently validated witnesses enter the incumbent set. The selected witness minimizes the deterministic tuple `(bounding-box area, maximum side, route cells, placed logistics components, placement width cap)`. Failed narrower workers are not evidence that the caller's full hard bounds are infeasible. If every worker fails, the full-width worker's status remains authoritative. Each worker reports a `parallel-portfolio-worker-result` diagnostic keyed by its width cap, and `parallel-portfolio-selected` reports the worker count, successful candidate count, selected cap, and score. The caller's search time limit applies independently to each worker's CP search. Routing receives a per-worker deadline equal to the larger of that limit and five seconds so failed compact candidates cannot dominate portfolio tail latency.

## Output And Diagnostics

Integrated layout output adds placed logistics components with stable component ID, position, rotation, transport, component kind, and connected network references.

Constructive failure remains `unknown` unless a sound bound proves infeasibility. Stable diagnostics distinguish missing catalog capability, port assignment failure, corridor routing failure, and component placement failure. Optimality is reported only by an exact refinement stage that proves it.

## Verification

Tests must prove exact flow conservation through splitter and converger nodes, independent same-layer crossing through bridges, belt/pipe layer independence, capacity enforcement, deterministic normalization, and rejection of invalid component topology. The full internal Heavy Xiranite plan must produce a completely routed witness within the caller-supplied 500 by 500 factory bounds.
