## Input and output contract

Input: a completed audited short-pilot directory, selected seed, explicit worker
count, training duration, evaluation interval, output directory and resource
limits. The continuation protocol binds source files, runtime/data identities,
the source audit/report/checkpoint hashes and the complete initial optimizer
state. Preparation rejects an unaudited source or a discontinuous checkpoint.

Output: frozen protocol, initial resumed checkpoint, immutable per-batch results
and audits, policy/Adam/RNG checkpoints, an ordered compact batch manifest,
periodic matched evaluations, progress snapshots and a terminal report. Progress
must not rewrite every historical episode payload at every update. Retain all
actual generated inputs, starts, selected trajectories and episodic gradients.
Expose counts of attempted/admitted/rejected factories and selected actions,
the current update/attempt cursor, latest evaluation and termination reason.

The reduced execution mode explicitly shortens batches, horizons and setup and
caps the number of updates. It starts from the same saved optimizer state but
its output is never eligible as the full continuation's source checkpoint.

## Runtime and verification

Use one persistent 24-worker collection pool under frozen weights per batch.
Restore model, optimizer and RNG before continuation. Verify the actual restored
weights and Adam moments against the audited source. A direct replay of an
optimizer transition from saved gradients must reproduce the updated weights
and Adam moments. Independently reopen every admitted initial and terminal-best
witness in native validation before accepting a batch. Incomplete batches cannot
update the policy. Keep the existing sampled RSS, task and batch limits.

Run for up to 43,200 training seconds, including routine generation, collection,
updates and periodic evaluations. Evaluate every 64 completed global updates.
A final evaluation may use a separately bounded 600-second finishing window.
If the training deadline interrupts a batch, preserve its partial evidence and
the last complete checkpoint; report a time limit, not a successful update.
Unexpected worker, validation, source-identity or numeric failures stop the run
with a structured diagnostic. Signals clean owned worker process groups.

A separate Linux supervisor survives SSH disconnection and enforces an outer
wall limit of training plus finishing, worker-startup allowance and 30 seconds.
It tracks descendant process birth identities and session groups, requests
graceful coordinator shutdown, and cleans remaining owned workers if necessary.
It must not signal an unrelated process after a numeric PID is reused.

Check free disk space before starting another batch, with a 16 GiB reserve.
After a batch's native/checkpoint audit, record hashes and sizes and delete only
its regenerable accepted-construction candidate report and HTML visualization.
Retain constructor roots and initial witnesses, original requests, randomized
starts, failures, setup traces, policy trajectories, gradients and checkpoints.
Never delete a source input or a file referenced by the actual episode-case
identity manifest. Record cleanup in an artifact manifest; do not retain bulky
constructor candidate histories merely to keep the long run reproducible.

Acceptance for launching the requested long run requires the source pilot audit,
restored-state continuity, reduced real-native continuation/audit checks, failure
cleanup checks, frozen full sources and a detached server process with observable
progress. Do not wait twelve hours before reporting that the authorized run is
