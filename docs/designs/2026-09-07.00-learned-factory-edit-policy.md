## Intended task and boundaries

Given a complete independently valid factory and its immutable production request, produce
an improved complete factory within an explicit computation budget. Keep recipes, required
facility identities, rates, commodity obligations, and real external inputs/outputs unchanged.
Factory width and height are measured outputs; temporary expansion is allowed. There is no
caller-supplied production canvas ceiling.

The quality order remains used bounding-box area, physical transport tile count, then directed
route turns. An improvement claim requires independent validation and this comparison.
Neither a rejected edit nor an exhausted episode proves global infeasibility or optimality.

The earlier 59-facility Heavy Xiranite target and its user-required density/visual goals remain
recorded in the [historical acceptance contract](../benchmarks/layout-production/contract.md).
This design does not revoke those requirements, certify their feasibility, or promote that
document's provisional numeric release thresholds into a new experiment plan. Initial area-only
learning would not satisfy the full routing, density, generalization, or visual requirements.

### Production policy comparison

The [accepted constructive design](2026-09-02.00-constructive-layout-planner.md) keeps production
construction connected and immediately routed, uses a dedicated path-search engine, and accepts
only independently valid improvements. This proposal addresses private improvement of an already
complete factory; it is not permission for global facility-only construction.

Best-result acceptance, immutable production obligations, runtime catalogs, score priority, and
isolation from the global exact solver are preserved. Learned path generation is a proposed
replacement for path selection inside a future improvement experiment. It does not change the
production A*/Dijkstra router, pipe-first production routing, CLI, or AGENTS.md. Production
integration would need a separate explicit contract/policy cutover. Research editing order is
still open and must not silently become a change to production routing order.

## Why an edit policy

A fixed router can consistently undo a useful detour: the policy may need to route around a
corridor now so that a facility can occupy it later. Selecting a placement while a router always
rebuilds the central path cannot express that plan. The policy need not imitate the router, but
it must optimize against its responses and cannot request paths outside its output choices.

The proposed boundary gives the model control of paths, ports, branches, merges, and changed
facility placements. Code expands specified geometry, updates indexes, and checks rules.
There is no implicit shortest path, automatic repair, snapping to a nearby destination,
heuristic candidate substitution, or exact-solver fallback.

Structured commands avoid regenerating unchanged geometry. They are not a text-generation
requirement: a decoder may select an operation, point to an input entity, and select typed
parameters. Human-readable command text is a trace rendering, not the learning interface.

## State and stage contracts

Names below are proposed logical DTOs, not implemented schemas. A future implementation must
version serialized inputs, observations, actions, and reports independently of model weights.

### Episode input

`EditEpisodeInput` contains:

- schema version, original request identity/content hash, complete initial layout and hash;
- explicit runtime catalog paths/hashes and validation/score contract versions;
- immutable required facilities, rates, terminals, and commodity networks;
- episode and command resource budgets, declared seed, and split/provenance identity.

Input admission independently validates initial geometry and original-request coverage. Missing
files, unsupported semantics, catalog mismatches, or invalid initial layouts are admission errors,
not episodes in which an invalid root is silently repaired. Rejected roots remain in admission
statistics. No constructor-success-only sampling claim represents the full requested distribution.

### Environment state

Keep three distinct objects:

| Object | Invariant | Purpose |
| --- | --- | --- |
| `best` | Complete, independently valid, best exact score seen; initially the input. | Only source of the final exported factory. |
| `working_base` | Complete, independently valid; may be worse than `best`. | Starting point for the current edit transaction and valid detour exploration. |
| `draft` | Explicit private edits over `working_base`; may have unresolved connections. | Model-visible multi-command work in progress. |

Also retain immutable production obligations, a monotonic observation revision, route cursors,
terminal bindings, pending obligations, a work ledger, and an edit trace. Do not collapse `best`
and `working_base`: doing so would reject valid detours. Do not score a disconnected draft as
a successful area improvement or use its missing transport as a density win.

Each command is atomic: either all its specified changes occur or the state is unchanged.
An unsuccessful command still consumes its charged budget. The draft can be topologically
incomplete, but accepted commands maintain defined geometry, entity identity, and mechanical
occupancy rules. Examples include unattached route ends and temporarily unbound terminals;
they do not permit lost facilities, changed recipes, or ambiguous overlapping channel semantics.

### Observation

`EditObservation` exposes the current revision, complete immutable request/network information,
draft placements and transport topology, bindings and unresolved obligations, active cursor,
remaining budgets, last command outcome, and current best/working-base score summaries.
The initial score must be visible if rewards normalize by it. Transaction mode is visible.

Facility and terminal references point into the current input entity tables rather than using
memorized training IDs. Created geometry receives explicit handles. Erased handles become invalid;
coordinates alone do not resolve two crossing channels. A stale revision or deleted reference is
rejected instead of resolving to a different object. A rejected command does not change geometry;
the observation revision still advances because budget/outcome information changed.

The logical observation contract precedes tensor encoding. A local raster alone can hide remote
dependencies and used-boundary changes. Candidate encodings are a whole raster with entity
features, an attributed graph with explicit geometry, or a graph plus precise local rasters and
global spatial context. A crop is an observation choice, not an edit boundary or factory limit.
Summaries/crops may make the policy partially observed; do not claim a sufficient Markov state
without checking it. Full working-base geometry or suitable memory may be needed to reason about
discarding edits; a scalar score alone does not describe that fallback.

### Action and response

`EditAction = {schema_version, observation_revision, operation, typed_arguments}`.
The model selects operation and conditionally decoded arguments; the executor owns validation.
Pointers refer to the supplied entity tables. Integer grid transforms are exact. Decoder order
for multi-entity commands is canonical, with no duplicate facility assignments.

`EditStepResult` contains the new revision/observation, applied or rejected status, explicit
geometry/binding delta, affected entities and pending obligations, charged work, and diagnostics.
No reward value is finalized until the learning objective is selected.

## Proposed command vocabulary

This is a semantic draft. It expands the conversation's shorthand where paper walkthroughs
expose missing operations. It is not yet a claim of coverage for every legal game layout.

| Operation | Arguments and exact effect |
| --- | --- |
| `SET_PLACEMENTS` | Explicit list of facility IDs and target origins/allowed rotations. Apply all assignments simultaneously; validate against unchanged geometry and one another. A singleton expresses an ordinary move. |
| `UNBIND_TERMINALS` | Explicit terminal IDs. Remove their physical port/boundary bindings in the draft; keep their immutable item, role, rate, and connectivity obligations. |
| `BIND_TERMINALS` | Explicit terminal-to-facility-port or terminal-to-external-boundary-anchor assignments. Check catalog compatibility and selected-port geometry; pending connectivity remains visible. |
| `ERASE_TRANSPORT` | Exact physical edge runs and/or component channel references, with explicit layer and network/channel identity. Delete that geometry, not an entire logical requirement's guessed path. |
| `START_ROUTE` | Network, anchor, and directed growth mode. Select an existing port connection cell, open end, or explicit compatible network attachment point; does not create a path. |
| `EXTEND` | Active cursor, cardinal direction, positive integer length. Materialize exactly that straight run. Every traversed cell/arm is checked; no jumping over obstacles or automatic turns. |
| `CONNECT` | Cursor and exact compatible target anchor/channel. Join only coincident or exactly adjacent endpoints according to the declared port/arm rule. It performs no path search. |
| `SET_TOPOLOGY` | Explicit cell/component geometry, permitted orientation, and directed arm/channel connectivity. Specify a branch, merge, or independent crossing whose choice is not uniquely implied by ordinary path segments. |
| `FINISH_EDIT` | Request full factory validation of the draft; do not repair it. |
| `DISCARD_EDIT` | Restore the current `working_base`, clear draft-created handles/cursors, and charge the work. It is not an episode reset or budget refund. |

### Placements and atomic groups

Facilities cannot be deleted or invented. Before moving/rotating a bound facility, explicitly
unbind the affected terminals and erase any transport/component geometry that would conflict
with the new footprints. Old transport does not move with the facility. Endpoint coordinates
are recomputed from catalog ports and chosen transforms; binding and route changes remain
explicit. A group command cannot hide auto-rerouting or delete obstacles.

Simultaneous assignments support swaps without representing an intermediate facility overlap.
This is a static layout edit, not a simulation of moving physical objects along collision-free
trajectories. Check final group geometry as a whole. Do not mask one group's destination simply
because another member currently occupies it. A singleton can instead use temporary free space.

Group size and decoder limits must be declared as action-domain limits before experiments;
they are not game rules. Sequential subassignments inside one command are charged even though
the final mutation is atomic. Truncated command decoding applies no partial geometry.

### Physical transport and terminal semantics

Use [the mathematical model](aic-game-rules-mathematical-model.md) to identify confirmed rules
and unresolved ambiguities. Never turn an unresolved ambiguity into a pruning rule.

- Shared trunks are one physical resource. Erasing one affects every dependent demand; retain
  and report all those demands rather than deleting one logical edge and pretending others work.
- Coincidence is not connectivity. Every shared/independent channel relationship is explicit;
  crossing two routes must not silently merge their materials.
- Ordinary degree-two geometry may determine one component uniquely. Deterministic mechanical
  derivation is acceptable only then. If geometry leaves a topology/component choice, expose
  it to the policy with `SET_TOPOLOGY`; do not silently select a router preference.
- The exact interface between `EXTEND`, `CONNECT`, and `SET_TOPOLOGY` at a junction is OPEN.
  Before implementation, specify atomic arm addition and cursor advancement for every catalog
  topology, including crossings. A placeholder command is not evidence of expressibility.
- Port reassignment preserves supply/demand direction, transport kind, item, and rate. Aggregate
  compatible terminal rates on shared resources and check their actual capacities.
- External inputs/outputs are immutable obligations with editable geometry, not fake endpoints
  that can appear wherever convenient. Boundary membership is checked against the final actual
  used bounds, including all retained geometry. Expansion can invalidate an unchanged old anchor.
- Pending flows may be unresolved during drafting. `FINISH_EDIT` requires a valid flow/capacity
  certificate for the exact specified geometry, with no geometry repair. How to derive/check that
  certificate for shared networks and cycles is OPEN; no global placement-routing solver fallback.
- A finite per-command segment length can be repeated and must not become a fixed W/H ceiling.
  Length-one segments should be expressible; this alone does not prove full topology coverage.

### Completing and discarding work

On successful `FINISH_EDIT`, independently verify the complete original request, geometry,
terminal closure, topology, capacities, actual external boundary, and score. Promote the draft
to `working_base` even if its valid score is temporarily worse. Update `best` only if its score
strictly improves the configured lexicographic order; retain the earlier best on a full tie.
Clear transient cursors and start a clean draft over the new working base.

If completion fails, return the smallest available diagnostic scope and leave the draft editable.
Validation resource exhaustion is distinct from invalid geometry. On `DISCARD_EDIT`, return to
the working base, not automatically to the best. A separate explicit best-reset operation may
be considered later; it is not silently bundled into rejection or discard.

At episode termination, export `best`. A final dirty draft is unfinished, not implicitly accepted.
The policy must budget for `FINISH_EDIT`; there is no uncharged final repair/validation search.
Deadline handling must preserve an already independently validated best result even if the
latest completion check did not finish. Diagnostic draft output, if retained, is labeled invalid
or unvalidated for factory use and kept outside tracked source.

## Paper walkthroughs

These are conceptual command/obligation checks, not executed experiments or catalog-valid
fixtures. Coordinates, port identities, capacities, and component choices must be supplied
before any walkthrough becomes executable. They show required interfaces, not a solvability
proof or evidence that the model can discover the sequence.

### A. Detour a route, then compact a facility

Assume an outer corridor permits a valid replacement for a central route and its terminals.

1. Erase the exact central physical run; affected connections become pending in the draft.
2. Start at the retained upstream anchor, extend explicit outer straight runs, configure any
   needed topology, and connect to the downstream anchor.
3. Finish the edit. This can be a valid worse working base with more transport or larger bounds;
   the original best remains available. Repair any actual-boundary obligations before finishing.
4. Unbind ports of the facility to move, remove conflicting geometry, and set its new placement.
5. Bind its terminals, explicitly redraw affected connections, and finish the edit.
6. Compare the complete result's actual score with best. No credit comes from the disconnected
   small draft after step 1 or 4.

Design consequence: direct paths, valid detours, terminal rebinding, and best/base separation
are all necessary. An engine that reinstates the central shortest path defeats this sequence.

### B. Exchange two facilities

Assume the two final footprints/rotations fit and eventual port routing is possible.

1. Unbind affected terminals of A and B; erase precisely the conflicting route geometry.
2. `SET_PLACEMENTS` assigns A to B's prior region and B to A's prior region in one atomic command.
3. Rebind legal ports; route the actual obligations with explicit segments/topology; finish.

A singleton-only interface requires a buffer location and additional moves; it is a narrower
bounded action domain. A rigid group translation cannot express a swap. The proposed list of
independent final placements resolves that particular interface gap. It does not guarantee the
resulting factory can be routed. The action edits an existing complete-factory draft, not an
empty constructor's global placement phase.

### C. Relocate a shared trunk

Assume one compatible commodity network supplies several consumers through shared geometry.

1. Identify the shared physical run and junction channels to replace. Erase that explicit set;
   retain every original consumer/supply obligation and expose all impacted pending terminals.
2. Draw the replacement trunk, specify directed branch/merge topology, and connect all retained
   branches. Existing independent crossing channels must survive untouched when not selected.
3. Check capacities/flow for the whole affected network and external boundary, then validate
   the full factory. A success for only one consumer cannot finish the edit.

Design consequence: per-requirement path deletion is insufficient; topology and physical identity
belong in both observation and actions. This is the first walkthrough to resolve in detail next,
because it exercises the currently open topology/flow semantics.

## Budgets, masking, and diagnostics

The proposed fixed-T episode counts every submitted command, including rejection, route start,
finish, and discard. Expose remaining commands. Also charge decoded group entries, expanded
transport cells, rule checks, full validation calls/work, elapsed time, and peak memory. A long
straight command and a singleton move are not equal computational work. Model inference and
mask construction are included in time comparisons. No free retries, internal route search, or
unlimited validation inside one nominal action.

Exact T, per-command limits, and deadline behavior need a predeclared experiment configuration.
If T defines the actual objective, it is a true finite-horizon episode. If data collection merely
cuts a longer task, it is truncation and requires appropriate value bootstrapping; do not mix the
two when selecting a learning algorithm. Longer evaluation is a separate generalization test.

Masks may exclude malformed references and proven immediate rule violations under the actual
command semantics. They must not silently prune inconvenient detours, future-disconnectivity
guesses, or heuristic candidate rankings. Report domain restrictions and mask costs. An inability
to decide legality within a bound is a resource diagnostic, not proof of illegality.

Proposed `EditDiagnostic` fields: `code`, `severity`, `stage`, `message`, `entity_refs`,
`observation_revision`, `command_index`, and relevant budget/contract details.

| Proposed stable code | Stage | Meaning |
| --- | --- | --- |
| `edit-input-invalid` | admission | Initial layout or immutable request fails validation. |
| `edit-input-missing` | admission | Required input/catalog path is absent; include the path. |
| `edit-semantics-unsupported` | admission or validation | Declared rules cannot be represented or verified. |
| `edit-reference-stale` | decode | Revision mismatch or deleted/unknown entity reference. |
| `edit-command-malformed` | decode | Invalid operation/arguments or incomplete atomic command. |
| `edit-geometry-conflict` | execute | Specified geometry violates a known immediate rule. |
| `edit-topology-ambiguous` | execute | Channel/component decision is missing; no automatic choice. |
| `edit-terminal-incompatible` | execute | Explicit binding contradicts terminal/catalog semantics. |
| `edit-obligations-open` | validation | Full original connectivity/boundary obligations are incomplete. |
| `edit-capacity-invalid` | validation | Specified network cannot satisfy the checked rate contract. |
| `edit-validation-exhausted` | validation | Verification budget ended without a conclusive check. |
| `edit-budget-exhausted` | episode | Command, decoded-work, time, or memory bound was reached. |
| `edit-draft-unfinished` | episode | Termination leaves private edits that cannot be exported. |

`EditEpisodeReport` records input/version hashes, seed/split, admission result, termination reason,
initial/best scores and geometry hashes, validated best improvements, valid detour completions,
command counts by operation/status, unfinished/discarded work, rule and capacity failures,
validation work, time/memory, and output paths. Exported best always has its validation evidence.
Artifacts belong under ignored `target/` or retained `artifacts/`; commit only concise findings,
source/configuration, and compact provenance. A model checkpoint alone may not resume a stream.

## Learning objective and evaluation: deliberately not selected

The product objective is complete factory quality within budget. A possible first scoped reward
is `r_t = (best_area_before - best_area_after) / initial_area`, with undiscounted finite-horizon
return. Only successfully completed validated edits can change best area. Its sum is the final
relative area improvement, averaged over the declared episode distribution. It supplies no
signal for unfinished edits and does not train the lower-priority routing objectives. Many
command sequences may therefore receive zero task reward. This is an open credit/exploration
problem, not a reason to silently add rewards for drawn tiles or short diffs.

No arbitrary weighted sum is accepted as preserving area/transport/turn priority. Avoid penalties
that rule out useful valid detours or rewards for small disconnected drafts, filler geometry,
partial connections, or frequent finishes. The exact objective, shaping, baseline/value targets,
discounting, and failure treatment need to be designed together before any learner is built.

A later experiment should freeze a question, distribution and admission accounting, train/dev/test
groups including related-layout descendants, independent seeds, checkpoint selection rule, and
budget before execution. Controls should share the same edit semantics: unchanged initial factory,
untrained model, random policy, and simple geometric/greedy search. Single-edit greedy search and
multi-command search have different reachability; report that distinction and search costs.
Compare both charged work and elapsed time, preserve every failure, audit actual returned layouts,
and distinguish fixed-root learning from held-out topology/scale generalization.

No numerical budget, training run, hardware allocation, success margin, CNN/GNN comparison, or
algorithm has been scheduled. Loss movement or parameter changes alone will not establish useful
factory improvement. Small paper examples are interface checks, not substitutes for that goal.

## Research references and their limits

- [NeuRewriter](https://papers.nips.cc/paper/2019/hash/131f383b434fdf48079bff1e44e2d9a5-Abstract.html)
  studies learned local region/rule selection. It motivates an improvement-policy framing, not
  this game's command completeness or achievable packing quality.
- [Graph Networks](https://arxiv.org/abs/1806.01261) and
  [Graph Attention Networks](https://arxiv.org/abs/1710.10903) distinguish relational representation
  from a particular aggregation mechanism. They do not select our encoder.
- [Time Limits in Reinforcement Learning](https://proceedings.mlr.press/v80/pardo18a.html)
  distinguishes task horizons from collection truncation and explains remaining-time observations.
- [Attention Routing](https://arxiv.org/abs/2004.09473) learns routing order with routing rules in
  an algorithm. Do not cite its results as proof that a model directly generates physical paths.
