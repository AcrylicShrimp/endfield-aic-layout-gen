# Variable entity observation cutover preparation

Status: preparation contract implemented by schema note 19; merged after stage-3
first-pass confirmation. New-policy learning remains a separate experiment.

## Confirmed current restrictions

The observation raster has `2*(facilities + networks + 8 + terminals)+3` channels.
Terminal rows have network/facility one-hots; candidate feature width also depends
on those identity counts. `Policy.fusion` flattens all object embeddings into a
fixed-width input, and batch preparation uses `np.stack` on object rows.
`two_case.validate_compatibility` additionally requires the same production signature,
instance IDs and category ordering. Padding a larger object table alone therefore
cannot admit variable facility counts or production chains.

Candidate generation currently admits a single-facility move/rotation or a pair
position swap that preserves both existing rotations. The old feature encoding
records only the first assignment's rotation and uses ID-sorted assignment positions
as ordered point features. This is not a demonstrated same-state action alias:
the second rotation is available from the current state. The new operand contract
should represent both assignment poses explicitly and make equivalent unordered
assignments independent of ID order. It must not widen the admitted action domain.
The old discard command uses the first facility's position as a spatial context;
that incidental ID dependence should disappear in the new representation.

## Proposed bounded first cutover

Keep existing directed, non-crossing belt-path acceptance, edits, production
obligations, rewards and best-valid state transitions unchanged. Separate this
representation milestone from the later multi-terminal network/pipe/cycle contract.
Add observation/model schema versions and reject old checkpoint schemas explicitly.
Remove old cardinality-sized one-hots, flattened object fusion and same-production
compatibility checks; retain historical experiments through their Git revisions.
No compatibility adapter or automatic legacy policy fallback.

The new observation contains constant-width semantic tensors with variable rows:

- Dense geometric raster channels for draft/base occupancy, directed arms, coordinates
  and real-cell mask. Width/height follow used geometry and configured work guards.
- Facility, network and terminal entities for draft/base, with a fixed feature schema
  containing type, snapshot, position/shape, role/binding/direction, legal rotation
  mask, rate/capacity and relevant runtime catalog properties. IDs are references,
  not categorical one-hot inputs. Exact rational validation stays in Rust/reference.
- Typed ownership, source/target incidence and snapshot-correspondence edges. Every
  tensor index is validated against its entity domain; padding has explicit masks.
- Integer entity maps at facility, network and terminal cells. The policy gathers
  learned entity features into spatial cells so compatible network identity is not
  erased by a single aggregate occupancy channel. This map representation assumes
  the currently admitted non-overlapping belt paths; layer-aware maps follow only
  with the explicit multi-layer semantic extension.
- Fixed-width candidate operation/numeric fields plus masked operand rows. Each
  operand carries its entity reference, semantic role and relevant proposed geometry.
  Both facility assignment poses/rotations are represented. Unordered assignment
  operands share a role and are pooled symmetrically; directed source/target operands
  have distinct roles. Discard has no arbitrary facility/spatial operand.

Use a shared entity MLP with typed graph messages and masked pooling/gathering,
a spatial CNN with existing masked BN, and a shared candidate operand scorer.
Model parameters depend on declared feature/hidden widths, not entity counts or
instance labels. Minibatch and prepared CUDA rollout storage pad/crop raster,
entity, edge, candidate and operand axes with correct masks. Node embeddings should
be projected to a bounded spatial width before dense gather. Width and message-depth
settings are experimental configuration, not presumed optimal choices.

Do not encode game-balance constants in source; derive all facility/recipe/transport
features from the loaded runtime catalogs. Do not use graph inference to prune legal
edits. Candidate generation and final acceptance remain authoritative. Resource
failures report tensor dimensions and exhausted byte/work guard, never infeasibility
or a canonical game canvas size.

## Verification required before cutover completion

1. Compare native/reference domains and transitions on the existing fixtures; the
   observation rewrite must not change those mechanical contracts.
2. Match the new observation schema and numeric fields between native and reference
   on root, partial edit, reconnection, discarded and improved states.
3. Batch different facility/network/terminal counts and raster sizes in one forward
   and PPO update; validate padding invariance and finite masked-BN behavior.
4. Rename/reorder entity IDs and remap candidate commands: logits/values must match
   within ordinary floating tolerance. Test pair-swap operand permutation and
   explicit encoding of both existing rotations. Do not require identical sampled
   trajectories after ID-driven candidate reordering.
5. Reject incompatible checkpoint schema and stale native build with explicit errors.
6. Generate valid curricula for a small external-data serial-chain matrix with varied
   facility counts, then declare fresh training/development/held-out chain splits
   before learning. Do not claim all stage-4 semantics from this first count milestone.

The later slices must cover shared branching/merging commodity networks, separate
belt/pipe layers, terminal rates/capacities and required production cycles against
`docs/designs/aic-game-rules-mathematical-model.md` and the accepted constructive
planner design. Those requirements are not removed by this limited first cutover.
