# Batch-normalized spatial policy

Status: implementation in progress. The user requested BatchNorm and accepted ordinary
floating-point trajectory variation. Do not optimize this slice for bitwise training
reproducibility or introduce QAT.

## Contract

The existing no-normalization policy remains an explicit experimental control.
A run configuration may select `normalization: "batch"`; absent selection means
`"none"` for the existing baseline. Reject unknown selections. Add affine spatial
BatchNorm after each of the three convolutions, before ReLU. Do not normalize the
variable candidate set or the scalar policy/value outputs. Common network weights
retain the same seeded initialization; BN scale starts at one and offset at zero.

Only real raster cells contribute to calibration means and variances. BatchNorm
uses epsilon 1e-5, EMA momentum 0.1, biased variance for calibration normalization
and unbiased variance for running estimates, matching PyTorch BatchNorm conventions.
Every saved policy state includes scale, offset, running mean/variance and update
counts. A frozen policy's inference is independent of other batch members and padding.

This is **BatchNorm with frozen statistics during PPO**, not conventional per-minibatch
training-mode BatchNorm. Action collection, value estimates, PPO likelihood ratios,
mastery feedback and root evaluation all use running statistics. Those buffers must
not change during action sampling or gradient updates, regardless of `.train()` or
`.eval()`. Affine parameters train normally. This avoids comparing rollout likelihoods
using eight-example statistics to likelihoods using unrelated 64-example statistics.

After each completed PPO update, recalibrate with one sequential pass through its
collected observations, in configured minibatches. Calibration runs without gradients,
uses masked batch statistics in the forward pass and updates EMA buffers. Never use
mastery or root evaluation data. The next rollout and evaluation snapshot see the new
buffers. This statistical refresh is an explicit additional policy change outside
PPO clipping; record its cost and count. It does not add environment commands or
optimizer steps. A calibration failure produces no completed checkpoint for that update.

## Experiment and outputs

Use the successful short-mastery protocol: horizon eight, three seeds 17/29/43,
65,536 sampled edits, eight streams, 1,024 samples per PPO update, unchanged mastery
thresholds and original-root 128-edit evaluation. Run three BN policies and compare
them descriptively to the three completed no-BN short-mastery policies from
`a395c5c` (training source `6e1a606`). Do not retune parameters or gate thresholds
in response to interim results. This is a bounded architectural follow-up, not a
new claim of generalization or universal BatchNorm superiority.

Report root success and returned area reduction by seed/case, stage progression,
training time including calibration, and calibration observations/batches/time.
Keep architecture choice in configuration and normal checkpoint provenance. Audit
must load the declared architecture and verify saved normalization update counts.
Unknown normalization has stable diagnostic `policy.normalization`; nonfinite
calibration has `normalization.nonfinite`. Existing stage diagnostics remain intact.

## Verification

Compare masked statistics to ordinary PyTorch BN on packed valid cells, test padding
exclusion and batch-independent frozen inference, check that PPO begins with unchanged
likelihood ratios and cannot mutate statistics until calibration, and verify saved
state/actor transfer. Exercise the clean-source CLI and the existing independent
assessment audit. Run standard Python and workspace checks; use the same server
hardware. Ordinary floating-point tolerances are sufficient.

[PPO objective](https://arxiv.org/abs/1707.06347). The frozen-stat lifecycle is this
experiment's engineering choice, not a claim that these sources endorse this variant.
