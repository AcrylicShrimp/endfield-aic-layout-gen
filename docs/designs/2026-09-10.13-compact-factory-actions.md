# Compact full-factory action granularity

## Contract

The stopped PPO trial spent most of its 32 decisions removing individual empty
rows and columns. Replace that action boundary before starting a fresh trial.
The policy still selects one candidate index. Its 32-column action features,
42-column history tokens, network architecture and episode horizon do not grow.

- `contract(axis, count)` removes every currently removable strip on one axis
  in one transaction. `count` describes the derived operation, not a list of
  coordinates emitted by the policy. At most two contraction candidates exist.
  Protected facility bodies, terminals, components, branches and turns retain
  their coordinates relative to the surviving grid. Straight routes are spliced.
- `insert(axis, position, count)` opens a corridor in one transaction. Offer
  widths 1 and the largest current facility span on that axis plus two routing
  cells. Retain at most 32 evenly distributed legal cuts per axis: at most 128
  insertion candidates total. These are heuristic proposals, not a complete
  search domain. Multi-cell interpolation preserves directed rates.
- `component(id, x, y, rotation)` places one component directly, including a
  catalog rotation. Retain at most 32 candidates per component from at most 256
  destinations, alternating local offsets and a deterministic scan across the
  used bounds. Exclude bodies and fixed same-layer terminals/components before
  retention. Existing routing relocates incident chains atomically.

Facility poses already encode distant translation, rotation plus translation,
and bounded rigid groups. Port changes already select a compatible destination
port directly; rerouting already edits an entire chain. Bridge release operates
on one meaningful object and restore selects the entire retained best layout.
These five action families need no broader output contract.

## Invariants and failure behavior

The selected native handle owns the exact current vocabulary. Strip counts are
checked against that vocabulary before execution. Edits produce one candidate,
with one existing native physical validation and acceptance decision. Invalid
geometry keeps the current state and reports the existing structured
`factory.edit-parameters` or validator diagnostic. There is no hidden search,
repeated policy selection, reward split, or uncharged route work inside an action.
Used dimensions remain outputs; destination bounds limit these heuristic
proposals and do not establish factory feasibility limits.

Axis-wide contraction deliberately trades local gap choice for immediate simple
compaction. The policy can reopen a selected corridor or move facilities afterward.
Compression does not guarantee that the resulting harder packing task is learned.

## Schema and verification

Action feature 30 is the strip count divided by the current axis span; feature
31 marks axis-wide contraction. Other action features and tensor widths retain
their meaning. Bump the native/Python input schema, PPO checkpoint schema and
harness schema so old single-strip checkpoints cannot silently resume. Diagnostic
vocabulary JSON advances to schema 4 for the changed action descriptors.
Historical vocabulary/observation parity tests cannot define this new contract;
replace those assertions with native invariant and transaction tests.

Verify multi-strip width/height changes, no remaining same-axis strip candidates,
directed segment adjacency and rates, protected events, multi-cell insertion and
inverse contraction, and full physical acceptance against fixed requests. Check
component distance/rotation availability and candidate caps. Then run repository
checks and a bounded real CUDA readiness run with checkpoint continuation before
freezing a fresh one-hour run. Preserve the stopped runtime and checkpoints.
