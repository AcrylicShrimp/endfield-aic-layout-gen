# Model-connected compound facility poses

Status: implementation contract, declared before model or experiment outcomes.

The boundary teacher preserved a 41x52 incumbent with 377 physical transport tiles;
it did not reduce area. The current model can translate a connected group or rotate
one stationary facility, but cannot select the rigid two-facility rotation/translation
that enabled the historical 41x53 to 41x52 trajectory. Rechecking that historical
action through the current 5000-expansion, two-crossing, internal-junction executor
validates a complete original factory under all three pipe-first route orders.

## Contract and hard cutover

Executor RPC and description become schema 3. Observation/checkpoints become
`full-factory-spatial-relational-v3`; old schemas, weights and the `relocate`/`rotate`
actions are rejected. Replace both operations with one `pose` action containing
`poses: [{member, x, y, rotation}]`. Members are unique current placement indices;
coordinates and catalog rotations describe final facility poses in the current
frame. At most sixteen facilities and four distinct translation vectors share one
transaction, matching the existing local kernel. Catalogs supply body/port geometry.
Metadata contains the final body envelope, source origin and total facility body area.
The executor derives translation primitives and rotated ports from this one final
pose contract, starting from the original valid parent. It never executes an invalid
intermediate facility placement. A no-op pose is rejected. Native complete-witness
acceptance remains schema 1, preserves all original requirements and the best valid
lexicographic score, and may retain worse complete states privately for exploration.

Each member contributes its source graph embedding, destination CNN sample and ten
normalized final-position/displacement/shape/orientation features. Apply a nonlinear
member encoder before pooling, so swapping two members' destinations or rotations
can change the group representation. Preserve full physical networks, rational rates,
ports, ownership and both transport layers; string IDs address relations only.

## Finite candidate domain

Existing local/distant and connected-group translations emit the new pose contract
directly. Include catalog rotations of a single facility at its current origin.
The compound domain additionally rotates and translates two-to-four-facility groups:
required terminal closures, physical production SCCs/pairs and connected contiguous
aligned runs. Rigid transforms preserve relative body geometry and catalog port arms;
this is not an affine rotation of every logistics component or route in a region.
Routing rebuilds affected connections using the existing ownership semantics.

Use the current used extent as an explicit local neighborhood, retaining the existing
200000-cell observation guard. Default compound generation examines 256 origins per
group/angle and retains at most eight statically admitted poses per group/angle, at
most 128 groups and 512 movement preflights shared in round-robin stream order. These operational limits do not establish game dimensions or local
infeasibility. Include current origin and eight local shifts first, then corners and one-cell insets of the eight largest empty rectangles, and a deterministic
coprime stride through fitting origins. Interleave angles/groups in emitted candidates;
do not rank by successor score. Report scan counts, body/preflight rejection codes,
group/scan/candidate truncation and elapsed time.

Cache stationary-body occupancy per group; reject overlapping/out-of-extent final
bodies cheaply before projecting catalog terminals and running movement-only checks.
No A* or complete successor validation occurs during enumeration. For survivors,
check the existing movement planner and moved terminal/component/internal-path bounds.
Ordinary route cells remain reroutable. Selected actions retain pipe-first routing,
5000 shared expansions and two possible new crossings, followed by original-factory
native acceptance. Port reassignment, bridge release and regional topology rotation
remain separate actions/capabilities; they are not hidden uncharged pose fallbacks.
