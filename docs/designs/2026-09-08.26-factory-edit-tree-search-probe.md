# Bounded factory-edit tree-search probe

Status: proposed diagnostic contract; no search quality results or production cutover.
The user suggested MCTS while the six entity-capacity learning streams were running.
Complete those frozen streams without changing their source or learning protocol.

## Question and scope

Can bounded lookahead improve relocation and reconnection from an original valid
factory root at useful cost? CNN/GNN representation and tree search are separate
choices: a policy/value network can guide search. AlphaZero demonstrates that
combination in board games; it does not establish benefit for this editing environment.
Reference: [Silver et al., 2017](https://arxiv.org/abs/1712.01815).

The first implementation should be a diagnostic over the current admitted belt-chain
cases and owned native transition engine. Do not add shared-network, pipe or cycle
semantics as part of search. Do not claim completeness or global infeasibility.
Do not use curriculum prefixes, scripted repair, witness actions, or held-out outcomes
to guide search. The existing edit domain and validator remain authoritative.

## Stage boundary

Inputs: an admitted case and runtime catalogs, native environment configuration,
frozen optional policy/configuration, random seed, maximum executed commands,
maximum simulated transitions, wall-clock allowance and node-memory allowance.
All budgets must be explicit CLI arguments or external experiment configuration.
The execution horizon must agree across comparison arms and with the environment.

Outputs: a schema-versioned report, the best validated layout, an executable trace
from the original root, and provenance for inputs, source, native library and policy.
Report lexicographic area/physical tiles/turns, facility displacement, elapsed time,
executed and simulated commands, resets/restores, model calls, expanded nodes,
branching distribution, peak retained nodes/bytes and termination reason. Diagnostics
carry code, severity, stage, message and entity. Resource exhaustion retains the
validated incumbent; internal errors remain explicit diagnostic failures.

Use an independent engine for hypothetical transitions. Native snapshots include
best/base/draft, remaining horizon and trace; geometry alone is not a search state.
Restore invalidates candidate handles, so regenerate handles before every step.
Do not merge nodes by draft geometry alone. Initially use a tree with bounded depth;
a later transposition table requires a proof of equivalent future transition/reward
behavior. Snapshot restoration also restores counters: accumulate total search work
outside snapshots so rollback cannot erase charged work.

Every output must independently validate and replay from the original root. Keep the
original valid layout until a better complete candidate is accepted. If the diagnostic
returns a completion discovered in a hypothetical branch, label it as such, retain its
whole trace, and charge all exploration that found it. Do not present a simulated
completion as an improvement obtained by the executed action sequence.

## Comparison before quality claims

Compare policy sampling, MCTS with uniform priors and random rollout, and MCTS guided
by the same frozen policy/value network. Add independent random rollouts at the same
simulation allowance to isolate benefit from tree allocation versus additional trials.
For each arm report matched total native-transition allowances and matched wall-clock
allowances separately; a tree rollout is not a free policy action. Include observation,
inference, snapshot/restore, validation and retained-result selection in elapsed cost.
Report training cost separately for learned arms. Use the same hardware, roots and
sampling banks, and expose actual work when one bound terminates a run early.

First measure snapshot/restore, candidate count and shallow search cost on training
cases only. Then declare a small explicit search-budget matrix before opening quality
outcomes. Select search parameters on development cases and freeze all choices before
fresh outcomes. Existing chain held-out cases remain reserved for the declared entity
capacity study; they cannot silently serve as untouched search confirmation afterward.

Specify UCT/PUCT exploration constants, rollout depth, leaf-value convention and
backup discount in that executable protocol. The current PPO value estimates discounted
future area rewards under its training horizon; it is not automatically a calibrated
terminal layout score at arbitrary search depth. Validate that interpretation before
using it in backups. Final layout selection always retains the existing lexicographic
score, even when an exploratory tree statistic uses a scalar reward.

Begin without permanent top-k candidate pruning. If measured branching requires
progressive widening, declare its rule and coverage limitations explicitly. A bounded
heuristic search may miss legal improvements. Flat sparse rewards and many reversible
edits may still defeat MCTS; measure this rather than assuming lookahead solves credit
assignment. Search-generated training targets are a separate later experiment.
