# Sparse Integrated Feasibility

## Problem

The dense integrated solver creates placement candidates for every legal facility origin and directed route arcs for every grid cell and capacity-split route. That model is appropriate only for small bounds. A 500 by 500 diagnostic bound for the full Heavy Xiranite graph would create about 102 million route-arc variables before placement variables and constraints, so constructing the dense model is not a safe feasibility test.

The official 50 by 50 blueprint limit remains the final hard bound. A larger bound may only be used to construct an upper-bound witness and diagnose whether the production graph can be placed and routed at all.

## Stage Contract

The sparse-feasibility stage accepts the same validated facility-instance wiring, facility catalog, item catalog, transport-capacity catalog, and hard layout bounds as the integrated solver.

It must preserve these invariants:

- every facility instance is placed exactly once, without overlapping another facility;
- every logical material flow is split into the exact minimum number of routes required by transport capacity;
- every route uses the item's declared belt or pipe layer;
- facility endpoints use ports with the required direction and transport kind;
- routes do not occupy facility cells;
- routes on the same layer do not share cells;
- belt and pipe routes may overlap because they are separate layers;
- every placement and route cell remains inside the requested hard bounds.

The stage constructs a deterministic sparse placement with clearance corridors and routes fixed placements incrementally on a sparse search frontier. It may retry deterministic placement spacing and route order variants, but it must not instantiate variables for every grid cell and route pair.

## Output Contract

On success, the stage returns the existing integrated-layout placement and route DTOs with status `feasible`. The report must include a stable `sparse-integrated-layout-feasible` diagnostic stating that the result is a constructive feasibility witness and is not proven optimal.

On failure, it returns status `unknown`, not `infeasible`, unless a sound lower bound proves infeasibility. The failure diagnostic must distinguish placement construction failure from routing construction failure. A constructive search failure is not proof that no valid layout exists.

## Role In Optimisation

The sparse result supplies an upper-bound witness and future CP warm start. It does not replace the dense joint solver or the final requirement to fit within the official blueprint bounds. The intended search sequence is:

1. construct a feasible witness at a generous diagnostic bound;
2. reduce the bounds while continuing to construct witnesses;
3. use the best witness to seed or restrict the exact integrated model;
4. report optimality only when the exact model proves it.

## Verification

Tests must cover facility exclusion, same-layer route exclusion, belt/pipe overlap, capacity-split routes, compatible port selection, hard-bound enforcement, and deterministic output. The Heavy Xiranite contextual plan must be exercised manually at 500 by 500 before attempting to shrink the bound.
