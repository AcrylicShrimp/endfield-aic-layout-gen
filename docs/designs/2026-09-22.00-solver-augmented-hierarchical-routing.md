# Solver-augmented hierarchical routing

Status: accepted design direction; implementation active. This document records
the architecture agreed on 2026-09-22. It defines a new hybrid research path and
does not silently change the existing router-free direct-constructive PPO
experiment.

## Goal

Construct complete physical layouts by combining:

- an outer search that reasons about facility placement, terminal placement,
  port use, logical-network order and the long-term effect of route choices;
- a lower routing tool that returns several complete, diverse, native-valid
  route or network witnesses;
- learned spatial guidance that predicts the future opportunity cost of using
  ports, cells and corridors; and
- the existing native executor and independent validator as the sole commit and
  publication authorities.

The lower tool must not be a random walk or an autoregressive command generator
whose only safeguard is eventual rejection. It must combine exact graph search
with learned guidance, retain a non-learned anchor search, expose bounded work,
and distinguish budget exhaustion from fixed-request infeasibility.

The outer and lower models may have separate parameters and optimizer state.
They must still optimize the same downstream layout objective: outer-search
visits, candidate values and observed continuation outcomes become subsequent
training targets for the lower model.

## Motivation and current evidence

The flat constructive search mixes facility, terminal, port and primitive route
commands in one long tree. A successful connection may require many `extend`
actions before any committed progress appears. The native-valid MCTS experiment
confirmed that distance shaping can produce a complete route, but primitive
routing consumes substantial search depth and work before `connect`.

The learned route-option experiments provide a stronger warning against making
the lower tool a policy-only path writer. Corrected PPO and route-specific
successful replay learned aligned paths and occasional first crossed paths, but
neither completed a crossed route after its own earlier crossed route was
committed. The frozen frontier work later showed that valid second routes were
representable and locally discoverable, while fresh-root skill composition still
failed. See
[`2026-09-20-self-roll-in-route-options.md`](../reports/2026-09-20-self-roll-in-route-options.md)
and
[`2026-09-21-direct-constructive-research-summary.md`](../reports/2026-09-21-direct-constructive-research-summary.md).

The deterministic negotiated-routing prototype supplies a useful lower-kernel
starting point. On the retained panel it raised routed obligations from 61.9% to
83.3% in balanced placements and from 78.9% to 100% in spacious placements. It
did not improve the number of zero-overflow guide sets because the prototype did
not yet model shared same-item networks, exact capacity or catalog-backed
crossing legalization. It remains a comparison kernel, not a layout-admission
authority. See
[`2026-09-17-recipe-routing-negotiation-prototype.md`](../reports/2026-09-17-recipe-routing-negotiation-prototype.md).

The current
[`direct constructive policy`](2026-09-19.00-direct-constructive-policy.md)
intentionally forbids A*, automatic routing and hidden repair inside an episode.
That experiment and its evidence remain valid. Adopting this document is an
explicit architectural branch or cutover: route ownership changes from a policy
issuing every primitive segment to an outer planner choosing complete witnesses
produced by a bounded lower tool.

## Agreed architecture

```text
immutable production problem + current physical state
                         |
                         v
        outer beam search or policy/value MCTS
          |       |          |             |
          |       |          |             +-- choose a complete route candidate
          |       |          +---------------- choose a logical network and ports
          |       +--------------------------- place a terminal
          +----------------------------------- place a facility
                                             |
                                             v
                               lower candidate generator
                  exact graph + anchor heuristic + learned guidance
                    + negotiated congestion + diverse path search
                                             |
                           K complete witness candidates
                                             |
                                  native replay/validation
                                             |
                           valid macro actions for outer search
                                             |
                   visits, Q values and downstream outcomes
                                             |
                           next lower-model training round
```

The outer tree never contains a failed partial path. A lower candidate becomes
an outer action only after every primitive command replays successfully against
the exact state revision. Applying the candidate to an outer clone is atomic.
Publication still requires the independent full-layout validator.

The first outer-search comparison should use beam search as a simple,
batch-friendly baseline and MCTS as the adaptive-budget treatment. The lower
tool contract is shared by both; adopting learned routing does not predetermine
the outer search algorithm.

## Outer MCTS state and action boundary

Every outer node is a stable native construction state with no active partial
route. It contains the immutable production problem, committed facility and
terminal poses, committed physical networks, exact occupied resources, selected
ports, remaining logical obligations, accumulated physical cost and the current
resource limits.

The outer action vocabulary contains only state-level decisions:

```text
place one facility at one complete pose
place one boundary terminal
commit one complete lower-tool route or network witness
apply one explicitly bounded repair witness
finish when every immutable obligation is complete
```

Primitive `begin-route`, `extend`, `connect` and `abort-route` commands remain
inside a returned witness and are not separate outer children. Placement and
terminal actions still pass through the native domain. Route and repair actions
replay their entire witness into a clone before the child is admitted.

The search operates as receding-horizon construction. It searches on clones,
retains every independently validated complete layout it discovers, chooses a
root macro action after the configured budget, commits that action to the
working state, reroots on the exact resulting state and searches again. A
matching subtree may be retained only when the state identity and model/tool
versions are unchanged. This makes the committed trace explicit while allowing
the search to reconsider later decisions after every macro action.

## Outer policy-value model

The outer MCTS uses a separate policy-value model. MCTS is the tree-search
algorithm; this network supplies action priors and estimates leaves that have
not been searched to completion. The first model reuses the current
constructive typed-graph encoder and exact spatial-token encoder instead of
adding a second dense U-Net before evidence requires it.

```text
immutable production graph ----> typed graph encoder -----------+
                                                                 |
committed physical state ------> exact spatial-token encoder ----+--> fusion
                                                                 |      |
resource/progress scalars ---------------------------------------+      |
                                                                        v
                                                               state context h(s)
```

The graph stream represents facility instances, terminals, logical networks,
item and transport identities, exact rates, remaining obligations and their
directed relations. The spatial stream represents facility bodies, port escapes,
transport occupancy, layers, components, boundaries and selected locations.
Cross-attention joins logical obligations to the physical resources they may
use.

The lower U-Net remains a routing-specific dense predictor. Its costs,
uncertainty and optional frozen intermediate features may be supplied as
candidate features, but lower and outer model parameters are separate in the
first implementation. Sharing an encoder is a later measured treatment rather
than an assumed optimization.

### Candidate action encoding

The outer policy has no fixed logit for every coordinate, pose or possible
path. Native and lower-tool generators materialize a bounded variable-size
candidate set, and each candidate becomes an action token.

A placement token includes the block identity, complete pose, affected spatial
features, lower-bound footprint change, port exposure and logical importance. A
route token includes the logical network, selected ports, exact cost breakdown,
component and capacity use, structural-diversity features, lower-model cost and
uncertainty, plus a pooled representation of the spatial features along the
candidate witness.

```text
state context h(s) + candidate token e(a)
                    |
                    v
         candidate-to-state cross-attention
                    |
                    v
               policy logit
```

The resulting softmax over currently exposed candidates supplies `P(s, a)` to
the tree. The lower route score is evidence available to this scorer, not the
outer decision: the outer policy may prefer a longer route that preserves a
scarce corridor for later networks.

Candidate actions are decoded in factors so large domains remain tractable:

```text
action kind
  -> facility, terminal or logical-network identity
  -> complete placement pose or lower-tool candidate identity
```

Every selected identity retains the exact state revision and candidate version
used for scoring. Stale candidates are rejected without mutation.

### Value heads

The outer critic predicts several observable outcomes instead of hiding all
failure modes in one scalar:

- independently validated completion probability;
- expected additional completed logical networks under a fixed budget;
- probability that the next required network can be completed;
- expected blocked-network count;
- conditional final footprint and transport-cell cost; and
- calibrated uncertainty.

A configured search utility combines these heads while preserving the public
objective order: validated completion dominates partial progress, and quality
costs compare completed or otherwise equally complete states. The separate heads
remain in reports and training data so a smaller footprint cannot conceal a
collapse in routability.

The model value is a leaf estimate only. Exact committed progress, terminal
reward, physical costs and final validity come from the native state and
validator and replace estimates whenever observed.

## Outer tree policy and expansion

For an exposed candidate `a` at state `s`, the first MCTS treatment uses a PUCT
selection score of the form:

```text
Q(s, a) + c_puct * P(s, a) * sqrt(N(s)) / (1 + N(s, a))
```

`Q` is the backed-up observed or estimated return, `P` is the network prior and
`N` is the visit count. A simulation selects edges until it reaches an
unexpanded child, applies the complete macro action to a clone, evaluates the
new state once with the policy-value model, and backs the result through every
selected edge. Terminal native outcomes replace the critic estimate.

Both native placement domains and lower route domains use deterministic
progressive widening. A node begins with a small stratified candidate page. More
visits authorize additional pages or lower-tool candidates according to an
explicit schedule capped by action count, routing work and wall time. New lower
tool calls occur only on expansion or widening, never on an ordinary revisit.

The widening implementation must preserve candidate coverage rather than expose
only the current model's favorite actions. Every page includes non-learned
anchor candidates alongside learned-prior candidates. Duplicate semantic
actions are merged while retaining their best exact cost and generation
provenance.

## Outer training and lower feedback

One outer training sample retains the exact state identity, the candidates
actually exposed at the root, their priors, visits and Q estimates, the selected
macro action, and the later native outcome. The outer policy is trained toward
the normalized root visit distribution. Its value heads use observed
continuation, completion and quality targets from search or execution.

For a route decision, the same visit and outcome record is projected onto the
lower candidates. The lower model therefore learns which complete witnesses the
outer search found useful without sharing the outer model's gradient graph:

```text
lower model -> route candidates -> outer policy/value MCTS
     ^                                  |
     +---- candidate visits, Q and -----+
           downstream native outcome
```

Outer and lower model versions are frozen during one collection generation and
updated only for the next generation. This prevents a moving candidate set and
a moving critic from changing the meaning of labels inside one update.

## Routing unit: logical network before point-to-point wire

An immutable logical wiring edge states supply and demand. It does not always
require an independent physical point-to-point path. Compatible flows of the
same item and transport kind may share a capacity-sufficient trunk, and physical
split or merge components follow from network topology.

The lower tool therefore accepts one of two explicitly identified tasks:

1. a fixed point-to-point connection, used by the first bounded harness and by
   obligations that cannot share; or
2. a same-commodity logical network containing its sources, sinks, exact rates,
   compatible port domains and remaining capacity.

Full-factory integration requires the second form. Treating every wiring edge as
an exclusive path would teach the model the wrong resource economics and repeat
the known unit-capacity gap in the negotiated prototype.

## Exact routing graph

The graph is derived from validated external catalogs and the exact physical
state on each request. A search state contains enough information for route cost
and legality to be Markovian, including at least:

```text
(cell, incoming direction, transport layer, crossing state)
```

Capacity and shared-network state are carried either in the state or in the
network-embedding transaction, according to the finalized physical component
model. Illegal facility intersections, incompatible transport sharing,
wrong-direction port entry, illegal crossings and out-of-domain moves do not
become learned penalties; they are absent from the legal transition graph.

The learned model cannot authorize a transition, weaken a capacity rule or
declare a layout valid. This keeps changing model weights from changing physical
semantics.

## Search cost and learned guidance

For a legal directed routing edge `e`, the effective search cost is:

```text
c_phi(e | s, R, z) =
    exact_length_cost(e)
  + exact_turn_cost(e)
  + exact_component_cost(e)
  + present_and_historical_congestion_price(e)
  + learned_future_opportunity_cost_phi(e | s, R, z)
  + candidate_overlap_penalty(e)
```

`s` is the current physical state, `R` is the complete remaining routing demand,
and `z` identifies a diversity mode or learned guidance head. The learned term
answers a global question: how expensive will consuming this resource be for
the connections that remain? It is not a substitute for the exact immediate
cost.

The spatial model combines:

- a grid encoder for facility bodies, port escapes, terminals, completed and
  active transport, layers, bridges and boundaries;
- a graph encoder for facilities, logical networks, item identity, transport
  kind, exact rates, sources, sinks and the outstanding production graph; and
- cross-attention from the selected routing task into both representations.

The initial learned heads are:

- directed cell or edge opportunity cost;
- compatible port or terminal-pair prior;
- shared-trunk attachment value;
- several corridor or diversity guidance maps;
- bounded-search success probability and downstream routability; and
- calibrated uncertainty used for diagnostics and exploration, never validity.

This follows the useful separation in Neural A*: a network predicts a guidance
map and graph search constructs the path. It also preserves the repository's
existing graph and spatial encoding work instead of replacing it with a generic
sequence generator.

## Anchor and learned heuristics

At least one non-learned anchor queue uses a consistent lower-bound heuristic
such as Manhattan distance or an exact reverse obstacle distance when its cost
is justified. Additional queues may use learned and inadmissible heuristics.
A Multi-Heuristic A*-style scheduler shares progress between these queues.

The anchor has three purposes:

- a poor or out-of-distribution learned model may waste work but cannot remove
  every feasible route from the underlying graph;
- classical search supplies a stable baseline and exploration source during
  training; and
- completeness or bounded-suboptimality claims can be made only under the
  precise anchor algorithm and uncapped finite request conditions.

Production and experiments remain resource bounded. Exhausting the configured
work or deadline returns `unknown`; it is not a proof that the logical network
or complete factory is infeasible.

## Negotiated congestion

For routing network `n` and resource `e`, let `x[n,e]` record use and `cap[e]`
record exact capacity. The coupled restriction is:

```text
sum_n x[n,e] <= cap[e]
```

Negotiation moves this restriction into a nonnegative resource price
`lambda[e]`. Each network can then solve a priced shortest-path or bounded
network-embedding problem. After a routing round:

```text
lambda[e] = max(0, lambda[e] + step * (usage[e] - cap[e]))
```

Present overuse and persistent historical conflicts raise the price. Guides are
ripped up transactionally and rerouted in a deterministic conflict order. The
learned opportunity-cost head complements this mechanism by predicting scarce
resources before actual conflicts accumulate; it does not replace the exact
usage calculation.

Intermediate negotiated guides may temporarily overuse resources. They are
research states, not native candidates. Only completely legalized and replayed
outputs may cross the lower-tool boundary.

## Diverse candidate generation

Returning the first shortest path is insufficient because a locally short path
may destroy later routability. Returning small variations of the same corridor
is also insufficient. The tool generates candidates from controlled differences
in:

- selected compatible ports or boundary terminals;
- learned corridor head or diversity code;
- present and historical congestion prices;
- bounded overlap penalties against already returned candidates;
- legal shared-trunk attachment choices;
- crossing-component use; and
- bounded rip-up neighborhoods when the request authorizes repair.

After accepting candidate paths `P_1 ... P_(k-1)` into the response set, a later
search may add an edge penalty proportional to its overlap with those paths:

```text
c_k(e) = c_phi(e) + rho * sum_{j < k} indicator(e in P_j)
```

The response reports both cost and structural diversity, including resource
overlap, distinct port pairs and distinct corridor or topology identity. Random
perturbations may provide bounded exploration, but random walking is never the
primary generator.

The outer search uses progressive widening. A lightly visited state receives a
small candidate set; more visits authorize additional lower-tool work and new
candidates. The widening schedule, maximum candidates and charged routing work
are explicit configuration and report fields.

## Lower-tool contract

The conceptual request is:

```text
RouteGenerationRequest
  physical_problem_identity
  catalog_identity
  exact_state_revision
  selected_logical_task
  remaining_logical_networks
  permitted_repair_scope
  requested_new_candidates
  search_work_limit
  deadline
  generator_model_version
  deterministic_seed
```

One returned candidate contains:

```text
RouteCandidate
  stable_candidate_identity
  selected_ports_and_terminals
  network_topology
  complete_constructive_command_witness
  occupied_resources_and_components
  exact_cost_breakdown
  learned_cost_and_uncertainty
  diversity_features
  charged_search_work
  generation_provenance
```

The result also reports whether the fixed request was fully exhausted, stopped
by a resource limit, lacked a semantic legalizer, or produced candidates that
failed native replay. A timeout, capped frontier or heuristic failure is never
reported as global infeasibility.

Candidates are cached only while problem identity, exact state revision,
logical request, generator version and search configuration remain identical.
Model inference is batched across requests. Stable graph preparation and model
encoding are reused within that identity. Native replay is still repeated at
commit; a cache entry is not an authority token.

## Training without a shared gradient graph

Separate parameters do not imply separate objectives. Training proceeds as
alternating search and distillation rather than requiring backpropagation
through the full discrete outer MCTS.

### Warm start

The classical anchor, negotiated router, retained valid generated layouts and
bounded higher-work searches provide initial examples. Warm-start targets
include legal path occupancy, port choices, shared-trunk choices, exact
cost-to-go, conflicts, unsuccessful fixed requests and observed continuation
quality. Multiple valid solutions are retained so the model does not learn that
one arbitrary shortest path is the only correct answer.

### Search-coupled collection

For each outer route decision, collection retains a compact record of:

- the exact state and logical request identity;
- all candidates actually exposed to the outer search;
- their lower energies, costs and uncertainty;
- outer visit counts and Q estimates;
- the selected candidate; and
- observed later connections, final completion, area and physical cost.

The lower model remains frozen during a collection generation. The outer model,
lower model and validator versions are explicit. A completed collection becomes
eligible only for the next training generation, preventing the model from using
its current prediction as its own label.

### Search distillation

For candidate `P_i`, define a model distribution over the exposed set:

```text
p_phi(P_i | s) = softmax_i(-energy_phi(P_i | s) / model_temperature)
```

The outer search produces a stronger target distribution from root visits, with
candidate Q and downstream outcome retained as auxiliary labels:

```text
pi_search(P_i | s) proportional to visit_count(P_i)^(1/search_temperature)
```

The main coupling loss is cross-entropy from `pi_search` to `p_phi`. Auxiliary
losses predict bounded route success, later-route survival, completion, exact
cost and uncertainty. This sends the outer consequence of a route back into the
edge and port guidance that will generate future candidates.

This is policy improvement through search targets, not end-to-end
differentiation through the search tree. The approach is analogous to
AlphaZero's network-search loop: the network guides search, and the improved
search policy becomes the next network target.

### Optional later coupling

If search distillation demonstrably plateaus, two stronger treatments may be
compared independently:

1. advantage-weighted or policy-gradient updates to the sampled candidate
   distribution, using outer Q minus a baseline; or
2. a differentiable or black-box-differentiated shortest-path layer for the
   lower guidance model.

Differentiating through the complete outer MCTS is deferred. MCTSnets establish
that learned differentiable tree-search components are possible, but the added
memory, optimization instability and mismatch with exact native semantics are
not justified before the simpler target-level loop is measured.

Sharing an encoder between the outer and lower models is optional and is not a
first-slice requirement. Shared weights reduce duplicate inference only if their
training signals are compatible; separate parameters make failures, versioning
and frozen collection easier to diagnose.

## Inference lifecycle

For an outer state that chooses a routing task:

1. Validate and encode the stable physical state and complete remaining demand.
2. Reuse or compute the lower model's opportunity-cost and heuristic maps.
3. Run the anchor and learned heuristic searches under the explicit work limit.
4. Negotiate or diversify as authorized by the request.
5. Legalize capacity sharing, junctions and crossings.
6. Replay each complete witness through a cloned native session.
7. Deduplicate semantic candidates and return the valid set with diagnostics.
8. Add returned candidates to the outer node according to progressive widening.
9. Simulate later placements and networks in the outer search.
10. Apply only the chosen witness to the live session and independently validate
    a completed layout before publication.

The lower tool is invoked on node expansion or widening, not on every simulation
visit. Persistent workers, batched inference, compact graph representations,
prepared routing workspaces and safe caches carry forward the repository's
existing performance benefits.

## Invariants

- External catalogs and immutable logical obligations define every request; no
  game facility, item, recipe or balance value is hardcoded in a model or
  router.
- Learned outputs affect ordering and cost only. Exact domain generation,
  capacity, geometry, component legality, native commit and final validation
  remain deterministic authorities.
- An outer route action is a complete replayable witness. No failed partial
  route mutates an outer or live state.
- Same-item sharing uses exact rates and transport capacities; it is not inferred
  from visual overlap alone.
- Search limits are explicit and charged. `Unknown` remains distinct from a
  fully exhausted fixed-request proof and from global layout infeasibility.
- Candidate diversity is measured. K nearly identical shortest paths do not
  satisfy the candidate contract.
- The lower model sees the remaining logical demand, not only the active source
  and target.
- A frozen model version is used for each collection generation. Training labels
  come from exact costs, validator outcomes and outer search or execution, never
  from the same model's unsupported self-score.
- Training and held-out evaluation remain separated by immutable problem
  identities and fixed evaluation panels.
- Normal execution writes compact summaries and necessary checkpoints rather
  than per-simulation traces or repeated full snapshots.

## Failure semantics

The lower boundary distinguishes:

- invalid request or stale state revision;
- no compatible port or terminal domain;
- fixed-request graph frontier fully exhausted with no path;
- configured work, candidate or time budget exhausted;
- guide found but shared-network or component legalization failed;
- complete witness rejected during native replay;
- valid candidates returned but outer search rejected all of them; and
- complete layout rejected by independent validation.

Only the third item is a local proof under the exact frozen request. None alone
proves that another placement, port assignment, routing order, repair scope or
complete factory has no solution.

## Rejected alternatives

- **Uniform random paths or random walks:** they spend most work on loops and
  dead ends and supply neither quality nor reliable coverage.
- **A pure autoregressive `extend` policy as the lower production router:** the
  retained experiments show useful local skill but no dependable crossed
  continuation, and exact search structure would be discarded.
- **One deterministic shortest path:** it hides the long-term routing choice
  from the outer planner and repeats irreversible sequential-routing failures.
- **A learned heuristic with no anchor:** out-of-distribution model errors can
  erase useful corridors from bounded search without a stable comparison.
- **Independent shortest-path pretraining forever:** the lower model becomes
  locally selfish and never learns which spaces the outer problem needs later.
- **Full end-to-end differentiation through MCTS first:** discrete expansion,
  native validation, long horizons and large spatial states create substantial
  cost and semantic mismatch before target-level coupling has been tested.
- **Trusting a negotiated guide as a valid layout:** temporary overflow and
  missing component semantics are not native feasibility.
- **Point-to-point routing for every same-item obligation:** it prevents legal
  trunk sharing and encodes the wrong capacity model.

## Remaining research limits

The implemented boundary supports capacity-bounded same-commodity overlap but
does not invent explicit splitter or converger entities for a future catalog
that requires them. Such catalogs need a native physical-schema extension
before search can generate those components. The current held-out panels are
also contract and integration panels rather than evidence of broad game-scale
generalization. A long run should therefore expand immutable training cases,
retain the fixed held-out identities, and promote a generation only after its
completion and throughput comparison passes. Budget exhaustion and a failed
panel case remain bounded observations, never global infeasibility claims.

## Implementation progress

The first lower-boundary unit is implemented. The existing bounded A* accepts
optional nonnegative cell costs without changing its exact blocked-cell or
crossing rules. A stable constructive session can enumerate compatible port
pairs, run the unmodified anchor followed by overlap-priced searches, compress
each path into a complete command witness, replay it on a clone and atomically
apply it only at the originating state revision. The result reports work,
preflight work, duplicates, native rejections, termination semantics and
pairwise corridor dissimilarity. Unit and workspace verification cover weighted
corridor selection, multiple native-valid candidates, atomic application and
stale-candidate rejection.

The frozen-state panel harness and later-route survival measurement are also
implemented. The first four-case held-out contract panel returned diverse
native-valid candidates for every feasible request, preserved both specified
follow-up routes for every root candidate, and proved the sealed fixed request
locally. Its three-run release median was 357,632 complete route samples per
minute with four CPU workers. See
[`hierarchical-route-candidates/report.md`](../benchmarks/hierarchical-route-candidates/report.md).

The learned-guidance boundary and first dense model are implemented. The exact
router now accepts bounded directed-edge costs separately from cell-overlap
costs, and the candidate generator validates the state revision, connection and
model version before interleaving guided queues with a retained non-learned
anchor. Guidance cannot add an edge or bypass native replay. Each candidate
records its anchor, guided or diversified provenance and the learned cost along
its witness.

The native guidance input fixes the selected logical connection as graph focus
and emits a bounded dense raster for bodies, terminals, compatible and
incompatible occupancy, the other transport layer, selected and remaining
endpoint domains, boundaries, transport kind, rate and load. A separate model
instance reuses the established typed graph and spatial attention encoder, then
uses a compact two-resolution convolutional decoder to predict several
nonnegative directed opportunity-cost maps plus success and uncertainty heads.
The model produces native guidance batches on CPU or CUDA. Native boundary tests
cover anchor preservation, guided corridor changes and stale/task identity;
the LibTorch model shape and conversion test passed on the RTX 5090 server.

The first warm-start trainer now derives candidate labels from exact sequential
continuation outcomes rather than shortest-path imitation. Its frozen training
and held-out panels contain escape-corridor states where consuming one row
blocks the only later facility-port exits. It trains candidate energies,
directed regret costs, bounded-search success and uncertainty, then evaluates
both ranking of a fixed candidate set and fresh guided exact searches. The
published checkpoint retains separate encoder/model parameters, immutable panel
hashes and candidate samples per minute.

The first outer macro-search kernel is implemented for comparison. Both beam
search and receding-horizon PUCT operate only on stable native sessions. Their
actions are complete placement commands or complete route witnesses; child
states are admitted through native application, and only independently
validated layouts count as completion. Route tasks at one node share a batched
lower-model inference call, while an explicit Rayon pool runs their exact
candidate searches. Candidate generation occurs once per expanded node. The
frozen harness reports macro samples per minute and charged exact-routing work.

The separate outer policy/value model and its first search-supervised warm start
are also implemented. It reuses a separate instance of the typed graph and
spatial encoder, scores bounded variable-size macro-action tokens and predicts
the six agreed value heads. Tokens include exact progress, placement pose or
route geometry, lower cost and uncertainty, provenance and pooled path bounds.
Frozen root actions receive fixed-budget exact continuation targets; training
and held-out identities are separate. Receding-horizon MCTS now uses the learned
priors at selection and the completion head at newly expanded leaves, while
beam search remains the model-independent comparison.

The first alternating search generation is implemented. Every committed MCTS
root now records a hash of the exact stable native state, all exposed complete
macro witnesses, frozen-model priors, visits, Q estimates, the selected action
and the later native completion result. The record is replayed from its frozen
panel prefix before training. Root visits supervise the next outer policy; the
route-only projection of the same visits and Q estimates supervises the next
lower candidate-energy, success and uncertainty heads. Both source checkpoint
hashes and the catalog identity must match the collection, so a model cannot be
updated from records gathered by another generation. Models stay frozen during
collection and new checkpoints are published only after the complete
distillation pass.

The same-commodity network macro is now implemented on the physical-v2 native
semantics. All ready obligations with the same commodity and transport become
one lower task. Several deterministic route orders and learned candidate modes
advance in lockstep; guidance inference is batched at each network depth and
exact searches run in the existing CPU pool. Each member route is generated
against the state left by the preceding member, so shared-cell and shared-port
capacity use exact residual rates. The resulting network witness is replayed
atomically from its original revision. Tampered aggregate work or sharing
metadata, mixed commodities, duplicate connections and stale members are
rejected without mutation. The outer search sees one complete network action,
while its member routes retain their own lower-model provenance for the next
generation's distillation.

This is a complete cutover for compatible physical-v2 obligations; individual
point-to-point actions remain only for singleton commodity/transport groups.
The current physical schema represents legal junctions as capacity-bounded
same-commodity route overlap rather than materialized splitter entities. Future
catalogs that require explicit junction components will require a corresponding
native schema extension before those components can be generated.

The integrated full-factory boundary is now exercised from an empty native
session. A held-out case requires one facility placement, two boundary-terminal
placements and one two-member shared network before publication. Large
placement pages use deterministic prior-ordered progressive widening, so MCTS
can reach routing depth without first visiting every placement once. The
route-only outer checkpoint's value head is used only after every entity is
placed; exact native one-step progress supplies the leaf value before that
boundary. Learned and geometry/progress priors remain blended for action
ordering. Beam and MCTS both complete the fixed case in four macros and pass the
independent validator; the retained report is
[`hierarchical-full-factory/report.md`](../benchmarks/hierarchical-full-factory/report.md).

The integrated inference path is now compiled for frozen search generations.
Tensor-only lower traces are reused by graph count and raster dimensions, while
the outer trace supports varying action counts. First-use eager parity and
finite checks protect the trace boundary. Three-run full-factory medians
improved 3.98% for beam and 7.64% for MCTS, and matched Nsight runs showed that
the gain came from fewer runtime calls, kernels and launches. Exact-routing
pool scaling saturated at eight CPU threads, which remains the default. The
measurements and retained profile summary are in
[`hierarchical-performance/report.md`](../benchmarks/hierarchical-performance/report.md).

Generation training is also ready for process interruption. At configured
epoch boundaries it atomically saves both models and every Adam step, mean and
square tensor under the still-pending generation directory. Recovery first
checks the exact config, panel, frozen collection, catalog and source-checkpoint
identities, then restores the latest complete checkpoint. Collection models
remain frozen and promotion still occurs only when the whole generation is
published. A CUDA run interrupted after epoch 60 resumed to all 200 epochs and
its checkpoints completed the independent full-factory validation.

The final preparation cycle used the 18-case training partition for collection
and kept the four-case evaluation and empty-session factory panels held out.
Generation 2 completed every training and evaluation case, reduced both
distillation losses, and passed both held-out searches and the independent
full-factory validator. Search collection accepts only the explicit `training`
and `held-out` partition names so the same frozen harness can serve both sides
without erasing their identities.
