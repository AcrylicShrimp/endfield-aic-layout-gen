# Single-update controls for flat-return policy drift

## Status and decision

Complete; report 35 records exact native replay and all 18 branch outcomes. This
contract was specified before implementation. Report 34 found large policy movement at warm
groups 0 and 38 despite zero current task-reward gradients. Reproduce those exact
updates and isolate current entropy gradients, inherited Adam state and step size
before changing training. This is a mechanical intervention, not an estimate of
the effects of a new training algorithm on final factory quality.

## Inputs and outputs

The CLI takes an audited training directory, the completed report-34 diagnosis,
a version-1 JSON experiment configuration and a fresh output directory. The
configuration selects the two warm groups, a maximum 900-second wall budget, and
named branches with entropy-gradient scale, Adam-state reset, learning-rate scale
and skip-step fields. Scales are finite in [0, 1]; learning-rate scales are positive.

Before replay, freeze a protocol binding the consumed training/audit records,
before/after checkpoints, all eight episode/state pairs, the same ten fixed panel
observations and masks, configuration, diagnostic and runtime source hashes.
The version-1 report contains status, protocol hash, per-group replay statistics,
exact baseline policy/Adam reproduction, per-branch parameter displacement and
per-input total variation and action-kind mass. Report means weight inputs equally.
Retain generated outputs under ignored artifacts; do not overwrite training files.

## Intervention and invariants

- All selected returns and reward gradients must be exactly zero. Recompute the
  original entropy gradient with original behavior weights and complete retained
  on-policy traces, including exact probability and observation identity checks.
- Every branch starts from a fresh copy of the same pre-update policy and optimizer.
  Scale the recomputed entropy gradient before the original gradient clipping.
  An Adam reset clears its step and both moments. A zero-gradient step explicitly
  supplies zero tensors and calls Adam; a skipped step leaves policy AND optimizer
  unchanged. These operations are deliberately different.
- The baseline branch must reproduce every saved policy and optimizer tensor
  exactly. Failure invalidates the experiment; do not interpret other branches.
- Cross current entropy present/absent with inherited/reset Adam state. Also compare
  0.1 and 0.01 entropy scales with 0.1 and 0.01 learning-rate scales, and skipping.
  Group 0 has no inherited state, providing a direct reset equivalence control.
- Probe the ten unchanged report-34 initial observations using their exact masks.
  No actions are selected, no factory layouts are edited, and no branch becomes a
  training checkpoint. Reuse of traces is limited to these single-step branches
  from identical behavior weights. Subsequent learning requires fresh rollouts.
- Preserve factory score priority, valid incumbents, policy architecture, action
  vocabulary, sampling distribution and production interfaces.

## Failure handling and verification

Reject source/hash drift, nonflat groups, replay identity failure, nonfinite values,
baseline mismatch, malformed configurations and exceeded wall budget. Record
`on-policy.counterfactual-failed`, severity error, stage counterfactual, the active
group/branch or source entity and a message in partial.json; never mark a partial
matrix complete. Cooperative guards run between replay steps and panel probes;
the bound is not a preemptive interruption of a native call.

Tests distinguish explicit zero-gradient Adam updates from skipped steps, verify
branch state isolation and reset behavior, and reject mismatched baselines. Run
the actual native replay/panel CLI, existing full-factory Python tests and required
workspace/artifact checks. Interpret results only within these two observed
transitions. Select the next fresh on-policy comparison from the measured effects;
do not claim that smaller movement alone establishes better factory improvement.
