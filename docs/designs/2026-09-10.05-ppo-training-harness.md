# Durable PPO training harness and monitoring

Status: implementation contract, written after the device/input setup decision.
The user requested production-grade training and monitoring, independent reviews
and representative execution tests before the renewed shallow input comparison.
This is a CLI experiment harness for the native-valid factory editor, not a
replacement for the production constructive planner.

## Frozen execution setup

Use persistent CPU collectors with one Torch thread each and one central CUDA
FP32 learner. Use the original width-32, depth-2 actor and separate full-world
critic, PPO/GAE configuration, mini/microbatch 64, actual sampled behavior and
direct retained-best area reward. The existing measured collector choice is 24
workers. CPU learning is an explicit configuration for development checks; a
CUDA failure must not silently change device or precision. Record library,
driver/device, native binary, runtime catalog, source and configuration identities.

The user-requested twelve candidates and seeds 17/29 are the screen population.
The exact shallow budget and evaluation schedule will be frozen only after
readiness passes. Every training episode draws a fresh request, rate and starting
layout. Shared generation/action seed schedules allow matched candidate
comparisons without resetting training repeatedly to a fixed factory. Evaluation
uses a disjoint held-out seed schedule shared across candidates/checkpoints and
regenerates its factories. No evaluation gradients or best-score selection alter
the training schedule.

## Durable data and transitions

`protocol.json` is immutable. It contains resolved external inputs and a complete
runtime source hash manifest. `state.json` is the durable commit pointer: schema,
protocol hash, status, ordered candidate/seed jobs, each latest checkpoint,
completed phase records, admitted training actions and cumulative elapsed budget.
Checkpoints carry schema, protocol/job identity, actor/critic parameter hashes,
weights, optimizer states and RNG state. A phase record carries task identities,
generation outcomes, aggregate quality, timings and PPO epoch diagnostics.

The coordinator executes the frozen job/phase schedule. For each phase it
publishes tasks, collects or reuses immutable complete results, performs at most
one PPO update, writes the new artifacts, then commits the state pointer.
Files use same-directory temporary writes, flush/fsync, atomic rename and parent
directory fsync. Newly created directory links are synced through their ancestors;
claim the final run directory exclusively so concurrent preparation cannot overwrite
another experiment. Resume terminates a lost session before reading its final
commit pointer, including commits made during shutdown. An artifact published before its state pointer may be an orphan;
resume must not infer a completed update from its presence. Keep failed attempt
evidence and continue from the last durable state. Checkpoint corruption and
source/configuration drift fail before training resumes.

Live `progress.json` is advisory and may be ahead of the commit pointer. It
contains session identity, current job/phase, task counts, learner stage and
last progress time. `supervisor.json` owns process identity, heartbeat, sampled
resources, stop reason and exit status. Session identities prevent an old stop
request or stale advisory file from controlling a later resume. A coordinator
heartbeat cannot replace a progress timeout: workers or updates must advance
within their configured bounds.

## Monitoring outputs

The supervisor atomically publishes its heartbeat at least every two seconds.
`status` reports measurement age, run and job position, committed/active work,
current stage, task completion, elapsed/remaining budget, worker count, CPU/RSS,
disk free and optional GPU utilization/memory. Missing GPU telemetry is marked
unavailable and is not a training failure. Resource samples go to bounded local
JSONL segments. Monitoring never calls the actor, critic or native environment.

Record generation, collection, loading/credit, preparation/transfer, learner,
statistics and checkpoint time separately. Report admitted attempts, generation
rejections, selections, facility/rate/geometry diversity and selections per second.
Retain PPO ratio mean/range/quantiles, clipping fractions, sampled KL, entropy,
actor/value losses, explained variance, gradient norms, actual optimizer-step
count and KL early stops. Undefined explained variance is null, not a fabricated
zero. No monitor may silently turn incomplete data into a measured point.

`plot` creates standalone PNG/SVG and a JSON snapshot from committed records.
Show held-out area reduction and paired change from each candidate's untrained
baseline against completed batches, admitted actions and elapsed time, plus
training quality, phase timings and PPO diagnostics. Keep per-seed curves and
generation coverage visible. Report the primary comparison on the shared admitted
evaluation seed intersection across all candidates and all evaluation checkpoints
for each initialization seed, and show attrition. Publish these shared-cohort
`outcome/*` points only once all jobs for that seed complete. Keep the earlier
`evaluation/all_admitted/*` curves explicitly provisional; a two-seed shallow screen does
not establish a statistically reliable winner. Rendering failures are observable
and cannot mutate or stop training. Watching is bounded and terminates on a
terminal run state; a stale source remains labelled stale.

W&B publication reads committed local records through a separate observer. It
cannot hold up collection, optimization or durable commits. Persist export
progress and stable run IDs locally; reconnect without losing or fabricating
measured points. Surface initialization/sync failures, the dashboard URL and
export lag in CLI status. Use explicit offline mode for development checks;
online screen mode uses the user's entity/project. Local records remain the
recoverable source if the tracking service is unavailable. Do not upload code,
raw observations, credentials or model checkpoints as a side effect of scalar
tracking. Commit each SDK history ordinal explicitly; the default when an explicit
step is supplied leaves the latest point pending. `export --run ...` retries
terminal-run publication while holding the same writer lock. Surface terminated
observers and unfinished terminal exports separately from training completion.
Discover tagged detached SDK services for resource accounting and cleanup, including
services launched before a process registration was durably recorded. Use W&B's documented custom step metrics for the three outcome axes.

## Readiness evidence

Unit/fault tests must exercise invalid protocol, duplicate writers, stale task
envelopes, a corrupt checkpoint, source drift, partial writes, crash boundaries
around commit, exact nonempty optimizer/RNG resume, completed-result reuse,
interrupted attempt retention, worker EOF/hang, stop requests, hard timeout,
resource stops, descendant cleanup and stale/missing monitoring data. Test the
state transitions rather than copying implementation expressions.

Run a small native fresh-generation job through the real supervisor, workers,
GPU learner and observer. Check initial/best native validity in the standalone
test, actual updates, changed factory draws, an intentional stop/resume and final
completion. Include the rich history contract and a no-restore contract. Verify
that stored behavior probabilities match the optimized learner outside normal
training. Run the required repository checks. Freeze and execute the shallow
comparison only after independent review findings and these readiness checks
are resolved and committed.
