# Compiled CPU Actor and Persistent Cache

Status: implementation, 2026-09-08. The user explicitly accepted initial compilation cost
for longer training and requested accounting for reuse of the on-disk compiler cache.

## Contract

Optional `compile_actor: true` config enables `torch.compile(dynamic=True, fullgraph=True)`
for the existing CPU actor forward pass. `compiler_cache_directory` names an explicit directory
relative to the repository root (or absolute). Disabled compilation retains the supported eager
CPU path. Save effective compiler settings in metadata; config differences remain subject to
the existing strict CPU continuation contract. No model/loss/precision/allowance change.

The eager actor owns parameters. The compiled callable reads those same tensors, and existing
post-update `load_state_dict` refreshes them in place. Sampling remains on CPU with the existing
RNG. Frozen CPU evaluation remains eager for comparable assessment. Outputs may have the
permitted floating-point differences from kernel fusion. Checkpoint parameter names and tensor
payloads remain eager model state dictionaries; never serialize a compiled module as the model.

Charge wrapper construction plus the first no-grad forward to `actor_compile_setup_seconds`
inside total training time. Warm-up does not sample actions or mutate the environment/RNG.
Charge later compile/recompile work to the inference call that triggers it. Report compiler
callback events with phase, code, severity, stage, compile ID, trigger, elapsed seconds, and
cache directory; these event clocks are nested in setup/inference and must not be added again.
Remove callbacks after completion/interruption. Compiler failures use the runner's structured
interruption evidence; do not silently substitute eager execution.

PyTorch's compilation callbacks are an internal diagnostic API. Keep their use isolated in
one module, test against the deployed runtime, and fail explicitly if the required hooks are
unavailable. Do not infer machine-code recompilation or cache misses merely from callback count:
a new process may still trace/load a cached graph. Cache directory existence is not a cache hit.

## Evidence

Compare fresh-cache and reused-cache invocations in separate processes, plus repeated calls
inside each process. Use an isolated explicitly named cache for cold measurement; never delete
the user's existing cache. Record cache environment, invocation timing, compiler events, and
runtime/source/input hashes. Persistent caches remain ignored generated output.

Check all retained dynamic shapes and post-update weight refresh against eager outputs; verify
no input mutation and no extra compilation on same-shape weight updates. Existing CPU exact
continuation remains tested with eager execution. Compiled continuation does not claim bitwise
identity across fresh compiler processes without separate evidence.

Run longer eager and compiled CUDA-learner configurations with equal command/episode/update
allowances. Separate controlled fixed-input throughput from differing sampled full trajectories.
Report cold setup, in-process steady cost, disk-cache restart cost, and any shape-driven compile
work. Full layouts and representative traces must pass independent audit.
