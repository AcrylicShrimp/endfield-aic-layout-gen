# PPO execution optimization after measured profiling

Status: implementation contract; follows the completed CPU profile.

## Evidence and decision

The 48-batch confirmation spent 1,414.87 seconds collecting and 4,359.21 seconds
updating plus reconstructing updates. A representative 32-selection collection
profile spent 2.197 of 5.000 instrumented seconds building observations, including
82 full world/candidate encodings. Physical-key calculation took another 0.644
cumulative seconds. A 64-selection reference minibatch took 0.420 seconds without
instrumentation. Backward, convolutions and linear layers dominate learner cost.

First remove duplicate full-update reconstruction from the normal update API,
share actor/critic observation construction, reuse immutable witness identities,
and batch independent model computations. CPU/GPU and AMP measurements follow
this implementation. The historical confirmation and its frozen sources remain
separate reproducible research inputs.

## Inputs and outputs

Inputs are native-valid fresh trajectories, their actual behavior log
probabilities and old critic values, frozen actor/critic parameters, separate
Adam states, a dedicated shuffle RNG and the existing PPO configuration. The
actor remains action-only; the critic retains current/best world and candidate
information. This slice changes execution, not parameter names or architecture.

Prepared minibatches contain concatenated candidates and member references,
per-example masks and logit adjustments, concatenated disjoint graphs and raster
buckets grouped by exact height/width. Preparation and device transfer are
separately measurable. GroupNorm receives unpadded rasters; graph indices are
offset, and node means and action distributions remain per example.

Outputs include updated models/optimizers/RNG, optimizer-step counts, frozen
credit, measured probability/value/gradient differences, phase timings and
structured failures under `ppo-training.*`. Recorded behavior denominators are
never replaced with batched or device-specific recomputations. GAE and
standardization retain their whole-rollout and terminal boundaries. Gradients
may accumulate over bounded microbatches inside the same shuffled minibatch;
normalization uses the complete minibatch length, with exactly one actor and
one critic Adam step afterward.

## Observation and validation invariants

Build the full critic observation once and derive the actor's hidden-world view
from its candidate descriptors. Zero hidden references and context identically
to the historical action-only contract. Evaluation still builds only the actor
view. Reuse witness identity only for immutable Python snapshot objects owned by
the episode; do not cache by a bare recycled object ID or retain all prior worlds.
Native proposal validation, full selection budgets, temporary valid worsening,
best retention and physical-action memory remain unchanged.

Normal updates consume trusted collector output without rehashing observations,
rechecking masks/rewards or replaying behavior networks. Schema and batch-version
checks belong at the experience boundary. The user explicitly requested removing
these redundant runtime validations. Keep only the finite gradient-norm guard
before the optimizer step, using the norm already calculated for clipping;
successful tests cannot guarantee numerical stability at future learned weights.
Updates do not rerun the entire optimizer to verify themselves. Mathematical
regression checks, measured reference parity and
nonempty Adam/RNG checkpoint continuation establish bounded execution confidence.
Native-valid collection and checkpoint continuation receive an actual execution
check before this slice is complete. Precision changes will have explicit
measured tolerances; exact cross-device byte identity is not required.

## Verification and scope

Verify actor/critic forward values and gradients on variable raster shapes,
empty/nonempty graph edges, unequal candidate/member counts, and aliased or
separate best worlds. Check that padding or cross-example pooling cannot change
per-example normalization. Measure before/after on retained representative native
experience and verify the optimized collection's observations, actions and
physics against the frozen replay. Record speedups separately for omitted
reconstruction, collection and learner execution.

This slice does not launch long training. The subsequent device/AMP experiments
must finish before the user-requested production harness, monitoring,
independent-review and thorough-test readiness stage.

## Follow-up scope amendment

The user replaced the 12-hour long run with a shallow PPO comparison of the
previous twelve input contracts, using fresh generated factories for every
training episode. The production harness, monitoring, independent reviews and
readiness checks remain prerequisites. Extend actor batching beyond action-only
