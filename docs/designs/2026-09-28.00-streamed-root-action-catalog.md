# Draft: streamed exact root-action catalog

## Provisional decision and evidence boundary

The current candidate is an exact, source-bound action catalog for Gumbel roots. Native Place and PlaceTerminal commands remain complete. Score them in admitted pages, stably sort the resulting priors through bounded external sorting, retain only a bounded simulation shortlist in memory, and store frozen first-stage and anchor priors in native source order for sequential target replay. Retain the initially exposed nonplacement witnesses and the visited shortlist evidence. This aims to preserve the current root policy target, subject to an explicit floating-point parity tolerance. Page and dense matrix multiplication can round differently: a local 64-action fixture measured 124 pair-order reversals among nearly tied scores at maximum prior error 7.451e-9. Stable sorting is exact for the paged priors, but rank-indexed Gumbel noise and selection cannot be promised bit-identical to the dense root for arbitrarily close scores. The catalog must report this versioned numeric behavior and test its effect on the shortlist and selected action. It does not introduce a fixed spatial, first-page or coordinate cap. The decision remains provisional until the complete alternative comparison and local cost gate pass independent review.

The [local root-scale report](../reports/2026-09-28-hierarchical-root-action-scale-gap.md) found 5,715,346 legal Place actions on a legal 100-block partial panel and 66,977,600 on a hypothetical 320 × 320 bound around a generated 167-block logical graph. The latter is not physical feasibility evidence. The dense root requires multi-gigabyte buffers before search. A temporary `f32` logit stream needs about 22.9 MB or 267.9 MB respectively. The **retained source-order** ledger stores one `f64` first-stage prior and one `f64` anchor prior per action: about 91.4 MB or 1.07 GB. Native rank is implicit in its offset, so training reads this ledger and native pages sequentially. Twenty-four hypothetical upper roots need about 25.7 GB retained before metadata. Rank-noise search needs 24-byte `(f64 prior, f64 anchor prior, u64 native ordinal)` external sort records; two copies at the hypothetical upper root reach about 3.22 GB. Action-identity noise needs an additional 8-byte precomputed noise value in each temporary sort record, so its two 32-byte copies reach about 4.29 GB. The retained 16-byte ledger is identical in both modes, and the extra noise bytes leave with the search-only sorted temporary. The exact catalog still pays complete enumeration, model scoring and sort once per root. An unproved sampled shortlist would have very low inclusion probability for a rare good pose. The choice must be revisited if the complete streamed workflow fails its physical throughput or storage admission gate; it must not be silently replaced by a small sampled set.

A release-mode local integrated probe on the 100-block partial physical root took 106.699 s to enumerate, apply, featurize, anchor-score and CPU-score all 5,715,346 Place actions. Full child application and feature/anchor derivation consumed 103.551 s; model forwards consumed 0.508 s. A separate four-offset sample of 1,024 legal placements showed that a prepared connection table can reproduce all feature rows, child values and anchor scores bit for bit, with 0.000116 s in the prepared calculation versus 0.018435 s in the existing child path. The prepared calculation plus native pager then traversed all 5,715,346 legal Place commands in 1.782 s in a local release run, retaining only a checksum. This is evidence that the analytic placement scorer is a throughput requirement and a plausible optimization. Parity excludes final-placement transitions and terminals; the probes omitted global normalization, sorting, replay and backward training, so the proposed catalog has no measured end-to-end cost yet.

## Inputs, identities and order

One catalog is bound in memory to the native `Session` instance/revision. Its **persistent** identity includes the source state hash, problem/catalog identities, the digest of the case's versioned native `Limits`, the digest of the complete effective versioned search/training configuration, placement bounds, lower candidate configuration, outer checkpoint identity, action-feature schema, Gumbel controls and seed. The effective digest covers all settings that can change legal actions, features, scores, shortlist, target or optimizer eligibility; per-case `Limits` are separate because `hierarchical_state_sha256` covers only the problem and observation. Compute canonical serialization digests once at publication and verify them once when loading or resuming a record, not per action. A restarted `Session` instance/revision cannot substitute for these persistent identities. The catalog first enumerates the same unsorted source sequence as the current `ensure_node_expanded(..., exhaust_placements=true)`: all native Place pages, all PlaceTerminal pages, then the lower route/network/repair witnesses exposed before Gumbel entry. Its placement ranks are the native `Domain` ranks, not a new geometric index. The current code then performs a stable descending sort on `edge.prior`; the catalog must use that same comparator on its computed paged priors, with the unsorted ordinal as the exact tie key. Well-separated bounded fixtures must preserve dense order. Near ties may change order within measured score tolerance; quantify resulting rank-noise, shortlist and selection differences instead of claiming dense bit parity. Rank-noise mode consumes its deterministic noise sequence in **sorted** order; action-identity mode hashes the same physical ID. Physical action IDs follow Plan [06](../plans/2026-09-27.06-stable-gumbel-action-identity.md). Appended lower witnesses after the root budget freezes receive zero current-root target mass, and remain eligible only for a later budget or reroot.

The catalog records the initial eligible count and a retained table of **all** initially exposed nonplacement witnesses keyed by unsorted ordinal and route `(connection,id)`, even when they are outside the simulation shortlist. It also records any lower witnesses appended during simulations after the eligibility freeze: they have zero frozen target mass but must remain in the training model's softmax denominator and lower-model examples, matching the current dense `RootRecord`. A lower `RouteUpdate` resolves against this retained table or an appended witness by physical route key, merges `additional_provenance` exactly as the current edge update does, and marks the final action-feature provenance slots for recomputation; it must not require the witness to be a live simulation edge. The update does not change the frozen initial prior or root eligibility. Placement commands, features and entity references are regenerated from source plus native rank during training. Selected and visited actions keep their physical IDs, **sorted** initial rank, frozen prior, visits and Q evidence. A source revision, bounds, checkpoint or schema mismatch rejects replay. All output changes are schema-versioned; old dense records are either read by their existing reader or rejected explicitly by the new versioned reader, with no ambiguous interpretation.

## Enumeration, features and scoring

The native placement domain remains owned and charged across pages under Plan [21](../plans/2026-09-27.21-constructive-learning-spatial-admission.md). A catalog page carries exact commands, rank and physical ID in old order. In action-identity mode, compute the existing SHA-256 digest prefix from seed, source identity and physical ID while each native witness is present, apply `gumbel_from_bits` once, and carry the resulting `f64::to_bits()` value through the raw-score and sort passes. Those are the same bits retained in the v11 shortlist evidence, not the untransformed SHA prefix. Rank mode assigns noise after sorting and has no per-action noise sidecar. Its output size, action rows, entity indices, model input tensors and temporary shortlist updates are admitted before allocation under the shared tree and request budgets. A refusal returns a typed resource stop with the source, page cursor and uncommitted outputs intact; it never means no legal actions. One completed page commits its cursor and sidecar segment atomically. In-process retry uses the retained source-bound owner; process restart may discard an unpublished partial sidecar and rebuild that root from its immutable inputs.

The Place/PlaceTerminal feature and anchor scorer derives the same progress, coordinates, rotations, entity reference, connected-endpoint distance and metrics flag as the current `MacroAction::features` and `prior_score` without cloning one `Session` per pose. Precompute a fixed per-connection contribution array and affected incident indices/peer positions per entity; each pose scans the compact contribution array **in original connection order** and substitutes only its incident terms. A fixed-plus-incident aggregate changed `f64` rounding in the local probe; ordered accumulation preserved exact anchor bits and stable prior ties. This compact scan must be measured at intended graph size so it does not become a new per-action bottleneck. The scorer also derives each child `state_value` and a streamed maximum `exact_value`, since that maximum participates in root value and completed-Q targets. Compare rows, anchor scores and the maximum against actual child application across blocked holes, rotations, placed/unplaced peers and final-placement transitions. A transition requiring native validation may use a direct child application; it must be admitted, measured and cannot be skipped to claim success. Full child application remains mandatory for shortlisted simulations and the selected action. Other action kinds continue using their established complete replayable witnesses and physical-cost features.

The outer model exposes a narrow encoded-state owner and a score-page method. Encode the graph once per frozen root; gather context/entity and score only an admitted action page, returning raw `f32` logits and the one state-value vector. The score-page method does not normalize within the page. A first sequential pass writes `(f32 raw logit, f64 anchor score)` to a 12-byte/action temporary in rank mode, or adds the already computed 8-byte physical-ID noise bits for a 20-byte/action temporary in action-identity mode, while accumulating stable full-set log-sum-exp normalizers in unsorted source order. This adds about 0.536 GB at the hypothetical upper root in action-identity mode. A second sequential pass reads that temporary and reproduces `score_action_rows`: convert the globally normalized model log probability through `exp` in `f32`, promote to `f64`, and mix it with the `f64` normalized anchor prior using `Factory::anchor_prior_mass`. It writes each resulting `(f64 first-stage prior, f64 anchor prior)` into the **source-order** ledger and `(first-stage prior, anchor prior, native ordinal[, physical-ID noise bits])` into admitted 24/32-byte sort runs. Externally merge the runs by descending prior and ascending ordinal. The sorted stream is a search-only temporary and is removed only after shortlist selection and frozen target scalars are computed; the verified source-order ledger is required training data. The later Gumbel `root_policy_prior` applies its **second** anchor mixture with `GumbelControls::anchor_policy_mass`; these two mixtures must not be collapsed. Avoid repeated graph encoding, full action tensors and an uncharged dense logits vector. Search preserves the current validation of finite logits and values at the page boundary.

## Gumbel shortlist and target

After external sorting, stream the frozen **sorted temporary** with its retained anchor priors. Rank mode draws each noise value in sorted order. Action-identity mode reads the precomputed noise bits carried in its 32-byte sort record; it does not seek back to each native ordinal or regenerate each witness during the sorted scan. Keep only the best `anchor_candidates` and the best `candidates` Gumbel rankings using bounded heaps with the current tie and sorted-rank rules. The final union and quota behavior must match `considered_root_actions` on a small full-action fixture. A selected ordinal is resolved in **one ascending-ordinal batch** against sequential native pages before simulations; per-entry random `command_page` calls are forbidden. Keep only those actions as simulation edges; resolve later updates by physical ID, not mutable vector position. The complete nonplacement witness table remains owned separately so route updates and lower replay can address witnesses outside that shortlist. Sequential halving uses the current simulations-per-move budget and completed-Q transform. The common completed-Q transform for unvisited initially eligible actions follows from the same root value and visited totals as the dense implementation. Later root widening may append lower witnesses and renormalize/re-sort live edges today; because the forced Gumbel root always resolves by physical ID and uses frozen initial priors, the new versioned record may retain the initial sorted order plus appended witnesses in publication order, provided a parity test proves selected action, visits, Q and target are unaffected by this record-order change.

The improved-policy target remains `exp(log(w_i)+q_i-logZ)`, where `w_i = max(root_policy_prior_i, f64::MIN_POSITIVE)` applies the current second anchor mixture and clipping. `q_i` is the frozen **common unvisited Q transform `q_0`** for every unvisited initially eligible action and a retained override for each visited shortlist action. Stream the sum `W_unvisited` over **unvisited** initially eligible actions, without subtracting nearly equal floating-point sums. Compute `logZ = logaddexp(log(W_unvisited)+q_0, log(w_v)+q_v for each visited v)` using a max-shifted accumulation; skip the first term when `W_unvisited=0`. This remains finite for large legal `value_scale` and mirrors the current max-shifted normalization within the stated numeric tolerance. Before discarding the sorted temporary, make a second sequential pass to sum the resulting f64 improved-policy probabilities in record order and retain that **second normalization denominator** from `visit_target`. Training divides each generated f64 probability by this stored scalar and then casts to f32. Record `q_0`, `logZ`, `W_unvisited`, the second denominator and visited Q overrides, not one target per action. A replay parity test reconstructs the f32 targets using only these persisted fields and the source-order ledger. The selected action and root summary retain existing lineage fields, including pending lower pages and initial eligible count. Later appended actions are retained with zero target for this root budget; training still scores them in its softmax denominator.

## Publication, storage and replay

The collection report contains a versioned catalog descriptor for each root: relative sidecar name, length, action count/order version, byte count, checksum, source identity, **case Limits digest**, **effective configuration digest**, outer checkpoint identity, `q_0`, normalizers, selected action, visited overrides and retained nonplacement witnesses with their final provenance updates. The sidecar is a binary stream of `(f64 initial edge prior, f64 anchor prior)` entries in **native source order**; its ordinal is the entry index. It is required training data, not optional diagnostics. The trainer sequentially zips this stream with `Domain::command_page` and action-row generation. It never performs one random native lookup per sorted prior. At 24 hypothetical 67-million-action roots the retained ledgers occupy about 25.7 GB before framing. During normalization, the active root holds one raw score file, one sort-run copy and its 16-byte ledger. The fully consumed raw reader is dropped and removes its raw file **before** the first merge output is created; merges then hold at most the input runs, one output copy and the ledger. Thus at 66,977,600 hypothetical actions, rank mode's active-root peak is `N * max(12+24+16, 2*24+16) = 4.29 GB`, and action-identity mode's is `N * max(20+32+16, 2*32+16) = 5.36 GB`, plus earlier retained root sidecars and filesystem headroom. The action-identity raw file alone is 1.34 GB and its two-copy sort peak alone is 4.29 GB; these are separate phases, not simultaneous maxima. Disk admission uses the actual mode and simultaneous active replay window, with each completed temporary removed after report publication. A write or storage refusal is a typed resource stop. Retain only the sidecars referenced by the active collection and replay window; do not create per-epoch copies or a second journal. A valid source ordinal maps to either a sequentially regenerated native placement command or a retained nonplacement witness. Late lower witnesses also retain action ID, visits, Q and provenance for `collect_lower_examples`; their outer policy target is zero, but the lower trainer still consumes them exactly as before.

Write temporary sidecars under the output directory, verify their length and checksum once, rename them, then atomically publish the report that references them. A valid report with a missing or mismatched sidecar fails input admission. Unpublished temporary files are safe to remove during recovery. Existing recovery binding includes the catalog descriptor and sidecar checksum, so resumed training cannot substitute a different target. A replay-window source holds descriptors and bounded file/page readers, not all reconstructed action rows or targets in RAM. Drop its sidecars when the source leaves the required replay window, subject to the repository experiment closeout rules. A committed conclusion retains compact metrics, configuration and provenance; full sidecars survive only while continuation or replay requires them.

## Exact training gradient

For a training state, stream regenerated action rows and frozen target pages from its catalog. Include late appended witnesses in the current-model denominator, with zero frozen target. Encode the current model graph once with gradients. A first no-gradient score pass over current action pages obtains the full current log-sum-exp and value prediction; parameters do not change between passes. Let `T = sum_i t_i` for the actual `f32` target values produced by `visit_target`; `T` must be measured, not assumed exactly one. A second pass computes current page logits and detached coefficients `T * softmax_current_i - t_i`. The sum of `coefficient_i * logit_i` gives the same policy gradient as dense `-sum(target * log_softmax)` at those unchanged parameters. Accumulate head-parameter gradients and context/entity gradients page by page, then backpropagate the summed encoded gradient through the shared encoder once. Include the existing value loss once per state, preserve batch-state scaling, policy eligibility (`train_failed_policy`) and optimizer step timing. This is a gradient construction, so its scalar monitoring loss must separately reconstruct the true cross entropy `T * logsumexp(z) - sum_i t_i z_i` from the first-pass normalizer and frozen target-weighted logits. A small dense-versus-streamed test must compare loss and every parameter gradient, including replayed roots and visited/unvisited target mass, before replacing the trainer.

## Resource and verification gates

Use dynamic admission based on available tree memory, page tensor peaks and actual sidecar writes. Page size is a performance choice, not a legal-action count cap. Host allocation, disk exhaustion, deadline and work stops preserve Unknown/resource semantics and the source-bound cursor. No routine full revalidation, repeated hashing or per-action distribution audit is added. Verify source/checkpoint/sidecar identity once at publication and load boundaries. PUCT progressive widening stays on its Plan 21 path; this boundary handles exhaustive Gumbel roots.

Offline gates compare every action ID, analytic row, anchor score, mixed prior, completed-Q target, loss and gradient against the existing dense implementation on bounded fixtures. For well-separated priors, also compare exact sorted order, shortlist, Gumbel assignment and selected action. For near ties, compare priors within measured numeric tolerance and verify the comparator and exact-tie ordinal behavior. Build a separate bounded reference with the same actions/child values and the page-computed priors injected into existing dense Gumbel selection and target helpers; compare shortlist, selected action, visits, Q, q_0 and every f32 target against that reference, including a fixture where the original dense-model selected action changes. Check action-identity noise bits per physical ID and record any changed rank-indexed noise assignment. Do not hide a changed near-tie selection as an exact dense parity pass. Run the full integrated CLI path on 30/100-facility partial and placed panels, measure elapsed, RSS, temporary peak, sidecar size and replay training cost. A generated upper logical graph may test admission and throughput but cannot establish physical success. Representative upper *physical* inputs and GPU throughput are later server gates after renewed user authorization. If disk or elapsed cost is prohibitive, measure it and review a mathematically specified sampled-policy alternative rather than quietly narrowing the exact catalog.

## Implementation decomposition

Separate reviewed implementation plans should own (1) placement row/anchor parity, (2) encoded-state page scoring and normalizer, (3) source-bound catalog/Gumbel shortlist with bounded sidecar publication, and (4) streamed target replay and gradient. Integrate in that dependency order, reviewing each completed module. The sidecar schema and complete search/trainer handoff must be reviewed together before either implementation is treated as sufficient for broad experiments.
