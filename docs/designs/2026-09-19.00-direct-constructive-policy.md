# Direct constructive layout policy

Status: first environment slice in implementation, 2026-09-19.

## Goal

Train a policy to construct facility poses and physical transport paths from an
immutable logical production problem. No complete input layout, routed-layout
dataset, A* call, automatic reroute or hidden geometry repair participates in an
episode. The environment executes explicit policy commands, checks their local
legality, measures certified logical progress and independently validates a
complete result.

The first bounded experiment uses the recipe-independent
`aic-physical-layout-v1` problem boundary. It proves the direct placement and
path-command interaction before adding recipe external terminals, shared trunks
and catalog components. Those omissions are experiment boundaries rather than
claims that pairwise paths are the final factory representation.

## First environment contract

An episode owns:

- one immutable physical problem and validated external catalogs;
- optional poses for every required facility block;
- completed routes for immutable logical connections;
- at most one active route, including its selected ports and explicit path;
- selected facility ports, occupied body cells and occupied transport cells;
- a bounded action count and maximum straight extension length; and
- an explicit focus consisting of the active logical connection and open path
  endpoint.

The initial state has no poses or paths. The policy issues:

1. `place(block, origin, rotation)` exactly once for an unplaced block;
2. `begin-route(connection, source-port, target-port)` after both endpoint
   blocks are placed;
3. `extend(direction, length)` from the active open endpoint;
4. `connect` only when that endpoint equals the selected target-port connection
   cell; or
5. `abort-route` to discard the active attempt and release its selected ports.

An extension materializes every traversed grid cell. It is rejected atomically
if a coordinate overflows, leaves the first experimental coordinate domain,
touches a facility body, revisits its own route or intersects a completed route
on the same transport layer. Belt and pipe cells may share an XY coordinate.
Same-layer crossings remain unsupported until an explicit bridge action or
derived-component contract is added. The executor never selects a direction,
length, target, port or replacement path.

Port choices are reserved while a route is active and committed when it is
connected. A rejected action does not mutate state. `abort-route` is the only
first-slice rollback and cannot change a completed route or facility pose.

## Progress and reward boundary

For the first pairwise problem, a logical obligation is complete exactly when
its immutable connection has a completed explicit route. The progress potential
is:

```text
completed connection count / total connection count
```

Every accepted or rejected turn reports the before and after values and their
difference. The learning layer owns reward scaling, invalid-action penalties,
the dominant independently validated completion bonus and any completion-only
quality reward. It must not repeatedly pay the absolute progress value.

The environment runs full independent layout validation only after all blocks
and connections are complete. Ordinary extensions receive local checks only.
This keeps validation out of the hot path while preserving the final public
layout contract.

## Model boundary

The first learned policy will retain the existing small graph encoder, PPO/GAE
update path, batched collection and pooled critic. It will use cold weights and a
new constructive observation/action schema.

The observation exposes the active connection and open endpoint as ordinary
state. A decoder query built from that focus cross-attends to encoded facility,
terminal, connection and transport entities. This provides continuity with the
last command without recurrent hidden state or an unbounded action-history
buffer. Exact occupancy also receives a spatial encoding; the existing averaged
path-edge representation is not sufficient for direct routing.

The actor conditionally decodes command kind, logical connection or block,
anchor/port, direction, length and target. Masks remove only syntactically or
immediately locally illegal choices. They do not perform reachability search or
future route feasibility tests.

## Continuity and limits

The slice reuses external catalog validation, facility projection, physical
layout serialization and independent final validation. It intentionally does
not reuse the automatic route repair path. The old complete-factory policy
weights and checkpoints are incompatible with the new observation and action
semantics.

The first slice does not yet support external terminals, shared networks,
splitters, convergers, same-layer bridges, multi-route drafting, facility moves,
route retraction or recipe balance. The next slice must be chosen from evidence
produced by an executable authored command trace and a bounded random-policy
probe, not by treating this minimal domain as the final architecture.

## First evidence

The environment implementation must demonstrate:

- a valid authored sequence from an empty state reaches the independent
  validator without invoking a router;
- progress changes only when an immutable connection is committed;
- abort releases provisional port ownership;
- collision, reused port, wrong endpoint, same-layer intersection and stale
  terminal actions are rejected without partial mutation; and
- the active connection and endpoint are directly observable for the future
  attention query.
