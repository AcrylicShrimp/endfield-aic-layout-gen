# Direct constructive layout policy

Status: full logical production-graph preparation and the physical-v2 constructive
environment are implemented, 2026-09-20. A full-scale training result is pending.

## Goal

Train a policy to construct facility poses and physical transport paths from an
immutable logical production problem. No complete input layout, routed-layout
dataset, A* call, automatic reroute or hidden geometry repair participates in an
episode. The environment executes explicit policy commands, checks their local
legality, measures certified logical progress and independently validates a
complete result.

The current environment uses the recipe-independent `aic-physical-layout-v2`
boundary. It accepts full facility-instance production graphs, explicit factory
boundary terminals, capacity-bounded parallel lanes and shared same-commodity
transport cells. Explicit splitter and converger component placement remains a
later physical-fidelity cutover; shared cells currently carry that junction role.

## First environment contract

An episode owns:

- one immutable physical problem and validated external catalogs;
- optional poses for every required facility block;
- completed routes for immutable logical connections;
- at most one active route, including its selected ports and explicit path;
- selected facility ports, occupied body cells and occupied transport cells;
- a bounded action count and maximum straight extension length; and
- an explicit focus consisting of the active logical connection and open path
  endpoint.

The initial state has no poses or paths. The policy issues:

1. `place(block, origin, rotation)` exactly once for an unplaced block;
2. `place-terminal(terminal, position)` once on the configured canvas perimeter;
3. `begin-route(connection, source-port?, target-port?)` after both endpoints
   are placed; boundary terminals omit a facility port;
4. `extend(direction, length)` from the active open endpoint;
5. `connect` only when that endpoint equals the selected target-port connection
   cell; or
6. `abort-route` to discard the active attempt and release its selected ports.

An extension materializes every traversed grid cell. It is rejected atomically
if a coordinate overflows, leaves the first experimental coordinate domain,
touches a facility body or unrelated terminal, revisits its own route, or uses
an incompatible completed route on the same transport layer. Same-commodity
routes may share cells and facility ports while their aggregate rate remains
within one catalog transport line. Belt and pipe cells may share an XY coordinate.
Other same-layer crossings still require a declared bridge. The executor never selects a direction,
length, target, port or replacement path.

Port choices are reserved while a route is active and committed when it is
connected. A rejected action does not mutate state. `abort-route` is the only
first-slice rollback and cannot change a completed route or facility pose.

## Progress and reward boundary

For the first pairwise problem, a logical obligation is complete exactly when
its immutable connection has a completed explicit route. The progress potential
is:

```text
completed connection count / total connection count
```

Every accepted or rejected turn reports the before and after values and their
difference. The learning layer owns reward scaling, invalid-action penalties,
the dominant independently validated completion bonus and any completion-only
quality reward. It must not repeatedly pay the absolute progress value.

The environment runs full independent layout validation only after all blocks
and connections are complete. Ordinary extensions receive local checks only.
This keeps validation out of the hot path while preserving the final public
layout contract.

## Model boundary

The first learned policy will retain the existing small graph encoder, PPO/GAE
update path, batched collection and pooled critic. It will use cold weights and a
new constructive observation/action schema.

The observation exposes the active connection and open endpoint as ordinary
state. A decoder query built from that focus cross-attends to encoded facility,
terminal, connection and transport entities. This provides continuity with the
last command without recurrent hidden state or an unbounded action-history
buffer. Exact occupancy also receives a spatial encoding; the existing averaged
path-edge representation is not sufficient for direct routing.

The actor conditionally decodes command kind, logical connection or block,
anchor/port, direction, length and target. Masks remove only syntactically or
immediately locally illegal choices. They do not perform reachability search or
future route feasibility tests.

## Continuity and limits

The slice reuses external catalog validation, facility projection, physical
layout serialization and independent final validation. It intentionally does
not reuse the automatic route repair path. The old complete-factory policy
weights and checkpoints are incompatible with the new observation and action
semantics.

The current slice does not yet place explicit splitter or converger components,
move facilities, retract committed routes, or enforce recipe execution inside the
physical validator. Problem preparation already preserves the complete logical
recipe graph and external flows; a successful physical episode covers every one
of those immutable obligations.

## First evidence

The environment implementation must demonstrate:

- a valid authored sequence from an empty state reaches the independent
  validator without invoking a router;
- progress changes only when an immutable connection is committed;
- abort releases provisional port ownership;
- collision, reused port, wrong endpoint, same-layer intersection and stale
  terminal actions are rejected without partial mutation; and
- the active connection and endpoint are directly observable for the future
  attention query.

## Implemented learning boundary

`aic-constructive-learning-v2` converts a constructive session into stable
problem-order entity rows, directed source/connection/target relations, and one
token per occupied body or transport cell. Active path cells, the open endpoint
and selected target remain separate tokens even at coincident coordinates. The
placement canvas, ordered extension-length list, maximum pose bank and maximum
spatial bank are explicit bounded-pilot inputs.

The action domain is conditional rather than a Cartesian product. It advances
through command kind and only the applicable factors: block then complete pose,
connection then source and target ports, or direction then length. Each bank
contains choices that are immediately locally legal in the observed revision.
Selected commands retain that revision and the executor rejects stale choices.
No factor runs route reachability or chooses a future path.

`aic-constructive-attention-model-v2` uses cold parameters and a checkpoint
namespace separate from the edit policy. It retains small typed graph message
passing and a pooled critic. Exact spatial tokens are encoded without path
averaging. A query containing the persistent focus entity, endpoint/target
geometry and episode globals cross-attends to the combined graph and spatial
memory. The resulting context scores every choice in the current conditional
factor and produces one state value.

Continuity checklist:

| Existing benefit | Constructive approach | Check |
| --- | --- | --- |
| Batched variable-size graph execution | Packed entity, relation, spatial and choice banks with segment reductions | Two different focus states run in one tensor batch |
| Small graph encoder and pooled value head | Same message/update shape and pooled critic role | Finite actor probabilities, entropy and values from cold weights |
| Exact native legality and action identity | Native domain filters local choices and binds selections to revision | Local-domain and stale-selection tests |
| Compact geometry representation | Sparse exact occupied-cell tokens; no dense empty canvas or route copies | Active endpoint and target remain distinct observable tokens |

Sampling now consumes this conditional likelihood exactly: an executed command's
log probability is the sum of its factor log probabilities. Batched native
collection, terminal GAE, clipped PPO, separate fixed-seed evaluation and a compact
constructive-only learner snapshot are connected through the CLI. The first controlled
result and selected learning rate are recorded in
[`2026-09-19-direct-constructive-policy-pilot.md`](../reports/2026-09-19-direct-constructive-policy-pilot.md).

## Full production-graph distribution

`aic learning prepare-constructive-problems` consumes the established sampling
policy and normalized runtime catalogs. For each stream draw it samples a target,
target load and complete contextual source plan, calculates contextual throughput
and facility requirements, and compiles every facility-instance wiring node and
edge into the immutable physical problem. A rate above one transport line becomes
the minimum number of capacity-bounded parallel connection lanes. External input,
target and surplus edges receive explicit boundary terminals.

Preparation stops at the logical graph boundary. It does not create a constructive
session, enumerate poses or ports, route paths, build a layout, or invoke physical
validation. Training creates the empty session and action domains later. The
serialized problem retains the source plan plus wiring-node and wiring-edge/lane
provenance.

Training and evaluation targets use the sampling policy's disjoint target-item
partitions. Successful unique graphs are classified by observed facility count
into open-ended power-of-two bands and selected round-robin across the bands.
`max_facilities` is an explicit sampling-work guard and can be raised; it is not a
product limit. The tracked starting policy covers loads from one quarter through
sixteen times one recipe output and admits up to 256 facilities per prepared
sample. The 2026-09-20 seed-101 smoke run produced training cases with 2, 4, 8,
16, 32, 48, 70 and 156 facilities. The 156-facility case preserved 316
connections and 80 external terminals, and a separate training-boundary probe
created its empty session and first 552-entity observation successfully.

## Device execution and PPO memory

`auto` selects CUDA when available and otherwise CPU. Device-side stochastic
decoding keeps packed probabilities and their float64 CDF on the accelerator,
transfers one draw per active graph, and returns only selected indices and
likelihoods. CPU retains its direct categorical path because the smallest pilot
is faster without accelerator launch overhead.

Every training configuration declares `ppo_minibatch_size`; there is no legacy
fallback for configurations that omit it. Advantages are normalized over the
complete rollout. Every minibatch contributes its sample-weighted loss to the
same accumulated gradient, and the optimizer still steps once per epoch. A
value larger than the collected transition count gives the established
full-batch PPO update, while a smaller value bounds the largest live autograd
graph. The 512-transition setting reduced measured peak VRAM from allocator
exhaustion to 1,250 MiB on the recipe-diverse workload.

The full-graph environment is a complete configuration cutover to
`aic-constructive-training-v3`, model schema v2, learning schema v2, physical
schema v2 and problem-set schema v2. Earlier pairwise checkpoints are incompatible.
The tracked full-graph configuration uses a 128 by 128 canvas, lazy per-selected-
facility pose expansion and a 4,096-turn episode guard.

Prepare and train a reproducible split with:

```sh
cargo run --release -p aic-cli --features outcomes --bin aic-cli -- \
  learning prepare-constructive-problems \
  --sampling docs/benchmarks/direct-constructive-full-graphs/sampling.json \
  --catalog-root data/game/normalized \
  --output target/direct-constructive-full-graphs.json \
  --seed 101 --training 232 --evaluation 64

cargo run --release -p aic-cli --features learning --bin aic-cli -- \
  learning train-constructive \
  --config docs/benchmarks/direct-constructive-full-graphs/config.json \
  --catalog-root data/game/normalized \
  --problems target/direct-constructive-full-graphs.json \
  --output target/direct-constructive-full-graphs-training \
  --device auto
```
