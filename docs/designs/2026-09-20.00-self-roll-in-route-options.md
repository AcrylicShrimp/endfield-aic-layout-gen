# Self-roll-in learned route options

## Status and goal

Accepted for a bounded implementation experiment on 2026-09-20. The direct
constructive policy currently learns facility and boundary-terminal placement
but completes no held-out connections. This experiment isolates one physical
connection at a time so routing receives a short credit horizon, while exposing
later route attempts to occupancy created by the policy's own earlier routes.

The first result is evidence about route learning, not a production solver or a
claim that the full hierarchical constructor is complete. A learned option may
be integrated into full-factory training only after it completes held-out route
tasks from cold initialization.

## Architecture

The existing constructive model, conditional action decoder, native session,
exact occupancy encoding and PPO update remain in use. A route-option episode
adds only a restricted action domain and a new collection boundary:

1. A fresh experimental problem contains one to four facility-to-facility
   connections. A deterministic, externally configured placement initializer
   places the facilities without creating ports or transport cells.
2. The collector selects exactly one unresolved connection. Before a route is
   active, its domain exposes only `begin-route` for that connection and its
   locally legal port choices. While it is active, the policy selects every
   `extend` and `connect` command. The first bootstrap slice omits explicit
   `abort-route`; the bounded option timeout performs the same full rollback
   without adding a high-probability cold-policy exit at every segment.
3. One successful `connect`, one accepted abort, or the per-route command bound
   terminates the PPO episode. A success commits through the normal native
   session; failure leaves no provisional route.
4. After success, the same session may start the next connection as a new PPO
   episode. The observation contains all previously committed paths as exact
   occupied-cell tokens. After failure, that session stops and does not expose
   easier later connections.

If a committed route occupies every locally legal port cell for the next
connection, the next option is recorded as blocked before its first action. A
bounded continuation penalty is added to the preceding successful option's
terminal reward. This one-option lookahead makes the route that created the
blocking occupancy responsible; silently dropping the blocked option would
teach no avoidance signal.

This is self-roll-in: every occupied route seen by a later option was emitted
and committed by the same learned policy. No routed layout, A* call, automatic
repair, imitation target or privately selected path participates in collection.
The placement initializer is research scaffolding and is not a replacement for
the learned outer placement policy.

## Reward and termination

A successful connection receives a constant bonus independent of factory size.
Every command may receive a small cost, and rejected commands receive a bounded
penalty. Accepted abort and route-budget exhaustion receive a bounded failure
penalty.

Dense guidance uses potential shaping within one route option. Let
`Phi(s) = -Manhattan(open_endpoint, target) / canvas_span` while a route is
active and zero while no route is active. For discount `gamma`, the shaping
term is:

```text
gamma * Phi(next) - Phi(current)
```

The next potential is forced to zero at every option boundary. Consequently an
abort or timeout closes the shaping ledger instead of retaining approach reward,
and a begin/extend/abort cycle cannot create net discounted shaping return.
Because that cancellation otherwise makes all unsuccessful paths nearly
indistinguishable, a failure also receives one terminal penalty proportional to
its remaining normalized endpoint distance. A nearer failure is less bad, but
it remains below the committed success bonus and cannot be collected repeatedly
inside one option. Raw per-cell positive reward is excluded because it would
favor unnecessarily long paths.

## Curriculum and partial occupancy

The bounded experiment begins with one aligned connection. It then opens row
offsets for a single connection before adding two, three and four connections
with aligned and reversed target ordering. This fills the difficulty gap between
a straight route and a congested multi-route state. A session reaches occupancy
depth `k` only after the policy has completed the first `k` routes. Evaluation
reports success by aligned/crossed shape, requested route count and occupancy
depth so a good aggregate score cannot hide failure on partially routed states.

Training problems are generated online from the configured facility and
transport catalog entries. Facility identity, transport kind, rate, canvas and
curriculum bounds remain external configuration. The implementation must not
embed game facility, item or balance identifiers.

## Invariants and boundaries

- The policy selects every port, direction and extension length.
- Configured run lengths include the curriculum's common coordinate deltas so
  one straight segment does not require an arbitrary binary decomposition.
- Existing native legality, capacity, collision and final-validation behavior
  remains the commit authority.
- A route option cannot place or move facilities, place terminals, select a
  different logical connection, or alter a committed route.
- One option produces one PPO trajectory. Returns never cross a connection
  boundary, even when successive options reuse one native session. The sole
  continuation adjustment is the explicit next-option blocked-start penalty.
- Setup commands and successful roll-in routes are observable in the session
  but setup commands are not training samples.
- Route and full-construction command counts are reported separately.
- The experimental generator and collector are separate from normal
  full-factory training.

## Continuity checklist

| Existing benefit | Route-option treatment | Check |
| --- | --- | --- |
| Exact sparse occupancy | Reuse native session and constructive input encoding | A later option observes earlier committed route cells |
| Conditional valid action factors | Restrict the existing domain to one connection | Every decoded command replays through `step_selected` |
| Batched model execution | Batch active route options across sessions | Mixed active and not-yet-begun routes collect together |
| PPO implementation and checkpoint shape | Reuse the constructive learner unchanged | Route checkpoint loads as the same model schema |
| Router-free policy ownership | No generated or repaired paths | Retained commands contain every committed segment |

## Rejected alternatives

- Increasing the full episode turn limit leaves delayed routing credit and
  makes large episodes more expensive.
- Paying every extension a positive reward favors longer paths and permits
  abort loops to farm reward.
- Preloading A*-generated partial factories teaches occupancy handling but
  violates the direct policy's router-free learning boundary.
- Training only isolated routes on empty occupancy does not test the state
  distribution encountered after earlier connections have been committed.
- Committing several independently decoded routes as one transaction creates
  ordering and collision ambiguity before single-route competence exists.

## First implementation slice and decision gate

Add a route-restricted observation domain, a separate CLI training command, an
online one-to-four-connection task generator, self-roll-in collection, compact
metrics and a compatible constructive checkpoint. Verify the route restriction,
potential-ledger closure and observation of committed occupancy with bounded
tests.

Run a small release-mode GPU experiment from cold initialization. Compare the
fixed held-out panel at update zero and after training. Continue to full-factory
option integration only if held-out connection success is positive across
multiple seeds and later occupancy depths are actually reached. If only the
single empty-occupancy route improves, diagnose the roll-in distribution before
increasing training duration or graph scale.
