## Question and candidates

Which observation contracts exhibit useful learning under one fixed on-policy
recipe? This is an exploratory screen, not a proof of RL convergence, a final
architecture choice or a production cutover.

The action-only arm intentionally lacks a whole-layout representation. Candidate
availability and geometry still convey state information; it is not state-free.
Geometry input retains positions, shapes, node types, orientations and occupancy,
but removes rates and relational message passing. History stores the actual
selected action's geometric descriptor and normalized compound-member summary.
Outcome variants add observed status, unchanged flag and signed current-score
changes. Historic coordinates use their original observation frame; raw IDs do
not become learned numerical categories. This is bounded action memory, not a
complete state history or a proof of Markov sufficiency.

All histories reset to empty at every episode. No future outcome enters the
observation of the action that produces it. Best and current layout use the same
encoder weights and feature schema. Input families have fixed slots; disabled
slots are zero, without a trainable candidate-ID embedding. Identical random
seeds initialize the same parameters for all candidates. Report both allocated
parameter count and disabled branches; equal allocation is not equal effective
capacity. Current-best-2 is the closest input-contract control to the prior model,
not a claim of byte-identical architecture or a resumed old checkpoint.

## Environment and learning invariants

Use the existing native acceptance/runtime, complete requests, score order,
unranked ordinary candidate vocabulary, 32-action horizon, 5000 route expansions
per action, action-kind balancing, history masking and temperature 1.

Every arm retains a validated best incumbent outside the actor for terminal
scoring and output. Removing actor input does not remove this record. The two
no-restore arms additionally exclude that action from both sampling and the
gradient distribution. Exhaustion of all permitted actions is a structured
failure, not an implicit restore, silent retry or extra action.

Freeze the existing group-relative REINFORCE recipe: four fresh episodes from one
reset under unchanged weights; lexicographic pairwise terminal-best ranks; all
selected action log-probabilities receive their episode rank; one Adam update,
learning rate 0.0003, entropy coefficient 0.001 and gradient norm clip 0.5.
Do not modify this algorithm based on early candidate outcomes. These choices are
legitimate ingredients whose adequacy remains an experiment question.

Accumulate per-episode score-function and entropy gradients while the behavior
weights are frozen, then apply relative-return coefficients after all four
outcomes arrive. This is algebraically the same group objective and avoids a
second environment/observation pass. Verify against a direct buffered objective;
floating-point addition order can differ. No optimizer step occurs before the
entire group completes. Interrupted groups retain evidence but supply no update.

## Frozen screen and evaluation

The configuration selects 12 candidates, two initialization seeds (17, 29), and
32 updates per candidate/seed: 128 episodes and 4096 selected training actions.
Four intact 23-facility resets are used: Medical/Food originals and their prepared
contraction-exhausted layouts. Each reset receives 32 episodes per candidate/seed.
This intentionally studies a manageable subset; larger layouts are not cropped.

Evaluate frozen checkpoints at 0, 16 and 32 updates with two separate evaluation
seed banks, on those four training resets and four intact 48-facility Medical/Food
original/prepared controls. These controls were opened in earlier studies; call
them held-out-from-this-training controls, not untouched prospective data.
Keep all checkpoints in the report, including regressing or flat candidates.
Compare each endpoint with its own initialization and compare the time series,
full-score wins/ties/losses, area reduction, relocation behavior, rejection rate,
wall time and sampled memory. Equal random seeds pair randomness, not identical
action trajectories when distributions differ.

This screen is smaller than a convergence study. It may identify candidates for
longer replicated training; mixed or flat results must not be reported as evidence
that a contract cannot learn. Do not select a lucky intermediate checkpoint as
the endpoint. Any promotion is a separately labelled post-screen decision.

## CLI, limits, evidence and completion

Use explicit prepare, worker, run and summarize commands with fresh output paths.
A smoke configuration exercises all contracts with reduced groups/horizon and is
never included in learning evidence. Measure it before launching the screen.
The coordinator permits up to four isolated worker processes, one CPU inference
thread each, with bounded per-job/study wall time and sampled aggregate RSS.
Source/configuration and input hashes are frozen before execution. Use a distinct
schema for model/checkpoint/report contracts; never reinterpret old checkpoints.

Retain per-group optimizer/policy/RNG checkpoints, complete episode action and
native-validation traces, score/observation/mask hashes and best witnesses under
ignored artifacts. No need to retain duplicate full observations: physical replay
from intact reset plus recorded actions verifies their hashes. Preserve partial
groups and failed runs. Emit stable diagnostic code, severity, stage, entity and
message on failure. Reject stale identities and incomplete evidence in summaries.

Completion requires semantic tests (including input isolation, history causality,
reset, shared best encoder, no-restore masks and gradient equivalence), native
smoke runs, registered comparison runs, independent replay samples across every
contract, all comparison rows and a report with limits. Run repository-required
verification and commit only completed source/configuration/findings. Preserve
the unrelated cancelled-study drafts.
