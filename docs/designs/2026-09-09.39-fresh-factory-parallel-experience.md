# Fresh factory generation and parallel experience

Status: completed with audited scaling and learning results. The user requires a newly sampled
production target, rate and initial geometry for every training episode, minimal
actor input, the existing action vocabulary and use of the experimental server.
The earlier twelve-hour proposal and interrupted fixed-reset screen stay stopped.

## Scope

First verify the generator and compare same-policy experience collection on
`ashrimp-arch`: 24 CPU cores, 64 GB system RAM and RTX 5090 with 32 GB device RAM.
Use an isolated checkout and preserve historical source trees and checkpoints.
Compare 1/2/4/8/16/24/32 worker processes with the same logical sample schedule,
fixed policy and total requested episode count. Worker count is independent of
the number of episodes in an optimizer batch. Measure initialization separately
from steady collection; count generation, validation, physical edits, policy
calculation and gradient collection in total throughput.

Run the serial semantic reference first and shuffle the remaining worker counts
with the registered order seed. Use two independent banks of 32 requested
episodes per worker count, eight policy selections per admitted episode and
one CPU Torch thread per worker. The short learning check uses two initialization
seeds, 32 updates of 32 newly drawn requests, 32 policy actions per admitted
episode, and evaluation at updates 0/16/32 on 16 separate matched generation
seeds per initialization. Each scaling or learning command has a two-hour safety
ceiling; neither command is a twelve-hour continuation.

A short learning check follows successful generation, collection parity and
native validation. It is not permission to restart twelve-hour training or a
claim that task randomization guarantees learning. Fixed-environment RL is valid;
this slice changes the task distribution to match the user's intended experiment.

## Episode generation contract

Input: an external distribution configuration, logical episode identifier,
independent generation and policy-sampling seeds, immutable runtime catalogs,
constructor/validator binaries and explicit time/facility/route-work limits.

Draw a source plan (and hence target product) from the configured pool and a new
requested throughput from its configured range. Generate complete instance wiring
and invoke ordinary downstream-closed production construction for that draw.
The pool defines the measured training distribution, not all possible game
requests. Never alter an existing graph's requirements, substitute boundaries,
crop a request or invoke the global exact solver to admit an episode.

The initial rate distribution uses a one-second grid for the requested period.
An admission probe found rounding diagnostics for arbitrary millisecond periods;
all 81 grid periods from 20 through 100 seconds passed contextual throughput for
both medical and food source plans. Keep the rejected arbitrary-period draws as
evidence. This is an explicit sampling distribution, not a repair of that numeric
limitation or evidence that arbitrary rates are supported.

After complete independent graph/geometry acceptance, sample a bounded sequence
of ordinary native edits to vary initial geometry. Sample operation kinds and
their offered arguments using the generation RNG, without a learned policy or
improvement-based selection. Retain the final valid current layout as the episode
start; reset best-incumbent bookkeeping to that start. Generation steps do not
enter policy gradients or the policy action budget. The subsequent actor retains
all ordinary actions, including restore-best.

Generation uses the existing basic/local pose proposal option to bound setup
cost. The learner still uses the ordinary full compound vocabulary. Report this
generator prior explicitly; varied starts do not imply uniformly random geometry.
Draw two through six setup edits per request. The initial server timing probe
found about 2.3 through 10.7 seconds for two setup edits on its medical/food
samples; choose this bounded setup distribution before the full run and retain
all setup time in throughput accounting.

Every requested episode runs generation afresh. Do not cycle a saved layout pool
or call a new action RNG a new factory. Fresh independent draws can repeat;
report unique request, rate, geometry and facility-count coverage rather than
assuming uniqueness. Geometry identity must exclude flow-rate-only differences.
Record setup edits and generation failures, including their timing and original
draw. Invalid/incomplete factories never become training episodes. Do not hide
failed generation attempts by silently substituting a fixed successful layout.

Output: source plan, original wiring obligations, validated request and initial
witness, generation trace, seed identities, factory/geometry hashes, timings,
admission status and structured diagnostics. Retain actual generated inputs;
seeds alone are not sufficient evidence or recovery state.

## Actor, collection and learning contract

Use the tested action-only observation: candidate descriptors and compound-member
geometry plus basic episode context. No full current map/graph, best record or
action history enters the actor. Preserve the ordinary candidate vocabulary,
history mask, action-kind balancing and native acceptance semantics.

Each worker owns its runtime, RNG and episode state. Policy weights stay fixed
through an entire collection batch. Reassemble results by logical episode order,
not completion order; do not let faster factories contribute extra samples.
Bind every result and gradient payload to the exact policy and generated inputs.
Changing worker count must preserve generated factories, selected actions, native
outcomes and the assembled optimizer update for a fixed schedule on one server.

Different factories must not be ranked by raw terminal area. For the short
learning check, compare each terminal best with its own initial score and use
the lexicographic tuple of fractional area, transport-tile and turn changes.
Use exact rational comparisons when deriving group-relative ranks. This retains
the score priority within each request and makes cross-request scale explicit;
different task difficulty remains a source of variance. Preserve the existing
episode score-function/entropy objective and Adam settings. Report this changed
return normalization and batch size; do not call the new study a one-variable
causal test of data diversity.

Evaluation uses independently declared generation seeds and initial/checkpoint
policies on matched freshly regenerated starts. Training never consumes the
evaluation draws. Keep all scheduled evaluations, including flat or regressing
ones, and distinguish performance from positive relative-return frequency.

## Limits, diagnostics and acceptance

Use explicit subcommands for preparation, collection, scaling, learning and audit.
Keep worker/task/wall/RSS limits and signal cleanup for owned process groups.
Failures carry a stable code, severity, stage, entity and readable message.
Incomplete collection cannot supply an optimizer update. Preserve interruption
evidence and complete checkpoints. No automatic restart of cancelled studies.

Acceptance requires fresh generation evidence, independent initial/best validity,
serial/parallel semantic and update parity, measured throughput and sampled RSS,
target/rate/geometry diversity, all rejection denominators and a bounded learning
check with checkpoint evaluation. Run repository verification and document the
server source/native identities and remaining limitations. Commit source and
concise findings; keep generated factories, traces, gradients and checkpoints in
ignored artifacts. Clean regenerable intermediates only after required inputs,
selected evidence and summaries are retained.
