# Game Data Normalization

## Scope

The repository stores an identified extracted game-data snapshot under `data/game/source/` and deterministic solver-facing catalogs under `data/game/normalized/`. The normalizer is a data preparation boundary, not part of the spatial solver.

## Flattened Facilities

`FactoryMachineCrafterTable` maps each machine recipe group to a mode. Every machine-mode combination used by `FactoryMachineCraftTable` becomes a dedicated facility:

```text
furnance_1 + normal -> furnance-1-mode-normal
furnance_1 + liquid -> furnance-1-mode-liquid
```

Recipes directly reference these IDs. The normal variant exposes belt ports used by normal recipes. The liquid variant exposes the belt and pipe directions used by its mixed solid/liquid recipes. No mode variable reaches the solver.

## Fixed Transport

Factory item phase type establishes transport:

- solid phase `1`: belt;
- liquid phase `2`: pipe;
- gas phase `4`: pipe.

Source port `isPipe` independently establishes port transport. Routing must later require the item and both endpoint ports to match.

`FactoryGridBeltTable` and `FactoryLiquidPipeTable` establish exact transport capacities. The normalizer writes one belt capacity of 1 unit per 2000 milliseconds and one pipe capacity of 1 unit per 500 milliseconds to `transports.json`.

## Coordinates

Source building `range.width` and `range.depth` become the facility footprint. Source port position `(x, z)` becomes normalized `(x, y)`. The boundary coordinate establishes north, east, south, or west. All generated facility and port records pass the strict facility catalog validator.

## Recipe Planning

Machine recipes retain quantities and use `progressRound * 1000` as duration milliseconds. Multiple producers and cycles are legal catalog data. Multiple producers become explicit planning ambiguities when traversed. Cycles are preserved for steady-state material-balance planning. External input cutoffs can stop before either condition.

## Reproducibility

The generator sorts source records and normalized collections. Repeated generation from the same source snapshot produces byte-identical catalog hashes recorded in `data/game/normalized/manifest.json`.
