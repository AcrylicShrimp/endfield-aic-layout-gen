# Interface-first frontier assembly

Start from validated SCC source-bank alternatives and a complete incumbent. Unlike the
occupied-only control, do not rigidly pack every source before assigning the common
downstream interface. Discover currently input-closed belt consumers from the graph and
group only the source regions that jointly supply those consumers. Unrelated regions
remain separate and unchanged. Group counts are graph-derived, not fixed at two.

For each active group, jointly choose source-region pose/packing, target order and ports,
then instantiate the shared catalog-backed branch/merge/permutation interface. Route the
new frontier immediately and independently validate the resulting compound region.
Retain a bounded set of envelope alternatives with identical membership. Unselected
regions are never duplicated or used as fake external sources.

Rigid source poses rotate all facilities, ports, transport cells/segments/terminals and
logistics component orientations together. Only runtime-allowed rotations are candidates.
The existing structured interface has an explicit east-facing free-ray domain. Screening
a pose outside that domain is not proof of a game-level impossibility. Record exclusions.
For the first control, choose either the least- or most-extended source cut with a valid
pose. Include the independently rechecked retained parent as a lookahead alternative;
otherwise an existing dependent cycle may be mistaken for an impossible seed boundary.

Every accepted compound must preserve exact pending margins, unused port capacity and
closed-pocket access. Preserve an east-facing future interface for later structured
composition. A failed group retains its last validated banks; it does not discard other
accepted groups. Stop a wave with no accepted growth and report its exhausted frontiers.

When no further supported belt frontier can be grown, pack the remaining concrete
regions using explicit shelf/occupied alternatives, then try the existing mixed-input
closure and true external-boundary stage. This handoff is a measured restriction, not
a claim that generic mixed-transport structured interfaces have been implemented.
Accept a new factory only after complete independent validation and a better full
area/physical-transport/turn tuple; otherwise retain the complete incumbent. Report new
construction completion separately from incumbent retention.

This is a bounded JavaScript research control with real graph/catalog inputs, immediate
physical wiring and native rendered evidence. It is not a Rust production cutover,
global optimum or infeasibility proof. Source cut/pose and interface planning are
heuristics. Recipe breadth, whole-factory compactness and later product stages stay open.

## Commands and evidence

`run.mjs` accepts explicit graph, region-inventory, complete-incumbent, five catalog,
validator and fresh output-directory paths. Controls are `--source-cut min|max`,
`--shape-limit 1..16`, `--packing-limit 1..16` and `--route-family simple|perimeter`.
The shape limit is also the occupied-packing beam width; these are diagnostic budgets.
Equal-size alternatives of one selected source cut must have identical membership.
An unsupported source boundary or inconsistent membership is a structured failure,
not permission to omit an obligation.

`report.json` separates the retained `selected_directory`, `best_new_directory`,
`newly_complete`, source exclusions, checked wave candidates and mixed-input closure
attempts. Per-candidate files preserve witness, independent validator/process report,
graph coverage, pending interface and native HTML. A top-level `failure.json` includes
stable code, severity, stage, message and optional entity. Stdout is one short completion
record, never the candidate history. Source hashes are captured before execution.

`summarize.mjs` checks current construction hashes, repeat-run complete witness hashes
and original-graph audit identity before emitting compact source-cut/refinement evidence.
Full trial histories remain in the explicit output directories; they are not duplicated
in the compact summary. Crossing dimensions from old composition metadata are labeled
pre-compaction templates, never measured dimensions of a subsequently refined witness.
