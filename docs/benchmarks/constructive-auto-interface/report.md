# Geometry-free automatic interface construction

Historical exclusive-port baseline at `e4de275`. Current implementation and DTOs are described in
`tree-report.md` and `contract.md`; reproduce this baseline from that commit. Its retained matrix
is unchanged. In particular, the former `port-pressure.json` request now succeeds through trees.

## Outcome

The common JavaScript constructor takes recipe instance IDs and exact utilizations only. It
chooses compatible pair flows, capacity lanes, bank order, catalog rotations, positions, port IDs,
approach bends and residual crossing modules. Input geometry fields are rejected. The existing
`buildDedicated` helper now also lowers **generated** specifications; the original explicit
fixtures remain manual baselines. Neither Rust production construction nor routing semantics changed.

Eight positive local requests pass the unchanged optimized Rust witness validator with complete
recipe-terminal coverage. A port-pressure control fails at its intended stage, and removing the
automatic four-facility candidate's bridge is independently rejected as a transport collision.
All ten audit expectations pass. No full heavy-xiranite graph has been generated by this experiment.

Timings are local observations, not service-level guarantees. Construction includes allocation,
ordering, placement and route lowering, but excludes catalog IO, output serialization, process
startup, validation and rendering. Fresh-process values are one observation per child process.
Warm values are medians of 20 in-process runs after a discarded run, with shared loaded catalogs.
The audit stores minimum and p95 too. JS has no Rust debug/release switch; validation uses
`target/release/aic-witness-probe`. The separate workspace checks use normal dev/test profiles.
The matrix ran on the development machine; it is not a CPU-isolated benchmark.

The former fixed full-rate five-facility example used 35 x 22 and 157 tiles; automatic construction
uses 20 x 16 and 71 tiles at the same instance utilizations, with zero bridges. Both facility
positions and route geometry change in this comparison. It is not an isolated estimate of the
benefit of port ordering. The symmetric A0/A1 suppliers may exchange roles without changing margins.

## Method and verification

Per item, monotone exact allocation preserves all terminal margins and stable same-item lane order.
The bounded bank insertion search reallocates flow on every trial. It prioritizes avoiding port
pressure, then lane inversions, then lane count; this is a local interface-order proxy, not the
production area-first score or an optimality proof. All tested runs finish below 512 order trials.
Ports follow opposite-bank order. Strictly monotone approaches use distinct bend columns; 3,136
endpoint-sequence pairs test mixed upward/downward shifts without shared cells.

Zero-inversion candidates use a single ordered corridor. Others use the previously tested
permutation primitive, planned before lowering, between ordered approaches. The independent
validator checks actual facilities, rates, component arms, global external boundaries and complete
recipe coverage. Construction detail remains explicitly unaccepted until the separate report gate.

Twenty-one Node tests pass across automatic interfaces, fixed binding fixtures and permutation
modules. `cargo check --workspace` passes and `cargo test --workspace` passes all 524 tests with two
existing ignores. No new dependencies or Rust edits. The shared renderer now identifies internal
commodity colors by actual facility-to-facility networks rather than special example node IDs.

Actual four/five-facility, three-consumer and sixteen-facility screenshots were inspected. Each
passes six width/theme browser checks. The port-pressure logical diagram was also inspected and
passes six browser checks. It is explicitly not a placement or physical routing witness.

## Next bottlenecks

`port-pressure.json` retains the same two suppliers and total throughput as the four-facility
example, but divides consumption among four instances at 1/4 utilization. Each supplier needs
four dedicated pair lanes, while its selected catalog face has three output ports. Fifteen
bank-order trials cannot change that degree. Aggregate rate is **not** the problem: supplier A
has 1/s, B has 1/2/s, and each output lane carries up to 1/2/s. A could export on two lanes and B
on one if the constructor synthesized capacity-aware downstream splitter trees. The current
dedicated-port contract cannot express that sharing. This is not global infeasibility.

The next functional slice should synthesize same-item split/merge trees **before** permutation
embedding, retaining exact rates and catalog port/component capacity. Do not add duplicate
facilities or silently alter utilization to bypass this case. External multi-lane residuals,
pipes, multi-output producers, cycles and full-graph composition are still explicit scope limits.

Visual inspection also exposes an efficiency issue: independent replicated groups share one
large permutation envelope and every lane crosses the width of all serial swap stages. The
sixteen-facility image has four isolated interaction groups but stretches them across a 71-cell
width. Partitioning independent groups and packing their interfaces is a separate follow-up;
it does not resolve the four-consumer port-pressure failure.

## Reproduction and artifacts

From the repository root, use a new output directory on every run:

```sh
node docs/benchmarks/constructive-auto-interface/run.mjs \
  --request docs/benchmarks/constructive-auto-interface/five.json \
  --recipes data/game/normalized/recipes.json \
  --facilities data/game/normalized/facilities.json \
  --items data/game/normalized/items.json \
  --transports data/game/normalized/transports.json \
  --components data/game/normalized/logistics-components.json \
  --validator target/release/aic-witness-probe \
  --output-directory target/auto-interface-reproduction
```

Use `audit.mjs` with the same catalog/validator/output flags and without `--request` for the matrix.
Detailed witness, validation, generated decision geometry and HTML files stay in its output tree.
`matrix.json` retains measurements, failure evidence, catalog/executable hashes and request/witness
hashes. CLI stdout remains one completion line; subprocess output is written to a dedicated log.

Tailnet pages on the existing port-8765 server: `bound-interconnect-auto-five.html`,
`bound-interconnect-auto-four.html`, `bound-interconnect-auto-fanout-three.html`,
`bound-interconnect-auto-sixteen.html`, and `auto-interface-pressure.html`.
