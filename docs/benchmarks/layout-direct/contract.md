# Dynamic-factory direct-action learning contract

Status: replacement experiment contract; no learned benefit or readiness claim.

## Why this is a different experiment

The user clarified that fixed-root action and learning pilots are useful prerequisites, but
must not replace the desired general layout learner. `layout-sequential` is retained only as
a measured baseline. Candidate selection versus direct proposal is a design choice serving
the goal, not the goal itself. Do not increase the old pilot's
training budget as a substitute for this contract. Do not relabel its categorical candidate
index as a direct action, or randomly select its old roots and call that dynamic generation.

The target remains diverse complete factories, low futile-action rates, and visually audited
Heavy Xiranite empty XY area at most 1%. Those requirements have not been achieved.

## Dynamic production problem DTO

Input: freshly loaded catalogs, sampling-policy version/hash, stream seed, sample ordinal,
training/development/sealed-test partition, source-node and instance-count operational guards,
and construction budgets. No built-in product/recipe list, topology template or stored root
corpus determines training environments. The target-replay fraction, if any, is explicit and
reported separately; it cannot count as novel environment exposure.

Sample a target item and one of its producing recipes from the runtime catalog. Sample the
requested rate and upstream producer alternatives. Every active input is recursively sourced;
repeated ancestor recipes remain explicit cycle references for the existing exact material-flow
checker. Keep co-products and original surplus obligations. External procurement is limited by
the declared sampling policy before geometry exists, never introduced to rescue construction.
Do not filter to single-output, belt-only, acyclic, easy-to-route recipes or a short family list.

Output per attempted sample: replayable original source-plan request, source-choice trace,
recipe-structure fingerprint, exact facility-instance wiring or structured graph failure,
construction report, complete independently validated initial witness or structured construction
failure, and separated sampling/flow/construction/validation costs. Source-plan or instance guards
reject the whole attempted request; they must not crop it or replace its dependencies externally.

Freshness is semantic, not an incrementing ID: measure distinct requested recipes, targets,
source structures, rates and production graphs. A duplicate does not become a new environment
by translating geometry or renaming instances. Bounded retry/rejection counts and failure strata
must accompany every accepted training episode, so hard factories cannot disappear invisibly.
Generate held-out target-family partitions before drawing training requests; additionally reject
cross-partition equivalent production graphs. Never use sealed evaluation failures for tuning.

Training may use several independent trajectories on the same newly sampled request to estimate
terminal comparisons. Each such group is a fresh generated problem, not a draw from fixed saved
roots. Save all generated requests for audit/replay, but do not make this audit log the generator.

The initial stream policy uses the source-plan API's explicit procurement of any non-root
catalog item, chosen before geometry with probability 0.25. This is not a claim that every
intermediate is a naturally mined raw material. It defines the requested factory's purchased
inputs. One producer/procurement choice per item per request limits random bottle-recycling
permutations; occurrence-specific choices remain a separately configurable distribution. Root
targets always use a recipe. Record these distribution choices with each generated request.

## Initial complete-factory contract

Use connected transactional construction and original-margin plus independent geometry checks.
Route each newly added frontier or closed dependency transaction before expanding it again;
do not globally place all facilities and defer routing. The existing small tree constructor is
not a general backend. Unsupported SCCs, mixed transport, reconvergence or boundary closure must
produce an explicit failure. A partial layout cannot be an RL reset state for this experiment.
Before training, measure which sampled graph strata the selected constructor actually completes.
There is no automatic fallback to old stored witnesses, simpler source requests or exact search.

## Direct action DTO

The policy emits an operation and its parameters conditionally, for example:

- `relocate`: a model-selected connected facility set and a common integer displacement;
- `pose`: a facility, an allowed catalog rotation and an integer destination;
- `port`: a terminal and compatible catalog port;
- `reroute`: a network/chain selection and declared repair-order parameter;
- `compact`: one explicit whole-grid event-free-strip contraction;
- optional terminal `stop`, with zero-action outcomes reported rather than hidden.

No environment method returns a list of fully specified candidate mutations. Entity IDs,
allowed operations, catalog rotations, ports, coordinate ranges and sound partial-choice masks
are action vocabulary, not a geometry-ranked shortlist. The model chooses coordinate values
and group members; code must not choose likely destinations, contact poses or good groups for it.
Masks may enforce game legality or explicitly scoped execution guards, but may not use routing
outcomes, validator results, score gains or unproved heuristics as inference-time information.
Charge mask/encoding work. Invalid complete proposals remain charged transitions with reasons.

Expose exact body/belt/pipe/component occupancy, ports and transport direction, rates and
production graph information needed to distinguish routing situations hidden by box summaries.
Version the observation contract. Entity ordering must not encode historical solution labels.

The executor repairs the emitted mutation pipe-first and validates every committed candidate
against the unchanged original production request. Current exploratory state may worsen; the
best timely validated witness is separate and only improves in the exact configured score order.
Failed, late or invalid proposals cannot corrupt either retained witness. Multi-phase mutations
validate phases independently. Expansion/reboundary behavior needs an explicit executor contract;
the old kernel's frozen current-extent/external-anchor restriction must not become a game limit.

## Learning and evidence contract

Train actual multi-step trajectories long enough to cover the tested delayed effects, with
curriculum and target replay exposure recorded. Terminal lexicographic comparison is the first
control signal; value baselines, imitation or reward shaping must be separately specified and
measured, not silently added. Policy-update, task-gradient and prediction-change checks only
prove that optimization ran, not that a useful strategy was learned.

The minimum end-to-end evidence is a streaming reset -> direct proposal -> repair -> validation
-> reward -> optimizer update -> new generated reset, followed by untouched problem evaluation.
Compare trained policy with its exact initial weights and a uniform direct-proposal policy,
using common generated evaluation requests, explicit per-root random streams, and matched selected
action, routing-work and elapsed budgets. Distinguish generation benefit, action freedom, model
representation and actual learned selection. Report failures, duplicates and preprocessing cost.
Require repeated seeds and uncertainty estimates before calling a training method effective.

## Implementation order and stop points

1. Implement the catalog-wide seeded source-plan stream and audit exact wiring diversity/failures.
2. Connect a general transactional constructor; measure acceptance bias before claiming an RL
   environment stream. If it cannot provide the required strata, fix construction or report that
   blocker, not an easier hidden dataset.
3. Implement direct conditional action decoding and its executor/observation invariants.
4. Run a small genuine streaming training/control experiment, then longer training only when the
   learning problem and measurements are credible. No product integration until learned evidence.

This ordering is a sequence of verifiable prerequisites, not a replacement of the original goal
with source sampling, action generation, or a single successful factory.
