# Link-aligned group coalescence and bridge release

Input: a complete validated factory, runtime catalogs and normalized original graph.
Two disjoint terminal-closed facility groups (at most sixteen total facilities) may
receive different translations in one schema-3 transaction. Derive their relative
offset from actual directed terminal connectivity, not facility labels or recipe IDs.
Try adjacent connected terminal positions, then translate the combined occupied shape
against existing body contacts within the explicit incumbent-extent neighborhood.
Do not preserve obsolete relative group order or require an exchange of their origins.
Screen actual bodies and retained terminal ownership; final acceptance requires complete
restoration, independent original-graph validation and a better area/cells/turns score.

Existing bridges along affected paths may be explicitly released (bounded unique IDs).
Only catalog bridge components qualify, never splitters/convergers. Remove membership
from their owners in a private draft, suppress the old cross-network coincidence anchor,
and rebuild every incident directed chain. Preserve terminal identities, rates and
required logical reachability. The old crossing coordinate is no longer a waypoint.
Restore legal intersections through the existing catalog-backed new-bridge route engine.
The accepted factory may contain fewer, relocated or newly necessary bridges; a removed
bridge without successfully restored owner paths must never be promoted.

Diagnostics: release IDs, affected chains, candidate family, body-envelope proxy,
bounded enumeration counts, repair failures, full score and validation evidence.
Report bridge-retained controls separately. No global infeasibility or optimum claims.
Do not promote a smaller body envelope without the complete routed factory. Native
renders must be inspected, including a representative failed candidate if repair stalls.
This is research-only transactional improvement, not a placement-first production cutover.

The CLI selects `--move-family coalescence --bridge-policy retained|release`, with the
normal complete-graph/catalog/validator arguments. The current release proposal scope
is bridges on collapsed owner paths incident to either selected group. A 250,000-pose
enumeration ceiling and 32 valid positions per pair/direction are explicit research
budgets; this is not an exhaustive pair-packing claim. Chain IDs and explicit routing
priorities refer to the post-release decomposition, also used by diagnostic replay.
New bridges do not recycle a component ID removed in the same transaction.

Bridge-release validation includes a standalone audit: unchanged complete input,
unrestored removed-bridge negative controls and independently restored positive controls.
These controls do not promote a new incumbent merely because reembedding succeeds.
