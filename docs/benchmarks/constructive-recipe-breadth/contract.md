# Complex-recipe breadth gate

Status: in progress.

## Inputs and invariants

Exercise additional runtime-catalog recipes from explicit schema-1 source plans,
not modified heavy-xiranite witnesses. Preserve the existing independently validated
heavy-xiranite incumbent. Begin with enriched bottled food, enriched medical supplies
and a tier-three battery: these combine multiple inputs, plant return cycles and
mineral or container processing. Include a mixed belt/pipe recipe if the source
hierarchy and existing constructor support it.

Produce each original facility-instance wiring graph through the existing Rust CLI.
No fabricated external substitutions, omitted inputs, facility-only global placement,
relaxed capacity, or reuse of another recipe's witness is allowed. Source selections
are explicit test data; they are not built-in game defaults. Ambiguity, unsupported
structural shapes and exhausted construction bounds must be reported, not hidden.

Assess which existing constructive stages can run from these inputs without a
previous heavy-xiranite geometry artifact. Define the missing stage contract before
implementing it. Structural interfaces should remain runtime-recipe-independent.
Use bounded independent workers where work can safely overlap.

## Outputs and completion evidence

### From-wiring region construction

The new runner accepts successful schema-1 facility-instance wiring plus the five
runtime catalogs and independent validator. It projects graph identities and exact
margins without creating any placement-only geometry artifact. Initial regions are
supported productive SCCs or a single facility with only declared external inputs.
Each region is independently validated. Add one ready consumer to exactly the regions
supplying it, route all newly internal inputs, validate the connected union, and then
commit that union while leaving unrelated regions unchanged. Never place the whole
facility set before routing internal dependencies.

During this explicit internal-region stage, only original external input demands and
outgoing original graph cuts may remain pending. Missing internal inputs, substituted
external identities, excess rates and invented cuts remain invalid. This is distinct
from the existing closure stage that has already connected external inputs; its
default validation contract must not change. A pending-external-input region cannot
be reported as a complete factory.

After one connected region contains all original facilities and all internal margins
are routed, realize the actual external inputs/exports at the used boundary. A private
one-cell translation provides a boundary routing margin; no caller canvas constraint
is introduced. Enumerate all four boundary sides, pipes first, and validate every
terminal against the original graph. Publish only a complete independently validated
factory, or report the retained valid internal region and the exact failed boundary.

Bounds: at most 256 input facilities, four initial-candidate validator workers, 256
growth transactions, 128 ordering trials per composition, and finite existing
corridor templates. Bounds limit this experiment, not game or production dimensions.

For each case report input/source hashes, requested rate, instance/edge/cycle counts,
construction stage status, independently validated covered membership, full-factory
acceptance or structured failure, used area/cells/turns and separated timing.
Any accepted complete witness must pass both Rust geometry validation and original
graph margin/external-identity coverage. Partial or unsupported cases are not success.

Inspect the actual full and focused render for each completed construction milestone.
Record controls, tests and reproduction commands in the report. Breadth evidence does
not claim minimum area, universal recipe coverage, a production cutover or completion
of the eventual web workflow.
