# Native Catalog, State and Snapshot Ownership

Status: first migration milestone implemented, 2026-09-08. Normal training remains on the
existing environment until the candidate, transition and observation milestones pass parity.

## Contract implemented

`aic-pilot-native` now loads the case and its external facility/recipe/transport catalogs itself.
It retains typed root, draft, working-base and episode-best layouts, scores, episode accounting,
traces and cumulative counters. Case order remains the category/terminal order. Exact production
obligations and belt capacities use arbitrary-precision rational arithmetic, with bounded integer
JSON inputs and no floating-point acceptance comparisons. Facility catalog schema 3 and recipe/
transport schema 1 match the tracked runtime inputs; these versions are schema contracts, not
embedded game data.

The explicit `Engine.open(root, case_path, environment_config_json)` API admits the root through
native acceptance. `metadata_json`, `export_layout_json`, `export_state_json`, `restore_state_json`,
`check_layout_json` and `reset` expose setup, snapshot and diagnostic operations. JSON is confined
to these cold operations; no per-action training boundary is introduced by this milestone.

Native acceptance independently rebuilds footprint occupancy, rotated port locations, directed
arms, actual used bounds, terminal roles/port use, path degree/reachability and the area/tile/turn
score. It shares typed schema/geometry primitives with mechanical validation but does not consume
cached edit conclusions or serialized validity flags. It preserves the existing directed-path
pilot scope and does not invoke the constructive planner or global research solver.

Snapshot schema 2 includes native engine version 1, SHA-256 input provenance, root identity,
environment configuration, all three mutable layouts, scores, counters and traces. Restore checks
provenance/accounting, mechanically validates the draft, and independently accepts base and best
before committing any mutation. Scores are recomputed. Failed restore leaves every live field
unchanged. Successful restore increments the generation; reset clears episode state while keeping
cumulative performance counters. Candidate handles will consume the identity/generation/revision
contract in the next milestone.

## Verification and explicit limits

Seven native boundary tests compare initial exports, the six-command improving witness, partial
draft snapshots, all four bound-port rotations, negative and large translations, reset/counter
ownership, and failed-restore atomicity. Individual acceptance failures cover inventory, collisions,
rotation, duplicate cells/edges, incomplete paths, unbound/boundary terminals and port roles.
An equivalent large rational request is accepted; a one-unit numerator perturbation that rounds
away in float64 is rejected as a coverage mismatch. Zero denominators, missing files, noninteger
coordinates and integer overflow produce explicit failures.

Local release-extension Python verification passes 33 tests, with three platform/CUDA tests
skipped. `cargo fmt --all`, `cargo check --workspace`, `cargo test --workspace`, and artifact
worktree/index checks pass. Reproduce the native tests with the release build command in the pilot
README and `AIC_NATIVE_LIBRARY=<absolute-release-library> <venv-python> -m unittest discover
-s tools/factory-edit-pilot -p test_native_engine.py -v`.

Native DTO integers are signed 64-bit; geometry and score arithmetic checks intermediate overflow.
Malformed typed DTOs use `layout.malformed` rather than reproducing Python exception wording.
Where several independent violations coexist, the native checker uses case order and ordered cells;
Python's dictionary/set traversal may report a different first violation. Accepted layouts and the
reachable witness diagnostics agree. This is not a claim of arbitrary malformed-input text parity.

Root path expansion and individual facility materialization are admitted against the configured
work guard, with `input.resource_guard` on exhaustion. These are operational failures, not factory
infeasibility or game dimensions. Restoring already materialized geometry does not impose a raster
bound, so an interrupted draft can be restored even if its next observation would exhaust that
guard. Candidate generation, native array assembly and training cutover remain subsequent work;
this milestone makes no runtime speedup claim.

## Architecture review

Compared with the observation-only trial, Rust now owns the authoritative factory state and loads
its own catalog inputs. Snapshots no longer require Python to rebuild native geometry on each
future action. The constructive planner design and `AGENTS.md` remain unchanged: this is an explicit
learned local-edit pilot over complete admitted factories, not a new construction algorithm or a
fallback around exact research. No generated layouts, binaries, traces or benchmark outputs are
added to Git.
