# Entity failure completion diagnosis

Status: retrospective training-case diagnosis of the two audited seed-17 streams,
followed by a deterministic repair-witness replay. No new policy inference, training
or development/held-out evaluation was performed.

At the final scheduled checkpoint, every failed translated-improvement episode
issued a placement command, and every command in those episodes applied mechanically.
Most failures never completed a changed valid layout. This narrows the next diagnostic
to completing edits after placement, rather than merely inducing placement actions.
It does not identify the learning cause or establish convergence.

| Failures with no changed valid completion | 15 | 43 |

`SET_PLACEMENTS` counts issued commands, not necessarily a net translation. All-applied
accounting excludes rejected commands in these episodes, but does not prove each
placement changed coordinates. `new_completion` means the accepted draft differs
from the previous accepted base (`transition.rs`); it does not mean a new global best.
The eight failures with completions therefore cannot be called reconnection failures
from counters alone. Exported best layouts remain independently validated incumbents.

Among failed width-one episodes, the first acceptance diagnostic was `network.degree`
on 815 commands and `terminal.unbound` on 1189 of 2176 commands. Width two had 3300
and 2314 respectively out of 6272 commands. These are repeated state observations,
not independent defects or exhaustive diagnoses: acceptance returns its first error.

## Concrete retained trace

Width-two battery gap-zero rotation-two has a failing upper-median episode. Its
saved `evaluation-3145728-representative-trace.json` contains 128 commands:

- Command 1 discards the draft and has an unchanged valid base.
- Command 5 applies placement `F = [-2, -14, 180]` after unbinding terminals and
  erasing transport.
- No later command completes a valid factory. The remaining work includes transport
  extension/erasure, terminal rebinding and connection commands.
- Final acceptance reports `terminal.unbound` for `glass:target`. The best exported
  area remains 133, as recorded in the audited median result.

This trace is a retained median, not a sample drawn to represent all failures.
It shows an actual incomplete reconnection sequence; episode counters alone do not
establish its ordering or prevalence elsewhere. The trace records 44 extensions,
36 erasures, 16 unbindings, 15 bindings, 15 connections, one placement and one discard.

### Exact repair witness from the failed prefix

Follow-up at source `490a029`: replay the first five policy commands, including the
move, then apply witness commands 1, 4, 7, 8 and 9 (one-based indexing). These unbind
the external quartz source, erase its old tile, bind the furnace input and output,
and bind the quartz source at the new boundary. No further placement is needed.

All ten commands belong to the reference candidate domain and mechanically apply.
Native and reference draft geometry, outcomes and rewards agree after every command.
The final layout exactly equals the previously audited witness, with score
`[119, 12, 1]` from initial `[133, 14, 1]`. The selected facility moves from
`[-2, -16, 180]` to `[-2, -14, 180]`; all other facility poses remain unchanged.

Thus this particular failure is not an unroutable placement: a five-command suffix
completes the exact draft reached by the policy. The 128-command allowance could
contain that sequence. This is an existence witness, not evidence that the policy
can discover it, that all failures have this cause, or that a compound-action policy
will learn better. Commands were selected by a human-authored witness, not a router
or learned policy; do not add this result to any policy success count.

Retained local artifacts: `artifacts/factory-edit-pilot/selected-repair-witness/`
contains `result.json` (input hashes and native build provenance), `trace.json` and
`layout.json`. Reproduce the core replay with the local virtualenv Python and
`PYTHONPATH=tools/factory-edit-pilot`; use the platform's release native library:

```python
import json
from pathlib import Path
from native import Runtime, layout, check
from reference.acceptance import Catalog, check as reference_check
from reference.environment import Environment, serialize

root = Path.cwd()
directory = root / 'artifacts/factory-edit-pilot/entity-learning/width2-seed17/train-battery-four-gap0-turn2'
case = root / 'artifacts/factory-edit-pilot/generated-chains/train-battery-four-gap0-turn2.json'
read = lambda name: json.loads((directory / name).read_text())
config = read('metadata.json')['config']
engine = Runtime(root, case, config, root / 'target/release/libaic_pilot_native.dylib').new_engine()
catalog = Catalog(root, case)
reference = Environment(catalog, config)
prefix = read('evaluation-3145728-representative-trace.json')[:5]
witness = read('witness-trace.json')
actions = [r['command'] for r in prefix] + [witness[i]['command'] for i in (0, 3, 6, 7, 8)]
for command in actions:
    assert command in reference.candidates().to_dicts()
    native_result = engine.diagnostic_step_json(json.dumps(command))
    reference_result = reference.step(command)
    assert native_result[2]['applied'] and reference_result[2]['applied']
    assert native_result[0] == reference_result[0]
    assert native_result[2] == reference_result[2]
    assert layout(engine, 'draft') == serialize(reference.draft)
assert layout(engine, 'best') == read('witness.json')
for result in (check(engine, layout(engine, 'best')),
               reference_check(catalog, serialize(reference.best))):
    assert result['valid'] and result['score'] == [119, 12, 1]
print('Validated five-command repair from the exact failed prefix')
```

## Interpretation and next diagnostic

Both final scheduled mean success rates and mean median area ratios are their best
observed values, after substantial intermediate regressions. See
[the paired curves](2026-09-08.36-first-capacity-pair-results.md). Neither plateau nor
generalization failure is established. Sixteen training geometries across two chains
provide narrow structural diversity despite millions of sampled actions.

Complete the frozen remaining streams. A subsequent bounded intervention should
distinguish whether a placement leaves a routable local repair, and whether the
policy can finish that repair within its allowance. A dedicated bounded rerouting
oracle can be diagnostic evidence; it must not silently supply uncharged work to
the existing policy result. Failure within its bound is not proof of unroutability.
If comparing compound relocation/reconnection actions, charge routing costs and
validate the entire transaction before replacing the incumbent.

Dataset expansion remains a separate plausible intervention. Hold model/action/reward
contracts fixed when comparing it, and distinguish equal total work from adequate
per-case exposure. This report does not choose a larger dataset, macro action or
from-scratch construction policy based on unmeasured benefit.

## Reproduction and provenance

Inputs are the retained full `width1-seed17` and `width2-seed17` directories under
ignored `artifacts/factory-edit-pilot/entity-learning`. Their source, metadata and
independent audit hashes are recorded in reports 33 and 36. The following read-only
command reproduces the main counts; it opens training-case records only:

```sh
python3 - <<'PY'
import collections, json
from pathlib import Path
root = Path('artifacts/factory-edit-pilot/entity-learning')
for width in (1, 2):
    counts = collections.Counter()
    paths = sorted((root / f'width{width}-seed17').glob('train-*/evaluations.jsonl'))
    assert len(paths) == 16
    for path in paths:
        rows = [json.loads(line) for line in path.read_text().splitlines()]
        initial = next(row['score'][0] for row in rows if row['commands'] == 0)
        final = [row for row in rows if row['commands'] == 3145728]
        assert len(final) == 32
        for row in final:
            counts['episodes'] += 1
            if row['score'][0] < initial and row['translated_facilities']:
                continue
            c = row['counts']
            counts['failures'] += 1
            counts['placement_command'] += c.get('SET_PLACEMENTS', 0) > 0
            counts['all_applied'] += c['applied'] == c['commands'] == 128
            counts['no_changed_completion'] += c.get('new_completion', 0) == 0
            counts['area_only_improvement'] += row['score'][0] < initial
            for key in ('commands', 'network.degree', 'terminal.unbound'):
                counts[key] += c.get(key, 0)
    print(width, dict(counts))
PY
```
