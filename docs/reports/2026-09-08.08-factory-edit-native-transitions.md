# Native Candidate and Transition Parity

Status: second Rust migration milestone implemented, 2026-09-08. The native engine owns the
complete edit transition path; observation assembly and normal training cutover remain next.

## Implemented boundary

`Engine.candidates()` retains the typed command domain and geometry index and returns only an
opaque handle plus its size. `step(handle, index)` performs the selected edit, mechanical checks,
independent acceptance, base/best promotion, reward, horizon and trace accounting in Rust. No
whole-state Python conversion is needed. Explicit candidate JSON export and JSON command replay
are diagnostic operations. All seven existing operations retain their domains and behavior.

Candidate sort keys exactly reproduce Python's `JSONEncoder(sort_keys=True)` separators and
ASCII escaping, including control characters, DEL and supplementary Unicode surrogate pairs.
The native command representation preserves facility assignment order for subsequent feature
encoding. A bounded 4,096-entry LRU stores only pure sort keys. Its eviction cannot alter domain
membership or ordering. It retains entries across episode reset, as before.

Opaque handles include engine identity, generation and state revision. A foreign/stale handle
or out-of-domain index is an uncharged API error. A selected edit still consumes one command
when mechanical validation rejects it. Every accepted edit consumes one revision, including
discard; a complete restored base does not count as a newly completed edit. Incomplete drafts
remain editable. Reward remains the decrease in best validated area divided by initial area.

## Limits and architecture review

Restoration rebuilds disposable derived caches; previously recorded cumulative counters survive,
but subsequent cache hit patterns can differ from an uninterrupted process. This affects timing
diagnostics, not commands, arrays, reward, episode accounting or training RNG. Malformed diagnostic
commands use the new typed boundary's error wording; legal candidates and tested mechanical
rejections preserve existing outcomes.

Compared with the partial observation experiment, Python no longer needs to enumerate or decode
all candidates, clone layouts, run rules or calculate rewards for native transitions. The normal
runner still uses its existing path until observations pass byte parity. This remains the explicit
local-edit pilot described by the ownership design. It adds no construction, global solver fallback,
route search, ranking heuristic, pruning premise or new game rule, consistent with the constructive
planner design and `AGENTS.md`.
