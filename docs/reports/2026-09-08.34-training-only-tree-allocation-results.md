# Training-only tree allocation: complete first comparison

Status: all 576 predeclared cells complete and independently validated. This is a
training-geometry diagnostic with one fixed learned policy, not held-out confirmation.

Policy-guided PUCT does not improve the case-median area curve over independent policy
rollouts in this study. It does find one better individual factory at the largest
allowance: battery gap-zero rotation-zero, sampling seed 1000001, area 98 versus 105
for independent policy rollout. The other 47 matched pairs at that allowance tie.
This isolated gain is worth reproducing; it does not establish a general advantage.

## Cost, validity and limits

Total elapsed time is 569.33 seconds on the local Apple M4, CPU inference with one Torch
thread. Work includes 1794048 hypothetical native transitions, 56064 restores and
897024 model calls. There are zero executed production commands. All 576 retained
layouts pass native and independent acceptance; complete selected traces replay
independently (3592 total replay commands). No policy parameter or BN buffer changes.

At most 257 nodes are used, while the fixed tree pool allocates 655920 bytes including
array headers. Process-lifetime peak RSS is 238354432 bytes; this is not a per-method
peak-memory comparison. The modest tree depth and sparse reward remain limitations.
The value head is unused; this is not evidence about calibrated value-guided search,
progressive widening, search-generated training targets, or global layout optimality.

No development or held-out outcomes were opened. The capacity matrix continues on the
server with its five remaining streams. Before claiming the isolated tree gain is
reliable, use an explicitly selected-case follow-up with fresh sampling seeds and
matched wall allowances, clearly labeled as post-selection training diagnostics.
