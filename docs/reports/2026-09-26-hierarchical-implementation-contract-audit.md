# Hierarchical implementation contract audit

Status: confirmed source-level audit for local repair planning. No server was used.

## Scope and method

Compare the accepted [hierarchical routing design](../designs/2026-09-22.00-solver-augmented-hierarchical-routing.md), the [game topology contract](../designs/aic-game-rules-mathematical-model.md), current normalized catalogs, the `aic-layout` validator, native constructive session, route candidate boundary, outer search, and lower model. A missing design feature is classified as a defect only where the accepted contract calls for it or where the current output can be misclassified as physically valid. An explicit experiment budget is recorded as a limit, not automatically a bug.

This audit identifies source-visible gaps; the independent plan review must challenge both the findings and completeness of this inventory. Final readiness still requires integrated local evidence after repair.

## Already implemented or bounded by explicit configuration

- Native candidate replay is revision-atomic and completed physical-v2 layouts are checked by an independent validator; the validator's topology contract is incomplete as H1 states.
- Separate lower/outer checkpoints, held-out identity separation, root records, Gumbel root selection, placement widening and resumable curriculum state exist. Repair must preserve these established benefits.
- `horizon`, `max_moves`, root candidates, route candidates and route searches are visible configuration controls. The [inert-horizon probe](2026-09-26-inert-search-horizon-probe.md) found identical case-level completion masks in three paired evaluations; that does not validate the chosen budgets on a corrected topology.
- The present physical-v2 schema can express bridges but has no selected branch component. Treating the current catalog's splitters and convergers as hypothetical future data is an implementation-scope error, not a supported exception.

## Repair order and acceptance

Plans 00-02 close physical legality and truthful failure semantics before any search/training promotion. Plans 03-06 restore the missing routing and learning responsibilities. Plan 08 closes the training-distribution and scale-calibration gap. Plan 07 then exercises all critical paths locally, compares the corrected workflow with the retained baseline where meaningful, and records a reviewed readiness verdict. Every plan gets a fresh proposal review before execution and a separate implementation review after verification. No GPU/server work or long training is part of this sequence without new user authorization.
