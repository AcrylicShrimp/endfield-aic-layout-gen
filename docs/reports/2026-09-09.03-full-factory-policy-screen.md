# Full-factory policy learning screen

Status: model-connected stage-four prototype implemented in `908e996`; corrected
screen and audits complete. Learning benefit is small and inconsistent. Stage four,
production learned inference, and the final density/visual target remain open.

The new policy observes actual complete production witnesses and selects physical
edits on 4-, 8-, 9- and 59-facility factories. This replaces the preceding
acceptance-only experiment with real gradient updates, frozen policy evaluation,
selected facility relocation and routing. It does not establish a successful
full-factory learner. There is no fundamental impossibility result.

## Contract and implementation

The [predeclared contract](../designs/2026-09-09.01-full-factory-policy-pilot.md)
specifies the inputs, vocabulary, budgets, learning objective and comparison. The
immutable original-request ledger and production Rust validator remain authoritative.
The policy sees a 28-channel raster and sparse typed entities/edges, including both
transport layers, separate network-cell ownership at bridges, terminals, catalog
ports, facilities and components. Float32 features include rate value and numerator/
denominator signals; exact rationals remain in the physical witness and validator.

The fresh policy has either zero or four message layers, width 32, spatial
convolutions, GroupNorm, and LayerNorm in the message updates. Parameter counts are
26241 and 39041; this also changes compute and capacity, not only graph depth. There
are no legacy weights, item/recipe string features, teacher candidate scores, or
routing-result preselection. A selected local edit invokes bounded dedicated A*
reembedding, pipe-first. Strip insertion/contraction explicitly edits full geometry.
The observer and vocabulary have no two-terminal or single-path representation limit.

All accepted exploration states are complete valid factories. Private exploration
may temporarily worsen the score; retained best only changes after full validation
and lexicographic improvement in area, physical layer tiles, then turns. All selected
commands are charged, including failed reembedding, rollback and unchanged results.
Native proposal count separately records only submitted physical candidates. There
is no global exact fallback, facility-only construction, or game W/H limit. Comparing
this slice with the constructive planner design confirms that the published incumbent
remains validated and nonworsening; exploration remains outside production commands.
The existing constructor is unchanged.

## First run exposed an insertion defect

The original screen completed in 112.595 seconds. Its 1440 retained best witnesses
passed original-graph/score checks, and all 11520 selected actions replayed. However,
370 insertions failed native attachment geometry validation. A cut could avoid a
facility body while separating it from an adjacent used port connection. The defect
was in the intended shape-preserving insertion vocabulary; the validation boundary
correctly rejected every affected proposal.

The fix excludes cuts through used facility/terminal arms. It uses the accepted
state's geometry, with no routed-outcome or score filtering. The immutable crossing
fixture checks every offered insertion and independently compares excluded cuts to
projected catalog ports. All 176 offered insertions across the 23 dataset starts also
passed. The entire screen then ran again from fresh seeded initializations, with the
same budgets and splits. Both matrices remain retained; they are not pooled.

The original source differs from committed runtime source only in the executor.
Its exact pre-fix copy and SHA manifest are retained under
`artifacts/factory-edit-pilot/full-factory-policy-screen-source/`. The original matrix,
summary, final audit and replay remain under the `full-factory-policy-screen` prefix.
To reproduce that historical execution, use the retained executor in an isolated
checkout and verify the original protocol's source hashes. Do not replace current
source in the shared checkout. The results below use the corrected vocabulary.

## Corrected experiment

Each depth uses training seeds 17, 29 and 43. Each actor receives 1024 selected
training actions: 32 groups of four independent eight-action episodes on one root
per group. Rotate battery-38, citron-48, iron-nine-108 and closure-refined. Terminal
lexicographic ranks drive policy gradient with entropy .01, Adam .0003 and gradient
norm clip .5. This is a short signal screen, not PPO or a curriculum completion claim.

Each untrained/final actor and both controls receive the same 24 inputs, two sampling
seeds (1170000/1180000), and eight selected actions. The inputs comprise all 23
retained roots plus the pre-existing strong Heavy Xiranite layout: seven four-facility,
nine eight-facility, five nine-facility and three 59-facility starts. The latter three
share the original production graph. Related graphs also span training/evaluation.
These are historically opened geometries, not sealed new-family generalization.

Bounds are 5000 routing expansions per action, 30 seconds per episode, and 1800
seconds for the screen. The corrected run completed in 113.222 seconds on local CPU,
one Torch thread, with deterministic operators (Python 3.14.7, Torch 2.14.0, Node
26.5.0). All 1440 episodes completed all eight actions: 6144 training and 5376
evaluation selections. No deadline or whole-screen guard was reached. Timings include
checkpoint/output work inside the driver, but exclude Python import startup and the
separate audits; this is not a production latency benchmark.

## Behavior, cost and coverage limits

The corrected 11520 selections produce 4835 native proposals, all valid: 449 best
improvements, 3375 private exploratory acceptances, and 1011 equal-score acceptances.
There are 6685 executor rejections, 7529 unchanged states and 47 changed-state revisits.
The 762700 total routing expansions include 29 actions that exhaust the local work
budget. No unexpected untyped executor exception occurs. The insertion defect no
longer appears: all 146 selected insertions validate.

The action mix is strongly uneven: 4955 moves, 3734 ports, 1658 rotations, 802
reroutes, 149 component moves, 146 insertions, 66 rollbacks, eight bridge releases,
and two contractions. 801/802 reroutes leave the state unchanged. Moves fail on
4077/4955 selections. Body/endpoint collisions and shared-terminal ownership account
for many failures. These are measured limitations of this local vocabulary and
selection strategy, not proofs that the factory request is infeasible.

Changed valid move actions occur at every size: 213 at four facilities, 265 at eight,
121 at nine, and 279 at 59. Six bridge-release actions improve the retained score.
The two changed actions explicitly selecting pipe operands are training-time port
edits on closure-refined; both are exploratory, not incumbent improvements. Pipe
networks, branching/merging and required production cycles remain validated in the
full 59-facility states, but learned improvement specifically using those capabilities
has not been demonstrated reliably. Native acceptance alone does not complete this
requirement.

Rank groups contain nonzero advantages in 17/20/20 groups for depth zero and 16/21/21
for depth four, out of 32 each. The signal exists; that does not diagnose why the
short adaptations are weak. Median/p95/max episode wall times are .0194/.2987/.6166
seconds; corresponding observation times are .0088/.1553/.2769 and inference times
.0035/.0259/.0583. Full resource accounting and every per-case score remain in the
retained matrix and summary.

## Original Heavy Xiranite target

All six final actors keep the strong input at `[2132,392,148]`, `41x52`. None improves
its area. The uniform control discovers a valid port change to `[2132,390,148]` in
sampling seed 1170000. This is an executor/control discovery, not learned benefit.
It is retained as `artifacts/factory-edit-pilot/full-factory-policy-heavy-best/witness.json`
with its original-graph audit and provenance in `report.json`; the prior incumbent
and both complete experiment matrices are also preserved.

The new layout has 1133 facility XY cells, 364 transport XY cells, 1497 occupied and
635 empty cells in area 2132: **29.7842% empty XY**. Removing two transport cells at
unchanged area slightly raises the empty fraction from 29.6904%, while improving the
required lexicographic score. No footprint, density or visual-target success is
claimed. The original 59-facility request, its productive cycles, shared commodities,
water/sewage boundaries and target rate remain unchanged. The at-most-1% goal remains
unmet.

## Verification and next decision

- `cargo check --workspace` and workspace tests: 536 passed, two pre-existing ignored.
- Python suite with the current native library: 154 passed, three platform skips.
  Six new tests cover exact ranks, graph ownership/rates/gradients, bridge release,
  charged failure/rollback, strip inverse and used-port-arm insertion safety.
- Corrected audit: all 1440 retained witnesses pass original-graph coverage and
  independent JavaScript score/density checks. Geometry validation still uses the
  same production Rust implementation through its separate CLI.
- Corrected replay: all 11520 actions reproduce status, geometry, score, route-work,
  unchanged/revisit flags and best witnesses; all 5376 frozen evaluation samples
  reproduce their selected action, and checkpoint tensors remain immutable. Training
  optimizer updates are not independently reconstructed.
- CLI screen, summary, audit, replay and view commands run manually. Source/index
  artifact checks and `git diff --check` pass. No Rust source changed in this slice.

The next experiment should discriminate action selection and useful neighborhood
coverage. A flat candidate list rarely selects structural operations; the simple
geometry control repeats failed actions; single-chain rerouting is almost always a
no-op. Compare operation-balanced selection, remembered failed/revisited choices,
and longer or compound relocation episodes under declared equal budgets. Explicit
outward routing support is also still limited: the borrowed reembedding engine uses
the current extent, and some states admit no geometry-preserving strip insertion.
These are separate hypotheses worth a short broad comparison. Do not turn this small
result into another reliability gate, an instruction to keep adding message layers,
or a reason to stop the goal. New-family training/evaluation and production bounded
CPU inference remain required later work.
