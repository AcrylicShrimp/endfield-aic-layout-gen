# Frozen learned policy on the first complete 116-facility original

## Result

The learned policy now runs on a complete, independently validated 116-facility
original, but it does not demonstrate successful large-factory relocation. All
seven selected poses across the main screen and cold-runtime control fail local
routing. Accepted improvements are strip contractions. With a fresh runtime for
each method, parent, learned and geometry all retain `[84838,11157,697]`, a 1.57%
area reduction from `[86190,11189,697]`.

The main newly exposed limit is description/observation generation. It consumes
32.2–33.8 seconds in the cold controls, while policy selection and related accounting
consume only 0.77–1.08 seconds. The existing episode deadline is checked between
operations; the last expensive description overruns the nominal 30-second budget
without selecting or accepting another action. A strict production wall-clock
bound is not established by this research runner.

The [contract](../designs/2026-09-09.17-large-factory-frozen-transfer.md) freezes
report 13's best-mass checkpoint and corrected trajectory parent at T=0.05. Both
checkpoint bytes match retained provenance, their training-protocol identities
match, and policy/observation source, selection source and episode accounting are
unchanged. The report explicitly records the four transitive JS source changes and
new native library from [report 16](2026-09-09.16-same-item-bridge-channels.md).
This is a new runtime with frozen weights, not unchanged-runtime replication.

## Additional proposal-graph defect

Inspecting the description cost reveals another coordinate-only graph in
`full_factory_poses.mjs::productionEdges`. It infers facility reachability for
connected pose groups and still joins the two same-item bridge axes. This function
is separate from the corrected constructor path and acceptance validators.

An independent traversal carrying the incoming direction across bridge cells
finds 171 actual facility pairs on medical 116. The current proposal graph reports
283: **112 extra pairs**, with no missing real pair. This is verified with the
retained original and `full_factory_pose_graph_audit.mjs`. It explains an inaccurate
candidate-group domain; its contribution to total runtime is not yet isolated.
Do not reduce candidate limits or train around this known semantic defect. Correct
this graph next, preserve real directed pairs, then measure the resulting domain
and description cost before planning further large-factory learning.
