# Durable PPO harness readiness

Status: readiness gate complete. Independent fixes, native executions, CUDA
continuations and real W&B history checks pass.

The new CLI harness implements the
[training and monitoring contract](../designs/2026-09-10.05-ppo-training-harness.md)
after the CUDA FP32 / 64 setup decision. It uses persistent CPU collectors, one
CUDA learner, immutable fresh-generation tasks and transactional batch commits.
The former short experiment runners remain historical reproduction tools; the
renewed twelve-input comparison uses this harness directly.

## Behavior and recovery

`prepare` exclusively claims a fresh run directory and freezes source, binary,
catalog, runtime and configuration identities. `run`, `stop`, `resume`, `status`,
`plot` and terminal-run `export` are explicit operations. Resume first terminates
a lost session, then reads its final durable state, validates identities, restores
actor/critic/Adam/RNG state and reuses complete published task results. Interrupted
attempts are retained and retries are recorded. The state pointer advances only
after checkpoint, record and directory links have been synced.

The supervisor bounds cumulative wall time, coordinator progress, aggregate RSS,
free disk and cleanup. Session tags include detached W&B services and descendants
whose original group leader has exited. Linux uses process environments; Darwin
uses a private `ps` environment query. These environment bytes are never logged.
Workers receive no W&B credentials. `.env` accepts only the three documented W&B
keys without shell expansion; existing environment values take precedence.

The W&B observer reads committed metrics without participating in learning.
Stable candidate/seed run IDs survive resume. Each history ordinal is committed
explicitly. Primary `outcome/*` curves use the intersection of held-out generation
seeds across every candidate and every evaluation checkpoint for each initialization
seed. They appear after all candidates for that seed complete. Independent admitted
means remain provisional, with coverage visible. Plot and export failures remain
separate from the authoritative training result.

## Independently reviewed findings

Three reviewers separately inspected durability, operations and experiment/PPO
semantics. Each accepted finding was reproduced locally before repair. Reviewers
then rechecked their fixes; no actionable issue remains within those scopes.

| Finding | Evidence and accepted repair |
| --- | --- |
| Resume overwrote a late coordinator commit | Controlled shutdown interleaving reproduced a committed job disappearing. Cleanup now precedes state loading. The regression asserts the late commit survives. |
| New ancestor directory links were not durable | fsync instrumentation showed missing job/phase parents. Durable directory creation and ancestor syncing cover task, checkpoint and native result publication, including generation metadata. |
| Experience envelope/bytes were insufficiently checked | Four wrong identities, a shortened trajectory and changed compressed bytes were independently rejected after repair. Read/hash compressed bytes once and check actor/critic/task/candidate and trajectory length at the batch boundary. |
| Retention could follow a symlink to another job | A generated-directory symlink reproduced foreign deletion. Cleanup now rejects symlinks and paths escaping the exact attempt. |
| Detached W&B service escaped resource accounting/cleanup | Actual Linux SDK check found a separate service process group; both groups contributed 199,761,920 bytes RSS and cleanup left zero live owned processes. Session discovery also covers launch-before-registration. |
| Darwin orphan group ownership failed | A real orphan descendant ignoring TERM now receives bounded cleanup, while an unrelated process survives. The tests also exposed Darwin EPERM on all-zombie groups; independently reproduced and handled without hiding permission errors for live members. |
| W&B latest explicit-step point was pending | The real offline SDK kept `run.step == 0` after default logging at step 0; `commit=True` advanced it immediately. Specific outcome axes follow generic metric definitions. |
| Terminal observer failure was hidden | A completed training fixture with killed observer incorrectly reported tracking running. Final exit status and pending/failed export health are now explicit; training completion stays intact. |
| Different evaluation cohorts reversed the ranking | Candidate A's independent mean 10 versus B's 15 became A 20 versus B 15 on their common factory. Primary curves now use one shared cohort across all candidates/checkpoints. Empty cohorts publish coverage without fabricated outcomes. |
| Invalid external generation settings passed preflight | Zero temperature, negative episode time, unknown selection fields, invalid setup kinds and float product-duration bounds now fail before run creation or worker launch. |
| Durable mkdir introduced a concurrent prepare overwrite | Follow-up review reproduced two successful prepares replacing seed 17 with 29. Exclusive final-root creation now rejects the second prepare and preserves the original protocol. |

The restore-enabled fallback was examined and retained: it is the previously
approved action contract. No-restore exhaustion remains an explicit failure.
No per-step observation/mask/reward replay or duplicate optimizer execution was
added to normal training. Tests cannot demonstrate durability under an actual
power cut; the fsync ordering and fault boundaries are the verified evidence.

## Verification

- macOS and Linux: 23 harness unit/fault tests pass, including real pipe EOF/hangs,
  startup/task limits, oversized messages, out-of-order completion, credential
  stripping, resume/prepare races, retained attempts, checkpoint/Adam/RNG recovery,
  cleanup scope, actual process-group cleanup and supervisor progress/RSS/wall stops.
- macOS and Linux: seven batched PPO tests pass, including reference numerical
  behavior, exact nonempty optimizer/shuffle continuation, six boundary faults
  and absence of normal model/observation replay.
- `cargo check --workspace` passes. `cargo test --workspace` passes: 538 tests,
  two existing ignored tests. No Rust source changed in this slice.
- Worktree artifact-policy check passes. Final index check is required at commit.

The revised native run `ppo-harness-development-v2` completed in 149.091 seconds
across two supervisor sessions, with 6.446 GiB sampled peak aggregate RSS. It ran
history-no-restore and current-best-layout-history at seed 17, two batches of four
fresh attempts and horizon eight, with evaluation at 0/1/2. Both jobs admitted
seven training episodes (56 actions); 38 of all 40 generation attempts completed.
The two rejections were recorded without replacements. Four interrupted attempt
directories survived the intentional stop after the first committed update.

The standalone audit verified native initial/best validity for accepted results,
actual behavior probabilities/values and exactly one nonempty second-batch Adam
continuation per job. Both continuations matched actor, critic, Adam, shuffle RNG
and epoch statistics exactly on CUDA. W&B contained eight history ordinals per
job, including three shared-cohort points: all 173 exported scalars per job matched
committed local records. Terminal `export` then completed without duplicate history.

The earlier development v1 stop/resume test also completed; its frozen runtime
snapshot preserves the pre-review implementation. It is superseded by v2 for
readiness conclusions.

The representative `ppo-harness-representative-v1` run used 24 collectors and
current-best-layout-history at seed 17. Both 32-attempt training batches and both
16-attempt evaluation phases admitted every factory: 2,048 training actions,
1,024 evaluation actions and 128 Adam minibatch steps. It completed in 163.780
seconds with a sampled peak aggregate RSS of 39,762,501,632 bytes (37.032 GiB),
within its 40 GiB ceiling. Training collection took 27.503/30.016 seconds; complete
PPO updates took 20.839/21.123 seconds. These end-to-end timings include rich
observation preparation; they do not equal the earlier resident GPU microbenchmarks.

The standalone audit checked all 96 results, behavior probabilities/values, an
exact nonempty second-batch CUDA continuation and all 142 W&B scalars in six
history ordinals. All passed. The two-batch result is an execution load test,
not a learning comparison or a guarantee about memory usage in longer runs.

The [compact provenance manifest](2026-09-10.05-ppo-harness-provenance.json) records
three frozen protocols, their native audits and W&B URLs. A 144,152,162-byte
retained archive contains checkpoints, selected training/evaluation evidence,
interrupted attempts, the older runtime snapshot and a shared 278-file source,
binary and data snapshot. Its SHA-256 is verified on the workstation and server.
Regenerable constructor HTML/intermediates were removed by post-commit retention;
credentials are outside the retained run directories. These are execution readiness
checks, not comparative learning evidence.

## Reproduction

From the repository root, after filling the ignored `.env` from `.env.example`:

```sh
uv run --project tools/factory-edit-pilot python tools/factory-edit-pilot/ppo_harness.py prepare --config tools/factory-edit-pilot/ppo-harness-readiness.json --output artifacts/factory-edit-pilot/ppo-harness-readiness
uv run --project tools/factory-edit-pilot python tools/factory-edit-pilot/ppo_harness.py run --run artifacts/factory-edit-pilot/ppo-harness-readiness
uv run --project tools/factory-edit-pilot python tools/factory-edit-pilot/ppo_harness.py status --run artifacts/factory-edit-pilot/ppo-harness-readiness
uv run --project tools/factory-edit-pilot python tools/factory-edit-pilot/ppo_harness.py stop --run artifacts/factory-edit-pilot/ppo-harness-readiness
uv run --project tools/factory-edit-pilot python tools/factory-edit-pilot/ppo_harness.py resume --run artifacts/factory-edit-pilot/ppo-harness-readiness
uv run --project tools/factory-edit-pilot python tools/factory-edit-pilot/check_ppo_harness_native.py --run artifacts/factory-edit-pilot/ppo-harness-readiness --output artifacts/factory-edit-pilot/ppo-harness-readiness/native-check --check-wandb
uv run --project tools/factory-edit-pilot python tools/factory-edit-pilot/ppo_harness.py export --run artifacts/factory-edit-pilot/ppo-harness-readiness
```

Issue stop from another terminal while the run is active, then wait for its
terminal stopped state before resume. The checked-in generation config targets
the Linux experiment server's existing native binaries. For the representative
run, prepare a separate directory using `ppo-harness-representative.json`.
