# Full-factory selection and horizon results

Status: bounded comparison complete. The previous goal turn made progress, and this
turn adds tested selection/history behavior, a complete controlled experiment and a
new validated learned target incumbent. Stages four and five remain incomplete.
There is no fundamental impossibility finding.

The flat policy improves 72/100 evaluation cells after 4096 training actions, versus
56/100 before training. Its paired comparison is 37 wins, 51 ties and 12 losses.
Operation balancing and failure memory help some outcomes but do not solve action
waste. A learned rollout reduces the current 59-facility incumbent from
`[2132,390,148]` to `[2132,386,148]`; the corresponding untrained policy reaches
`[2132,388,148]`. All retain the same `41x52` area. The new best has **29.9719% empty
XY**, so neither the 1% requirement nor visual acceptance is achieved.

## What changed

Implementation commit: `9eb9d80`. The
[predeclared contract](../designs/2026-09-09.02-full-factory-selection-landscape.md)
compares flat versus operation-balanced sampling, with or without observed-failure
memory, and a longer episode regime. The existing physical executor, observation
schema, native acceptance and score order are unchanged.

Balanced sampling subtracts log available-candidate count for each operation from
its candidate logits. At zero logits each operation has equal mass; training can
change it. The categorical entropy objective remains common, so it does not enforce
permanent operation balance. Memory masks only actions already observed to fail,
leave the geometry unchanged, or return to a previously visited state. It performs
no speculative routing or validation. It resets per episode, and all-masked
exhaustion would explicitly select charged restore-best. No exhaustion occurred.

State identity sorts unordered witness DTO lists while retaining entity identities,
directed segment records, rates and geometry. Reroute memory uses network identity
and directed chain geometry rather than enumeration indices. Rollback keys include
the retained best identity. These avoid reusing a stale failed-action entry after
list reordering or a best-state change. This is episode memory, not a recurrent
model or an infeasibility proof. Both new physical and previous serialization-based
unchanged/revisit counters remain recorded.

Compared with the constructive planner design, this remains bounded improvement of
complete factories: pipe-first dedicated routing, full original-request validation,
private exploratory states and nonworsening retained best. No constructor, global
exact fallback, game rule, or caller-supplied W/H feasibility bound was introduced.
The new sampler is separate from the unchanged physical acceptance boundary.

## Experiment and limits

All five policies start from exactly the same depth-zero, width-32 initialization,
training seed 17. Each receives 4096 selected actions, with the same terminal-rank
objective, four episodes per update, Adam .0003, entropy .01 and norm clip .5.
Training rotates battery-38, citron-48, iron-nine-108 and closure-refined.

The four short-episode arms receive 128 updates of four eight-action episodes. The
longer arm receives 32 updates of four 32-action episodes. Thus the longer comparison
also changes update count and credit-assignment span; it is not an isolated horizon
test. The flat arm's first 32 groups exactly reproduce the preceding screen's
`d0-s17` cases, scores, ranks, losses and gradient norms.

Each initial/final policy and three controls use all 23 original roots plus both
strong starts (`[2132,392,148]` and `[2132,390,148]`). Four sampling banks receive 32
selected actions per input: four independent eight-action attempts or one 32-action
episode. Each cell retains the best across its attempts. There are 25 inputs,
1300 cells and 6176 episodes, totaling 20480 training and 41600 evaluation selections.
The 25 inputs include seven four-facility, nine eight-facility, five nine-facility and
four 59-facility starts. The latter four share the same original production graph.

These are historically opened geometries with related graphs across train/evaluation.
Eighty-four cells per method exclude the four exact training geometries, but this
is not sealed new-family generalization. Only one training seed is used. The earlier
three-seed 1024-action screen remains separate and does not provide replication of
these 4096-action outcomes.

Per-action routing allowance is 5000 expansions; per-episode wall allowance is 30
seconds, with an 1800-second whole-screen guard. The comparison completes in 699.701
seconds on local CPU, one Torch thread, with no exhausted episode or screen guard.
The restart schemes have different aggregate theoretical wall allowances because
the 30-second cap is per episode. All measured sums of episode times per evaluation
cell are below 3.212 seconds. This is equal selected/routing allowance evidence,
not the final release comparison under one common per-factory wall deadline.
Checkpoint/output work is included in the screen timer; import startup and separate
audits are excluded.

## Learning and control outcomes

Each row uses 100 cells (25 inputs x four banks), with 32 selected actions per cell.
"Improved" means a strictly better retained lexicographic score than that cell's
input. Mean area reduction averages relative reductions across cells. Futility
counts physical unchanged outcomes, including rejected actions, plus changed-state
revisits. A novel valid temporary deterioration is not automatically futile.

All five sampled learning deltas have more wins than losses, but the effects and
failure patterns differ. Flat has the largest learned mean area reduction and most
improved cells. Memory lowers its final futility relative to flat without memory,
while lowering quality. Operation balancing exposes structural actions more often,
but is not uniformly better. The longer regime gives little sampled learning benefit;
its different number of updates prevents a claim that long episodes themselves fail.

## Work and physical behavior

Across training and evaluation, 62080 selections submit 33561 physical proposals,
all accepted as valid: 2501 retained-best improvements, 21129 private exploratory
acceptances, and 9931 equal-score acceptances. The other 28519 selections fail in the
bounded executor. There are no native geometry rejections, untyped executor errors,
or lost incumbents. Routing uses 3292194 expansions; 145 selections hit the local
routing-work bound and remain charged failures.

Selections comprise 18202 moves, 13194 port edits, 9349 rotations, 6737 reroutes,
5474 insertions, 4634 rollbacks, 1559 bridge releases, 1477 component moves and 1454
contractions. This is substantially broader structural exposure than the earlier
flat eight-action screen. It still does not solve the retained target's footprint.
No final-policy evaluation action explicitly selecting a pipe operand improves the
incumbent. Full mixed-network and productive-cycle validity is preserved, but robust
learned use of all required semantic capabilities remains unproven.

The largest failure categories are body collision (6442), no route in the selected
neighborhood (5568), endpoint/body collision (5329), and non-detachable shared-terminal
movement (4145). History cannot make these unavailable moves physically possible.
Representation-order effects are measurable: for balanced-final, serialization counts
1856 unchanged and 273 revisits, while physical identity counts 1857 and 287. Neither
version comes close to the operational futility targets.

Median/p95/max episode times are .0245/.4101/2.9260 seconds. Observation is
.0091/.1659/1.0077; selection, inference and history processing are
.0065/.0922/.8473. These timing components and masked counts are retained by arm.
The final flat method's futility p95 is 87.5%, far above the release threshold.

## Original target and retained evidence

The best learned target cell is flat-final, bank 1220000, starting from the current
`[2132,390,148]` incumbent. Its third eight-action attempt changes two belt ports,
first reaching `[2132,387,148]`, then `[2132,386,148]`. The best untrained result over
the same four attempts is `[2132,388,148]`. This is a postselected discovery with a
paired learned advantage, not a repeatable target-success claim. Three other banks
for flat-final leave that incumbent unchanged.

The new witness has area 2132 (`41x52`), 1133 facility XY cells, 268 belt cells, 118
pipe cells, 26 belt/pipe overlaps, and 1493 occupied XY cells. Empty XY is 639/2132,
**29.9719%**. Its largest empty rectangle is **7x10** at `(27,26)`. The original
59-facility request and all original boundaries/rates remain unchanged. The saving
is in transport cost, not footprint or density; the empty fraction rises slightly
as wiring is removed at fixed area.

The new best is retained separately in
`artifacts/factory-edit-pilot/full-factory-selection-heavy-best/witness.json`, with
source cell, paired untrained result, original-graph audit, density and route
metrics in `report.json`. Prior `[2132,390,148]` and `[2132,392,148]` starts remain
unchanged. The inspected full-plan comparison PNG/SVG and input/hash manifest are
under `full-factory-selection-heavy-view/`. Both panels show the same facility
packing and substantial empty regions; no visual approval is claimed.

Other postselected minima are the loose original's `[12480,2312,264]` and refined
start's `[4032,871,184]`, both from the untrained longer regime. They illustrate
executor/search benefit and must not be credited to learning or compared only with
the loose constructor while ignoring the stronger incumbent.

## Verification and next action

The complete original-graph/metric audit passes all **6176** retained episode bests
and all **1300** aggregate cells, including exact attempt/group completeness, ranks,
physical identity, density and largest-empty-rectangle metrics. Geometry uses the
existing production Rust validator through a separate CLI; metric and original-graph
checks are independent JavaScript logic.

Replay covers **1044 episodes / 10992 selected actions**: every method/input in the
first sampling bank, the first/last training groups, and best heavy outcomes outside
that bank. It reproduces 10736 sampled choices where the appropriate frozen policy
is available, all replayed masks/geometry/work counters, and retained witnesses.
Training optimizer updates are not independently reconstructed. The first 32 flat
updates separately match the preceding experiment exactly. All initial policy
weights are identically seeded; evaluation leaves their tensors unchanged.

`cargo check --workspace` and workspace tests pass (536 tests, two existing ignored).
The Python suite passes 159 tests with three platform skips. Five new tests cover
balanced probability mass and gradients, physical identity, semantic reroute keys,
history/exhaustion/rollback semantics, and geometry control advancement after failure.
The screen, summary, audit, replay and full-plan view ran manually. No Rust source or
new dependency changed. Worktree/index artifact checks and diff checks pass.

A root-state diagnostic finds **zero eligible x or y insertions and contractions**
on the new strong incumbent. The current move vocabulary offers only one-facility
cardinal displacements of one or two cells, and the borrowed reembedding kernel
restricts moves/routing to the current extent. External terminals have no direct
re-anchoring action. These are explicit prototype limitations, not game constraints.
Zero strips at this one state does not prove that every longer trajectory is blocked.
The diagnostic and original external-anchor geometry are retained in
`full-factory-selection-neighborhood.json`.

The next useful implementation should widen concrete relocation choices, such as
moving into a distant free region and moving bounded groups that share terminal
ownership, with affected routing and full validation in the same transaction.
Measure these against the existing local moves before spending another turn merely
increasing training duration or repeating seed gates on this vocabulary. The visible
7x10 empty region gives a concrete target for that investigation. Broader new-family
pipe/cycle data and production CPU CLI integration remain necessary; this screen
completes neither stage four nor the final goal.
