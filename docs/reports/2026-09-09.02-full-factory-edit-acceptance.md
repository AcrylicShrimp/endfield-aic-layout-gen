# Full-factory edit acceptance

The learned-improver backend now has a Rust transaction boundary over production
physical witnesses. It accepts the original 59-facility Heavy Xiranite factory,
including its pipes, shared belt networks, crossings and required production cycles.
This is semantic/infrastructure progress, not a new learned layout or a density gain.
Observation/action encoding and learning on this representation remain next.

Implementation: `0fb8ebe`, following
[the stage contract](../designs/2026-09-09.00-full-factory-edit-acceptance.md).

## What changed

`FactoryEditRequest` fixes the original facility IDs, recipes, utilizations and
facility/external terminal commodity rates. `FactoryEditSession` validates closed
physical proposals using the existing production geometry validator and a separate
original-request ledger. Valid exploratory states may worsen, while the best state
only improves in used area, physical layer tiles, then directed turns. Invalid,
malformed, budget-exhausted and late proposals cannot overwrite retained layouts.
Parsing and validation are charged inside the proposal deadline.

The new Python binding and `full_factory.py check|replay` accept the production
`WitnessProbeInput` DTO. They do not reconstruct a two-terminal belt-only case or
reuse its tensor schema. Shared-network, pipe, junction, crossing and reachability
rules now come from the production validator instead of additional learning-side
implementations. `aic-data` is an existing workspace dependency; no new third-party
version was added. Native build provenance now covers its Rust sources as well.

This does not change the constructor or invoke exact search. The old single-path
engine remains a historical research control. No old checkpoint is declared
compatible with the new API; it currently exposes physical transactions, not model
observations or a learned action decoder.

## Actual factory checks

Imported all 23 retained roots from the explicit historical root artifact. The
request ledger was derived from each original production graph, independently of
candidate geometry. Original requests and initial witnesses were copied into the
retained input directory so the audit does not depend on disposable parent files.
The mandatory request matches
`artifacts/benchmarks/constructive-chain-blocks/gap-1-placement.json` exactly.

| Facility count | Retained geometries | Result |
| ---: | ---: | --- |
| 4 | 7 | Complete acceptance and retained-state checks passed |
| 8 | 9 | Complete acceptance and retained-state checks passed |
| 9 | 5 | Complete acceptance and retained-state checks passed |
| 59 | 2 | Complete acceptance and retained-state checks passed |

Each root receives an unchanged valid proposal, malformed JSON, and a proposal
with all transport removed: 69 charged proposals, with the initial best preserved
in every case. A separate audit rechecks all 23 exported layouts against the original
graph and independently recomputes their scores and XY occupancy. Geometry checking
uses the same production validator through its separate CLI; this is not a claim
of two independent geometry implementations.

The 59-facility request has 96 material requirements and eight nontrivial production
SCCs (seven of size three and one of size five). It retains the original four water
requirements, sewage input, low-polymer surplus export and Heavy Xiranite output
of 1/10 per second. These are actual mixed-transport/cyclic inputs, not generated
single-path substitutes.

## Existing Heavy Xiranite layouts through the new boundary

A seven-proposal replay supplies previously retained layouts and deliberate invalid
variants. The executor does not discover these layouts.

| Supplied proposal | Outcome | Retained best area / tiles / turns |
| --- | --- | --- |
| Existing refined layout | Improved | 4032 / 879 / 194 |
| Existing 41x52 layout | Improved | 2132 / 392 / 148 |
| Original loose layout | Accepted exploration | 2132 / 392 / 148 |
| Remove required pipes | Rejected: pending recipe obligations | 2132 / 392 / 148 |
| Existing 41x52 layout again | Accepted exploration | 2132 / 392 / 148 |
| Invent an external procurement identity | Rejected: original terminal mismatch | 2132 / 392 / 148 |
| Malformed JSON | Rejected and charged | 2132 / 392 / 148 |

The final retained witness contains 59 facilities, 16 commodity networks (five pipe
networks), one belt splitter, one belt converger, five belt bridges and three pipe
bridges. Its 392 physical layer tiles occupy 366 distinct XY cells. Facility bodies
occupy 1,133 cells, leaving 633 of 2,132 XY cells empty: **29.69%**, far above the
required 1%. There is no new visual-quality claim.

The explicit score definition is `used-area-layer-tiles-all-terminal-arms-v1`.
It includes external terminal arms as the current small-path learner does. The
historical full-layout scorer omitted those arms and reported 147 turns for this
same 41x52 witness. The new 148 is a definition change, not an added route or a gain;
all comparisons in this replay use the same new definition. Translation is
canonicalized to actual used minima; a fixture whose old probe reported 35x22
capacity has a measured 35x20 used footprint.

## Cost and verification

The 23-root native matrix took 0.151 seconds inside its measured loop, including
per-root catalog loading, snapshots and proposals but excluding module/source-check
startup. Core initialization checks ranged from 0.063 to 2.928 ms, excluding catalog
loading. Valid full-target replay proposals took roughly 1.30–3.21 ms including JSON
parsing and validation. These are single local runs, not a throughput benchmark.

Nine new Rust tests cover original request errors, full inventory and recipe
coverage, shared components, external identity, translation, explicit facility
relocation/reconnection, all-terminal turn scoring, charged malformed/equal proposals
and best preservation after worse, invalid and late proposals. Workspace check/test
passed (536 tests passed, two pre-existing ignored). Python regression tests passed
with the explicit native library (148 passed, three platform skips). The first
Python invocation omitted that environment flag and skipped native tests; only the
subsequent explicit-library result supports the regression claim. CLI help, actual
`check` and `replay`, independent audit and tracked-file checks passed.

Development caught and fixed the chain importer's map/array dialect difference and
the neutral port-projection schema constant. No game pruning rule was added.
The signed-coordinate normalization and single-cell component guard are explicit;
non-single-cell logistics components remain unsupported by this validation boundary.
The deadline prevents late commits but does not preempt a running validator. Power,
startup, learned policy quality and production release readiness remain outside this
slice's evidence.

cargo build --release -p aic-pilot-native
cargo build --release -p aic-cli --bin aic-witness-probe
python tools/factory-edit-pilot/full_factory_matrix.py \
  --inputs artifacts/factory-edit-pilot/full-factory-inputs-verified/inputs.json \
  --native-library target/release/libaic_pilot_native.dylib \
  --output artifacts/factory-edit-pilot/full-factory-matrix-reproduction

  --request artifacts/factory-edit-pilot/full-factory-inputs-verified/closure-original/request.json \
  --initial artifacts/factory-edit-pilot/full-factory-inputs-verified/closure-original/initial.json \
  --catalogs artifacts/factory-edit-pilot/full-factory-inputs-verified/catalogs.json \
  --native-library target/release/libaic_pilot_native.dylib \
  --proposals artifacts/factory-edit-pilot/full-factory-heavy-proposals.jsonl \
  --max-proposals 7 \
  --output artifacts/factory-edit-pilot/full-factory-heavy-replay-reproduction
