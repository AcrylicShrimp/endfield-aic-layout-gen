# Rust Observation Geometry Trial

Status: positive bounded experiment, 2026-09-08. Retain the explicit native benchmark; normal
training still selects the Python environment. The user requested a Rust adoption trial and
then explicitly requested updating the server's default Rust toolchain.

## Result and scope

One PyO3 call now builds draft/base facility occupancy, network/directed-arm/terminal raster
channels and dynamic object rows. Rust owns immutable runtime-derived metadata and copies the
required snapshot geometry during each call. Returned arrays own their storage. State ownership,
candidate generation/features, NumPy coordinate channels, stats, transitions, reward and independent
acceptance remain in Python. No game data, action pruning, neural model or training allowance changes.

This is a meaningful bulk operation, but a partial environment migration. Input conversion is
included in observation time; its cost has not been isolated from native geometry computation.

The final server comparison uses Rust 1.98.1, Python 3.12.13, PyTorch 2.14.0+cu130, NumPy 2.5.3,
the RTX 5090, and the existing 16-thread setting. Each input has 256 recorded commands. Eleven
alternating measured pairs follow warm-up. Prior-trial garbage is collected before each setup;
automatic GC stays enabled throughout replay. Environment construction is reported separately.

Environment-only observation time falls from 0.045122/0.050749/0.068347 s to
0.027705/0.032524/0.048164 s, respectively (29.5–38.6% lower). With CUDA inference interleaved,
the initial input spends 0.052457 s in Python observation versus 0.034900 s native; inference
itself stays 0.139110 versus 0.138843 s. The smaller total gain reflects the limited migrated
fraction. It does not demonstrate that language-boundary overhead cancels the native benefit.

The CUDA replay includes input preparation, completed transfers, forward evaluation, CPU
sampling, candidate/observation construction, state updates and validation. Inferred actions
are discarded so both variants execute exactly the retained state sequence. PPO updates and
sampled training quality are not measured; these are not full-training speedup claims.

## Timing contamination and interpretation

Initial fresh-environment comparisons without explicit prior-trial cleanup produce bimodal
times separated by roughly 35–60 ms. Their CUDA medians misleadingly favor different variants
on different inputs: initial 0.290857/0.307434 s, later 0.363046/0.343395 s, elongated
0.464426/0.493664 s (Python/native). These results are retained, not discarded from the record.

A follow-up with GC callbacks reproduces the initial-input reversal (0.283443/0.303189 s).
Slower calls have an additional generation-two collection of approximately 36–40 ms; faster
calls have one such collection across the entire call, slower calls have two. Inference remains
approximately 0.135 s in both variants. The fresh-environment benchmark leaves cached bound-method
cycles and diagnostic objects for later collection, allowing prior trials to affect the next one.

The final table explicitly collects prior garbage before setup for both variants, with automatic
collection still enabled during the timed loop. Environment-only initial ranges narrow to
0.1253–0.1269 s Python and 0.1073–0.1087 s native. GC records cover the entire replay function,
including untimed setup and diagnostic serialization; they must not be subtracted from the loop
clock. This is a controlled replay result, not proof about GC behavior in a persistent training
environment. Full sampled training remains a later integration check.

## Parity and verification

All 768 distinct retained transitions across initial/later/elongated inputs match in candidate
order, observation shapes/dtypes/bytes, transition outputs and final draft/base/best states.
The final two matrices repeat this check 12 times per input, including warm-up. Six boundary
tests additionally cover the improving witness, rotations with bound ports, unbound terminals,
negative and large coordinates, stale candidates, resource guards, invalid geometry/arithmetic,
and returned-array ownership. Local replay also passes on all three retained local inputs.

Local Python: 26 passed, three CUDA/compiler skips. Server Python: all 29 passed against the
release extension. `cargo fmt --all`, `cargo check --workspace`, `cargo test --workspace`, and
worktree/index artifact checks pass. The crate uses checked geometry/allocation arithmetic and
inherits the workspace unsafe-code prohibition. Python extension type errors remain ordinary
binding errors; semantic geometry failures use `native.input` or `observation.resource_guard`.

The server's default stable Rust and Cargo were updated from 1.94.1 to 1.98.1 at the user's
request. Final server measurements were rebuilt and rerun after that update completed. The
earlier separately installed 1.95.0 toolchain was only used for a preliminary probe; it is not
selected by the final build. The workspace retains Rust 1.95 as its minimum supported version.
Local comparison used Rust 1.98.0 and Python 3.14.7.

## Reproduction and decision

Follow the native build commands in `tools/factory-edit-pilot/README.md`. Run
`native_observation_benchmark.py --case <case> --config <config> --input <initial.pt> <late.pt>
<elongated.pt> --native-library <release-library> --output <fresh-directory> --repeats 11
--collect-before-replay`; repeat with `--cuda-inference`. Omit the cleanup flag to reproduce
the cross-trial GC investigation. Source/input/library hashes and compiler/runtime versions
are recorded in each result. No release library or raw observation payload is committed.

The measured improvement justifies retaining this small native boundary. A larger migration
should let Rust own evolving state and move candidate generation/indexing/validation in cohesive
steps, with the Python implementation retained as an independent semantic oracle. The current
experiment supplies neither a complete native environment nor a new training backend. Its
results justify further investigation, not an assumed speedup for a full port.
