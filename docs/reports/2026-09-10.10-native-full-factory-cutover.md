# Native full-factory caller cutover

## Result

The current PPO harness, PPO study workers, evaluation and fresh-start setup now
use the retained `FullFactoryRuntime`/`FullFactoryEpisode` Rust API. Python calls
`observe(include_critic)` and `step(handle, index)` directly. It no longer copies
factory witnesses, builds candidates or observation arrays, updates selection
memory/history, or invokes the Node executor in this path.

`native_factory_runtime.py` only loads and verifies the native build, loads
catalogs and translates cold configuration. It does not adapt the previous
`FactoryEpisode` interface. Historical Python/Node research scripts and migration
oracles remain explicitly separate; use their frozen runtime for old experiments.
The old environment and Python observation module are labeled as reference code.

Fresh generation calls the same Rust wiring and construction CLI with the same
source plan, rates, target supplier and constructive bounds. Its immutable request
ledger comes from wiring, with exact rational sums and the original internal-then-
external terminal order. Native admission validates recipe margins and complete
geometry. Setup samples native kind/index arrays with the existing Python RNG.
The actual randomized current layout is reopened as the training start.

This preserves the constructive-planner policy and the September 2 production
design: the production constructor and its transactional downstream-closed growth
are unchanged. No facility-only global placement, solver fallback, new canvas
bound, route-order change or relaxed terminal acceptance was introduced.

## External contract and interruptions

- New harness protocols/checkpoints use `ppo-training-harness-native-v2` and
  `backend: retained-full-factory-native`. The source guard rejects an older
  protocol before collection/resume and identifies the frozen-checkout workflow.
- Generation records and acceptance references use schema 2. A reference records
  the immutable request hash and native acceptance; it no longer pretends a Node
  coverage probe was executed. Request/layout DTOs and their compact file bytes
  retain their previous schema and identities.
- Actor/critic parameter names, array meanings, experience schema, sampling,
  kind balancing, rewards, PPO/GAE and optimizer behavior are unchanged.
- Complete episodes and learner checkpoints remain the resume boundary.
  Interrupted collection/setup exports partial trace and accepted current/best
  geometry once on failure. Incomplete work is not published as a completed
  result. There is no new mid-episode snapshot/restore API.

The removed work is substantial: no per-worker Node process, whole-state RPC,
Python snapshot/identity cache, per-candidate Python geometry hashing, Python
history bookkeeping or Python raster/graph assembly in ordinary collection.
Native-owned arrays are retained directly in the existing experience payload.

## Verification

- Existing retained behavior: all five selected 32-action episodes match complete
  actor/critic experience hashes and physical/sampling traces. All 32 fresh draws
  in the 24-worker batch match request/start file hashes and physical/sampling
  traces across 1,024 actions. See the [second profile](2026-09-10.11-native-ownership-profile.md).
- Actual native-v2 readiness CLI: `current-history-16`, seed 17, two workers,
  two training batches of two eight-action episodes and three two-episode
  evaluations; CUDA learner, one PPO epoch, tracking disabled. All ten episodes
  complete. Standalone native audit reopens all starts/bests, checks behavior
  probabilities/values and exactly reproduces the second update from a checkpoint
  with nonempty Adam state.
- Deliberate interruption after two PPO edits preserves two trace rows, partial
  experience and native-valid current/best layouts without a completed episode.
  Setup interruption after one edit preserves its current/best/trace without a
  completed generation. These are cold evidence exports, not resume snapshots.
- Manual final generation matches the frozen copper-liquid start bytes; lowering
  the explicit experiment facility guard returns `family.instance-guard` with
  structured stage/severity/entity diagnostics.
- `cargo check --workspace`; `cargo test --workspace`: 541 passed, six explicit
  historical/migration tests ignored. No Rust code changed in this caller slice.
- `AIC_NATIVE_LIBRARY=$PWD/target/debug/libaic_pilot_native.dylib
  tools/factory-edit-pilot/.venv/bin/python -m unittest discover
  -s tools/factory-edit-pilot -p 'test_ppo*.py'`: 44 passed. An initial run used a
  stale local release library and correctly failed its source guard; explicitly
  selecting the current build resolved it. No guard was bypassed.
- Artifact worktree/index checks pass before commit. Unrelated cancelled-study
  drafts are preserved.

The checks establish the implementation and bounded harness integration. They do
not establish improved learning quality or a speed ratio for different workloads.
