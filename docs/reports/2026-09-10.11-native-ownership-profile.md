# Second full-factory ownership profile

## Controlled comparison

All five requested stages are complete. Compare this result with the
[unchanged baseline](2026-09-10.07-full-factory-ownership-profile.md) and the
[caller cutover](2026-09-10.10-native-full-factory-cutover.md).

The same Core Ultra 9 285K server, release build mode, Python/Torch environment,
single Torch collection thread, `current-history-16` actor, seed-17 batch-3
actor/critic checkpoint, batch-4 case selection and 32-action episode budgets
were used. One warmup precedes three uninstrumented repetitions per case.
Separate cProfile/native counters are diagnostic and excluded from these medians.
Collection includes experience serialization, compression and file hashing, as
in the baseline. Runtime/checkpoint opening is outside these serial medians.
Fresh generation includes construction, validation and randomized setup.

Every repetition and the separately profiled episode matches the retained full

with equal DTOs and geometry; the importer was corrected to preserve the original
compact serialization. The complete passing measurement is `after-v2`.

## Actual 24-worker batch

One batch per implementation, 32 identical fresh draws and 1,024 actions:

| Measurement | Before | After |
| --- | ---: | ---: |
| Collection window, including fresh generation | 29.046 s | 4.131 s |
| Worker startup | 2.060 s | 1.792 s |
| Whole measured batch lifecycle | 32.155 s | 6.853 s |
| Peak sampled aggregate RSS | 30.38 GiB | 26.39 GiB |
| Maximum related process count | 59 | 27 |

The collection window is 7.03x faster; the measured lifecycle is 4.69x faster.
RSS falls 13.1%. All 32 results match retained generation and physical/sampling
identities. Mean area reduction is the identical 25.328826%, not new learning
evidence. The sample has two to 26 facilities. This is one controlled batch,
not a repeated throughput distribution or an extrapolation to 59-facility cases.

The native batch uses a fresh native-v2 protocol with actual executed source
identities. Its checkpoint explicitly imports the retained actor/critic weights
for read-only comparison, records the original file hash, and has a new envelope
hash. It is not presented as an ordinary continuation of the old harness schema.

## What remains expensive

The largest case's separate profile measures about 0.852 s in native candidate
index/domain construction, 0.140 s in action-key construction and 0.371 s in
actor plus critic forward calls. Selected execution is 0.026 s and acceptance
0.032 s. Native world/action array construction and export are individually
milliseconds. Python still pays for model execution and durable experience
serialization/compression. These nested instrumented measurements must not be
summed with uninstrumented medians or interpreted as a new throughput trial.

The previous food setup repeatedly hashed complete Python geometry inside its
candidate loop. Native setup now returns compact masks/kind IDs and retains
geometry and memory. That removed repeated work explains why fresh generation
improves much more than ordinary collection. No action-domain reduction or
changed physical acceptance was used to obtain these gains.

The much earlier directed-path Rust pilot still has different physical scope,
model and work. Its historical comparison remains in the baseline report;
these new before/after ratios apply only to the complete-factory workload above.
No additional optimization or long training run was launched.

`ownership-after-runtime`. Their imports are independent. Source/build manifests,
raw cProfile data, selected experiences/witnesses, read-only imported checkpoint,
actual native-v2 readiness run and its exact checkpoint-continuation audit are in
`artifacts/factory-edit-pilot/ownership-after-retained.tar.zst` on both server and

[manifest](2026-09-10.11-native-ownership-provenance.json). Regenerable duplicate
repetitions and batch construction visualizations were removed after successful
verification. The failed serialization-only attempt is not the reported run.
