# First CPU Factory Edit Result

Status: completed diagnostic, 2026-09-07. One fixed problem, one independent training seed.
The user requested the first visible outcome regardless of success. This report closes that
first experiment; it does not complete the longer training, model-size, or architecture study.

## Result

The 100,898-parameter CPU CNN+MLP learned a small repeatable edit on the fixed four-facility
battery factory. After 65,536 training commands, all 32 declared evaluation rollouts returned
area 147 from initial area 154: **4.545% area reduction**, with belt tiles 25 -> 24 and turns
remaining zero. The untrained initialization improved in 0/32 of those evaluation rollouts.
No GNN, demonstrations, automatic routing, or inherited learner was used.

The learned output shortens the external battery-export belt by one cell. Facility positions
remain identical. The used footprint changes from 7x22 to 7x21. This is evidence that the edit
interface/reward/PPO loop can fit this small behavior on this instance, not evidence of learned
facility relocation, general compaction, or performance on another factory.

task reward caused learning. The eventual fixed-allowance outcome increase is the useful signal.

## What the retained behavior actually does

The best training trace completes the improvement in three commands: unbind the export terminal,
erase the outer export cell, and bind the export at the remaining boundary cell. The selected
final evaluation trace uses four commands: it first adds a temporary cell, then erases that cell
with the original outer cell, and rebinds the export. Both outcomes independently validate.
There is no reward for shorter scripts, so an unnecessary intermediate edit is unsurprising.

The policy continues editing after an improvement. Of the 512 training episodes, 509 end with
an unfinished private draft; the returned episode-best factory remains complete and valid.
This is permitted by the declared environment. Do not present retained valid output as evidence
that the last private draft is complete or that the policy learned to stop editing safely.

The separate six-command environment witness reaches area 140, a 9.091% reduction, by shortening
the two raw-input tails. It was checked before training and never used as a training label,
reward term, or candidate-ordering hint. The learner did not reach this known better result.
The witness is not a proven optimum, and neither result establishes a capacity ceiling.

## Configuration and cost

Source implementation: `42ade74`. See the [execution contract](../designs/2026-09-07.02-fixed-factory-pilot-execution.md)
and [CLI/configuration](../../tools/factory-edit-pilot/README.md). The four recipes, exact rates,
geometry, and port definitions use the external normalized catalogs. The fixture preserves all
request obligations. The first geometry domain is explicitly non-crossing, non-branching belt
paths, with no pipe or transport-cycle coverage.

- CPU only; PyTorch 2.14.0, Python 3.14.7, arm64 macOS; one PyTorch intra-op and inter-op thread.
- CNN channels 16/32/32, 24 object rows through a shared width-32 MLP, width-64 fusion/command
  scoring, shared policy/value features; 100,898 total trainable parameters.
- Seed 17; PPO/Adam learning rate 0.0003; 256-command rollouts, four epochs, minibatches 64;
  gamma 1, GAE lambda 0.95, clip 0.2, value coefficient 0.5, entropy coefficient 0.01.
- 4,096 optimizer steps. 65,536 training commands and 20,480 evaluation commands.
- Reported training elapsed time: 343.83 seconds; checkpoint evaluation time: 32.51 seconds.
  The training elapsed counter includes checkpoint/plot/startup overhead and excludes evaluation;
  it is not pure optimizer time or a controlled cross-hardware benchmark.
- Optimizer updates: 236.22 seconds; inference: 21.75 seconds; observation construction:
  38.23 seconds; candidate enumeration: 19.09 seconds; environment steps: 10.60 seconds,
  including 5.50 seconds of final acceptance checking. Nested timings must not be double counted.
- 7,480,705 candidate commands enumerated during training/preparation; all submitted commands
  in the recorded training/evaluation runs applied mechanically. Peak process RSS: 873.75 MiB.

The first comparison includes the retained initial layout and the model's own untrained
initialization. Separate random/search controls and independent training replications remain
unrun. Observed 32/32 repeatability on this one checkpoint is not universal reliability or a
generalization claim. The next question can be further fit on this same instance, followed by
the predeclared size ladder; a larger model is not justified as necessary by this result alone.

## Verification and diagnostic correction

Before training: ten behavioral tests passed, the admission CLI accepted both initial and
witness layouts, and `cargo check --workspace` / `cargo test --workspace` passed. Tests include
actual relocation/rerouting, invalid request coverage/capacity, incorrect port/boundary geometry,
disconnected transport, discard/reset, non-mutating rejection, padding-invariant logits, and
finite PPO updates. Every evaluation export was checked independently during the run.

After training: five retained layouts and seven retained command traces passed a separate audit.
Replayed candidates, transitions, rewards, and final scores match. The recorded source/catalog
hashes all match commit `42ade74`. The metadata's base Git HEAD predates the source commit because
the first run started from that worktree; its file hashes, rather than that base HEAD alone,
identify the executed source exactly.

Local inspection found that the original `new_completion` diagnostic counted restoration of a
previously validated base, including discard, as a new completed edit. Corrected it to compare
against the prior valid base and added a regression test. This field does not feed observations,
rewards, value targets, best selection, or action generation. The original raw counters remain
unaltered and must be interpreted as closures including restoration. Replay finds seven such
counter differences in the selected traces, with no change to geometry, rewards, or outcomes.
Current verification passes eleven Python tests and all Rust workspace checks/tests.

The final geometry figure also uses one shared coordinate scale across panels, and empty
pretraining legends no longer warn. These are reporting changes after the original learning
run; no model was retrained or checkpoint selected using the correction.
