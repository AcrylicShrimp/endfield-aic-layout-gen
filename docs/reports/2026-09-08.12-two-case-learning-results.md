# Two-Case Learning Results

Status: complete, 2026-09-08. All nine declared runs and their independent audits completed
at source `4d7286e`. No architecture, reward, input, seed or allowance was retuned after seeing
learning outcomes. Follow the [predeclared protocol](../designs/2026-09-08.05-two-case-learning-experiment.md).

## Result

Adding B did not produce an observed learning benefit at either matched total allowance or
matched per-case exposure. All three training seeds (17, 29, 43) returned 0% area improvement
on both A and B at every checkpoint in all three conditions. There were no positive rewards
in the entire 786,432-command training matrix or the 393,216-command frozen evaluation matrix.

| Training condition | Total training commands | A exposure | B exposure | A evaluation reduction | B evaluation reduction |
| --- | ---: | ---: | ---: | ---: | ---: |
| A-only | 65,536 | 65,536 | 0 | 0% | 0% |
| B-only | 65,536 | 0 | 65,536 | 0% | 0% |
| A+B, equal total allowance | 65,536 | 32,768 | 32,768 | 0% | 0% |
| A+B, equal case exposure | 131,072 | 65,536 | 65,536 | 0% | 0% |

Every entry is 0% separately for each of the three independently trained models, not only an
average hiding successful seeds. Every checkpoint evaluates 32 action-sampling seeds on each
case. Improvement frequency and the frequency of two or more positive improvements in one
episode are both zero. Training champions also remain the original roots, so this is not a
case where a successful training discovery was later forgotten by the frozen policy.

Case A stays at `(154,25,0)` and B at `(385,50,2)`. No returned best layout contains a learned
facility relocation. Private drafts do include editing and placement attempts; those attempts
must not be presented as complete valid factory improvements.

Earlier experiments did learn an A policy reaching `(147,24,0)`. These fresh A-only controls
did not reproduce that success. Consequently, this matrix does not establish that diversity
is intrinsically ineffective or harmful: the single-case controls also failed to acquire their
first positive signal. It demonstrates failure to discover an improving edit under this
declared initialization/training budget, not optimality, convergence, model-capacity limits,
or global infeasibility. The user had declined further investigation of tiny GPU numerical
differences; no numerical repeatability campaign was added.

## What changed in B

B preserves the exact production request, four facility/recipe identities, utilization, items,
rates, network identities, feature categories and external catalog data. Only the starting
geometry/bindings/paths differ. Facilities have larger gaps, the powder path has two turns, and
the import/export tails are longer. Its initial used footprint is 11 by 35, compared with A's
7 by 22. These are measured occupied bounds, not planner input limits.

The separate 21-command witness produces five successive complete positive improvements:
`385 -> 363 -> 341 -> 319 -> 297 -> 275`, ending at `(275,36,2)`, a 28.571% area reduction.
The first three closures shorten the battery export; the next two shorten both import tails.
The witness is a feasibility check, not a training demonstration or an optimum. It retains the
inefficient facility gaps and bent internal route. A's original six-command witness still
reaches `(140,21,0)`.

More available improvement does not imply easier discovery. The native initial action domain
contains 34 commands for A (21 erase, 12 unbind, one discard) and 83 for B (70 erase, 12 unbind,
one discard). Later domains depend on the private edits. Thus B simultaneously introduces
different geometry, more choices and different normalized reward sizes. The experiment cannot
attribute outcomes solely to pattern diversity. All witness commands remain inside the actual
model action domain, and their positive rewards pass independent replay.

## Controlled execution

The nine runs use one driver, one 100,898-parameter policy architecture, the existing CUDA learner
and eager CPU actor, 16 CPU threads, unchanged PPO settings and the same Rust-owned environment.
The server uses Core Ultra 9 285K / RTX 5090, Python 3.12.13, NumPy 2.5.3, PyTorch 2.14.0+cu130,
float32 with TF32 disabled, and the existing Rust 1.98.1 release library.

All models for a given seed have bit-identical initial parameters, verified from the actual
initial checkpoint. The comparison checks common source, runtime, catalogs, model dimensions
and configuration, excluding only the declared seed/allowance/checkpoint differences. The
seed-17 initial parameter hash is `2839a22ae7532c4225f02e72fc036dde018f441ac2cf1ebb9b4794972bab9eea`.

Each 128-command episode starts from its selected original root. Mixed collection alternates
A and B, yielding one complete episode of each in every 256-command PPO rollout. GAE uses the
episode termination boundaries. Case-specific best layouts, normalization and accounting stay
separate. This is one learner seeing two cases sequentially; simultaneous environment stepping
or batched actor inference was not introduced.

Totals are 6,144 training episodes and 49,152 Adam steps. Solo runs have five frozen checkpoints;
mixed runs have six, with both cases evaluated at each. All nine runs, evaluation, startup,
audits and comparison generation took 836.464 s (about 13.9 minutes).

## Reproduction and follow-up boundary

```sh
tools/factory-edit-pilot/.venv/bin/python tools/factory-edit-pilot/two_case_matrix.py --protocol tools/factory-edit-pilot/two-case-study.json --native-library target/release/libaic_pilot_native.so --output artifacts/factory-edit-pilot/fresh-two-case-learning
```

The matrix executes each condition sequentially, audits it, and generates the exposure-controlled
comparison. CLI usage and checkpoint/interruption scope are documented in the
[pilot README](../../tools/factory-edit-pilot/README.md). No global exact solver, constructor
fallback, reward shaping, curriculum, demonstrations or best-layout carryover were introduced.

The next decision is how to obtain useful first-success experience. Parallel collection is
compatible with PPO: its original algorithm collects T steps from N actors before the shared
update ([PPO paper, Algorithm 1](https://arxiv.org/pdf/1707.06347)). This changes wall-clock
collection capacity; total rollout size, update cadence and per-environment GAE boundaries
still require an explicit contract. Curriculum starting near success is a separate way to
make informative experience more frequent ([reverse curriculum](https://arxiv.org/abs/1707.05300)).
Neither intervention was mixed into this completed comparison.
