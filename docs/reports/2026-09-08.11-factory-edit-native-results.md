# Rust-Owned Factory Edit Environment: Final Results

Status: complete, 2026-09-08. This closes the user-requested migration goal. The production
pilot now uses Rust for all environment state/rules/observations and Python for PyTorch and
experiment orchestration. No further performance campaign is included.

## Result and scope

The release native environment reduces fixed-action replay time by 75–80% across the three
retained workloads. Including the existing CPU actor reduces replay wall time by 44–49%.
A full 65,536-command CUDA training run finishes in 45.93 s versus 73.80 s for the Python
baseline, a 37.76% reduction in recorded training time. The full runs have equal exposure but
different sampled trajectories, so the replay measurements are the controlled speed comparison.

Rust owns catalog admission, exact rational obligations, root/draft/base/best state, candidates,
all seven edits, independent acceptance, scores/rewards, episode accounting, snapshots and
complete observation buffers. Training and evaluation use the same retained engine. The
per-action boundary consists of owned arrays outward and an action index inward. Python rule
modules are isolated under `reference/` for independent audits/tests and historical probes;
the partial observation bridge and normal Python environment path are deleted.

The implementation commits are `aaf8ff5` (catalog/state/snapshots), `60165bc` (candidates/edits),
`d8bcff7` (observations), and `40b0159` (runner/evaluation/checkpoint cutover). The final server
native run and benchmarks used clean `40b0159`; the Python full baseline used clean `d8bcff7`,
before its runner cutover. Final reporting/probe sources do not alter the measured algorithms.

This is a local-edit pilot migration. It does not change the constructive planner, legal edit
domain/order, objective priority, learner, policy architecture, sampling allowance or routing
rules. Review against the constructive planner design and `AGENTS.md` found no production
constructor or global exact-solver dependency introduced.

## Controlled release replay

Server: Core Ultra 9 285K, RTX 5090, 16 PyTorch CPU threads, Python 3.12.13, NumPy 2.5.3,
PyTorch 2.14.0+cu130, Rust 1.98.1. Each input contains 256 recorded actions. The third input
preserves a formerly interrupted rollout with elongated geometry. Each implementation has a
warm-up and 11 measured repetitions in alternating order. Automatic GC stays enabled;
prior-trial garbage is collected before each replay. Values below are medians in milliseconds.

Inference is interleaved with the real environment boundary, but inferred actions are discarded
to preserve the recorded trajectory. CUDA inference is diagnostic; normal training still uses
the eager CPU actor. Observations are byte-identical, transitions match, and final draft/base/
best states match in every paired replay. Separate domain replay also checks candidate order.

Setup is outside the timed loop and reported separately: native setup loads catalogs and
verifies input identity, while the reference constructs an engine from its already-loaded
catalog. Diagnostic candidate/state export is outside the timed native loop. GC callbacks cover
the whole replay call, including setup/exports, and must not be subtracted from loop timings.
These results cover this pilot's retained inputs, not arbitrary factory sizes.

## Bounded numerical check

The initial checkpoints match exactly for model, Adam, all recorded RNG streams, exposure,
counts and champion. The first full-training PPO metrics differ at roughly the last few digits;
episode rows first differ at zero-based row 16, after 2,048 training actions. Later policy
checkpoints and outcomes differ.

`native_learning_parity.py` restores the same initial model and sampling RNG, collects the
first 256 actions through both engines, and confirms exact candidates, every observation byte,
sampled action, log probability, value, sampling RNG, transition and draft/base/best state after
every action. It then repeats the same CUDA update from identical model/Adam/minibatch/RNG state.
Four default-mode updates produce different parameter hashes; four deterministic-mode updates
produce one identical hash. The largest default-run parameter difference from its first repeat
is 0.0000798519 after 16 Adam steps. Both diagnostic modes use `CUBLAS_WORKSPACE_CONFIG=:4096:8`;
the deterministic mode additionally enables PyTorch deterministic algorithms and cuDNN
determinism. Normal training configuration is unchanged.

This confirms that identical environment/learner inputs can diverge numerically on this GPU.
It does not identify every cause of the later full-run trajectory difference. The user explicitly
declined further investigation of tiny numerical differences; no deterministic production mode
or additional optimization was added.

## Reproduction

Use the recorded native source `40b0159` with the locked Python environment and a fresh output
directory for each command. Historical Python full training uses `d8bcff7` and its original
`run.py train` without a native-library flag. Build the extension against the chosen interpreter:

```sh
PYO3_PYTHON="$PWD/tools/factory-edit-pilot/.venv/bin/python" cargo build --release -p aic-pilot-native --features extension-module
cargo check --workspace
RUST_MIN_STACK=16777216 cargo test --workspace
export AIC_NATIVE_LIBRARY="$PWD/target/release/libaic_pilot_native.so"
tools/factory-edit-pilot/.venv/bin/python -m unittest discover -s tools/factory-edit-pilot -v
tools/factory-edit-pilot/.venv/bin/python tools/factory-edit-pilot/native_engine_benchmark.py --case tools/factory-edit-pilot/case.json --config tools/factory-edit-pilot/run-server-cuda.json --input artifacts/server-setup/initial-input.pt artifacts/server-setup/late-input.pt artifacts/server-setup/interrupted-input.pt --native-library "$AIC_NATIVE_LIBRARY" --output artifacts/factory-edit-pilot/fresh-native-replay --repeats 11 --inference none --collect-before-replay
tools/factory-edit-pilot/.venv/bin/python tools/factory-edit-pilot/run.py train --case tools/factory-edit-pilot/case.json --config tools/factory-edit-pilot/run-server-cuda.json --native-library "$AIC_NATIVE_LIBRARY" --output artifacts/factory-edit-pilot/fresh-native-training
tools/factory-edit-pilot/.venv/bin/python tools/factory-edit-pilot/audit.py --case tools/factory-edit-pilot/case.json --output artifacts/factory-edit-pilot/fresh-native-training --source-commit 40b0159
```

Repeat replay with `--inference cpu` and `cuda` and distinct output directories. Input `.pt`
files are explicit retained evidence, not tracked fixtures. The final two source helpers can
be run from the reporting commit with `PYTHONPATH` pointing at the measured checkout:

```sh
python native_training_comparison.py --reference <python-run> --native <native-run> --output <fresh-result.json>
python native_learning_parity.py --root <native-checkout> --case <case.json> --config <run-server-cuda.json> --checkpoint <python-run>/checkpoint-0.pt --native-library <library.so> --output <fresh-probe-directory> --repeats 4
```

The simpler ownership boundary is the outcome of this cutover: one retained native environment,
one observation/index interface and explicit cold evidence exports. Python no longer reconstructs
or revalidates factory rules on each sampled action.
