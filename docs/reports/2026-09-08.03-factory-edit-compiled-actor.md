# Compiled Actor: Throughput, Cache, and Behavior

Status: measured, 2026-09-08. CPU inference tuning is closed for this slice; the user
prioritizes GPU execution for future larger models and investigation of Python environment costs.

## Fixed observations and compiler cost

On the server's retained elongated 256-observation input, CPU eager inference takes
0.120034 s versus compiled 0.099414 s (17.2% lower). A separate process reusing the cache
takes 0.120041 versus 0.098814 s (17.7% lower). First-pass cost falls from 7.158602 s with
a fresh cache to 2.459161 s with a reused cache. These include the measured inference pass,
wrapper setup and compilation, rather than only a compiler callback timer.

The additional CUDA probe uses the same retained input and includes input preparation,
completed device transfers and CPU sampling. CUDA batch one takes 0.122060 s eager and
0.100589 s compiled. CUDA batch two takes 0.078052 s eager and 0.067089 s compiled for the
same 256 observations. CPU and CUDA single-state compiled costs are similar; batching offers
the larger measured opportunity. The CUDA result is an actor microbenchmark, not a completed
training speedup. The planned additional CPU thread sweep was canceled before measurements.

All retained shapes and an in-place weight refresh pass eager/compiled numerical checks
with absolute/relative tolerance 1e-5. Maximum absolute logit difference can exceed 1e-5
because the assertion also includes relative tolerance. No model or precision change is made.

## Full training and quality

Both source `1535060` configurations execute 262,144 commands, 2,048 episodes, 1,024 PPO
rollouts and 16,384 Adam steps with equal exposure settings. They have identical initial
parameter tensors and saved CPU/CUDA RNG states. They do not have identical later trajectories.

| Measurement | Eager | Compiled |
| --- | ---: | ---: |
| Training seconds | 244.766 | 369.264 |
| Separate evaluation seconds | 12.783 | 16.636 |
| Actor inference seconds | 83.172 | 112.491 |
| Candidate commands generated | 19,986,478 | 42,932,984 |
| Observation seconds | 38.202 | 55.503 |
| Candidate generation seconds | 25.205 | 47.739 |
| Step seconds, including validation | 41.369 | 66.227 |
| CUDA peak allocated bytes | 731,209,728 | 2,522,764,288 |

The compiled run is slower overall. Its much larger candidate workload prevents attributing
the difference to inference implementation alone. Its setup takes 1.026 s; five compiler
callbacks total approximately 4.159 s, including four later events nested in inference.
There are three local graph-cache hits and two misses. Compilation is occasional, not repeated
on every update. Disk cache reuse does not prevent every new-shape compilation.

Eager frozen evaluation succeeds on 32/32 seeds at 65,536 and 131,072 commands, each with
4.545% mean area reduction. At 262,144 it succeeds on 2/32 seeds with only 0.284091% mean
reduction. Compiled evaluation succeeds on 0/32 at every checkpoint. Its best training score
is `(154, 24, 1)` (area, transport tiles, turns), versus the eager run's `(147, 24, 0)`. Longer training
did not yield stable quality improvement. These independent sampled learning runs do not
isolate the cause of their quality difference.

## Controlled action parity

`actor_parity.py` loads seven checkpoints (four eager including initialization and three
compiled), sharing the exact parameter tensors between eager and compiled forwards. At
every observation it clones the CPU sampling RNG and calls the actual `Policy.act` twice.
It follows the eager action through the environment and checks both output tensors and
post-sampling RNG states. Across 28,672 observations, all actions and all post-sampling RNG
states match. Maximum probability difference is 9.23872e-7; maximum logit difference is
2.67029e-5. No compiler behavior defect was observed in this controlled sample. This does
not prove universal bitwise identity or identify why the independent training runs diverged.

Both full runs pass local `audit.py --source-commit 1535060`: five layouts and six traces
each, without counter differences. Checkpoints, raw traces, compiler caches and generated
figures remain ignored under `artifacts/factory-edit-pilot/`, retained locally and on the server.

## Reproduction and next boundary

Use `actor_compile_benchmark.py --case <case> --config <config> --input <retained-input.pt>
--cache-directory <cache> --output <fresh-directory>`; add `--device cuda --batch-size 2`
for the GPU batch probe. Use `actor_parity.py --case <case> --config <config>
--checkpoints <checkpoint.pt> ... --cache-directory <cache> --output <fresh-directory>`.
The result provenance records source/input hashes and runtime details. `costs.py --runs
<long-eager> <long-compiled> --output <fresh-directory>` separates nested timing correctly.

Compiled CPU remains available explicitly. No further CPU neural thread tuning is planned.
GPU batched collection still requires the documented episode-major GAE and interruption
contract before runner integration. Python candidate/observation/environment work accounts
for 42.8–45.9% of these runs; profile its internal costs before selecting a Rust boundary.
