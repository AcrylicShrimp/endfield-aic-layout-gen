# Native Training and Evaluation Cutover

Status: implementation cutover verified locally, 2026-09-08. Release server comparison and
equal-exposure training/audits are the remaining migration evidence work, not another architecture
or optimization experiment.

## Completed cutover

Normal `run.py check/train`, frozen evaluation, layout validation and plotting use the same
Rust-owned engine. `native.py` provides setup/provenance and explicit cold exports, not an
environment adapter or Python rule implementation. The training loop calls `observe()` and
`step(handle, index)`. It exports geometry only for selected evidence, episode/checkpoint
boundaries and interruption. Native episode summaries provide counts and current acceptance.
Python continues to own PyTorch sampling/training, GAE order, rollout storage and scheduling.

The former Python environment, acceptance and command modules are isolated under `reference/`.
Only audits, migration tests and historical research probes import them. The observation-only
`GeometryEncoder`, Python bridge and obsolete experiment benchmark/tests are removed. Historical
trial reproduction uses its recorded commit. Plotting obtains validated boxes and scores from
Rust and only draws them. Evidence writing/provenance is a separate rule-independent utility.

`--native-library` explicitly selects the built release extension. The build embeds source,
manifest, build-script and lockfile hashes plus compiler/profile/target information. Startup
rejects source/build mismatches and input changes within one execution. Run provenance retains
the actual binary hash and embedded build record; audits verify it against source and the library
artifact. Worktree cleanliness is recorded separately from the Git HEAD and file hashes.

## Checkpoints and interruption

Run/checkpoint schema 2 contains the versioned native snapshot. Completed CPU continuation
checks model/runtime/configuration, Python semantic sources, native sources/build identity,
runtime inputs and champion acceptance. It restores native state alongside model/Adam/RNG state.
Only the cumulative allowance and evaluation schedule may change. Native performance measurements
restart for the new invocation; semantic episode/command totals remain cumulative.

Legacy Python schema-1 checkpoints are rejected with `resume.legacy_checkpoint`. This is an
explicit hard cut, without conversion, compatibility routing or Python environment fallback.
The supported automatic continuation scope remains a completed CPU final checkpoint with an
eager actor. GPU/compiled or interrupted PPO continuation is not newly claimed by this migration.

Interruption preserves the current native draft/base/best, scores, trace and episode accounting,
partial rollout arrays/actions/returns, learner/actor/optimizer state, all RNG streams and the
interrupted phase. A mid-collection interruption test stops after three edits, restores the
partial native episode, compares its next observation bytes with independent replay, restores
the actor and sampling state, and verifies the next transition. A separate update-phase
interruption retains the complete collected rollout without overwriting the last checkpoint.

## Verification

Local Python suite: 38 passed, three platform/CUDA skips. Completed CPU continuation matches
uninterrupted training exactly for parameters, Adam, every saved RNG state, training counts,
champion and episode rows. Invalid lineage, legacy version and false native score claims are
rejected. Stale native builds and changed runtime inputs have dedicated boundary tests.

The normal CLI preflight and native layout checker accept the root `(154,25,0)` and the scripted
witness `(140,21,0)`. A normal 32-command CPU training CLI invocation completes initial/intermediate/
final evaluation and native-validated plot rendering with an import hook that rejects every
`reference` import. This checks the entire production path for accidental Python rule fallback.
All source syntax, workspace format/check/test and artifact worktree/index checks pass.

Before the final cutover, the server release build at `d8bcff7` passed all 45 then-existing tests
and all three retained input replays, including full observation byte parity. The cutover changes
the runner/boundary/provenance and removes the partial experiment; it does not change the verified
native candidate, transition or observation algorithms.

The new `native_engine_benchmark.py` measures the actual `observe`/index-step boundary without
diagnostic candidate/layout export inside the loop. It alternates implementations after warm-up,
optionally collects prior-trial garbage before setup while keeping automatic GC, and compares
all observation bytes, transitions and final states after timing. CPU or CUDA inference can be
interleaved while following fixed recorded actions. Native catalog/setup/identity checks are
reported separately; the reference reuses its already-loaded catalog.

An initial local 256-action check measured median environment replay of 0.117263 s Python versus
0.017303 s native over three measured pairs. This is only a local first-input smoke measurement,
not the final server or full-training result. The final evidence will distinguish environment
compute, array export, inference, PPO and total training wall time.

## Architecture review

Rust now retains state throughout an episode and owns all rule/observation work. Python has one
native observation/selection path for both training and evaluation and explicit evidence exports.
The obsolete partial bridge and normal Python rule path are gone. No production constructor,
frontier growth, route search, global exact dependency, legal candidate, objective priority,
sampling RNG consumption or learner exposure was changed. This remains the local-edit pilot
per the ownership design, constructive planner design and `AGENTS.md`.
