# Batched Collection Probe

Status: measured, 2026-09-08. No training-runner cutover.

Five alternating measured repetitions follow a warm-up. Each collects 256 commands from
fixed policy weights and a reset CPU sampling generator, with unchanged 128-command episodes.
Every selected command stream is replayed and every best layout independently accepted.

| Policy input | CPU serial s | CPU batch two s | CUDA batch two s | CUDA batch two inference mode s |
| --- | ---: | ---: | ---: | ---: |
| Initial | 0.234971 | 0.257077 | 0.249073 | 0.217960 |
| Later | 0.280523 | 0.354892 | 0.258810 | 0.253726 |

CUDA batch two with inference mode improves complete collection by 7.2% and 9.6% compared
with CPU serial on these probes. Initial candidate counts are 37,888 serial versus 39,252
batched; batching changes which RNG draws each independent episode receives. Per-episode
streams, exact actions, costs and final states remain in the result JSON. Environment creation
and independent audit are outside timing; the timed loop includes generation, observation,
completed inference/transfers, sampling, steps, trace records and resets. Environment caches
start cold for each measured rollout. This does not establish long-running trained throughput.

The user steered the ongoing work toward compiled CPU inference and cache amortization.
Complete that simpler execution change before deciding whether the additional collection
contract is worthwhile. A future GPU collector must flatten streams by episode before GAE
and retain every partial environment on interruption; this benchmark does not implement that
runner integration. See the corresponding stage contract.
