# Native snapshot cost before bounded tree search

Status: cost measurement complete; no MCTS or search-quality result.

On an Apple M4 arm64 host, release native engine at source `a98cb4d`, the declared
training-only cost instrument completed 64 eight-command random branches for each of
16 frozen training cases. All 8192 simulated commands and 9216 restores were charged
outside snapshots; no wall or snapshot-byte bound fired. The separate original
engine remained byte-for-byte unchanged in every case.

| Operation | Calls | Total seconds | Mean microseconds |
|---|---:|---:|---:|
| Full JSON snapshot export | 8192 | 0.07999 | 9.76 |
| Full validated restore | 9216 | 0.35686 | 38.72 |
| Candidate generation | 8192 | 0.19116 | 23.34 |
| Observation export | 8192 | 0.12615 | 15.40 |
| Native transition | 8192 | 0.07845 | 9.58 |

Measured branch-loop time sums to 0.84910 seconds across cases. This excludes runtime
initialization, provenance collection and report writing, and includes no neural
inference, tree allocation, final layout validation or independent replay. It is not
an end-to-end search throughput claim or a prediction for the training server.

These shallow random-state samples support trying bounded lookahead: snapshot restore
alone is not a large cost on this host. They do not establish that sparse rewards,
tree memory, deeper branching or policy inference will be tractable. The byte guard
limits a serialized payload, not process RSS. Retain the existing engine contract;
there is no evidence yet that an unsafe partial-state shortcut is needed.
