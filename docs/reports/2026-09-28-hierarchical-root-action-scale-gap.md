# Hierarchical root action scale gap (local inspection)

## Finding

The native learning domain can page legal placements on a 320 × 320 canvas, but the hierarchical Gumbel root still asks `ensure_node_expanded` to exhaust every placement page. `Factory::placement_actions` appends all commands to an unreserved `Vec` before `apply_scoring_children` or the node edge reservation. The latter applies every action to a copied child state and stores one feature, entity index and anchor score per action. `score_action_rows` then builds one outer-model action tensor and normalizes priors over the complete list. Gumbel selection creates full eligible-ID, initial-prior and noise collections. Finally, each `RootRecord` copies every action and policy target. A paged native domain alone therefore does not bound the actual root workflow.

The current Gumbel root would try to materialize all legal placement actions, and the finite tree-memory cap is checked too late. The first unreserved `actions.extend` or outer tensor can exhaust host memory before a typed resource stop.

## Contract at risk

- A root candidate shortlist is a search budget, not a spatial or legal-action cap. Dropping unvisited legal placements solely to fit a small list changes both the behavior policy and the training target.
- Current Gumbel root target uses the frozen initial eligible action IDs and priors, then a completed-Q transform after simulations. Widening can append late actions, but those receive zero target mass for the current root budget. Any streamed replacement must preserve this identity and eligibility rule or explicitly version a changed target.
- `RootRecord.actions` and the outer optimizer consume a dense per-action target. A search-only streaming selector would leave an unresolved training and publication memory cliff.
- `outer_model::Batch::from_rows` and the model's segmented softmax currently assume the complete action rows for a state are in one batch. Repeated graph encoding for each small action chunk would regress the existing inference path; an efficient scored-action boundary must reuse the encoded state or prove a comparable integrated cost.

## Current root and optimizer trace

The native Place domain pages are interleaved by per-block pose rank. `placement_actions(..., exhaust_placements=true)` drains every Place page and then every PlaceTerminal page before lower route witnesses are appended. `apply_scoring_children` clones and applies every resulting action, keeps a 49-float feature row, entity index and anchor score per action, and updates the exact-value maximum from each child. `score_action_rows` normalizes anchor scores over all actions, constructs one `OuterBatch`, encodes the graph once, scores the full action tensor and normalizes its logits over all actions. The prior is a fixed mixture of model and anchor distributions.

At Gumbel entry, the initial edge identities and mixed priors are frozen. The current rank-noise mode assigns deterministic noise by the current action index; the action-identity mode hashes each physical ID. Anchor quota and Gumbel ranking both sort full index lists, retaining a bounded shortlist only after those lists exist. Sequential halving simulates only shortlisted identities, while completed-Q computes a common value for every unvisited eligible action and uses visited Q values for the shortlist. The final target normalizes the frozen mixed prior multiplied by the exponentiated completed-Q transform over every initially eligible action. Later widened actions receive zero target mass for that root budget.

`RootRecord` copies every root action, prior, visit count, Q value and target, and the generation loader later replays every copied action to reconstruct its feature row. `OuterExample` keeps full feature, entity and target vectors. The optimizer flattens them into one `OuterBatch`, runs the same full graph and action forward pass, and applies dense `-sum(target × logp)` policy loss. A successful stream conversion must therefore handle both inference normalization and the optimizer gradient; changing only root selection would still leave the dense replay and training peak.

Mathematically, a two-pass streamed policy can preserve the present Gumbel target: the first pass obtains both policy and anchor normalizers from one encoded state, and the second computes normalized mixed priors while retaining only a bounded top-K shortlist. Once simulations finish, all unvisited eligible actions share one completed-Q transform, so their target mass can be represented by a common multiplier plus the frozen prior stream; only visited shortlist actions need Q overrides. This is a candidate design, not a completed implementation: frozen priors must survive collection/replay without an unbounded record, and chunked training must preserve the exact full-softmax gradient while reusing the encoded graph. The complete streamed search, replay and backward costs remain unmeasured locally.

## Established interfaces considered

- [Gumbel AlphaZero / MuZero](https://openreview.net/pdf/4f2c0c813d0fbe127329c69b1ba216fbcd95d52c.pdf) uses Gumbel top-k and sequential halving for the search shortlist, then a completed-action-value policy improvement. This supports separating the small simulation set from the full policy target. It does not make a dense implementation safe for millions of legal actions.
- [Sampled MuZero](https://arxiv.org/abs/2104.06303) gives a principled policy-iteration framework when full action enumeration is infeasible. It is a viable alternative only with an explicit proposal and sample-based target contract; it does not justify a fixed first page or coordinate cap in this project.
- [Rayon's indexed iterator](https://docs.rs/rayon/latest/rayon/iter/trait.IndexedParallelIterator.html) provides stable known-length iteration and bounded chunking patterns. Existing native `command_page` already supplies the required deterministic rank/order, so adding a second iterator framework offers no immediate advantage. [Roaring's rank/select API](https://docs.rs/roaring/latest/roaring/bitmap/struct.RoaringBitmap.html) is useful for comparing compact ordered membership, but its `u32` index boundary is narrower than this domain's checked coordinate/count types; it should not be introduced to hide a new size cap.
- [PyTorch autograd](https://docs.pytorch.org/docs/main/generated/torch.autograd.backward.html) accumulates gradients across backward calls and supports retaining a shared graph. A chunked exact gradient needs a fixed-policy two-pass normalizer and a verified shared-encoder backward schedule; the current `tch` wrapper and model have no such interface yet. This is an implementation requirement, not evidence that the current optimizer can stream.

## Boundary comparison and local decision

An exact streamed catalog can regenerate legal placement commands from a frozen source state and native rank, admit a small page of action rows, encode the graph once, and stream scores. The current root **stably sorts every edge by descending first-stage prior** before assigning rank Gumbel noise, so search must externally sort `(f64 first-stage prior, f64 anchor prior, u64 original ordinal)` records. The sorted stream is temporary. Replay instead retains `(f64 first-stage prior, f64 anchor prior)` in **native source order** and zips it with sequential native pages; sorted-order random rank lookups would repeatedly rebuild native pose counts. The retained source-order ledger takes about 91.4 MB for 5,715,346 actions or 1.07 GB for 66,977,600, before framing/checksums; 24 such hypothetical upper roots take about 25.7 GB. Sort run and output copies can temporarily add 3.22 GB at one hypothetical upper root, plus about 0.80 GB of raw scores/anchors. It can compute model and anchor normalizers over all initially exposed actions, then retain only the Gumbel/anchor shortlist as live search edges. A placed-action row and its child value must be derived without cloning and applying a full child for every legal pose; parity against the existing child path is required, with an admitted fallback for completion transitions. Disk admission and replay retention must therefore be explicit, not an assumed free resource. It avoids a multi-gigabyte *host-memory* action/feature/tensor peak but still evaluates and sorts the complete legal set once per root.

The frozen root target needs no dense target vector. All unvisited initially eligible actions share one completed-Q transform. Let `w_i = max(root_policy_prior_i, f64::MIN_POSITIVE)` include the **second** Gumbel anchor mixture and clipping, and let `v` be the small visited set. Stream `W_unvisited = sum_i w_i` over unvisited actions, then compute `logZ` by a max-shifted `logaddexp` over the unvisited term `log(W_unvisited)+q_0` and each visited term `log(w_v)+q_v`. This avoids overflow in large but legal completed-Q scales and cancellation when visited mass approaches total mass. A training page sequentially recovers each frozen first-stage and anchor prior from the **source-order** ledger, applies the visited override by physical identity, reproduces the dense f64 normalization and `visit_target`'s retained second f64 denominator, then casts to f32. The source ordinal, initial sorted-rank evidence for visited actions, source/catalog/config/checkpoint identities and sidecar digest determine the exact initial eligibility and order. Search-only streaming without this trainer path is insufficient.

The current outer loss is cross entropy over a full softmax. For current logits `z_i`, actual `f32` target `t_i`, its mass `T = sum_i t_i`, and full softmax `s_i`, its policy gradient is `sum_i (T*s_i - t_i) * grad(z_i)`. A first no-gradient scoring pass computes the current model's full log-sum-exp and `T`. A second, gradient-enabled page pass can use detached coefficients `(T*s_i - t_i)` with per-page logits and accumulate the resulting gradients, propagating a summed context/entity gradient through the encoder once. This is mathematically the same gradient at unchanged parameters; numeric parity against the dense path, value-loss handling, and optimizer-step timing must be demonstrated offline. The existing `tch` wrapper exposes `Tensor::f_run_backward`, and the constructive encoder already exposes its encoded context and entity tensors, but no integrated training implementation has been verified yet.

A standalone optimized [external-sort probe](../benchmarks/hierarchical-root-scale/sort-probe.rs) generated 5,715,346 synthetic `(f64 first-stage prior, f64 anchor prior, u64 ordinal)` records in 12 sorted runs of 500,000 while retaining a separate 16-byte source-order prior ledger. On local macOS the retained ledger was **91,445,536 bytes**, sort runs plus merged output reached **274,336,608 bytes**, and the combined measured file peak was **365,782,144 bytes**. Run generation/sort took 0.437 s and merge 0.316 s; `/usr/bin/time -l` reported 47,382,528 bytes maximum RSS and 1.21 s process wall time. This isolates sorting and source-ledger mechanics; it excludes temporary model logits, actual prior distributions, feature derivation, sidecar checksums and replay training. The local volume had about 11 GiB free at measurement time, below the projected 25.7 GB for 24 hypothetical upper roots. Actual upper-run storage admission therefore needs the server after the user permits it. Reproduce locally with `rustc -O --edition 2021 docs/benchmarks/hierarchical-root-scale/sort-probe.rs -o artifacts/plan00-sort-probe` followed by `/usr/bin/time -l artifacts/plan00-sort-probe 5715346 500000 artifacts/plan00-sort-work`; the probe removes its transient output after checking the sorted length/order.

A complete sampled alternative can be specified as follows. First enumerate native pages once to determine the full legal count `N`, an analytic-anchor top set `H`, and counts `n_r` by declared entity × rotation × coarse spatial region. Keep every member of `H` and every initially exposed nonplacement witness deterministically in a forced set `F`. Draw `K` ranks independently with replacement from the remaining `N-|F|` legal ranks using a seed bound to state/config/checkpoint identity; merge duplicates by rank. Every nonforced action then has inclusion probability `rho = 1-(1-1/(N-|F|))^K` and every forced action has probability one. Score only the unique sampled set with a reused graph encoding. Normalize model and anchor unnormalized weights after Horvitz–Thompson division by each action's inclusion probability, then apply the current two-stage mixture, Gumbel shortlist and completed-Q transform **within this sampled set**. This is a versioned sampled-policy target, not the current exact full-action target; normalized ratios and improved targets are not unbiased estimators of the full target even though the mass estimators before normalization are unbiased. The root record keeps selected actions, rank, inclusion probability, seed, `N`, `F`, visited Q and frozen sampled prior; replay verifies source identity and trains over the sampled actions plus any later lower witnesses with zero outer-policy target and their unchanged lower-learning evidence. Its in-memory ownership is proportional to `|F|+K`, and a memory/work refusal returns Unknown without treating unsampled actions as infeasible.

The sampled boundary has an explicit coverage test. For any region with `n_r` nonforced legal actions, its probability of at least one draw is `1-(1-n_r/(N-|F|))^K`; a single rare good pose has probability `rho`. With `K=4,096` and no helpful anchor, this is only about 0.072% at 5,715,346 actions and 0.0061% at 66,977,600. A 95% inclusion guarantee for one unknown pose needs about `3N` replacement draws, so a small uniform pool cannot establish rare-placement coverage. Offline controls must measure actual solved-witness neighborhood sizes and region probabilities on legal partial physical states, and the accepted sampler would require a declared minimum coverage probability across its intended distribution. If that threshold demands more actions than the admitted budget, it must stop as resource Unknown or switch to the exact contract through an explicit configured policy version; it cannot silently lower the threshold. No such physical coverage evidence exists yet. This is why the exact streamed boundary remains the provisional local candidate despite its storage cost.

## Provisional decision and remaining gates

The [reviewed exact catalog design](../designs/2026-09-28.00-streamed-root-action-catalog.md) is the provisional candidate. It covers enumeration, score pages, stable sort, Gumbel shortlist, frozen target, source-order replay and streamed gradient. Independent design reviews corrected a sorted-ledger random-replay cost, missing anchor prior ownership and persistent-identity gaps. The scorer has bounded parity tests and complete score-only local traversals; an integrated exact catalog and trainer cost gate, and representative upper physical/GPU evidence later under renewed server authorization, remain. A sampled-action policy remains a versioned alternative if exact storage or elapsed cost fails admission; a fixed first-page or top-coordinate cap is not acceptable.

No training server was used. The existing 30/100 placed panels and synthetic 256 graph remain useful bounded probes; final upper physical and GPU measurements remain later gates.
