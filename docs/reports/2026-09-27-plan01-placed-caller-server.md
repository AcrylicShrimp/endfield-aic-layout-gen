# Plan .01 placed-factory caller comparison

## Question and setup

The synthetic 256-facility caller calibration in [the local closeout](2026-09-27-plan01-one-shot-caller-closeout.md) found 2–3 ms before and 12–14 ms after the replay work, but did not represent placed factories. This follow-up measures the same public route-candidate harness on four actual generated physical layouts: 30-facility branching and 100-facility compact, balanced and spacious trees. All contain belt and pipe connections; the selected cases install 38 or 90 routes before requesting one more. The bounds are 73×79, 107×99, 141×124 and 210×194 cells respectively. These are performance samples, not the eventual training-distribution admission proof.

The panels derive from the retained `visual-qa-final-20260916` layouts under ignored `artifacts/layout-generator-v2/`. `build_panel.py` under ignored `artifacts/plan01-placed-input-20260927/` applies all poses and every selected route through ordinary `Place`, `BeginRoute`, `ReserveBridge`, `Extend` and `Connect` commands; the route candidate request follows the accepted prefix. Panel candidate configuration: one output, up to eight searches, 20,000 expansions per search, 160,000 total expansions, four crossings, overlap penalty eight. Prefixes and exact panels are retained locally in that artifact directory. Both source trees used the same normalized game data and Rust release `learning` feature on `ashrimp-arch`, under `~/Srv/plan01-placed-20260927`. The server had no active GPU jobs and about 152 GiB free before build.

A second dedicated checkout under `~/Srv/plan01-root-timer-20260927` applied the same temporary timer to both trees immediately around `Session::route_candidates`, so prefix replay and candidate application are excluded from that timer. The timer script `instrument_root.py` has SHA-256 `eba7d15dd5023ceed6628b6031b53ef7ec493144d5ce7317c13729050da665db`; the resulting `route_candidates.rs` has SHA-256 `e50b40f0a667b19e90da40751b277cbb39800245f7e5ca16237d4c206b282ff4` in both trees. It emits nanoseconds to standard error after the call. The local `server-export/root-timer-results.tar.gz` (SHA-256 `0a0842c2e997b77c081c767ad0f9d359b2758d40e17566cb288744f01bbb3dce`) retains every raw timer and report.

Baseline source is committed `b76c4bea9bfbe3a10998df221e6bfab9e8040ac4`. Current source is the uncommitted worktree snapshot whose `crates`, `Cargo.toml` and `Cargo.lock` archive has SHA-256 `48064c29f7aae43af0e4d0b3edb3c729cfaaf95271fc0832bfa5be4b2feb6ec3`, retained as ignored `artifacts/plan01-placed-input-20260927/server-export/current-measured-source.tar.gz`. Both revisions returned the same termination, endpoint count, candidate path length/turns/bridge summaries, search count, expansions and preflight expansions for each panel. An offline comparison of the retained `server-results.tar.gz` verified all 16 baseline/current run pairs (runs 2–5 for four panels). For every successful pair, the candidate arrays had identical **cell and step counts**, full bridge arrays, source/target ports and later-route completion/survival fields. All successful cases requested zero later routes, so the matching survival fields are vacuous. The spacious panel had zero candidates in both versions for all four pairs. The harness serializes `cells` and `steps` as counts, not sequences, so this archive cannot prove exact route-cell or command parity. Candidate SHA-256 differs on the successful panels because the current candidate serialization adds `physical_cost` and changed charged-work/provenance accounting; these results do not establish full candidate-byte parity. Current request peak is close to baseline in the balanced case, while charged copied bytes and validation records differ materially because the implementation changed. The placed cases show roughly 0.8–3.4 ms more root-caller time, not the synthetic 10-ms gap. The spacious case is censored by its deliberately finite 160,000-expansion budget in both trees, so it provides cost continuity evidence but not route success evidence.

Verdict from the server archive alone: the placed-input root-caller discontinuity is 0.8–3.4 ms in these four requests, with no observed candidate count, bridge, port or completion regression. The specific synthetic 10-ms caller gap did not recur here; the archive could not establish exact route-cell parity or broad distribution throughput. Plan .01 still requires the terminal validation first-turn bound and independent implementation review. Plan .10 owns full retained search-to-publication throughput and distribution-scale tests; final model exposure must include varied physical area and topology, not only this panel.
