# PPO execution after removing repeated training validation

The optimized CPU path preserves the actor/critic architecture and PPO credit
while removing duplicate optimizer reconstruction, behavior-network replay,
observation rehashing and repeated mask/reward validation from normal updates.
Collector output is trusted within the execution pipeline; schema and behavior
version checks remain at the batch boundary. The finite gradient-norm guard
uses the norm already required for clipping, before either optimizer steps.
Mathematical and replay checks run in standalone tests.

Actor and critic observation construction now share the full pre-action data.
A bounded cache reuses identities of immutable native snapshot objects. The
actor batches candidate/member processing. The critic groups equal-sized
rasters without padding, concatenates disjoint graphs with offset indices and
preserves per-world pooling. A microbatch of eight accumulates gradients within
the same shuffled 64-selection Adam minibatch. Parameter names, model shape,
GAE, behavior denominators, clipping and optimizer-step boundaries are unchanged.

## Measured CPU results

The final comparison uses the same retained seed-17 batch-8 minibatch and
preceding nonempty Adam state. Each learner cell has one warmup and three
independently reset timed updates. Collection runs twice per implementation on
one representative native episode, including experience serialization.

| Work | Reference median | Optimized median | Time reduction |
| --- | ---: | ---: | ---: |
| 64-selection learner update | 0.4356 s | 0.4100 s | 5.9% |
| 32-selection native collection episode | 3.3786 s | 2.7830 s | 17.6% |

These are small-sample local measurements, not complete training throughput.
The earlier microbatch screen covered 1/4/8/16/64; eight gave a reasonable CPU
memory/latency choice. The measured CPU batching gain is modest. Removing the
second full optimizer execution is a separate structural saving; these timers
do not include or claim to measure that saving. The original confirmation's
combined update/reconstruction timing must not be silently divided into an
independently measured update latency.

The representative optimized actor/critic gradients differed from the sequential
reference by at most 8.75e-8 and 6.61e-9. The only parameter difference above
1e-7 was the actor's final scalar score bias (1.87e-5). That common offset cancels
from every action distribution; Adam amplifies roundoff in its theoretically
zero gradient. Tests therefore compare all other parameters and actual post-
update probabilities, rather than demanding equality of that arbitrary offset.
Before-update recorded log probabilities and critic values also matched the
batched calculation within declared tolerances.

Both collection implementations reproduced the original actions, physical
trajectory and every stored actor/critic observation. The native integration
check then collected two distinct retained factories per batch under the current
policy, executed two on-policy 64-selection batches with four optimizer steps
each, and saved/reopened nonempty actor/critic Adam and shuffle state. Continuing
from that checkpoint reproduced model, optimizer, shuffle, credit and epoch
metrics exactly. That bounded duplicate continuation is a test, not normal
training behavior. Extra native start/best and experience audits run only in
this integration check. Its total time was 13.03 seconds; the two normal updates
took 2.38 and 2.06 seconds.

Six optimized-path tests cover variable-size forward/gradient equivalence,
per-factory independence, scaled masked entropy, complete PPO credit/update
parity, exact nonempty checkpoint continuation and absence of behavior/hash
replay during credit loading. The six historical PPO tests and the reference
minibatch test also passed. Workspace check/tests and tracked-file checks passed.

During implementation, a missing mask-digest import and integration-test artifact
metadata/directory omissions were fixed. The final successful runs above include
those fixes. Neither earlier failed trial is reported as successful. The unused
sequential device/AMP CLI was removed from the reference helper before committing;
its measured helper functions remain available for the next optimized probe.

Use fresh output paths for new runs. The profile, successful benchmark,
integration evidence and their original source snapshots are retained in the
[compact provenance manifest](2026-09-10.02-ppo-optimization-provenance.json).
The model utilities remain independent of the historical frozen study runner;
there is no runtime fallback to its duplicate-validation loop. The execution
code is intentionally not yet a production harness. CPU/GPU and AMP experiments
follow; production requirements, monitoring, independent reviews and readiness
checks must precede long training.
