# Plan: Admit generation-owned model artifacts by their committed parent report

## Current Status

- State: Completed
- Last Updated: 2026-09-28 05:01 KST
- Blocker: None.

## Goal and Scope

Make a completed hierarchical generation's `lower/` and `outer/` model directories usable as the next search or curriculum input while preserving catalog and checkpoint identity. These directories contain model configuration, parameter order and checkpoint; their committed parent generation report owns the completed status and checkpoint digests. Support existing committed generations without rewriting them. Keep direct route-guidance and outer-training outputs under their present per-directory report contract. This step does not change model weights, optimizer targets, the panel-file limit or the generator's search policy.

## Completion Criteria

- [x] `verify_training_artifact` accepts either a direct training output with its own completed `report.json` or an exact `lower`/`outer` child of a committed hierarchical generation whose parent report has the current schema, completed status, matching catalog identity and matching digest for that child checkpoint. Missing, malformed, wrong-role, incomplete and mismatched reports reject with a path-bearing diagnostic; a bad direct report never falls through to the parent form.
- [x] Existing generation directories need no mutation or duplicate report. Search, generation source admission, curriculum evaluation and replay restoration verify each derived model once at their stable input boundaries, retaining exact source, config and checkpoint bindings already checked by those callers.
- [x] A bounded local search → generation → next search/curriculum evaluation and resume path succeeds with distinct training and held-out problem identities. Two generations with a positive replay window exercise the second-generation source and replay restoration. Independent implementation review checks the entire handoff and input rejection rather than only the happy path.

## Proposed Changes

Extend the established `input::verify_training_artifact` boundary rather than teaching each caller a separate artifact layout. Use `symlink_metadata` on `output/report.json` to distinguish a truly missing directory entry from an existing direct report, including a dangling symlink. If the entry is present, parse its direct training identity and require complete status, catalog and checkpoint equality as today; any read or parse failure is fatal and includes the direct report path. Only `NotFound` permits the derived form: require that `output` itself is a real directory, not a symlink, named `lower` or `outer`. Read the lexical adjacent parent `output.parent().join("report.json")` under the same bounded file allowance, with path context on read and parse failure. Require the current hierarchical-generation report schema and complete status, then compare the corresponding child digest and catalog identity with the caller-supplied values. Other metadata errors fail with the direct report path. This is an explicit second committed artifact form already written by `hierarchical_generation`, not a missing-file success fallback. Export its schema constant within the crate instead of duplicating the literal. Search and normal generation already invoke the verifier. Replay restoration must invoke it once for both source models after its existing collection-bound hashes and catalog are established, before collecting examples. These are stable input-boundary checks, not per action or epoch. No per-child reports, migration writes, journal or repeated hashing are added. Preserve the existing atomic generation-directory publication.

- const REPORT_SCHEMA: &str = "aic-hierarchical-generation-training-report-v4";
+ pub(crate) const REPORT_SCHEMA: &str = "aic-hierarchical-generation-training-report-v4";
~ crates/aic-learning/src/input.rs
+ struct GenerationArtifactIdentity { schema, status, catalog_sha256,
+                                     lower_checkpoint_sha256, outer_checkpoint_sha256 }
~ fn verify_training_artifact(output, catalog_sha256, checkpoint_sha256) -> Result<()> {
     match symlink_metadata(output/report.json) {
       Ok(_) => {
          verify_direct_report_identity_with_path_context();
       }
       Err(NotFound) => {
         require_real_directory_not_symlink(output)?;
         role = require_exact_final_component(output, "lower" | "outer")?;
         report = bounded_parse_with_path(output.parent().join("report.json"))?;
         require(report.schema == hierarchical_generation::REPORT_SCHEMA && report.status == "complete")?;
         require(report.catalog_sha256 == catalog_sha256)?;
         require(report.checkpoint_sha256_for(role) == checkpoint_sha256)?;
       }
       Err(error) => fail_with_path(output/report.json, error),
     }
  }
