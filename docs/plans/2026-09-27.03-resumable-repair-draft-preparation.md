## Completion Criteria

- [ ] `RepairDraftPreparation` owns the checked source/removal identity, fork-copy progress, removal index, rebuild phase, data-dependent route/cell/port/bridge/channel/site/user/catalog cursors, old and derived maps, charged work and live memory reservation. A temporary stop preserves them without repeating work or exposing a half-rebuilt draft. Copy removed IDs directly within this owner only when their measured size fits the remaining first-turn work and time credit at that point; otherwise yield with the owner intact or use a justified copy index. It does not create three extra post-rebuild cursors solely to recount progress for reporting.
- [ ] Survivor rebuild retains native occupancy, port rates, bridge-channel ownership and deterministic junction selection. Source draft turn/revision advance exactly once after all selected removals are staged. A hard stop remains typed resource exhaustion, never a no-repair proof.
- [ ] The ordinary one-shot draft API drives the same implementation to completion with its existing diagnostics. The retained repair pager uses the progress object and transfers its reservation once to the prepared draft. No extra normal-run audit of every rebuilt item is added.
- [ ] A local surviving shared bridge and junction case yields inside each rebuild phase and after a retryable aggregate-memory refusal; resumed and uninterrupted drafts, work, revisions and release match. Upper-scale preparation time and memory include the initial fork and rebuild.
- [ ] Count placed and committed records during the necessary fork-copy traversal, subtract removed committed routes, and charge the established once-per-record `ValidationRecords` total. If exact parity cannot be preserved in that traversal, use one measured bounded direct scan after soft admission while the preparation owner retains the fork. Do not add a separate resumable count cursor. Review other small map snapshots and arithmetic against the actual first-turn credit before adding inner cursors.

## Proposed Changes

Replace the one-shot clone/removal/rebuild in `prepare_repair_draft_checked` and `rebuild_after_route_removal` with an owned state machine. Reuse `SessionForkCursor` and `JunctionOptionsCursor` from the dependencies. Stage old bridge/junction maps and new derived occupancy/ports/sites within the progress owner; commit them into the draft only after the last fallible scan, preserving the current source and draft while a page is pending. Admit each route cell, endpoint, bridge owner, site user and catalog visit against hard and temporary allowances before mutation; reserve exact vector/map growth. Accumulate placed/committed progress counts while an already required copy or rebuild traversal visits those records where practical; if that cannot share the visit, use one measured and soft-admitted direct count while the owner retains the fork. Do not add a separate resumable progress-count phase. Preserve the existing logical `ValidationRecords` charge once per record and copy removed IDs into the final `RepairDraftState` under the same reservation before transfer. Measure the removed-ID copy against the actual first-turn credit and add an inner cursor only if needed. Charge the current copy budget once and keep the same source/clone overlap peak. A small map-key snapshot may be an atomic step only under a measured, reserved soft-time bound; otherwise a retained cursor must own it before this step can be completed. Keep the public one-shot API as a drive-to-completion wrapper. A repair pager retains the same preparation object across pages and begins member routing only after prepared draft publication.
