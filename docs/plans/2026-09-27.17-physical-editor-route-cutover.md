## Goal and Scope

Move the physical editor's local route repair through Plan .14's safe one-shot adapter, remove its separate 250,000-cell routing-region and path-length rejections, admit the corresponding larger serialized procedural source, and keep the routing function's draft atomic on any finite search stop. This is an editor module integration step, not a new search engine or persistent resume owner.

## Proposed Changes

Use the existing editor draft and `aic_routing::shortest_path` entry point, which Plan .14 changed internally. Plan .20 removed the shared compiled-draft and independent-validator path caps; this step deletes the editor's earlier area guard and `check_path`'s independent length cap, replacing unchecked area arithmetic with checked positive extents and the external path uniqueness allocation with a fallible reservation. Build blocked cells with capacity reservation per collection/batch (not per cell), and return a typed resource diagnostic on reservation failure; the caller carries earlier charged work. The edit-detach loop must distinguish path-invalid from resource-unknown; a reservation failure returns a typed error before publishing the candidate draft. Keep the route function's atomic draft boundary and explicit `route_expansions` cap. Retain the measured-sufficient 16 MiB source-byte admission with a bytes/limit diagnostic; do not rescan each route. For a `shortest_path` result without cells, preserve its exact status and work in `EditWork.routes`; an exhausted shared budget before a later edge likewise records `work-budget` with zero additional expansions. Finite unknown statuses, including `elapsed`, become typed session diagnostics while the session's already applied action may remain as an incomplete draft unless its own deadline has expired. The standalone public edit returns the structured `EditWork` and likewise keeps the action-applied incomplete draft on a route stop. For an error after earlier route work, use one small crate-visible `RepairFailure { diagnostic, work }` result so both session callers charge actual expansions, preflight work and route calls before handling the diagnostic; the public wrapper maps it to its existing diagnostic-only error type because it has no cumulative budget. The full-factory declarative caller also retains partial route entries in its returned details and its existing diagnostic mapping. Its learning converter sets `WorkRecord.committed` from `details.repair_batch_applied` when present, rather than inferring commit from changed status. At the outcome ingestion boundary, normalize both callers' exact route statuses: censor operational search/resource errors before label construction, but keep a `work-budget` changed draft observed as incomplete under its effective routing allowance. Replace the physical converter's hard-coded 50,000/any-work-budget exhaustion rule with an explicit declared per-action limit supplied by its collection configuration; the factory converter already receives `limits.route_expansions`. For changed uncensored outcomes, set the budget-exhaustion head only when actual charged work reaches that per-action value, even when the session total remaining is smaller; otherwise leave that head absent. This distinction preserves the accepted `Completion under budget` and `Routing budget exhaustion` heads in the outcome-pretraining design. The private candidate remains uncommitted on such errors. Search `Err` diagnostics retain the routing failure code and context. Verify the actual library and `validate` CLI paths against baseline rather than assuming core router tests cover them.

## Verification Plan

Run the existing physical-editor library fixture with a crossing/blocked route, a sparse >250,000-cell routing region with small actual search, a legal route longer than 250,000 cells under sufficient explicit budgets, and a forced work stop. Include two pending edges where the first consumes the whole shared work budget: the second must produce a typed `work-budget` route entry without a zero-budget router call or `path-invalid-input` error. Use a focused deterministic error-classification seam to exercise both visited-set and blocked-set reservation failures without relying on real OOM: assert no prior path detaches and action application keeps its input draft unchanged. Force another reservation failure during a later blocked-set build after the router has consumed work, plus a post-search visited-set failure; assert the routing candidate remains uncommitted, both the physical-editor and full-factory declarative sessions charge that work once, expose their required diagnostics and route details, and repeated failures cannot bypass either `max_total_route_expansions`. Extend the existing between-edge `elapsed` fixture through `ProceduralSession::step` and assert its typed diagnostic and measured work. Pass the largest retained 256-facility Plan .22 output through `ProceduralAdmission::compile`, then run one finite-budget edit/repair on it (or a demonstrably comparable multi-edge source), recording the 1,333,196-byte source size, compile and edit outcomes, full editor-call time and peak RSS including blocked-set construction and validation; do not infer unrepresented terminal/bridge patterns from this file. Assert route-function input draft identity on stop, public edit's and outer session's action-applied incomplete-draft behavior, exact route status/work and typed session diagnostic, legal result on success, and no false infeasibility. Compare old/current route path, elapsed and RSS. At the offline outcome boundary, test physical and factory `draft_accepted` conversions for `work-budget` versus a resource/deadline/repeated-cell stop: only the operational stops are censored and produce zero pretraining loss masks and have no budget-head target; the work-budget case retains completion-under-effective-budget target zero, while its routing-budget-exhaustion target is true only after the declared per-action allowance is consumed.
