## Completion Criteria

- [x] `generation/routing.rs` records each `PathResult` once and distinguishes complete local no-path or invalid geometry from work, scan, frontier, deadline, allocation, numeric and `repeated-cell` search-incomplete stops. An incomplete search returns a typed `Execution` with no witness; it does not become `rejected` or a proof that the fixed region is impossible. Existing crossing, zero-length, port, path and work semantics remain.
- [x] `generation/routing/region.rs` may try independent changes after an incomplete attempt while explicit attempt/work limits permit, but retains any incomplete reason through later failures. It never concludes `fixed-boundary` or `region-exhausted` as a complete-search verdict if an unfinished route could have succeeded. At the final no-witness boundary, set `Report.termination`, returned `Execution.status` and a diagnostic together to `search-incomplete` when any relevant earlier attempt was unfinished, even if the last attempt was rejected. The report contract is versioned v2→v3 with actual work/attempt evidence. The original factory remains intact until a full candidate is accepted.
- [x] Full-factory route execution admits the requested finite `work` above the hidden 200,000 ceiling in `candidates::execute`, and region `Limits::validate` admits representable `attempt_work` above one million. Preserve explicit attempt count, total work and deadline controls; calibrate the actual default effort and upper-band yield without silently reducing a requested budget. Checked budget arithmetic returns a typed invalid/resource diagnostic only for unrepresentable requests. A finite exhaustion remains search-incomplete.
- [x] `routing::attempt` treats `changed.len() > limits.chains` as a finite region-capacity stop with its changed-chain count, not a geometric or path rejection. The `region::reembed` diagnostic-to-`Execution` conversion preserves this search-incomplete reason through subsequent retries. Review the default 64 and configured maximum 128 chain limits against the supported 256-facility factory distribution; raise or expose adequate finite limits when necessary, and classify an exhausted limit as unknown instead of pretending the candidate is impossible. Attempt/work/port/extra-chain retry exhaustion is also identified as a finite stop unless the particular fixed boundary has actually been proved exhausted.
- [x] Outer `generation.rs` retains a compact route and region summary in the action record on a search-incomplete result, so the source of `executor_status` and the consumed budget remain inspectable. Normal successful records stay compact. Readers/fixtures of the versioned report are updated.
- [x] Bounded real reembedding with blocked/crossing routes, an induced per-route stop and later independent retry verify result classification, atomicity, work accounting and evidence. Compare old/current path, yield, wall time and RSS. No default budget reduction, per-sample audit or new resume state is added.

## Proposed Changes

Keep the current `shortest_path` call and `PathOptions`; Plan .14 replaces its internal search. At the route result boundary, map only complete no-path to local rejection, and finite/numeric resource or repeated-cell stops to a typed unknown execution that preserves that route's `RouteReport` and the work already charged. The region retry owner retains an `incomplete` summary across attempts, even if a later attempt is a complete local failure. It still explores independent ports, blockers and orderings within existing limits. Treat chain, attempt, work, port-trial and extra-chain ceilings as finite exploration stops rather than complete region infeasibility unless an exhaustive proof is available. After the last retry, if no full witness succeeds, override the last attempt's status and diagnostic only at this final boundary: return `Execution.status = "search-incomplete"`, matching `Report.termination`, and identify the earlier reason/attempt in a compact diagnostic. Preserve the individual rejected attempt reports. Remove the two arbitrary route-work input ceilings at `candidates::execute` and `region::Limits::validate`, keeping positive checked finite budgets and explicit attempt/total controls; calibrate the chain cap at supported scale and preserve its capacity-stop status through `attempt` and `reembed`; profile representative upper-scale requests before changing defaults. Update `CONTRACT`, `schema_version`, diagnostics and readers for v3. On an incomplete outer generation action, include the existing compact `routes` and `region` report (or a bounded summary derived from them) in its JSON record. Preserve complete witness validation and commit boundaries.
