## Goal and Scope

Implement one reusable root catalog that enumerates every initial legal placement and lower witness, receives globally normalized source-order priors, stably sorts its computed priors and chooses the Gumbel shortlist, and emits a replayable frozen target descriptor with bounded host memory. The catalog owns its raw-score, sort and prior sidecars and selected physical action identity. It does not train the outer model; [Plan .04](2026-09-28.04-streamed-root-target-training.md) owns the integrated generation/trainer cutover. PUCT keeps its progressive-page path.

## Proposed Changes

Add a `RootActionCatalog` owner beside hierarchical search after Plan .06 establishes stable physical IDs. It consumes native pages and retained lower witnesses, calls the prepared scorer and catalog-owned `RootScorePass`, writes the source-order prior/anchor sidecar, and sorts 24-byte `(first-stage prior, anchor prior, ordinal)` records in bounded external runs for rank-noise mode. In action-identity mode, compute the existing SHA-256 digest prefix from seed, source identity and physical ID while its native witness is present, call `gumbel_from_bits` exactly once, and carry the resulting `f64::to_bits()` value through a 20-byte raw-score record and a 32-byte sort record. These are the bits stored in the current shortlist evidence. The retained 16-byte prior ledger stays identical; the extra bytes are search-only and disappear after target publication. Fully consume and drop the raw-score reader before starting any external merge output. During normalization, disk admission covers raw + one run copy + ledger; during merging it covers two run/output copies + ledger. At the hypothetical 66,977,600-action root, the active-root maximum is 4.29 GB in rank mode or 5.36 GB in action-identity mode, plus earlier retained root sidecars and filesystem headroom. The score pass owns and cleans its raw-score temporary; the catalog owns normalized ledger and sort files. A sorted scan assigns rank noise in sorted order or reads the transported action-ID noise, then keeps only bounded quota/halving candidates; selected ordinals are resolved in one ascending-ordinal native scan. After simulations, a second sorted scan derives target scalars and captures visited overrides. Preserve lower witness provenance updates and appends separately. Publish only a verified immutable sidecar with a versioned descriptor; process restart may discard an unpublished root and regenerate it. Keep output/recovery checks at publication and load boundaries instead of per action. The 4 GiB tree cap must admit the catalog's actual page, heap and sidecar-reader ownership before allocation; disk admission accounts for the replay window and the maximum of the two active phase peaks. The main generation/trainer cutover remains a single later dependency, not a claim that search-only streaming makes broad training ready.
