# Plan: Implement an opt-in bounded facility-edit protection policy

## Current Status

- State: Ready
- Last Updated: 2026-09-14 03:04:26

## Goal and Scope

Implement one indexed experimental retention policy that protects scarce
facility-edit successes even before utility matures, while preserving hard
capacity, ordinary experience, terminal credit and efficient replay. This is an
opt-in candidate with explicit parameters, not a selected production default.
No running launch or checkpoint is changed in this step.

## Proposed Changes

Extend `declarative_replay_retention.py` and Buffer admission. Keep
`declarative-replay-utility-v1` unchanged for historical/current launches; add
`declarative-replay-category-v2` for explicit experiments, sharing the existing
index, utility observation and stratum accounting. Unknown schemas and malformed
parameters fail with structured `declarative.replay-retention.<code>` diagnostics.
Do not relax execution-only migration's unchanged-`success` requirement.

The v2 configuration retains existing EMA/maturity/staleness fields and adds
`category_fraction` in [0, 0.2], `protection_updates` as a positive integer, and
`immature_order` equal to `oldest`, `area`, or `area_capped_exterior`. These are
experimental choices. The later screen fixes grace to 64 updates and fraction
to 0.10 while testing sampling quantity/method; neither is claimed optimal or
silently adopted. Do not add a quota sweep to that registered experiment.

Select the eviction stratum exactly as v1, counting the prospective incoming
stratum and preserving its tie rule. In that existing stratum let `n` be current
entry count, `p` the current place-containing count, and `floor=ceil(q*n)`.
When `p <= floor`, a place entry younger than the grace limit is temporarily
ineligible if there is at least one other removable entry. All expired place
entries and all non-place entries remain eligible. At/above grace, protection
ends regardless of uses. When `p > floor`, no category protection applies. If the
protected set covers the whole stratum, fall back to all entries and report the
capacity override. Recompute counts after every removal; incoming entries are
never sampled in their admission update. This is a soft minimum share, not a
guaranteed quota or a promise that every rare entry receives eight draws.

Within eligible entries, retain the existing mature-first removal with discounted
EMA and admission/ID ties. If no eligible entry is mature, `oldest` uses the v1
key. `area` uses `(admitted_update, gain, id)`; `area_capped_exterior` uses
`(admitted_update, gain + min(exterior_release, gain), id)`, smallest first.
Thus geometry only changes priority among equally old immature entries; it does
not combine incompatible utility/gain units or erase the age limit. Inward motion
is never required. This limited geometric comparator is deliberately testable
and may show no benefit. The area-only control isolates it from category effects.

Metadata `retention_features_v1` contains `has_place`, validated incremental
`gain`, and signed-then-clamped `exterior_release` using the existing scorer
definition. Factor the pure conversion/feature code into a shared module if
needed; normal code must not import an executable diagnostic. Build features
from all segment references at terminal, including preceding-best area and
actual post-place geometry, using already loaded evidence and canonical witness
extent. Metadata is not part of existing semantic ID/return calculation. Active
duplicates retain admission time/features; conflicting metadata for an identical
semantic ID fails explicitly. Rediscovery after eviction uses ordinary admission.
Existing checkpoints without metadata need the explicit transition in plan 04.
Validate required metadata in `Learner.__init__`, which has both configuration
and saved buffer state, before hydration; `Buffer.__init__` currently has no
configuration argument. Ordinary v2 or score-weighted restore rejects missing
metadata instead of rescanning sources. The same extractor supports the sampling
plan's v1-retention/score-weighted control; no score consumer means no new work.

Use separate mature/oldest heaps for the relevant category/age eligibility sets,
with lazy invalidation and token identity as today. Build the index once per
update's first eviction and use logarithmic add/remove afterward; do not scan or
sort all entries per victim. The ordinal is fixed within an update, so grace
eligibility does not require per-action timers. Preserve cache eviction,
selected-use totals, compact source references and no full-buffer inference.

    stratum = existing_most_represented_stratum_rule(incoming)

## Verification Plan

- Extend `test_declarative_replay_retention.py` with scarce category before utility
  maturity, q=0 control, floor crossings after consecutive evictions, grace
  expiry, all-protected override, single-stratum/single-entry cases, mixed label
  lengths, mature-versus-immature interaction, duplicates and stable ties.
- Compare the indexed implementation to a simple test-only oracle over bounded
  randomized ordered admissions/removals. At 4,096 sequences / 262,144 labels,
  verify both limits, indexed operation counts and no per-victim full scans.
- Exercise actual `Buffer.ingest`, `hydrate`, snapshot/restore and source pruning;
  test missing/invalid feature metadata and canonical rotated/transport extents.
- On identical retained updates, v1 before/after code changes must preserve model,
  both Adam states, RNGs, entries, selected IDs and ordered events. For v2, verify
  that only the intended retention metadata/decisions change at admission; do not
  demand identical later training once selected experiences differ.
- Run affected Python suites including scorer tests when shared extraction moves,
  `cargo check --workspace`, `cargo test --workspace`, and hygiene checks. Inspect
  the actual configuration validation command with v1/v2 and an invalid config.
  Use `cargo fmt --all` after any Rust changes. Record one bounded 4,096-entry
  runtime comparison and source-load counts; investigate regressions before use.
