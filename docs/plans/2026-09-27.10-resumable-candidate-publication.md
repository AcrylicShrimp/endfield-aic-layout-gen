## Goal and Scope

Retain a found direct path, completed network variant or validated repair draft through command construction, semantic comparison, native replay, exact physical cost, candidate sizing and final publication. A temporary page or retryable aggregate-memory stop must retain each partial result and charge each work item once; no semantic candidate or overlap penalty becomes visible before its full publication gate. This step owns publication state for the retained hierarchical direct/network/repair pagers. Plan .15 separately owns the public native one-shot API cutover and its v6 report/event contract; those wrappers are not completion criteria here. Lower task fairness and node widening are separate steps.

## Module Boundary and Comparable Libraries

This module owns a found direct path or chosen network/repair member through fallible replay, pricing, sizing, reservation and one final candidate commit. Its caller supplies the existing request allowance and source-bound ownership guards; it receives a published candidate, recoverable rejection, retained pending state or typed hard stop. The caller neither repairs partial semantic maps nor reconstructs a lost path. This retained owner is justified because a scheduling stop after search or replay otherwise loses an accepted result or repeats expensive work. Only phases whose physical-input measurements show a real page/work/memory interruption need their own cursor; bounded lookup, arithmetic and assembly can remain direct within this owner.

[Tokio's cancellation-safety guidance](https://docs.rs/tokio/latest/tokio/macro.select.html#cancellation-safety) explains why restarting a dropped in-progress operation can lose its result; this owner retains the found path and member through a page stop. [Tower's readiness contract](https://tower-rs.github.io/tower/tower_service/trait.Service.html) separates resource readiness from dispatch; the existing request allowance already supplies that boundary, so a new service layer is unnecessary. [Rust's map Entry API](https://doc.rust-lang.org/std/collections/hash_map/enum.Entry.html) is a useful model for a single semantic-map mutation after all fallible work, not a reason to add per-entry runtime validation. These are interface comparisons only; no new dependency or generic publication framework is proposed.

## Completion Criteria

- [ ] Take Plan .04's `FoundPathLease` exactly once with its path, source/pair/mode identity, charged search work and live path reservation; do not copy the path or re-run search at this boundary. A search-completion counter was committed when the lease became durable, while the pair/mode scheduler stays paused until this publication accepts or rejects the witness. A direct found path and its reservation then survive route-command construction, semantic-key/overlap/guided-cost work, native replay, exact cost and candidate-size accounting. The pair/mode scheduler advances once after the durable publication outcome; invalid native replay records a stable rejected semantic key without publishing.
- [ ] Network member/variant aggregation and repair transaction publication retain member/route/cell/owner positions, trusted draft with its completion `Metrics` when complete, exact net cost, candidate/step assembly and size accounting across a page stop. Each network or repair member selection retains its chosen route candidate, source pager, staged native replay and cost, post-replay reservation, and once-only transfer state until the member commits to its partial session or draft. A stop after successful network replay but before final reservation preserves the member and its original partial session; resumption does not replay or select it again. Prior complete network/repair candidates remain available if a later variant stops hard.
- [ ] Overlap penalties and semantic candidate vector changes commit once after all fallible work. Duplicate physical witnesses update provenance/cost without a second native replay or lost reservation. A temporary stop preserves the same source-bound child and trusted validation result. The replay handoff passes the current live source/node and member/candidate tree guard bytes that cannot be released until this replay completes, excluding bytes already owned by its RequestAllowance, so growth planning does not mistake those guards for temporary aggregate contention. Refresh that floor at each replay page; Plan .01 holds growth-peak escrow once its joint Extend replacement begins.
- [ ] Any indivisible generic JSON size pass is admitted only after a sound measured soft-time/work bound and memory reservation at upper accepted size; if it cannot fit a first-turn window, readiness remains blocked until a resumable candidate-specific size cursor replaces it. The bound cannot turn a potentially fitting legal candidate into hard infeasibility.
- [ ] Direct, network and repair local fixtures yield at every retained subphase and between top-level publication stages, including one aggregate-memory retry, then match uninterrupted candidate bytes, identity, provenance, cost, charged work and reservation release. Bounded direct subphases have measured admission bounds instead of artificial yields. A bounded upper-scale integrated publication measurement includes serialization.
- [ ] The actual direct, network and repair callers retain a found path or selected member across replay, physical cost, JSON sizing, final reservation and atomic publication. Compare full local search-to-publication elapsed time, work, RSS and admitted peak with the previous caller path, including serialization and validation; a soft stop never repeats a completed phase or loses a found result. Fair-first-turn Plan .08 owns scheduling, broad-distribution Plan 2026-09-26.08 owns supported placed-factory coverage and default caps, and final Plan 2026-09-26.07 owns experiment readiness.
- [ ] Measure each proposed publication subphase on physically valid local inputs against the actual first-turn work/time credit and memory ownership. Keep a retained cursor only where that phase can genuinely cross a page or must preserve progress through an unavoidable stop; use a sound admitted direct call for bounded lookup, arithmetic, copy or assembly. The implementation reviewer checks this decision per subphase and removes cursor state introduced only for uniformity. The top-level found-path/member owner remains until final commit regardless of which inner calls are direct.

## Proposed Changes

Replace `RouteCandidatePager::publish_found` with an owned `RoutePublishProgress` that takes Plan .04's already metered `FoundPathLease`; the pager keeps its pair/mode scheduler paused while the lease is in publication. Transfer the path reservation directly into the publisher and release it only after a completed accepted/rejected publication or cancellation. Search count is not charged again. The publisher retains the found path and progresses through crossing lookup, `route_commands` construction, semantic-key/overlap/guided-cost work, native replay from Plan .01, exact cost from Plan .07, candidate assembly and JSON byte count. Use a subphase cursor for data-dependent scans or copies only when offline measurement or the page contract requires one; otherwise finish that bounded operation directly after sound admission. If overlap-penalty work requires a cursor, retain its cell position and apply each increment once, while exposing neither candidate nor updated semantic entry until final commit. Reserve capacity before material vector/map/string growth. Extend the existing `SearchMemoryBudget` with a retained-owner byte counter, updated only when a long-lived `TreeReservation` is created, resized or dropped. Mark MCTS root/child `Node.memory`, root record reservations and all `Task.published` guards as retained; their bytes may grow but cannot be freed while the replay that uses this tree is pending. `RouteUpdate._memory` remains an ordinary aggregate reservation because append_node_actions can consume and release a pending update while replay waits. Hashing, row, inference and scratch guards are ordinary aggregate reservations too. If every relevant owner is blocked on aggregate memory and no release path can advance, surface typed resource exhaustion instead of leaving a replay Pending forever. `RequestAllowance` samples this retained counter at both `LowerPager::first_actions` and `next_actions`, then the active Task adds only the chosen network/repair member source/candidate guards that are outside both the retained counter and the same RequestAllowance. Direct replay needs no separate node snapshot. Exclude every guard already counted by the retained counter or allowance. Pass the refreshed sum to Plan .01 before it retries or chooses growth capacity; once its Extend growth escrow is admitted, keep that credit through both replacements even if other retained guards later grow between pages. This is owner memory bookkeeping at allocation and page boundaries, not an audit of candidate outputs. When a replay holds growth escrow, the nested publisher reports its exact owning task and direct/network/repair stage to `LowerPager`. This publication stage supplies a direct `LowerPager::drain_escrow_owner_page` and `Task::drain_retained_replay_stage` operation that targets the owner while bypassing unrelated pending-native flushing, task selection and desired-page gates. Every drain page still obeys active-time/work and hard limits; a hard stop releases escrow and preserves prior complete candidates. Plan .05 owns when MCTS expansion, widening and simulation invoke that operation before competing scoring, action append or child reservation. The publisher does not inspect or alter MCTS node state.

For networks, retain the member and variant owner across stops and retain inner shared-cell or candidate/command copy indices only if their measured work requires it; apply each completed member only once to the owned partial session. Reuse that validated source-bound partial session and accepted member results for the final internal network candidate instead of replaying and revalidating the whole network; external/deserialized network actions keep checked application. For repairs, retain `RepairDraft` and Plan .02's trusted finish state, including source-bound `Metrics` from the first completing Plan .01 replay, plus Plan .07 cost, consumed-obligation state, candidate/step copies and publication bytes. Do not consume the draft in a one-shot `finish` before a soft stop, or rerun full incomplete-state or terminal validation at normal internal finish. A missing terminal `Metrics` after a Plan .01 completion is an integration failure; only the legacy one-shot member path may perform its first terminal validation. The publisher exposes a drive-to-completion operation for Plan .15; this plan does not redirect or version the public `Session::route_candidates*` or unpublished `RepairDraft::route_candidates` APIs. A generic `serde_json::to_writer` size pass may stay atomic only when its actual accepted maximum is measured, its output size/memory is reserved, and a conservative soft-time bound fits; otherwise implement a candidate-specific incremental size cursor. External candidate application retains checked admission.

At the network member handoff in `hierarchical_search/network_pager.rs`, create `NetworkMemberCommitProgress` here, after Plans .01 and .07: it owns the moved original `Partial.session`, completed member pager, selected candidate, existing source reservation and retained native replay. It does not clone the source again. Advance Plan .07 cost and the final retained-memory reservation while the old source and validated child remain in this one state. A soft stop at any point resumes the same commit state. Once all fallible work and capacity reservations finish, transfer the child and priced candidate to `partial.session` and `partial.routes`, update `partial.depth` and retained accounting exactly once, then release the old source reservation, pager and temporary guards. On a recoverable native rejection, retain the pager and original source, mark the selected rank consumed, then choose the next untried rank in the existing deterministic order; once all ranks are consumed, mark only this variant exhausted. Do not repeat selection of a rejected rank or silently restart search. A hard resource stop discards only this unfinished partial/member with typed Unknown while preserving previously published complete network candidates. Route-empty exhaustion advances the variant once without replay. A post-replay reserve stop cannot expose the child without its matching route or depth.

At the repair member handoff in `hierarchical_search/repair_pager.rs`, create `RepairMemberCommitProgress` here: it owns the moved original `RepairDraftState.draft`, the chosen member pager/candidate, draft metadata and reservation, and retained native replay. Advance Plan .07 before/after cost, step assembly and final reservation in that same state. On success transfer the validated child, priced candidate and updated metadata to a live `RepairDraftState` once. A recoverable native rejection consumes the selected member once and enters Plan .12's retained failed-attempt history transition with the original source and conflict metadata; do not release the attempt before its history cursor owns every needed value, and never retry the same pager selection. On hard resource stop or cancellation discard the incomplete attempt and release its old-source, fork, pager and candidate reservations once, preserving earlier complete repair candidates. A soft stop retains the selected member and never reruns the search or replay.
