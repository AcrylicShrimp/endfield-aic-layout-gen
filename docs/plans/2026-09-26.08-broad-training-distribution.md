## Goal and Scope

Prepare the actual training and fixed held-out input paths to expose the eventual model to the intended production graph sizes and routing patterns. Keep small panels as fast diagnostics. This step prepares and validates configurations and local sampled inputs; it does not run GPU training or claim that the untrained model solves large factories.

## Completion Criteria

- [ ] State the intended production size envelope from the production sampling policy and project use cases, including facility, terminal and connection counts, physical area, belt/pipe mix and branching/crossing/repair patterns. Do not treat the 256-facility sampler ceiling as proof that 256-facility physical layouts are feasible. Record which upper ranges remain unproven on local hardware.
- [ ] The training curriculum draws a documented mixture of small, medium and intended large production graphs using the existing generator. Every required size band has nonzero exposure independent of small-band promotion success; realized per-generation counts and rejection reasons are recorded. A successful tiny level cannot silently become the entire training distribution. For each feasible band, explicit quotas cover belt-only, pipe-containing and logical branching graphs in both training and fixed held-out partitions; missing quotas fail panel publication. Select quota-compliant cases from a bounded candidate pool before the generator discards it, preserving uniqueness and partition split; report which quota exhausted the pool. Physical crossing, catalog-component and repair exposure cannot be inferred from an unplaced logical graph: collection reports actual legal opportunities and accepted witnesses by band, and any required category missing from model training or held-out evaluation blocks readiness. Distinct fixed held-out identities never enter training or promotion.
- [ ] Actual optimizer exposure is stratified too. Per-generation outer and lower target records and selected optimizer examples have declared minimum counts for each required size × pattern stratum. Deterministic selection reserves real usable examples for every declared stratum before filling remaining capacity; overlapping labels may share an example but unique selected example identities and each fulfilled quota are reported. Replay stays inside its reserved stratum and cannot consume another stratum's minimum. A large case with placement roots but no route-choice target does not count as lower exposure. If any stratum lacks usable lower or outer targets, the generation records a named blocked diagnostic and cannot pass distribution readiness by panel count alone.
- [ ] Audit the tensors and targets that actually reach each model update, not only prepared panels or search attempts. Report realized facility/terminal/connection and physical-pattern histograms for collected states, usable lower/outer targets and selected optimizer examples separately, across multiple bounded generations. A failed large-case search, a filtered target, or small-band replay cannot be counted as large-band learning exposure. Require the intended large and pattern strata to persist through the last selection stage, or block readiness with the missing stratum named.
- [ ] Each case has one immutable band key, an effective versioned search configuration and explicit per-case native `Limits` bound to that key before collection. Its placement bounds, model raster dimensions, input limits, candidate work caps, request deadline, peak-memory limit and episode command budget are validated for that band's intended physical scale. The panel case, collection report, episode identity, training-record lineage and resume state retain both effective identities. Training reopens the case with those same `Limits` and reconstructs action features, area/quality normalization, lower guidance inputs and directed-edge offsets using that case's bounds and candidate config; a single global training config may define shared weight shapes but cannot replace per-case geometry or budget. Model inference and updates support variable spatial sizes by band grouping or padding with a valid mask, without cropping. Limits remain finite and measured; increase, derive or expose them where bounded local probes show truncation. Do not silently downsample, crop, reduce graph obligations or substitute easier layouts to make a band pass.
- [ ] Bounded local preparation generates both partitions at each specified band and reports actual facility/terminal/connection histograms, transport mix, endpoint-degree/branch patterns, known component opportunities, duplicate identities, rejection counts, input bytes and estimated routing-work/memory needs. Include representative large prepared states in a CPU-only input/allowance smoke, and compare default with generous allowance settings. Record where the full large-layout search cannot be completed locally without calling it a passed gate.
- [ ] Measure aggregate process memory through collection, retained root/target records, publication, concurrent singleton inference and network pages, and both lower and outer optimizer updates. Include variable-size raster activations and the current `batch_states` selection/retention path. Per-request peak allowance alone is not an aggregate process bound. Calibrate finite inference and training batch/memory settings against representative medium and intended large inputs without cropping or excluding required strata. A small-panel 41 MB request peak and one successful CPU update are not evidence of upper-band safety. If a required band cannot complete a bounded local optimizer update, readiness is blocked with its exact memory or work stop.
- [ ] Exact configurations, seed, source/catalog identity, compact distribution results and a `ready` or blocked verdict are committed under `docs/`. Small route/crossing panels remain isolated regression fixtures and are not substituted for the production-distribution gate. No server access or long training occurs without renewed user authorization.

## Proposed Changes

Extend the existing curriculum configuration and panel preparation, without a second generator, to describe a stratified per-generation mixture over production size bands. Extend `ProblemGenerator::sample_facility_range` with a bounded, deterministic quota-aware selection over its existing generated candidate pool before the current balancing step discards candidates. Preserve the partition identity split, uniqueness, attempt bound and existing default selector for callers without quotas. Declare nonzero transport and logical-degree quotas where the production generator can supply them; if the candidate pool cannot meet a quota, fail with that category and realized pool counts rather than substituting a smaller graph. Keep promotion as a skill metric while ensuring that configured exposure to later bands does not depend on reaching a small-band completion threshold. Record the actual sampled band, graph signature and pattern stratum for each episode. Prepare a fixed held-out panel with matching declared coverage and distinct identities; keep the held-out set out of the training update path. Treat actual crossing/component/repair exposure as a separate post-placement collection metric and readiness requirement, because the unplaced generator cannot guarantee a spatial opportunity.

Derive or explicitly configure placement bounds and resource allowances per size band using small bounded CPU probes and conservative measured headroom. Bind the band key to an effective `hierarchical_search::Config` and native `Limits` for each case inside the existing collection path; keep one shared lower/outer weight set, with variable spatial extents handled explicitly in inference and training updates. Version the panel, report and resume identity for this binding. Replace the current single-domain equality checks with validation that each case's effective domain matches its collection record and the shared model's weight/channel definitions. In `hierarchical_generation`, reconstruct every session with the case's limits and derive action features, normalized quality, macro inputs, lower targets and edge offsets from the same case's effective bounds and candidate config. Verify eager and compiled inference at multiple band extents or explicitly disable compilation through a recorded per-band setting when parity cannot be established. If a large band exceeds local search or memory limits, report the unresolved scale requirement and leave readiness blocked rather than shrinking the production target. Keep diagnostic small runs cheap by retaining their separate configuration. Add a CLI-visible distribution audit for already prepared panels, with summary counts only, and use it as a required local admission check for the final readiness plan. This step does not change the game topology contract or claim model quality.

Treat process-wide memory as a separate measured limit from each request's allowance. The configured singleton batch size can hold several requests at once; account their simultaneous inputs, retained sessions, model outputs and publication buffers in the upper-band smoke. Also measure retained collection records and peak activation/optimizer memory during actual lower and outer updates with upper-band inputs. Set finite batch sizes or use bounded accumulation that preserves every declared size × pattern optimizer quota without cropping. Retain the measured process peaks and any stop reason in the readiness report.

Carry the band and realized pattern labels into root records and lower route-choice targets. Replace the current contiguous capped `outer_epoch_examples` rotation with deterministic quota-aware selection over usable records for every declared size × pattern stratum; reserve the required identities first, then fill spare capacity, and apply replay only within the selected stratum's allocation. Apply the same rule to lower route-choice batches. Recheck the quotas against the exact selected examples passed to each optimizer, reporting collected target counts, selected unique identities, per-stratum counts and overlapping labels separately. A stratum without route-choice targets must fail the lower-exposure gate, not receive fabricated labels or be counted because it appeared in the prepared panel.

## Verification Plan

Use local CPU preparation for the bands already shown feasible by the production generator, including the 4–64 and 65–256 probes in the distribution-gap report. Inspect exact realized counts, graph identities and belt/pipe/branch quotas in both partitions, not just configured ranges. Construct a bounded pool where the ordinary first selection misses an available pipe or branch case; verify quota-aware selection finds it, and verify a truly exhausted quota gives a named error. Confirm that a low small-band completion rate still leaves a nonzero configured large-band sample. Reject a deliberately undersized bound/allowance with a named diagnostic and verify the effective band config and native limits in each case's panel, report and resumed lineage. Compare a small regression panel, a medium prepared input and an upper-band input against generous caps; report actual stops, request peaks, concurrent batch/process peaks and which upper-band physical workflows cannot fit local resources. Exercise eager/compiled variable-size inference and bounded mixed-band lower and outer training updates on CPU, including retained collection records, publication and large raster activations; measure the process peak at each phase. Use two cases with unequal bounds and unequal turn budgets; reconstruct features, normalized quality, lower input/edge offsets and native session limits from their collection records, then swap config identities and require rejection. Verify collected outer and usable lower targets, unique selected optimizer identities and every required size × pattern quota at the exact update input after replay, for multiple bounded generations; a missing upper-band pattern target or a failed large-band update must block rather than report exposure. Check fixed held-out disjointness and episode identity after one bounded resume. Inspect actual component/crossing/repair exposure by band; missing required categories remain blockers. Run the relevant CLI, Rust checks/tests and tracked-file checks. Independent implementation review checks for hidden filtering or easier substitute graphs.
