## Goal and Scope

Remove the native constructive learning domain's hidden 65,536-cell placement rejection and two one-million-item theoretical count rejections where actual work and memory can fit. Preserve the complete legal placement and command choice set, its stable conditional indices, and bounded page behavior on large physical inputs. This is the reusable native learning observation/domain boundary used by hierarchical guidance; model tensor admission is Plan .16 and production band selection is Plan 2026-09-26.08.

## Completion Criteria

- [ ] `constructive::learning::Config::validate` checks positive bounds and representable area, rotations, spatial counts and extension lengths without rejecting a legal state solely because `area > 65_536`, `area × max_rotations > 1_000_000` or `spatial_upper_bound > 1_000_000`. Actual construction and observation memory/work use existing request allowance where supplied, and otherwise report a typed resource or invalid-input diagnostic at admission. No new fixed, smaller replacement cap appears.
- [ ] `Domain` placement and terminal choices preserve every legal pose, row-major/rotation order, stable factor index and command identity from existing supported cases. Large domains do not eagerly rebuild all poses for every small `command_page`; count/rank/page work is shared or indexed so a bounded page has cost proportional to its necessary scan and selected output. `advance_many`, `choices`, `command_page` and one-shot observation callers share that exact choice mapping. The actual hierarchical `next_placement_page` caller reserves a tightly measured construction peak against the tree budget *before* building the source-bound domain, then retains that domain/index and resizes the reservation to measured live bytes across successive pages. A temporary aggregate refusal is a typed resource stop that keeps the exact source and both page offsets for retry when memory decreases; it never constructs an uncharged large index repeatedly or omits actions. Invalidate cached identity only when session revision/bounds change. Both Place and PlaceTerminal page results and offsets commit atomically after both succeed; a failure in the second family leaves neither offset advanced. `Domain::new_route` builds only route-relevant fields directly instead of constructing and discarding placement/terminal banks and scanning the entire canvas on repeated route-learning observations. If callers demand all choices, their output allocation is admitted fallibly and its actual cost is measured; a small page never allocates the entire bank.
- [ ] `Input::new_bounded` computes checked entity/relation/spatial capacities and uses fallible host vector growth for its features, owners and indices under the supplied `RequestAllowance`; each failed growth refunds held bytes and propagates typed resource stop. Domain blocked/pose/terminal collections and Input's occupied-cell collection also have checked, fallible capacity admission; where `BTreeSet` cannot reserve fallibly, use an ordered compact representation while preserving exact feature order. `Input::new` and ordinary observation APIs no longer `expect` that an unbounded builder cannot fail; they surface a diagnostic for actual allocation failure. Existing graph/route work charges and exact feature values remain. This input is constructed before Plan .16's model `InputBatch`, so both admission boundaries are required.
- [ ] Candidate-guidance `RouteGuidancePreparation::new` continues requiring equal candidate and learning bounds and can construct its graph input above 65,536 cells after this cutover. Page/allowance refusal remains typed Unknown with retained source/owner, not an empty learning domain or no-route proof. Training/evaluation identity and the preexisting legal action set remain.
- [ ] Bounded 30/100-facility placed layouts and a sparse above-65,536-cell legal input compare prior/current choices and indices, page time, admitted peak and RSS. An upper intended band is measured to show the new admission does not explode by rescanning the entire canvas for each page. Independent implementation review checks page cost and all observation entry points.

## Proposed Changes

Keep `Config` and `Domain` as the public boundary. Remove the theoretical area/rotation/spatial count cutoffs from `Config::validate` after checked dimensions and counts. Inside `Domain`, replace repeated eager `placement_poses` banks in `command_page` with a reusable indexed legal-pose view tied to the immutable session/bounds identity. It may use per-row counts, an occupancy prefix or an equivalent direct index; it must retain the old total order and rank mapping and skip illegal bodies without materializing all poses for a small page. `advance_many` and `choices` resolve the same rank through that view; large complete choice requests use fallible output growth. The hierarchical placement-page owner retains that domain/index for the same source revision and effective bounds, so construction scans happen once per stable state; this cache is not an output audit. Build route-only domains directly from shared blocked/source data and skip `terminal_positions` and pose enumeration that `new_route` currently discards; repeated route-learning observations should pay only for route-relevant input. Make domain collections, Input occupied cells, and `Input::new_bounded`'s host feature and relation/spatial vector capacities checked and fallible with exact allowance release on refusal, and return a diagnostic from one-shot observation builders rather than panicking. Reuse existing retained page/admission machinery for data-dependent enumeration when it can cross a first-turn credit, and keep small direct helpers direct. Do not add a new generic scheduler or per-sample distribution audit.

For hierarchical pages, derive a checked, close construction-byte bound from the actual bounds, unique rotated shapes, block/terminal domain lengths and occupied source counts before allocating the occupancy prefix or row indexes. Reserve that bound from the shared tree budget, construct the domain, then resize the reservation to actual retained capacities. A failed pre-reservation leaves the owner at the same revision and offsets with a typed memory stop; it may retry only after shared live bytes decrease. Do not construct a large uncharged domain as a fallback. Page both command families into temporary results, and commit their offsets and appended actions together only after both succeed; any page failure drops temporary output and leaves the prior offsets intact.

For a comparable popular index, [RoaringBitmap's rank/select API](https://docs.rs/roaring/latest/roaring/bitmap/struct.RoaringBitmap.html) shows how a compact ordered legal-position set can support deterministic rank lookup and iteration. The native domain already has session-scoped occupancy and exact factor order; first measure whether per-row counts over that existing representation are enough. Do not add a bitmap dependency merely to copy the interface, or narrow supported coordinates to a bitmap's integer index type.

The native learning domain accepts large bounds only when actual host memory and visited work can be admitted by its caller or reported as resource unknown. One-shot external APIs still reject malformed bounds and impossible output allocations with the relevant path/diagnostic. Plan .16 separately makes raster and tensor allocation fallible. Plan 2026-09-26.08 provides the eventual per-band target extent and verifies that complete model targets, not merely the domain, include the intended physical sizes.

## Verification Plan

Run a bounded native observation/command-page case at existing bounds and a sparse >65,536-cell case. Compare every small-case legal pose/index/command and several large-case first/middle/last pages against a slow offline enumeration, including rotated footprints and occupied holes. Advance at least two hierarchical placement pages on one stable state and show one domain construction under an admitted pre-reservation; mutate revision and show one new construction. Under an insufficient construction reservation, assert no large domain is built, both offsets stay fixed, the stop names aggregate memory, and a retry after shared live bytes decrease matches the uninterrupted next page. Force the second command family's page to fail after the first succeeds; verify both offsets and published actions remain unchanged, then compare the retry's exact commands with an uninterrupted pair. Check peak and retained tree bytes return to the original level after owner release. Exercise repeated route-learning observations on a large sparse canvas and show they avoid full placement/terminal banks and interior-cell scans. Force memory/work stops in domain collections, occupied cells and `Input::new_bounded` host growth, verifying exact ownership/allowance release and no false infeasibility; a one-shot observation must return a diagnostic rather than panic. Compare page elapsed, RSS and retained memory before/after on representative placed inputs and one upper-band probe. Then `cargo fmt --all`, `cargo check --workspace`, `cargo test --workspace`, relevant CLI output and tracked-file check. Request independent implementation review.
