# Plan: Shared prepared route search

## Current Status

- State: Completed
- Last Updated: 2026-09-27 KST
- Blocker: None

## Goal and Scope

Make anchor and guided route search share one exact legal-successor and reverse-preflight workspace while retaining separate path costs. Search and completed paths resume after temporary work/time/memory stops without repeating a charged scan or losing a path. This step ends at an owned, metered `FoundPathLease` that the later publication module can take without copying or releasing it; native replay and publication subphases belong to Plan .10. The existing one-shot publisher remains an explicitly incomplete integration path until that required cutover and cannot be used to claim follow-up experiment readiness.

## Completion Criteria

- [x] Shared graph caches only legal transition/preflight results bound to source/pair/config identity; anchor and guided `g`/priority maps remain independent.
- [x] Reverse probe, successor construction and goal reconstruction own exact charged positions across temporary stops. The initial per-search work budget and derived preflight pair/probe key remain fixed through a memory retry of frontier admission; already charged preflight expansion/scans remain separate until frontier admission succeeds. Only then does the A* hard allowance become the original search budget minus charged preflight work. A completed search transfers an owned path plus its exact reservation to one `FoundPathLease`; a page/work stop discovered after the kernel returns `Found` stores that lease before yielding. Search count and charged work advance once at this durable search outcome. The pair/mode scheduler cannot start another search while the lease is outstanding. An explicit accept/reject/cancel releases or transfers the lease once; Plan .10 owns semantic dedup, the fallible publication stages and final candidate/penalty commit.
- [x] No hidden `MAX_STATES` cutoff narrows accepted configured search work. The existing finite request work, deadline, frontier and live-memory allowances control resource stops; a true frontier exhaustion may prove no path for that fixed state, while work/time/memory exhaustion is a typed unknown and cannot masquerade as completed no-path. Memory reservation covers each retained graph/frontier/path, including simultaneous path and frontier storage, and is transferred or released once.
- [x] `Frontier::new` requires a completed cached preflight for the same source/pair/config identity (or the documented zero-probe case). It cannot run a second synchronous reverse probe, discard a probe on reservation refusal, or make an unaccounted clone of its cached frontier. Tests using the constructor prepare that cache explicitly. No per-successor output revalidation is added.
- [x] Focused route cases compare anchor/guided outputs and work with the pre-cutover path; forced stops cover reverse probe, successor construction, goal reconstruction, after-found metering and lease handoff/release. A bounded integrated local measurement includes preparation and path search. Plan .10 later proves retained publication and full search-to-candidate continuity before the pipeline is ready.
- [x] Until Plan .10 cuts over the actual caller, the existing `RouteCandidatePager::next_page` remains the legacy one-shot publication adapter: it consumes a completed search lease into the existing publisher so hierarchical lower-pager callers still receive candidate IDs. This adapter is a compatibility execution path for the intermediate step, not evidence that publication soft stops retain the path; the known publication gap remains a blocking Plan .10 criterion and follow-up experiments cannot use this intermediate pipeline. The new search-only page/lease API is checked separately without a one-shot publisher. Do not add a second search algorithm or silently return perpetual `Pending` to pager callers. The separate public `Session::route_candidates` CLI harness still uses the old one-shot `shortest_path` and is not evidence of this pager path.

## Proposed Changes

Use the existing WIP `PreparedGraph`, `ProbeCursor` and `Frontier` in `aic-routing`, and the native `RouteCandidatePager` as the single scheduler for anchor/guided search. Complete the search-to-publication **handoff**, not publication itself: `Frontier` accounts the reconstructed path separately from expendable frontier storage and transfers its owned `PathResult` plus path reservation to a pager-held `FoundPathLease`. The pager stores a found lease before interpreting a post-kernel page stop, commits the completed-search count once, and pauses its pair/mode scheduler while that lease exists. A later Plan .10 `RoutePublishProgress` takes the lease and either commits/rejects it or retains it through a soft stop; releasing search storage never drops its path reservation. Keep the existing `next_page` output shape for intermediate hierarchical lower-pager callers by letting its legacy one-shot adapter consume a found lease after the search-only owner has completed. This does not make legacy publication resumable; Plan .10 must replace that adapter before final workflow adoption. The new search-only API is independently testable with a lease consumer that accepts, rejects or cancels without publication. The one-shot adapter and search-only API use the same frontier/preflight code, not two route search implementations. Preserve anchor admissibility by keeping guided penalties outside anchor cost state. Keep bounded cached transitions and no per-visit revalidation of already admitted internal graph entries.

For each search, retain the original work budget and pair/probe key until a `Frontier` is successfully admitted. Accumulate preflight's actual charged work separately, keeping the original key stable on page and aggregate-memory retries. A `memory-pending` from the initial frontier allocation leaves the already completed preflight cached and does not change `probe_cap`. Once the frontier is admitted, set its hard A* budget from the original budget minus the charged preflight expansions, transfer that charge once, and then clear the pending preflight counter. A completed probe cannot be run again merely because reserving the frontier's first 512 bytes temporarily failed.

Remove the one-million-state constant from the retained frontier; admit each state/heap/best growth under the existing live-memory allowance and distinguish a finite work/frontier/time stop from true fixed-state frontier exhaustion. `Frontier::new` consumes only preflight already completed by `advance_preflight` for its exact pair and probe cap (or the zero-probe case); remove the synchronous cache-miss probe. Borrow cached status/counts, and if a stopped diagnostic needs an owned blocked-frontier copy, admit that bounded copy and its temporary overlap. These are resource and ownership boundaries, not runtime audits of module output. The earlier scoped search reviews in the [split record](../reports/2026-09-27-plan05-pre-split-record.md) establish only their named cursor behavior.

+   share_legal_successors_and_preflight();
