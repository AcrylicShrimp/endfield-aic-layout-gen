## Completion Criteria

- [ ] A tracked frozen local panel contains cases that cannot complete without each required splitter, converger, belt/pipe bridge and bounded repair; controls cover straight sharing and failure semantics. Each successful layout has explicit catalog components and passes independent validation.
- [ ] The actual hierarchical CLI, from empty or documented prefix state through candidate generation, outer action, native replay and publication, completes the positive cases within recorded local resource budgets. No fixture can pass by routing around its targeted capability.
- [ ] A bounded local comparison records generation, search, validation, storage and end-to-end time against the relevant retained baseline, and records any performance or behavior discontinuity rather than assuming continuity from unit tests.
- [ ] A local CPU generation and resume exercise records episode identities and the train/evaluation split before and after restoring an interrupted checkpoint; no evaluation item enters training and no completed episode is replayed as new training input. Use a tiny bounded run or cite directly comparable retained evidence for unchanged paths.
- [ ] The final readiness verdict incorporates the audited production training/held-out distribution and representative medium/large request-allowance sensitivity from plan 08. Small forced-capability fixtures alone cannot establish scale readiness; any excluded intended band or uncalibrated default cap is a blocker.
- [ ] Design-to-code coverage matrix, independent implementation review findings and exact commands/configurations establish `ready` or enumerate unresolved blockers. Long training remains outside this readiness check; upper physical/server measurements require renewed user authorization.

## Proposed Changes

Add a small immutable panel under `docs/benchmarks` and register its source assets. Each case states the capability it forces and a machine-checkable postcondition, such as a bridge count and declared crossed route IDs or splitter direction degree. Record the allowed route geometry and independently reject bypasses of each forced capability. Extend the existing hierarchical harness output with compact component/repair summaries where necessary, without per-simulation traces. Run only local CPU smoke and checks proportional to the changed workflow, including one bounded generation interruption/reload that inspects episode identity and train/evaluation assignment. Compare complete layouts, not just a `fully_validated` flag from the old physical-v2 semantics. Record a durable report with exact commit, configuration and source hashes, measured limits, verdict and residual risks. An independent fresh reviewer must inspect fixtures to rule out bypasses and compare actual output against the full accepted design.
