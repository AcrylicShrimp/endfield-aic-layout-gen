## Goal and Scope

Keep generated full-factory training inputs publishable and readable across the supported physical-size distribution. The 16 MiB JSON guard is repeated in the source publisher and native input reader without measured evidence for 256-facility witnesses. This step owns the native full-factory serialized-input boundary and identity-preserving publication, including the checkpoint decoder that currently shares its size guard. It does not change the factory generator, routing policy or schema.

## Completion Criteria

- [ ] Predetermined small, medium and upper-band generated inputs and representative current/best-state checkpoints are serialized offline and their byte sizes, composition and retained memory recorded. Include 256-facility compact, balanced and spacious cases. If a valid input exceeds 16 MiB, producer and native readers admit it under one finite, evidence-based allowance. If 16 MiB covers generated inputs with margin, retain that input limit and record the evidence. Set an independently measured finite checkpoint decode limit that covers the larger restored state without borrowing the input-file limit blindly.
- [ ] Source::generate applies the same generated-input admission to new and committed slots; input::read accepts the producer's supported size, while checkpoint::from_checkpoint uses its separately admitted decode bound. A file size refusal identifies path, actual bytes and limit; in-memory decode identifies actual bytes and limit. Both remain resource/input diagnostics, never a smaller factory or infeasibility. Manifest SHA-256 still binds the exact JSON bytes to source/slot; publication remains atomic and resumable.
- [ ] Bounded loading prevents untrusted files from consuming unbounded memory. For a newly written file, a streaming hash over the bounded file avoids a second full-file copy solely for identity. For reuse, one bounded read buffer is both hashed and deserialized so the manifest binds the exact bytes returned. Retain simple write, sync and manifest ordering without a journal or per-sample audit.
- [ ] A real upper-band source generation, commit, reuse and native read check passes with identical layout and hash. A checkpoint of an admitted upper-band session roundtrips through restore, preserving source identity, current/best state, work and resume behavior. Compare elapsed, disk bytes and peak RSS; independent implementation review checks producer/reader agreement and remaining size guards.

## Proposed Changes

Measure actual serialized inputs from fixed production-band configurations first. Keep the current finite bound if sufficient; otherwise choose a measured bound with headroom for route/crossing variation. Place generated source and reader admission behind one shared native constant or narrowly scoped helper, and use a separate measured checkpoint decode allowance. Check metadata before a bounded read and parse one owned buffer. For publication, write input once, validate actual length, hash the file incrementally, write and sync the pending manifest, then atomically publish it. Reuse performs one bounded file read and both hashes and deserializes that same buffer, preserving the exact manifest-to-returned-value binding even if the file changes elsewhere. Preserve source identity, checkpoint schema, diagnostics and cleanup behavior. Restore remains a single parse of the caller-provided JSON string; no duplicate snapshot or replay audit is added.
