# Plan: Preserve terminal-to-port bindings through conditional policy learning

## Current Status

- State: Ready
- Last Updated: 2026-09-15 13:38:03

## Goal and Scope

Priority **3 for likely learning impact**: the current mean of prior port features
provably aliases different terminal assignments. This affects later conditional
choices in multi-terminal placements, rather than every observation, so it follows
the two broader input corrections. Replace only the conditional assignment-history
contract throughout collection, PPO, replay and restore. Native execution continues
to receive exact full mappings; no feasibility model or new action family is added.

- [ ] Prefix work/storage stays linear in recorded bindings per selected action;
  history is not copied once for every alternative or duplicated across all depths.
- [ ] Empty prefixes, heterogeneous graphs, replay/restore and byte guards pass.

## Proposed Changes

Replace `Branch.history` with immutable assignment records `(terminal_graph_node,
selected_port_features)` and prefix ranges. For a selected placement store one
complete assignment bank of length T, with branch depth d referring to `[0,d)`.
Batch packing supplies graph offsets, assignment owners and factor prefix bounds.
Online collection appends one record per chosen terminal. Frozen recording creates
the same bank once and retains the existing compatible alternatives/`keep` indices.
Remove the old mean-only field and all reconstruction paths that depend on it.
Use the prerequisite's 11-column conditional-port schema, including original-port
membership, and its current/baseline terminal rules. Width comes from that schema.
Maintain the online used-port set incrementally with the assignment bank. Frozen
recording walks the selected sequence once and updates the same set at each depth;
it does not rescan all earlier choices to reconstruct used membership. Total prefix
bookkeeping is O(T), separate from necessary enumeration of compatible alternatives.

Add a width-40 pair encoder `phi(terminal_embedding, port_features)` with a nonlinear
hidden layer before aggregation. For each prefix, use the mean of encoded pairs
and explicit `ln(1+d)`; use an all-zero summary at depth zero. A linear transform
of concatenated pairs followed by averaging would still lose the binding, so it
does not meet this contract. The port head consumes this summary, the current
terminal/facility references, graph context, root and alternative port features.
Use packed segmented prefix sums per assignment bank when evaluating all depths;
compute a summary once per factor, then gather it for alternatives. Reuse the
existing optimized reference path and batched per-depth sampling schedule.
During no-grad online sampling, encode only newly appended assignments and keep
the running encoded sum/count for each active placement. Frozen update packing
recomputes every pair once with gradients and uses segmented prefix sums. Neither
path repeatedly encodes an entire growing prefix.

Canonical terminal order is derived once at admission from each original terminal's
physical facility-local port position, boundary direction, input/output role,
transport and exact rate. Ports at distinct physical positions give distinct order
keys; add the original immutable endpoint-incidence descriptor as a tie breaker.
Port alternatives sort by their base catalog physical position/direction/transport,
not port IDs. A physical equivalence group must also have identical complete native
execution rules, including original-port membership and baseline endpoint headings.
If fully identical physical and execution descriptors remain, retain explicit
equivalence groups and compare probabilities aggregated over interchangeable labels;
never assert label-by-label equality for physically indistinguishable actions.
Keep native selection maps so sorted options still resolve to exact original slots.

No promise is made that arbitrary learned parameters must distinguish every pair;
the requirement is that the interface retains the relation and the model can learn
a distinction. Reuse this action-binding encoder for a future outcome head rather
than developing a separate unassociated average there.

## Verification Plan

Construct at least three terminal groups with two prior terminals choosing a/b
instead of their old c/d. The two swapped prefixes have identical legacy mean and
used masks but different new assignment records. With a controlled nonlinear pair
encoder, require different conditional logits; verify nonzero appropriate parameter
and terminal gradients. Do not assert inequality for zero/random symmetric weights.

Check empty prefix, one terminal, different terminal counts across graphs, reused
ports, out-of-range selections, and masks that remove noncontiguous option indices.
Compare sampled old log probability against frozen recomputation before updating
parameters; require 1e-6 CPU / 1e-5 CUDA tolerance for joint log probability/value
and exact selected mappings. Repeat after sparse replay publication and ordinary
checkpoint restore. The next optimizer update must match within the established
same-device regression tolerance. No live native state may be consulted by replay.

Rename/reorder terminals and catalog ports and compare the corresponding complete
action distribution on a tiny enumerable domain; compare aggregate mass for exact
physical equivalence groups. Verify assignment bank length T rather than T(T-1)/2,
and summary computation once per factor rather than per alternative. Retain batched
single-graph equivalence and exact masked-reference regression. Run required fmt,
default/learning-enabled workspace checks/tests and documentation checks, then commit.
Include identical catalog-port geometry with differing original-port/baseline rules
in an isolated descriptor test; these must not be collapsed into an equivalence
group. Count used-set insertions and pair encodings to exclude repeated prefix scans.
