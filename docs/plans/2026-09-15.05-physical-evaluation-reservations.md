## Goal and Scope

optimization. The current JSON geometry hash changes under translation and opaque

## Proposed Changes

Replace `generation.rs::geometry_identity` with typed identity construction in a
small `aic-layout` module, called through factory admission. Accept typed physical
primitives and explicit relations; do not hash neural float arrays. Normalize integer
coordinates with the frame contract. Drop opaque names only after replacing every
reference with its exact graph relationship. Retain multiplicity and directed path
order. The structural key ignores flow magnitudes and recipe/utilization values,
as the existing reservation intends, but retains transport, commodity equality,
body/port geometry, component kinds/channel membership and physical incidence.
Physical properties of referenced definitions replace catalog ID spelling.

Use deterministic colored-graph canonical labeling: initial colors contain typed
physical attributes and normalized geometry; iterative refinement sorts incident
typed/directed relation colors with multiplicity. If colors remain ambiguous,
individualize a color class and choose the lexicographically minimal complete
typed encoding across all branches. Hash only a completed canonical encoding;
never use input row order as the tie breaker. Preserve ordered path positions as
indexed relations or ordered attributes, not sorted point sets. Do not return a
Weisfeiler-Lehman refinement digest as a proof of graph equivalence.

Bound work with an explicit external `identity_limits` configuration: a maximum
100,000 individualization nodes for the first configuration, plus existing bounded
input/entity limits. Count every visited branch regardless of pruning; check the
limit before expansion. On exhaustion return `aic-learning.physical-identity-budget`
with source path/case ID and work used. Do not certify admission, silently drop
obligations or weaken equivalence. Retain the input for an explicit retry with a
changed bound; normal source retry accounting may handle it as a bounded admission
failure. Measure whether real inputs ever need individualization before adopting.

Build two projections from the same typed graph construction: the structural
projection omits rates/nonstructural balance values before canonicalization; the
exact projection includes exact rational rates and all applicable physical catalog
constraints before canonicalization. Canonicalize the projections independently.
Do not take a rate-sensitive ordering and remove rates afterward, or attach rates
to an arbitrary representative chosen without them. Share immutable graph storage
and refinement utilities, but not a chosen ordering across the two projections.
The configured 100,000-node budget is a combined allowance: canonicalize structural
first, then exact using the remaining allowance. Charge both traversals and return
no admissible identity result if either one exhausts it. Keep raw source digests
unchanged for file validation and actual-state restore. Cache computed keys with
source/catalog identity in existing admitted objects, not a new persistent journal.
Root lineage starts with a versioned structural root key plus the existing logical
source episode identity; descendants carry that root reservation unchanged. A new
shape does not release a held-out root into training.
Reservation membership compares the structural root key independently of episode
labels; a renamed or newly numbered episode cannot escape the root's partition.

Update `generation/source.rs`, curriculum `Root/Parent/Start`, evaluation `Case/Manifest`,
training binding and the supported input metadata formats together. Panels become
v2 and include identity semantics. Add an explicit `learning migrate-panel` CLI
operation taking old panel and new output: load/verify actual payloads, recompute
keys once, reject new duplicates and preserve case/action seed identities. Never
edit a retained old panel in place. Old reports remain valid historical reports
under their recorded reservation rule, not upgraded scientific claims.
In `training/run.rs`, load/validate runtime catalogs before `Panel::load`, then pass
their shared validated handle to panel/source identity admission. The current order
loads the panel first; new catalog-backed identity checks cannot preserve that order.

## Verification Plan

Build an identity matrix from the existing crossing and external-terminal fixtures:
positive/negative translation; array permutation; renamed facilities, networks,
terminals, ports and components; equal names with changed references; reversed
directed path; swapped bridge channel ownership; changed commodity partition; and
changed rates. Equivalents must match. Rate-only variants share structural identity
but differ in exact problem identity. Directed/incidence changes must not collapse.
Include repeated identical physical attributes to exercise symmetry handling and
an intentionally tiny work limit to prove deterministic exhaustion behavior.
Use symmetric fixtures with differing rates: changing rates alone must not change
the structural key; rename/reorder each rated graph and require its exact key to
stay fixed. Swap rate assignments across symmetric and asymmetric relations and
compare against a small exhaustive permutation oracle. Verify the combined budget
also rejects when structural succeeds but exact exhausts the remaining allowance.

Test panel preparation/loading, source cached/fresh admission and curriculum with
translated equivalents and inherited descendants. Use a retained legacy panel with
two newly equivalent cases: migration must reject with case IDs; it must not silently
select one. Verify source digests and actual inputs remain unchanged after a valid
migration. Run the real new CLI and inspect successful output and duplicate/budget
diagnostics. No unbounded graph-isomorphism or directory audit belongs in normal runs.

Measure admission time and canonicalization work on at most 32 retained small/large
layouts; preserve the resulting table and input manifest. Run required fmt, default
and learning-enabled checks/tests, documentation maintenance checks and commit.
