## Goal and Scope

Make public `aic_routing::shortest_path` a bounded one-shot adapter over the prepared search from Plan .04. Remove its hidden one-million-state and 250,000-cell area cutoffs without adding a second search engine. This step owns the reusable routing kernel, its public input contract, numeric safety and returned `PathResult`. Native candidate publication, learned guidance inference, physical editor, generator and full-factory caller policies are separate mandatory steps linked below; none may treat a finite stop as no-path.

## Completion Criteria

- [x] `shortest_path` delegates reverse probe, successor generation, forward frontier and reconstruction to one prepared graph/frontier. It has no duplicate A* loop, `MAX_PATH_STATES`, fixed area rejection or `work_budget * branching_factor` up-front reservation. It returns `no-path` only after actual complete fixed-state exhaustion; finite work, scan, frontier, deadline, allocation and numeric stops are typed unknown/resource results with actual charged work. A reconstructed goal path with a repeated cell is not a no-path proof: continue soundly if a valid alternative remains reachable under the state abstraction, or return typed `repeated-cell` search-incomplete and let callers preserve uncertainty.
- [x] Existing public input rejection remains at one admission boundary: checked positive extents, endpoints, directions and budgets; cell/edge penalty bounds with their old scan/deadline accounting; crossing map key/payload consistency with `path-invalid-crossing`. No per-successor input audit is introduced. Zero-length, blocked endpoint, crossings, `prefer_crossings`, cell/edge penalties and diagnostics remain usable.
- [x] Prepared search uses checked sparse state and cost representation over admitted extents. Replace area-flattened `i64` IDs with coordinate/direction/crossing/bridge keys; use checked lexicographic `(sum(penalty + 1), turns)` scoring and a wider checked Manhattan heuristic. Preserve the old heap order `(priority, accumulated cost, crossing preference, row-major key, insertion index)` on previously supported bounds. Check neighbor offset before arithmetic overflow in reverse and forward search; an out-of-range neighbor is skipped, and an unrepresentable score yields resource unknown rather than a panic or fake infeasibility.
- [x] Graph, probe, frontier, reconstruction and diagnostic growth use fallible allocation and release their temporary memory on each exit; an owned found path retains its bytes until the returned result owns them. The adapter needs no persistent resume object or separate runtime audit. Bounded release-mode cost of the same representative routes is comparable to the previous one-shot path, including input checks and allocation; the larger synthetic grid remained about 27% slower and is retained as a downstream integration measurement item.

## Proposed Changes

Reuse `PreparedGraph`, `ProbeCursor` and `Frontier` with one local adapter that advances them under the caller's existing work, scan, frontier and deadline budgets. Preserve externally visible `PathOptions` and `PathResult`; use fallible allocation at actual collection growth, drop one-shot temporary state on return and transfer an owned found path into the result. Reverse-probe resource stops end the call before A*. The no-ledger public router has fallible allocation rather than a fixed million-state or area cap. Keep input validation at the call boundary; the route successor loop relies on that contract.

Area flattening masks overflow in `PreparedGraph::advance_preflight`, `Frontier::new`, `state_id`, `Point::distance` and neighbor `offset`. Use a sparse state key and checked wider score/heuristic operations instead of deriving a scalar weight from grid area. Preserve deterministic tie order and `prefer_crossings` so existing paths stay stable where inputs were previously accepted. A genuinely unrepresentable numeric operation returns a typed resource result with work already completed. This is one routing module replacement; caller-specific result policies remain explicit follow-on dependencies, not silently omitted work.
