## Goal and Scope

Produce one reviewed, evidence-backed design decision for root action enumeration, scoring and target ownership at intended physical scale. This investigation does not change search or training code. It must preserve legal placement coverage or make and justify a versioned sampling contract explicitly; it cannot assume that the native placement page alone makes Gumbel roots scalable.

## Proposed Changes

Count with the existing `Domain::command_page(kind, offset, limit)` loop until `exhausted`; the domain has no current count API. A bounded interrupted loop yields only a named lower bound. Use a legal partially placed case for placement throughput and the fully placed 30/100 panels for route-state baselines.

Inspect and measure the existing root workflow with bounded local probes and calculation from exact collection lengths. Reuse the native domain's count/page interface and existing root records; do not start with a replacement framework. Record the strongest viable exact design first: one source-bound root-action catalog that iterates complete legal actions in stable order; bounded scoring over that catalog using one encoded state; compact per-action evidence only where needed for normalization and training; shortlist simulations retained by physical ID; resource refusal as Unknown rather than infeasible. Compare it with a sampled-action design using a mathematically specified proposal and target correction, not an arbitrary candidate cap. The accepted choice must account for training record size and optimizer consumption as well as search. The investigation is complete only when the selected boundary is reviewable and concrete enough to split into one-step implementation plans.

## Execution Result

Local investigation started after the revised proposal received independent PASS. No server is used. The existing retained 100-block panel begins with legal Place commands, so replaying a short prefix gives a real partially placed source for action/page and child-application cost. The 30/100 fully placed panels remain routing baselines rather than placement-root scale evidence.

A local macOS arm64 LibTorch installation was discovered under ignored `artifacts/local-libtorch/torch`. Feature-enabled `cargo check -p aic-learning --features libtorch` and the 88 library tests now compile/run locally. This removes the earlier local compile blocker but does not supply GPU throughput or actual upper physical factory evidence.

An ignored width-32 local CPU action-head probe now measures 4,096–262,144 synthetic rows per call; the 262,144-row forward with full softmax took 43.2 ms after a 70.4 ms batch build. A more stable 1,024-child native sample took 15.2 ms on the legal 100-block partial state and 19.9 ms on the hypothetical 167-block graph. These are isolated local timings, not integrated large-root performance. The present per-action child copy and replay path needs its own scalable boundary alongside chunked model scoring.

The first independent design review `/root/review_plan00_exact_design` returned `BLOCK`: the existing root stably sorts all actions by first-stage prior before rank Gumbel; the first draft omitted that order, the second anchor mixture and clipped weights, the all-child value maximum, the actual `f32` target mass in the gradient, and late lower witnesses in lower replay. The first draft also lacked a complete sampled proposal and quantified spill cost. The draft design and report have been revised to address those findings, but the decision is not yet marked ready. An updated local optimized external-sort mechanics probe processed 5,715,346 synthetic 24-byte sort records alongside a 16-byte source-order ledger with 47.4 MB maximum RSS, 365.8 MB combined file peak and 1.21 s process wall time; actual model score and replay training cost remain unmeasured. The local volume has about 11 GiB free, less than a 24-root hypothetical upper ledger projection, so that full storage gate will require the server after renewed permission.

The source trace now includes the first stable prior sort and the later edge re-sort, two-stage anchor mixing, clipped target weights, the all-child value maximum, and late lower witnesses in both the outer denominator and lower training. A versioned uniform-plus-anchor sampled boundary is specified and rejected as the current choice because its one-pose coverage at practical sample sizes is too low without physical evidence. The optimized native pager traversed all 5.7 million legal Place commands in 1.253 s and the hypothetical 67-million Place commands in 20.469 s locally. The real 100-block partial state's graph input took 0.0744 s to build a 262,144-action synthetic batch and 0.0348 s for a width-32 no-gradient CPU forward. Those independent components are not an integrated root or trainer benchmark; the draft decision remains under review.

A subsequent release-mode local probe integrated native enumeration, current full child application, actual feature/anchor extraction, bounded CPU model scoring and temporary score writes over every 5,715,346 legal Place command on the 100-block partial physical state. It took 106.699 s, of which 103.551 s was child application and feature/anchor derivation; model forwards used 0.508 s. This supersedes the earlier child-only linear projection as an estimate of the current complete-child path. The proposed analytic placement scorer must pass row, anchor and child-value parity before the design's throughput claim is credible. The probe did not use the server or measure the complete catalog/replay/trainer.

A bounded four-offset parity probe then compared 1,024 legal placements. A prepared connection-table calculation matched all feature rows, child state values and anchor `f64` bits; its measured calculation time was 0.000116 s versus 0.018435 s for full child application plus derivation on those samples. A fixed-plus-incident shortcut changed rounding, so the design now requires compact accumulation in original connection order. Final-placement, terminal and full-root throughput gates remain open.

The third independent design review `/root/review_root_catalog_r3` returned `BLOCK` because a retained **sorted** ledger would force random native rank replay and repeated pose-count setup for every training action. It also omitted efficient anchor-prior ownership and the second target denominator. The design now retains `(first-stage prior, anchor prior)` in native source order for sequential training, uses a 24-byte sorted search temporary, and stores the second target denominator. Retained upper storage remains about 1.07 GB per hypothetical root, but temporary sort peak is larger; a fresh review is pending. No server was used.

The fourth independent design review `/root/review_root_catalog_r4` accepted the source-order replay and cost boundary but returned `BLOCK` on two persistent record omissions: per-case native `Limits` plus effective versioned configuration identity, and the common unvisited completed-Q scalar `q_0`. It also requested explicit raw-score and normalized-prior passes. These have been added to the draft descriptor and scoring sequence; focused re-review is pending. The updated 24-byte external-sort probe retained a 91.4 MB source-order ledger and used 365.8 MB combined files at the 5.7-million-action local root.

The fifth independent review `/root/review_root_catalog_r5` returned `PASS_WITH_NOTES` for the final module boundary. It found no remaining contract omission; local implementation gates remain for close-prior sort parity, final-placement and terminal analytic parity, integrated replay/gradient and actual storage use. The full prepared analytic scorer and native pager traversed all 5,715,346 legal Place commands in 1.782 s locally. The upper logical count remains hypothetical and does not certify physical feasibility. The selected design is [the exact streamed root catalog](../designs/2026-09-28.00-streamed-root-action-catalog.md). Implementation plans may now be authored; no server was used.

The native ignored probe counted 545,380 Place commands for a legal 30-block partial physical panel and 5,715,346 for a legal 100-block partial physical panel. The two fully placed baselines have zero Place commands, as expected. A sparse 320 × 320 native fixture has 808,992. A generated 167-block logical upper graph under a *hypothetical* 320 × 320 bound has 66,977,600; the full page loop took 279.159 seconds locally in debug mode, while a separate four-page run had 64.9 MB maximum RSS. This upper result is not physical feasibility evidence. The source trace and tensor payload estimates are in [the root-scale report](../reports/2026-09-28-hierarchical-root-action-scale-gap.md). The exact-versus-sampled architecture decision and reviewed design document remain open.
