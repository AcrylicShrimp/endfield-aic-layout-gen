# Plan: Encode the physical constraints the editor actually applies

## Current Status

- State: Completed
- Last Updated: 2026-09-15 14:35:52

## Goal and Scope

Priority **2 for likely learning impact**: irrelevant fingerprints and wall time
consume representation capacity, and historical directions fail to state the
effective constraints after edits. Replace the production observation schema with
one physical view used by the existing factory learner. This is one integrated
encoder-input cutover, not a new editor, procedural compiler or pretraining model.
Preserve the pretraining design's eventual shared physical interface: no fabricated
recipes or synthetic labels, and no second procedural feature builder later.

The direction mismatch is confirmed. Its effect on learned quality and the harm
from omitted component details are hypotheses, not measured causal conclusions.
This plan removes the mismatch and makes the information contract testable.

## Proposed Changes

Add `PhysicalView` under the existing native declarative learning implementation.
Retain immutable catalog tables and explicit native-to-graph index maps at admission.
Cache geometry/constraint views by revision, refreshing decision/work globals when
attempts or work change even if geometry does not. Refactor effective endpoint
restriction derivation into one helper called by view construction and repair;
do not clone a whole routing blueprint merely to observe its directions.

Use the following packed schema, with named Rust constants/field accessors rather
than unrelated numeric literals. Column order follows table order. Zero is the
absent numeric value; kind/relation bits determine applicability. Directions use
the existing catalog cardinal order; boundary normals use exact integer vectors.
Positive rates/capacities use `ln(1 + quantity_per_second)` in neural inputs only;
the native authority retains exact rational values. Catalog capacities convert
`quantity * 1000 / duration_ms` with checked rational arithmetic before float encoding.

| Bank | Ordered fields | Width |
| --- | --- | ---: |
| node static | kind one-hot (facility, facility-terminal, external, channel, component, catalog-port, network, commodity); base footprint w/h divided by s; allowed rotations 4 bits; transport 2 bits; input/output 2 bits; log demand; log capacity; component kind 3 bits; permitted input/output cardinal masks 4+4 | 31 |
| node state | local x/y, current w/h divided by s; rotation sin/cos; boundary normal x/y; conflict count; selected-port bit | 10 |
| edge static | relation one-hot (transport, facility-terminal, facility-port, selected-port, original-port, component-channel, network-member, commodity-member); transport 2 bits; log rate; log effective capacity; current first/last restrictions each 4 direction bits plus unconstrained bit; baseline first/last headings each 4 direction bits plus no-recorded-heading bit; zero-length-permitted bit | 33 |
| edge state | pending bit; retained path length/s; relative dx/s, dy/s | 4 |
| path cells | local x/s, y/s; incoming direction dx/dy; outgoing direction dx/dy; start/end bits, with explicit transport-edge references | 8 |
| globals | best/initial score ratios 3; log initial score components 3; pending fraction; conflict area/initial area; remaining decision fraction; remaining cumulative work fraction; log next-action work allowance; search padding/s; log width, log height, 1/s | 15 |
| root action | existing family bits, local displacement, rotation, extent, axis and local band/count meaning from the coordinate plan | 12 |
| conditional port | facility-local connection x/y divided by s; boundary normal x/y; direction 2 bits; transport 2 bits; current-assignment bit; original-assignment bit; log applicable capacity | 11 |

For network/commodity nodes, inapplicable fields are zero and kind bits remain
populated, as specified below. Add one catalog-port
node per facility port at the current rotation, including unused compatible ports;
rotation-specific candidate features stay in retained port tables. Add component
nodes linked to their existing distinct channel nodes, network membership nodes
and commodity equality nodes. These typed relation edges convey information to the
encoder; only transport edges are routing obligations. Preserve ordered route cells
and directed endpoints. Never infer transport connectivity from coordinate equality.
No source recipe/utilization/product/port-name bytes enter numeric columns.

Relation endpoints are: transport node -> transport node; facility -> terminal;
facility -> catalog-port; terminal -> selected/original catalog-port; component ->
channel; terminal/external/channel -> network; network -> commodity. The existing
bidirectional message passing consumes each typed edge; this does not create a
reverse transport obligation. Non-transport edges have zero rate, capacity, path
state and restriction columns. Network/commodity positions, extents and rotations
are zero; applicability follows their kind bits.

Original-port relations use the original physical port definition at the current
facility rotation, never its name as a scalar. Baseline facility endpoint headings
are expressed in the unrotated catalog facility frame, derived from original
heading minus original facility rotation; external/component baseline headings use
the fixed grid cardinal frame. The endpoint node kind determines the frame. Retain
the original `None` case explicitly, because zero-length boundary-arm derivation
differs from a recorded heading. The current mask and the baseline mask therefore
have distinct meanings. Derive both from the same retained native rule authority;
do not remove the established original-turn behavior to simplify features.

Path-cell incoming/outgoing vectors are exact unscaled unit directions along the
retained ordered path. A missing endpoint neighbor has vector zero and the matching
start/end bit. A zero-length path has both bits set. This carries directed segment
information through the existing cell-embedding pool: x/y alone followed by mean
pooling would forget path order. Keep simple-path incidence and edge ownership exact.

Transport-edge capacity is the minimum of applicable transport and endpoint
component capacities from the same validation authority; component nodes also
expose their own capacity. A facility port has the relevant transport capacity,
not an invented per-port catalog field. Keep missing/invalid catalog references
as admission errors. Effective masks describe exactly the constrained query,
including the zero-length special case, rather than original port normals alone.

Update `learning.rs`, `input.rs`, `runtime.rs`, collection packing, model init/load,
config validation, `collection/rollout.rs::bytes` and
`training/frozen.rs::{compact,bytes,pack}` together. Graph
indices use maps; remove `facility_count + native_node_id` assumptions at consumers.
Temporarily retain the old mean-prefix behavior with its new 11-column port input;
the next plan replaces that behavior. Keep width 40/two message rounds and existing
PPO hyperparameters; changing feature sufficiency does not justify model tuning.
Use a shared typed allocation-size helper for every numerical bank: live memory
uses vector capacity times `size_of::<Row>()`, and compact serialized estimates use
retained lengths plus reference/branch storage. Count shared allocations once per
owner. Add all new banks and the eight-column path encoder to packing/validation;
remove the model's separate hardcoded two-column path input widths. Propagate new
view-construction errors through `Runtime::observe`, pool replies and collection
as structured diagnostics instead of unwrapping an invalid view.

## Verification Plan

Add native observation tests pairing the view's effective masks with actual repair
queries after 90/180-degree rotations, port swaps, immediate turns and zero-length
edges. Mutate each relevant physical property separately and assert the intended
field/relation changes. Check bridge channel non-connectivity and distinguish
same-commodity separate networks from different commodities. Include a component
with supported 1x1 footprint and nontrivial direction masks from a minimal external
catalog fixture; unsupported larger components must still fail admission.
Construct two drafts with the same current selected ports/masks but distinct
baseline headings, then select their original port. Require different baseline
input fields and exact agreement with each resulting native restriction. Cover
original-versus-reassigned port identity and both `None`/recorded baseline headings.
In a path-encoder helper test, compare an ordered path and its reversed traversal
and assert different incoming/outgoing cell features under fixed row correspondence;
this is not admission of a reversed path with unchanged directed endpoints. Verify
zero-length endpoint bits in a valid native case.

Rename opaque instance/network/terminal/port/catalog IDs consistently and permute
input rows; compare physical arrays under explicit correspondence. Changing commodity
equality must change relations, while changing just commodity spelling must not.
Artificial wall delay must change neither physical arrays nor logits/value. Remaining
decision/work changes must update globals even on unchanged geometry. Compare current
input to its packed/frozen/restored form. Allocate excess vector capacity and set a
memory limit between the old underestimate and actual new allocation: live collection
must reject before collecting more rows. Test compact replay's separate byte estimate
and shared ownership accounting as well as the actual observed process-tree RSS.

Run fmt, default and learning-enabled workspace checks/tests from the prerequisite.
Check batched versus individual graph forward/backward agreement (float tolerance
1e-6 CPU, 1e-5 CUDA, exact masks/indices), using distinct graphs to expose offset
mistakes. Do not require old-model numerical equality after the intentional schema
change. Preserve the isolated optimized masked-reference exact regression. Record
node/edge counts and packed/frozen bytes on retained small/large cases; the integrated
release runtime measurement belongs to the final readiness plan. Run documentation
maintenance checks and commit the complete native/learner schema cutover together.
