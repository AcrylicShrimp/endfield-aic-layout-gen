# Plan: Train and evaluate the bounded physical outcome predictor

## Current Status

- State: Ready
- Last Updated: 2026-09-16 00:15:00 KST
- Blocker: None

## Goal and Scope

Add and run one small supervised experiment over the completed 96-root physical
outcome dataset. Train the accepted multi-head state-action predictor, select its
checkpoint using development roots, compare it with constant and linear geometric
baselines, evaluate confirmation roots once, and publish a fixed pass/fail gate
for the later PPO transfer experiment.

This step does not change PPO, collect more data, tune from confirmation labels,
use predictions as action masks, or expand training after a failed gate. It reuses
existing packing, Adam, resource-guard and safetensors code instead of creating a
second training framework.

## Completion Criteria

- [ ] A strict external config binds the dataset/config/catalog hashes, native
  width-40 two-round model schema, seeds `930000` and `930001`, 12 epochs,
  four-root batches, Adam/loss settings, fixed baselines and transfer gate, plus
  30-minute, 8-GiB RSS and 512-MiB output limits.
- [ ] Dataset admission uses one shared verified-index API in `outcomes::storage`
  to check the completed manifest and split/source/chunk bindings once. Training
  reads bounded root chunks, keeps roots in their assigned split, and does not
  hold the full decoded 645-MiB dataset or revalidate source JSON in each epoch;
  the existing full validator delegates to the same index and reader.
- [ ] The predictor reuses the existing `nodes`, `edges`, `paths`, `messages`,
  `updates`, `context` and terminal-bound `port_pair` parameters. The model exposes
  one selected-root embedding helper that retains the existing optimized masked-
  reference behavior. Its action embedding binds every selected port feature to
  its terminal node and feeds one affine projection per disposable head.
  Encoder-only output excludes actor, critic, prediction heads and optimizer state.
- [ ] Censored rows contribute no loss. Changed/unchanged/rejected flags use
  uncensored charged rows; pending/conflict flags and counts use observed changed
  drafts; completion uses observed changed drafts; candidate metric targets use
  actual complete-candidate metrics divided by the initial score; routing-budget
  exhaustion uses only its explicit observed label. Each head averages over its
  own valid mask and reports its denominator.
- [ ] Training shuffles roots deterministically, encodes each state once per
  batch, checks finite loss/gradients, and atomically replaces one latest and one
  best-development checkpoint per seed. It does not retain an epoch archive or
  add a journal.
- [ ] The constant baseline uses training rates/means. The geometric baseline is
  one affine layer over global, selected-root, family, assignment-count and mean
  selected-port features with the same labels and optimizer. Development selects
  checkpoints before confirmation chunks are opened.
- [ ] Confirmation metrics are root-balanced and broken down by size, family and
  pending/complete pre-action state. Report completion log loss, Brier score,
  ten-bin ECE and AUROC only for two-class strata, plus raw and normalized metric
  MAE. Single-class strata remain explicit without accuracy claims.
- [ ] The fixed transfer gate passes only when the two-seed mean multi-head
  confirmation completion log loss beats both baselines, mean AUROC is at least
  `0.60`, and mean normalized area/transport/turn MAE beats the constant baseline
  by at least 5%. A failed gate is a complete result and ends this experiment.
- [ ] Add only two focused test cases for failures that could invalidate the
  experiment: one combines split isolation with label masks/denominators; the
  other checks terminal-bound action embeddings, shared gradients and the
  encoder-only allowlist. Do not add checkpoint, resource-limit, CLI-variation or
  byte-reproduction tests. Run the relevant tests once, the repository-required
  workspace checks once, and the registered CUDA experiment.
- [ ] Commit the implementation, fixed config and compact report. Keep model and
  checkpoint artifacts under ignored `artifacts/`, and report the commit and
  clean worktree state.

## Proposed Changes

Add `aic_learning::pretraining` behind `libtorch`, using only compact config,
model and run modules. Keep baselines and evaluation as direct helpers in the run
module instead of new frameworks. Extend `outcomes::storage` with a verified
manifest/index plus root-chunk reader so its current full loader and pretraining
share hash, framing and binding checks. Make the existing model's state encoder,
optimized selected-root embedding and terminal-pair encoder crate-visible so
policy and pretraining call the same implementation. Use the existing batch graph
packer, Adam wrapper, resource guard, ledger and safetensors support.

The selected-action embedding concatenates the two selected root references
(using graph context for missing references), graph context, the selected root's
12 features, the mean terminal-pair encoding of persisted assignments, and
`log1p(assignment_count)`. Non-placement actions use a zero assignment mean and
count. Each outcome head is one affine projection from this embedding.

Fix the registered experiment at two seeds, 12 epochs, four roots/128 rows per
batch, Adam learning rate `0.0003`, betas `0.9/0.999`, epsilon `1e-8`, foreach
updates and gradient clipping `1.0`. Normalize pending and conflict counts by
`log1p(64)`. Recover the initial area, transport and turn denominators from the
owned global log-score features, require a consistent positive value throughout
each root, and normalize the actual current metrics by those values.

Use weights: completion `1.0`; changed, pending flag, conflict flag, unchanged and
rejected `0.25` each; pending/conflict counts `0.25` each; area `0.5`;
transport/turns `0.25` each; routing-budget exhaustion `0.25`. Development
selection uses the same masked weighted loss and earliest-epoch tie breaking.

Index and hash all source/chunk bindings once, then decode four selected root
chunks per update and release them after the update. The epoch loop never loads
source layouts. The constant baseline derives masked training prevalence and
means with epsilon clipping. The geometric baseline concatenates 15 global
features, 12 selected-root features, a three-way family indicator, assignment
count and mean 11-dimensional chosen-port features, then uses the same affine
heads and 12-epoch schedule.

For each seed, atomically replace `latest` after an epoch and `best` after a better
development score. Each contains model/head/Adam/RNG state and dataset/config
bindings. The small publisher directly carries forward the existing PPO sequence:
write JSON and safetensors into one sibling staging directory, flush and `sync_all`
files plus directory, hash and ledger the files, rename the directory, then replace
the pointer. It does not generalize or change the PPO-specific `Store`. The bounded
screen restarts from scratch after interruption; it does not add a resume protocol.
On completion, save a separate encoder-only safetensors file. Reuse the existing
resource guard and byte ledger directly; do not add separate persistence layers or
new tests for those reused utilities.

Initial admission may hash opaque confirmation chunk bytes, but it does not decode
or expose confirmation labels. After all best-development hashes and baseline
hashes are fixed, record them in state before decoding confirmation chunks.
Evaluate confirmation once and write a
compact report with label counts, per-seed and aggregate metrics, single-class
strata, runtime/RSS/output, and every gate clause. Add one CLI command:

```text
aic-cli learning pretrain-outcomes --config ... --dataset ... --output ... --device ...
```

The command checks its final checkpoint hashes, encoder parameter allowlist,
metric denominators and output bytes before publication. A separate validator
would duplicate that small bounded final check and is not added.

## Verification Plan

Add exactly two focused tests under `pretraining::tests`:

1. A small two-root table checks split isolation, native statuses, censoring,
   target values and per-head masks/denominators, including a head with no label.
2. A tiny graph checks that swapping terminal-port bindings changes the action
   embedding, backward reaches every shared encoder family, and the transfer
   allowlist excludes every policy, critic, supervised-head and optimizer tensor.

Run them once, followed by the repository-required checks:

```sh
cargo fmt --all
```
