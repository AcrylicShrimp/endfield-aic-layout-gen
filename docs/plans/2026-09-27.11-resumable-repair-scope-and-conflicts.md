## Goal and Scope

Prepare one trusted repair request, permitted removal set and conflict order from an immutable macro source before the two first-turn quotas are snapped. Retain the small charged sizing result across temporary aggregate-memory refusal; admit the maximum simultaneous scope/hash or scope/conflict memory before the exact state hash and conflict pricing begin. Thus a pending task holds no partial scope reservation that could deadlock another pending task, and already charged sizing work is not repeated. The measured local preparation stages are short enough to keep their inner calculations direct for now; their hard deadline and work checks remain active. This step ends at an owned `PreparedRepair` plus ordered conflict cells; draft creation and repair attempts belong to later steps.

## Completion Criteria

- [ ] A small charged sizing pass that builds no new scope/conflict collection obtains the exact inputs to the existing scope/hash and conflict reservation formulas. Its result is retained during aggregate-memory wait, without repeated charges. Read the task's selected IDs through a borrowed slice; defer the pager-owned ID copy until after admission. Before the first scope copy/hash/pricing pass, the owner reserves `scope + max(hash workspace, conflict output/scratch)`, the peak of the two sequential stages rather than their sum. Trusted internals consume that preheld envelope without reserving it again; after hashing/sorting, release unused scratch and transfer only retained scope/order bytes to the pager. A waiting owner holds no partial scope reservation, and every allocation has one live reservation through transfer or release.
- [ ] An exact source-bound internal request is authenticated once when admitted and reused while the immutable source identity is unchanged. External/deserialized repair requests still receive the existing full identity and scope checks. No per-attempt state hash or full scan is added.
- [ ] Conflict pricing keeps its current physical capacity and commodity decisions and deterministic ordering. A hard deadline, hard work limit or impossible memory floor is typed unknown; only a policy-empty permitted removal set is an empty scope. A temporary aggregate refusal is pending, not a terminal result or a busy retry.
- [ ] The outer lower pager and MCTS wake gates recognize a pending repair-preparation memory refusal. `first_actions` and `next_actions` batch guidance and invoke `page` only for fully prepared tasks; pending tasks cannot execute a direct or repair page. On temporary aggregate refusal, pause that task's hard allowance clock before returning pending; resume only when live bytes fall and the task is eligible to retry. If pausing itself finds the hard deadline already expired, report typed deadline unknown. A task is skipped while shared live bytes have not fallen and retried once they do, including through a zero-action cached node without waiting for a new visit page. The initial zero-action drain stops when every pending task is memory-blocked; if no retained action or active owner can release memory, report typed resource unknown rather than leaving a permanently pending false no-action result.
- [ ] The two first-turn quotas are snapped exactly once after scope and conflict preparation finish. Preparation waits do not consume a partner's active first-turn clock; completion checks the remaining hard budget for both first turns. Representative placed upper-scale preparation, including state hash/serialization, time, bytes, category charges and process RSS, must be measured against the actual remaining first-turn credit. If an indivisible hash/sort phase cannot fit that credit, revise this plan to a retained cursor before readiness; do not introduce a smaller hard rejection or silently consume the other turn.

## Proposed Changes

Keep the existing native scope and conflict pricing rules as the single implementation. Add one preparation owner for the outer pager with `Sizing`, `AwaitPeakReservation` and `Ready` stages. It reads the immutable `Arc<Session>` and the task's selected IDs through a borrowed slice: change `Task::selected()` to borrow the route ID with `slice::from_ref` or the network IDs directly, and allocate the pager-owned copy only after peak admission. `Sizing` makes one charged pass over selected endpoints and committed route lengths without constructing scope/conflict collections, retaining the resulting scope/hash/order reservation numbers and the exact work charged; a retry never repeats that pass. Arithmetic is checked and an unrepresentable required size becomes typed resource unknown. Compute `scope_bytes + max(hash_workspace_bytes, conflict_reservation_bytes)` from the same formulas currently used by `repair_scope_for_policy`, `repair_state_sha256_inner` and `repair_conflict_order_checked`. This equals their maximum simultaneous reservation, so it is not a new hard ceiling. Reserve the entire envelope before the main scope scan or state hash. If shared aggregate memory is temporarily unavailable, retain only the small sizing result, pause the task's `RequestAllowance` before returning pending, and retry after live memory falls. `pause()` may itself reveal an elapsed hard deadline; classify that as typed deadline unknown. Resume the allowance only on an eligible retry, not on every scheduler visit, and pause it again if reservation is still refused. Two waiting preparations therefore cannot hold large scope reservations while waiting on each other or spend active request time while idle. If the source-owned envelope cannot fit either the per-request cap or the aggregate cap even after other requests release, stop as typed resource unknown. Once reserved, run the existing trusted rules and charge each actual scan/hash/pricing visit; teach them to use the preheld envelope instead of reserving twice. After hashing and sorting, shrink the envelope to live scope and order storage and transfer that guard into `RepairPager`; on error or cancellation release it exactly once. Public one-shot callers drive the same rules to completion and preserve their existing full validation boundary. The trusted prepared scope carries its one exact digest into internal draft/attempt paths; external/deserialized requests still run full state and scope validation.

No temporary page window runs before the first-turn snapshot. Each scope/pricing work charge and each 4 KiB hash-writer flush still checks the hard deadline; completed work is counted once. The short final sort and hash serialization are the remaining indivisible spans and must be measured at the placed physical upper tail. A hard stop releases the preparation owner and returns typed unknown, including when a 1 ms configured deadline expires during a legitimate computation; the code must not pre-reject a case solely because a conservative timing estimate exceeds a hard deadline while actual work could fit. If upper-tail measurements show an indivisible span can exceed the assigned first-turn opportunity, add a cursor fallback through a newly reviewed plan change. At the outer task, replace the premature `scope_prepared = true` assignment with an explicit pending owner. Resume after a real shared-memory release without spinning, and do not mark direct and repair complete on a temporary refusal. Snapshot all 16 cumulative work categories and the active time once after both preparation stages; keep the established equal first-turn split and do not create a new permanent search cap.

Wire that pending state through all scheduling gates. `LowerPager::first_actions` performs preparation for its initial indices, then filters **only `scope_prepared` tasks** into guidance batching and both direct/repair `page` calls; it never calls `page` on a pending scope. `LowerPager::next_actions` excludes unchanged-live pending tasks both when choosing one task and when assembling the inference batch, prepares newly eligible tasks, and filters out any that remain pending before guidance or a page. Other ready tasks retain their turn. `LowerPager::all_pending_blocked_on_memory` includes the waiting sizing owner at its last observed aggregate-live mark and returns true only if every remaining task is blocked. The initial `ensure_node_expanded` empty-action drain then stops without spinning and keeps the `LowerPager` on the node. `maybe_widen_lower` treats a newly ready scope-memory retry like its existing hash/publication retry, even when the node cached an empty action vector and the desired visit page count has not increased. A retry that still cannot reserve updates its live mark and yields again. If a zero-action node has no runnable task or retained action that could release the blocking memory, publish a typed aggregate-resource unknown diagnostic and close its pending owners rather than caching a permanent no-action conclusion or waiting forever. Do not mistake a pending resource refusal for an empty permitted repair scope.
