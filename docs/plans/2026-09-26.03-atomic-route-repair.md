# Plan: Atomic native route and network repair witnesses

## Current Status

- State: Completed
- Last Updated: 2026-09-26
- Blocker: None

## Goal and Scope

Represent an explicitly authorized bounded repair as one native macro transaction: remove a declared set of committed routes, install complete replacement route/network witnesses, and commit only if the resulting state is fully legal. This step provides the exact transaction, not the negotiated search policy that proposes it.

## Completion Criteria

- [x] A versioned repair request carries the trusted allowed-removal IDs and exact originating state identity separately from the untrusted candidate. The candidate declares removed connection IDs and complete replacements; stale, duplicate, unrelated or over-scope removals fail without mutation.
- [x] Removing routes releases occupied cells and exact port rates, recomputes junctions, and retains a bridge only when both axes remain legal and owned; surviving networks and bridge axes retain their identity and capacity where valid.
- [x] Every removed obligation and every obligation in the selected new task is satisfied exactly once by replacements, with no unrelated route changed. Each replacement's state revision must match the evolving draft after removals and earlier replacements. Replay and final independent validation are atomic for the live session; a failed member restores the exact pre-repair observation and metrics.
- [x] A local blocked-corridor fixture succeeds only after replacing an earlier route, while a tampered repair leaves the original route intact.

## Proposed Changes

Add a trusted `RepairRequest` supplied by the outer/lower caller and a separate `RepairCandidate` produced by search. The native `Session::apply_repair_candidate(&RepairRequest, &RepairCandidate)` checks the exact originating state/problem identity and candidate removal IDs against the trusted scope. Use a cloned session and a deterministic rebuild of derived occupancy, used ports and components from surviving committed routes at this rare transaction boundary. Its draft revision advances deterministically after removals; replacement candidates are generated for or checked against that draft revision at each replay step, preserving existing `apply_route_candidate` stale checks. The replacement set must cover every removed connection plus the requested new obligation exactly once. Route IDs and revision checks prevent a repair generated for one state from mutating another. The outer `MacroAction::Repair` variant carries the candidate and its trusted request reference, delegates to this native transaction and is encoded in state/action records. Do not expose partially removed states as ordinary outer nodes.

+   *self = draft;

+ }
