## Goal and Scope

Use the Plan .04 prepared pager and Plan .10 publisher's drive-to-completion operation for all native route-candidate one-shot APIs. This step alone owns public `Session::route_candidates*` and unpublished `RepairDraft::route_candidates` wrapper replacement and their versioned report/event contract; Plan .10 owns retained publication for hierarchical direct/network/repair pagers. Retire the legacy wrappers' duplicate search/publication loop, hidden `min(1_000_000)` state admission and separate 250,000-cell route-config rejection. Preserve result identity, explicit budgets, exact counter semantics and borrowed-allowance stop behavior. Learned model inference and direct `shortest_path` callers have separate plans.

## Proposed Changes

After Plan .10 owns found-path publication, route every `Session` variant and the repair-draft unpublished variant through the same `RouteCandidatePager`. Expose a compact ordered event stream: `Found` at durable lease creation, then `Duplicate` or `NativeRejected` only at their committed semantic outcomes. Build `Report` from pager counters and events once, calculate diversity once under the same allowance, and map unknown to the existing termination plus `allowance_stop`. Existing `RequestAllowance` work caps and identity stay authoritative.

For the public guided variants, keep the caller's `&Guidance` borrowed through one-shot preparation. After endpoint pairs, run the existing charged `GuidanceValidationCursor` directly over that borrow and retain its validated directed-cost maps. Change its currently infallible `IndexMap::with_capacity` and growth to fallible, preadmitted allocation. Build a small fallibly allocated, metered summary containing model version and each head's ID, predicted success and uncertainty; these are the only raw guidance fields used by the pager after validation. Hand the summary and map reservation to the pager once, without duplicating directed costs. The retained hierarchical path may pass owned guidance to the same preparation and release its raw directed-cost storage after validation, decrementing the current `route_output_bytes` guard for exactly those released bytes while transferring the surviving summary/map reservation. One-shot callers need no long-lived borrowed pager. An invalid input or a page/memory stop releases the partial map and metadata reservations and returns the existing typed result. Keep pair-before-guidance validation order, once-only `RoutingScans` charge, candidate provenance and learned scores. This is a private preparation handoff, not a public `Guidance` schema change or a second validation pass.

The wrapper clears stale `last_stop` before beginning. A preparation stop already carries its `RequestFailure::Stopped` and releases owned preparation. For pager `Pending`, query the borrowed page clock/relevant work limits at the boundary, and use a recorded aggregate-memory stop when present. Return a typed partial report on either stop; otherwise advance an internal page under remaining hard/window credits. `RepairDraft::route_candidates` uses the unpublished Plan .10 assembler, not a normal published candidate that later needs removal. Remove the v5 loop and its upfront capped state estimate after an exact local caller comparison. Do not add a second result validation pass or a per-sample distribution audit.
