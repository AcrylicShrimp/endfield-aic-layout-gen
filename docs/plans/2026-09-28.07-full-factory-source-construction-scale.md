## Goal and Scope

The current 249-facility medical source reaches a 16,384-A* per-growth-step budget after 27.6 minutes in release mode; it also inherits a fixed 64-search per-connection limit calibrated only on smaller diagnostic layouts. This step exposes and calibrates the constructor's actual finite effort and proposal limits and hands the exact upper witness and serialized byte measurement to Plan .24. Plan .24 owns upper input/checkpoint byte admission and final `Source::generate` publication/reuse, so an existing 16 MiB file gate cannot form a dependency cycle. This step does not change the hierarchical `ProblemGenerator`, train a model, or replace the constructor with a new framework. Constructor capability does not itself prove model exposure: Plan 2026-09-26.08 owns actual hierarchical panel and optimizer distribution. The existing `tools/native-training/training.json` remains a separate 64-facility native-pilot training policy until a reviewed pilot-distribution change; do not cite this source probe as evidence that this active policy samples upper factories.

## Proposed Changes

Add one explicit per-connection route-search allowance to the existing production request and source `Construction` config. Use the current 64 as the deserialization default and omit that field when serialized at its default so existing source configuration identity and committed-slot resume remain stable. The inner `connect_first` and external `connect_external` calls receive the configured value, still bounded by the existing per-growth-step `max_route_searches` and outer WorkControl deadline. Put the four existing request policy fields (`nearby_candidates`, `downstream_closed_growth`, `flow_direction`, `connection_first_placement`) in the source configuration with omitted-value serialization matching the current hardcoded values. Validate the existing direct-placement combination rule, 0..=8 nearby bound and 1..=16 analysis workers at source load, matching the production request boundary. Reject zero per-connection effort there and at the production request boundary. Do not add a second per-route timer, cursor or journal; the constructor's request and work control already own finite bounds and interruption.

At the private `network::first` and `network::external` search boundaries, retain `Option<ConstructiveNode>` for the existing callers but pass a small mutable stop-kind output through recursive search. Set it when a route-call allowance is reached or cooperative work stops; otherwise an unsuccessful return means candidate exhaustion/validation rejection. In `Constructor::close_internal` and the external-connection loop, count only failed connection calls by observed stop kind and by which effective allowance bound them. The existing `rejected_reasons`/diagnostics carry these compact counts and reasons into the report; do not create per-candidate traces. A `WorkControl::run` error at source completion supersedes a returned partial report; its exact string separates `native-work.elapsed-budget` from caller guard failure. Do not invent a report after `run` discards it.

The local trapped-port fixture shows that `network::external` currently spends the connection-wide allowance on every perimeter endpoint of the first attachment before trying another compatible port. The fresh review found that simply interleaving attachments at one recursive depth still lets a successful first lane descend immediately and exhaust the budget before another first-lane port is tried. Replace only this private external recursion with a deterministic connection-local work queue of partial states. Each state owns the already valid partial node, remaining rate, lane and local attachment/perimeter cursors. One scheduler turn attempts at most one A* route for one state, retaining its next candidate. After a successful final lane, immediately run the existing refresh and acceptance path and return if accepted; a rejected complete candidate leaves other branches available. Only a child with positive remaining rate enters the queue. Finish the root state's first attachment round before dequeuing incomplete children, then rotate root and child states in stable insertion order so neither a port nor a deeper branch monopolizes the shared allowance. A state with no candidates retires. Work cancellation, resource refusal or A* budget exhaustion discards all private partials and returns the unchanged source with the corresponding typed stop; no partial network is externally visible. The queue is bounded by successful route calls within the existing finite connection allowance, not an independent candidate cutoff; use fallible growth where available, carry an allocation refusal as a distinct resource/unknown result through the production caller, and release every partial on exit. Keep the existing route workspace, physical attach/crossing semantics and connection-wide counters. Avoid an eager attachment × perimeter Cartesian list, repeated full setup per A* call, and redundant copies of an unchanged parent; measure queued node bytes and process RSS before upper runs. Existing committed slots contain independently valid layouts and remain reusable; experiments record code identity because new uncommitted construction can follow a different order under the same default configuration.

At the existing failed-attempt boundary in `Source::generate`, retain a compact summary from the `ConstructiveProductionReport` before it is dropped. It already records failed-step statistics, placement attempts, accepted steps, report status, diagnostics, workspace/per-connection values and rejected reasons. Derive accepted closed facility/connection counts from the last accepted step or final closed incumbent (zero if neither is public), without rescanning candidate states. Include product, duration, seed and source identity from the current draw. When `WorkControl` returns no report, record the exact work error and known draw metadata before checking the caller guard again. If that guard cancels, write one compact failure record if the slot directory is writable, preserve the original cancellation error and leave the slot incomplete; never relabel every interruption a deadline. Keep atomic publication and reservation semantics. The normal successful path should not spend work on a repeated output audit.

Adapt the existing ignored source probe to read a complete `Source::Config` JSON path and slot from its environment, then call `Source::load` and `Source::generate` without mutating that loaded config. Outside the probe, materialize and retain exact per-arm JSON configs in ignored experiment artifacts before execution: include both medical and food products at 1,900 ms, set the same seed base, `max_attempts=1`, 256-facility ceiling and finite time/step/placement limits, then change only the stated per-connection or per-growth-step A* allowance between arms. Predeclare four slots whose deterministic source draws yield at least two distinct medical and two distinct food seeds **before** running construction. Record each config hash and slot draw; never call two arms comparable if they differ in another field. Save the selected complete `Source::Config` as a tracked benchmark asset, registered in the benchmark source-asset manifest and ignore exceptions. This fixture is a tested constructor capability, not an automatic change to the active native training template.

Use a fixed release binary to compare the same target/seed/config arm with 64 versus larger per-connection search and 16,384 versus larger per-growth-step search, changing one dimension at a time. Start with bounded local small/medium control cases and one upper seed; preserve their code/config identities. Run the upper matrix on the server only after renewed authorization and disk/GPU checks, closing each substantial run before another. If effort increases still fail, inspect the complete fixed-limit inventory and retained reason counts, then compare only existing policy switches under equal size/seed/effort. A newly binding hidden limit, new algorithmic policy or interface change outside the reviewed controls requires a revised plan and fresh review **within this same required outcome**; the upper case remains a gate here. The native training template's 64-facility distribution is recorded as a separate open policy, not silently promoted by this constructor result.

Keep Plan .24's byte admission boundary intact during this step. `Source::generate` writes `input.json` before the current bounded `hash_file` call. When that call rejects a valid upper file above 16 MiB, retain the incomplete slot as the exact Plan .24 handoff: measure its bytes, independently validate the physical payload with an explicit bounded offline reader, record the source/slot/config identity, and do not pretend it was committed or reusable. Give every arm and slot its own output directory because an incomplete slot cannot be rerun in place. If the current bound suffices, normal publication/reuse may pass and supplies stronger evidence. Plan .24 then adjusts the measured generated-input and checkpoint bounds and completes publication/reuse. A construction failure with no `input.json` is still this plan's unsatisfied constructor gate, not Plan .24's byte problem.
