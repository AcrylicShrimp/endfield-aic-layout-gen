## Goal and Scope

Provide one opt-in replay sampler component that varies the number of success
sequences per PPO minibatch and supports uniform, bounded score-weighted and
SIL-style positive-advantage priorities within each existing product stratum.
This supports separate tests of replay quantity, selection quality and retention.
Defaults and running training remain unchanged.

## Proposed Changes

Read-only live evidence from updates 1553–1568 (seed 29) shows 16,384 newly
collected actions, 7,936 success-sequence draws, 8,935 replayed action labels and
6,313 positive-weight labels; 2,218 new success admissions. Average update:
1,024 new actions, 496 sequence draws, 558.44 replay labels, 138.625 admissions.
Draws/admissions is 3.578, a throughput ratio, not measured lifetime per entry.
PPO actor epochs total 62: replay labels / fresh actor label presentations is
8,935 / 63,488 = 14.07%. Source: the seed-29 run in the scorer provenance,
`updates/1553.json` through `updates/1568.json`, fields actions, ppo.success,
ppo.actor_epochs and terminal events. This read did not change the active run.

For scale, the [SIL appendix](https://proceedings.mlr.press/v80/oh18b/oh18b-supp.pdf)
uses PPO horizon 2,048 and ten SIL batches of 512 transitions, or 2.5 replay
presentations per newly collected transition. Current measured ratio is 0.545;
count 32 would approximately quadruple it if call counts and lengths stayed
fixed. This motivates the quantity ablation, not importing paper batch sizes
without measuring graph/sequence cost. Our joint PPO auxiliary policy loss,
sequence units, critic treatment and optimizer schedule differ from that paper.


Extend `blueprint_execution_update.py` through an optional sampling argument
passed by `declarative_learning_runtime.Learner.update`. Validate it in
`declarative_learning_launch.validate`. Keep `success.sampler=balanced_available`
and introduce optional `success.sampling` with schema
`declarative-success-sampling-v1`, `sequences_per_minibatch` in {8,16,32},
`kind` in {uniform,score_mixture,positive_advantage}, and kind-specific fields.
Uniform has no priority fields; score mixture requires `mixture=0.5` and
`score_profile` in {rare_3pp,rare_3pp_exterior_capped}; positive advantage requires
`alpha=0.6`, `beta=0.1`, and `epsilon=1e-6`. Reject irrelevant or unknown fields.
The screen compares all three main kinds at counts 8/16/32; geometric profiles
are additionally gated by the native audit. These are registered experimental
choices, not inferred optimal defaults.

For each available stratum of size n, use the existing scorer formula:
`r_i = (1-place_fraction)` for a place-containing segment, otherwise zero;
`s_i = gain_i + 0.03*r_i`, optionally plus `min(exterior_i,gain_i)`.
Define `w_i = 1 + min(7, s_i/0.03)` and
`P(i) = (1-lambda)/n + lambda*w_i/sum(w)` with lambda=0.5.
These fixed experimental scale/cap choices give every item at least `0.5/n`
probability and no item above `4.5/n`. They are not claimed optimal. No mandatory
inward movement, zero-probability experience, or observed-utility requirement is
introduced by this score mixture. Thus unobserved successes can be sampled
without waiting for utility maturity.

The positive-advantage reference arm follows the paper's priority concept and
appendix alpha/beta, adapted explicitly to complete sequences and the existing
PPO/SIL kernel. Let `a_i` be the stage-balanced mean of `max(return-value,0)` from
the latest update that actually sampled sequence i. Its priority mass is
`m_i=(a_i+epsilon)^alpha`, and within-stratum probability is `m_i/sum(m)`.
Initial imported entries obtain `a_i` in one bounded packed inference pass during
the explicit transition; a fresh new entry gets the current stratum's maximum
known a, or 1 if none exists, as a temporary sampling priority. Never interpret
bootstrap priority as an observed utility. Active duplicates do not reset it.

Update sampled priorities after the optimizer update from measurements already
transferred by `imitation`, adding the stage-balanced positive-advantage aggregate
to `summarize_imitation` only when this consumer is enabled. Use latest-update
means, not a new EMA, and leave unobserved priorities unchanged. This is sampled
priority refresh once per PPO update, not full-buffer rescoring. Persist raw
priority and its observation update in `sampling_priority_v1`; ordinary restore
checks required fields before hydration. The existing utility EMA remains a
separate eviction signal and must not be overwritten by sampling priority.

Apply the reference arm's sequence importance factor
`c_i=(1/(n*P(i)))^beta / max_j(1/(n*P(j)))^beta` within its stratum. Attach it to
all labels of that draw in SIL only, retaining sequence/stage normalization.
Beta=0.1 is partial sampling-bias correction, not an unbiased uniform objective
or behavior-policy importance ratio. Measure future priorities and eviction
utility from raw uncorrected observations to avoid feedback from c_i. This arm
does not reproduce the paper's separate SIL optimizer steps or SIL value loss;
name it a priority/sampling reference, not an exact reproduction of the paper.

Draw half the configured count from each stratum when both exist. With only one
available stratum, balanced-available draws the whole count there; strict
balanced still rejects missing strata. An empty buffer yields no draws. Sampling
is with replacement and selected sequences keep every preparation label.
Use stable identity ordering. Build immutable CPU cumulative probability arrays
once after `Buffer.eligible` at the update boundary; use batched RNG uniforms
and binary search for each minibatch, then the existing order shuffle. Uniform
mode retains the original randint path, including exact default RNG consumption.
Do not reconstruct a distribution, reload sources or run the model per draw.

Preserve production per-update replay generator seeds
`5_000_000 + seed*1000 + ordinal` and order seeds
`6_000_000 + seed*1000 + ordinal`. Weighted draws intentionally consume a different
replay RNG sequence, but never the behavior sampler or PPO shuffle RNG. No new
persisted RNG/checkpoint journal is needed; update-boundary restore rebuilds the
distribution from checkpointed features and the explicit configuration.

Make `Buffer.hydrate` expose validated immutable retention features to the sampler
when needed, reusing plan 02's metadata. Feature extraction/backfill is activated
by score-mixture sampling even when retention remains v1; positive-advantage
sampling instead requires its initialized priority metadata. Ordinary restore
validates required metadata in `Learner.__init__` before hydration. Invalid probabilities,
unsupported count, missing metadata or inconsistent profile are structured
`declarative.replay-sampling.<code>` failures, not uniform fallback.

The score-mixture arm intentionally emphasizes its selected experiences in the
SIL objective; do not apply inverse-probability correction or multiply the loss by
the heuristic score again. Preserve existing `max(return-value,0)` and sequence/
stage normalization in `prepare_minibatch`. Increasing draws changes estimator
coverage/cost, not an unnormalized multiplication of the SIL coefficient. PPO's
fresh-data policy/value objectives and KL-tail behavior are unchanged. This is
not the partially corrected positive-advantage reference arm; report the different
SIL distribution/correction contracts explicitly when comparing outcomes.

Reuse existing selected IDs and utility measurements for actual draw counts,
unique sampled episodes, duplicate fraction and per-entry exposure. Record only
compact per-update distribution summaries (min/max probability and effective
sample size) once; detailed per-entry traces belong to the explicit screen.
