## Completion Criteria

- [ ] Trusted repair preparation changes only selected routes, rebuilds survivor occupancy, port and component indexes once, and native member replay changes only its selected obligation. Expected obligations are consumed once as members commit. Internal finish checks retained obligation and terminal state without rescanning every route, cell, port, bridge or junction, or rehashing a stable source.
- [ ] A completing member's Plan .01 replay supplies source-bound, independently validated `Metrics` to the same retained draft. Internal finish and Plan .10 publication carry those metrics without another layout build or validator pass. The legacy one-shot replay, which does not validate on completion, runs exactly one Plan 00 final validation. Missing metrics after a Plan .01 completion are an integration failure, not a reason to silently validate again.
- [ ] External repair candidate application retains request, schema, revision, coverage, member witness and cost checks, and reachable diagnostics for invalid supplied candidates. Its terminal state receives one independent validation. The former full incomplete-state checker is limited to an explicit offline audit or test oracle, absent from ordinary candidate execution.
- [ ] Offline fixtures exercise route geometry, occupancy owners, ports, bridges, junctions, unrelated routes and coverage, including deliberate corruption. Page and aggregate-retry fixtures verify retained obligation and metrics ownership, once-only work and reservation release. A bounded local upper-scale repair finish measures the normal path including any first terminal validation; no server use.

## Proposed Changes

In `crates/aic-pilot-native/src/constructive/routing_candidates/repair.rs`, make the repair draft's expected obligations an owned pending set established at the request boundary. `prepare_repair_draft_checked` already rebuilds survivor indexes and clears stale metrics after route removal; each successfully committed native member removes exactly its chosen obligation. Existing trusted repair scope and retained ownership bind the source without repeated hashing. Internal finish checks empty pending obligations, no active route or final failure, and the expected completion state, then hands the draft and its metrics to Plan .10. It does not call `validate_incomplete_repair_state` or compare every unrelated route in normal execution. Prove those preservation properties in offline tests. Keep the old full checker only in an explicit offline audit or test path if useful as an independent oracle.

Plan .01 validates the private child when the first member completes the factory and installs `Metrics`; moving that child into the retained draft preserves the exact metrics. A trusted internal finish treats missing metrics on this path as an integration error. The legacy one-shot repair member path calls command methods directly and does not run `Session::step` completion validation, so its completing finish must still advance Plan 00 materialization and validation once. Keep this fallback tied to that known path or cut it over to Plan .01. Never validate merely because a complete draft already has trusted metrics. No per-member or per-sample output audit is introduced.

`Session::repaired_candidate_with_allowance` continues to validate supplied request/candidate identity, ordered obligation coverage, member witnesses and final candidate equality and cost. Its checked admission drives the same native command rules and one terminal validation when needed; a supplied candidate cannot select trusted internal finish mode. Preserve user-visible diagnostics for reachable invalid supplied inputs. The old `repair-stable-state` result for deliberately corrupted private in-memory states belongs to the offline oracle, not ordinary publication. Plan .10 owns resumable cost, copying and atomic publication after this finish state is established.
