## Goal and Scope

Make the existing `hierarchical_search` panel publisher and loader agree on a finite, measured file allowance for the intended training and held-out size distribution. `prepare_panel_published` currently publishes a panel without checking the serialized size, while `load_published_panel` rejects a file above 16 MiB before `hierarchical_curriculum`, search or generation can use it. The loader checks metadata but the streaming parser itself has no byte bound if the file grows. This step owns only the hierarchical panel file boundary and exact published-byte identity. Plan .08 owns case selection, per-case effective limits, model exposure and distribution auditing.

## Proposed Changes

Measure existing panels and offline representative target-size assemblies first. Use one panel-specific finite allowance shared by publishing and loading; retain the separate `MAX_INPUT_BYTES` for search configuration and model metadata. Keep the current streamed digest writer and reader. At publication, obtain actual encoded bytes from `DigestWriter` before rename and abandon the pending file if the panel exceeds the allowance. At load, keep metadata as an early refusal, but wrap the file reader in an actual `limit + 1` byte bound and explicitly report oversize if reading reaches it; finish deserialization before retaining the streamed digest and byte count so trailing bytes participate in identity. Preserve panel schema, partition and case semantics. Keep report publication/loading on their separate existing path.

## Pseudo Code Diff

```diff
~ crates/aic-learning/src/hierarchical_search.rs
  keep MAX_INPUT_BYTES for config/model metadata;
+ const MAX_PANEL_BYTES = measured_finite_allowance; // distinct panel contract
  prepare_panel_published(...) -> publish_panel_json(...);
- publish_json_identity(...): rename(temporary, output) regardless of encoded_bytes;
+ publish_panel_json(...): stream_json_and_sha256_to_pending();
+ if encoded_bytes > MAX_PANEL_BYTES { remove_pending(); return size_diagnostic(path, bytes, limit); }
+ rename_pending_atomically();
- load_published_panel: metadata <= MAX_INPUT_BYTES; load_published_json(unbounded_stream);
+ load_published_panel: metadata <= MAX_PANEL_BYTES; load_published_json_with_read_bound(MAX_PANEL_BYTES + 1);
+ if bytes_read > MAX_PANEL_BYTES { return size_diagnostic(path, bytes_read, limit); }
+ preserve_hash_of_exact_parsed_stream_and_separate_report_loader();
```
