## Module Boundary and Comparable Libraries

The reusable unit in this plan is the **native replay module**, not its fork, command, map-growth or validation helpers. Its caller supplies one source owner, a command sequence, the existing request allowance and a live pinned external memory floor. The module owns its partial fork, preparation, admitted memory, command cursor, final materialization and validation until it returns an original source plus a completed result or typed failure. The caller may advance or cancel it, but cannot inspect or repair intermediate command state. Only a child whose entire command sequence was natively accepted crosses this boundary; a terminal child also carries independently validated, source-bound `Metrics`, while a nonterminal child remains explicitly incomplete for later member commands. Source identity, command outcomes, work delta, terminal-validation provenance and reservation transfer are part of the result contract; candidate pricing and publication remain the separate Plan .07/.10 boundary.

This boundary is informed by established Rust APIs: [Tokio's cancellation-safety guidance](https://docs.rs/tokio/latest/tokio/macro.select.html#cancellation-safety) explains why recreating a dropped in-progress future can lose work; this module retains one future across page stops and makes cancellation discard the private operation and release its reservation. [Tower's `Service::poll_ready` contract](https://tower-rs.github.io/tower/tower_service/trait.Service.html) demonstrates explicit readiness/backpressure before dispatch; the existing allowance already provides admission, so adding Tower would duplicate machinery. [futures `Stream::poll_next`](https://docs.rs/futures/latest/futures/stream/trait.Stream.html) distinguishes pending from produced results; replay needs one terminal result plus typed page/aggregate stops, so an owned progress object is smaller than a stream abstraction. These are interface and ownership comparisons, not new dependencies or permission to narrow the required native behavior.

Interruption belongs at this replay boundary when copying a large mutable session, applying a long route across shared occupied cells, or constructing and independently validating a completed layout exceeds a first-turn work window while a node still owns the source. Retaining necessary progress prevents repeated copying and keeps the source available on cancellation. Small geometry predicates, capacity calculations and ordinary bounded command calls stay direct; they do not gain their own public resume or resource-limit protocol. The implementation reviewer must verify that each retained cursor pays for a measured large or data-dependent operation and that no extra runtime audit or arbitrary limit was introduced for uniformity.

The synthetic 1.98-million-cell calibration alone does not prove that every command needs its own cursor in the supported physical domain. Before adopting each retained phase, measure its work and atomic time on physically valid local cases against the actual first-turn credit. Keep state only where a page can interrupt that phase or the caller must preserve a found candidate through a stop; simplify a bounded phase to a direct call when sound admission covers it. This is an offline design and implementation review check, not a per-sample runtime audit.

## Completion Criteria

- [ ] A private `NativeReplayProgress` owns its exact source identity, incrementally copied fork, command index, partial command state, completed-layout materialization and independent validation progress, meter deltas and memory reservation. A temporary page or retryable aggregate-memory stop preserves them; a hard stop is typed Unknown and cannot be reported as infeasibility.
- [ ] `Extend`, `ReserveBridge` and `Connect` can stop at each data-dependent route, user, occupied-cell, catalog and validation visit. All command-local native-invalid conditions are resolved before semantic mutation; final independent validation still runs after a completing command commits. `Extend` growth of both old fork containers is admitted at simultaneous-allocation peak and copied across pages when needed, without a fixed route-size limit or repeated full-route copies on ordinary pages. A private fork may then hold a partially applied command across a page stop, but no caller can observe or publish it; a completed hard stop returns the original owned source with typed Unknown, while cancellation discards the whole owning candidate/partial/attempt and its source. Each command's native effects, turn and revision become visible together only after its retained commit phase completes, with each effect applied once.
- [ ] The same replay primitive accepts borrowed, existing shared and moved-owned sources, and returns the original owned source, native-validated child, exact command outcomes and charged work on completion; a recoverable rejection also returns the source. A caller can retain progress across yields without a second full source clone. The one-shot internal adapter preserves existing caller behavior pending Plan .10 cutover. Public `Session::step` and externally supplied candidate validation retain their established behavior; internal replay does not repeatedly scan all poses/routes merely to construct unused public `Step` progress records.
- [ ] A completing route is independently validated before publication. On success, install returned `Metrics` into the unique fork before exposing the child, so `metrics()`, `done()` and `fully_validated` agree with ordinary native completion. On validation failure, map the same final-validation diagnostic and return the original source without publishing a child; public `Session::step` keeps its accepted-command/final-failure result. Soft first-turn windows include replay and final validation; no fixed conservative upper bound becomes a hard rejection when actual work could fit. If a smallest indivisible operation cannot fit the measured upper-scale time credit, report typed fairness failure rather than claiming fair coverage.
- [ ] Local route, network-source and repair-source fixtures force a stop during each replay cursor phase and compare resumed versus uninterrupted child, command outcomes, work and reservation release. They cover terminal and nonterminal results, branching, shared users, crossings and both supported transports with physically valid varied layouts. The module review checks exact work and reservation accounting, the live pinned floor, the one-shot callers' established results, and that legal inputs have no new arbitrary cutoff; a hard budget stop remains typed Unknown. Exact cost, candidate provenance and member commit are tested in Plans .07 and .10.
- [ ] A bounded local matrix measures initial fork and each replay command, the four ReplayWork categories, admitted peak and process RSS, terminal validation and the longest indivisible phase at representative physical sizes. Measure the existing one-shot caller's locally integrated cost against its previous path before accepting this replacement. Resolve an atomic phase that can overrun the actual first-turn credit, or demonstrate a sound admission bound for that credit. Plan .10 owns full publication cost and the broad distribution Plan 2026-09-26.08 owns the supported physical distribution and default-cap evidence for the final Plan 2026-09-26.07 readiness gate; neither later responsibility is waived by this primitive review.
- [ ] The module review records which retained phases are necessary on physical inputs and which bounded helpers remain direct. A replay phase with no measured scheduling or ownership need must not retain an independent cursor merely for interface uniformity.

## Proposed Changes

Continuity checklist for the replay replacement: immutable problem/catalog/index data remain shared across forks (`Arc`); mutable route, occupancy, component and port state remains isolated; native legality, turn/revision behavior and independent final validation remain common with the existing path; replay work, peak memory, page stops and hard Unknown diagnostics remain admitted by the existing allowance; the already-used one-shot route caller is measured before this module passes, and the retained direct/network/repair workflow plus upper-scale active time are measured before final adoption in Plan .10, the broad distribution Plan 2026-09-26.08 and the final readiness Plan 2026-09-26.07. The new cursor may retain bounded scratch across pages but cannot add a per-step output audit or a second full-state snapshot merely for ownership.

In `crates/aic-pilot-native/src/constructive.rs`, add a private replay progression API with a retained legality phase followed by a retained private-fork commit phase. Reuse the existing legality/capacity helpers and `ReplayMeter`; move their data-dependent loops into retained cursors rather than duplicating rules. `BeginRoute` may remain a measured atomic unit when its sound soft-work and upper-scale time bounds fit the first-page credit; data-dependent `ReserveBridge`, `Extend`, `Connect` and completing-layout materialization/validation use cursor fallbacks only where measured page or ownership boundaries require them; a bounded phase may use a sound admitted direct call. A conservative bound can yield a temporary first turn but cannot reject the hard request. Map temporary page and retryable aggregate stops to `Pending` and preserve exact charged deltas. Before commit, finish every rule that can return a native-invalid diagnostic and reserve each growth before it occurs. During commit, the fork is exclusively owned by replay progress and may contain a partially applied command after a soft stop; the cursor keeps exact cell/map indices and applies each effect once. No caller receives the fork until that command has completed and turn/revision have advanced once. A hard resource stop completes the future with typed Unknown and returns its original owned source after releasing the private fork; explicit cancellation instead drops the entire owning candidate/partial/attempt and its source. A native-invalid result returns the untouched original source. This permits per-cell commit without copying a large active route or occupied map a second time solely to enforce an internal intermediate invariant. Public `Session::step` keeps its existing failed-command turn consumption and accepted/final-validation-result semantics; its one-shot path shares native legality logic but is not made transactional by this internal rule. A private adapter drives the new primitive to completion for internal one-shot callers without changing their current publication sequencing. The primitive returns the child, the original source when owned, and compact per-command accepted/turn/revision outcomes needed by repair's later `Step` assembly; it does not perform physical cost or semantic publication. Plan .10 replaces the production one-shot publication paths with retained progress after Plan .07 supplies the cost cursor. Plan .02 proves incomplete repair invariants offline and reuses this primitive's trusted completing `Metrics` at repair finish; the primitive hands those metrics through with the exact child. Keep boundary checks for deserialized or external actions and the first final independent validation.

For `Connect`, inspect the active path through a borrowed route view of cells and endpoint ports while building junction/bridge updates; do not clone the whole active cell vector before legality is established. Make `site_arm_use` consume this view or its constituent borrowed fields. Its facility endpoint lookup retains a catalog port index across pages and calls the established `project_port` rule only for the selected port; it does not repeatedly allocate all projected facility ports for each touched endpoint. The existing `PortProjectionCursor` from Plan 00 remains the fallback if a caller actually needs all ports. After legality and reservations succeed, move `active.cells` into the committed `Route` once and apply occupancy, port and component updates through retained commit indices. Native `Connect` errors must be decided before this move; resource stops during private commit discard or retain the fork according to their typed cause.

The source-to-fork copy is part of replay work. Replace the current one-shot `self.clone()` in `replay_route_witness_with_allowance` with a `SessionForkCursor` over the source fields, nested routes/cells and derived maps, retaining all partial allocations and copied-byte charges. Reserve before each growth, then transfer the live fork reservation to `NativeReplayProgress` without a release gap. The current `route_cells * 4096` and similar padded replay preflights must give way to cursor-owned measured reservations; these estimates can exceed the request memory cap even when the actual fork and layout fit. A source clone may use an atomic fast path only when a sound measured soft-time/work bound fits the current page; otherwise use the cursor. Never turn a conservative copy estimate into a hard refusal when the actual copy might fit.

`Extend` has a separate growth obligation after its native-invalid checks finish: the fork copy currently gives `active.cells` and `active_cells` only their existing lengths' capacity, while an extension appends to both. The retained commit must track each old allocation's reservation as part of the fork ledger, along with the prepared new-cell scratch. If either container has enough capacity for the full extension, append through retained indices without reallocating or rehashing. If it does not, reserve a replacement container's whole allocation **while the old one remains live**, build it from old entries in admitted chunks, append each prepared cell once, swap only when that container is complete and drop the old allocation; retain its accounted bytes as escrow credit until every replacement is complete, then release excess credit. Plan both containers **together** before either growth: evaluate both replacement orders and the actual hash-bucket capacity steps, including old containers, prepared scratch, and every interim peak. First establish whether the minimal required capacities fit in either order under both stable hard caps: the request peak cap and the aggregate tree cap after subtracting tree reservations that this replay's source/caller owners cannot release until replay ends. This pinned external floor is supplied from existing reservation guards, excludes bytes already in this RequestAllowance, and is refreshed by the owner at every page advance because its node/action guards may grow while replay waits. The owner keeps a resource-bookkeeping counter; it does not rescan module outputs. If so, choose a feasible pair up to geometric growth that maximizes the smaller of the two post-extension spare capacities, then total spare capacity, and only then minimizes peak. This keeps useful amortized slack without letting the first replacement starve the second. Evaluate only hash-bucket capacity steps and analytical vector bounds; do not scan every possible vector capacity. If only one container needs growth, use its largest feasible capacity up to the geometric target. Only aggregate bytes held by owners that can release during replay cause a retained retry of the chosen plan; a preferred pair above either stable cap must be reduced to the best feasible pair before allocation. The aggregate retry feasibility helper uses the latest pinned external floor, or it can retry forever on a guard that cannot disappear. If the floor rises before growth begins, discard the unallocated capacity plan and recompute it. Reserve the chosen order's maximum simultaneous *additional* live bytes as one growth escrow before copying either container; the escrow remains charged while both replacements proceed, so later node/peer growth cannot steal space required to finish the already-started command. Transfer escrow credit to each allocation without a second reserve; after a swap, drop the old physical allocation but keep its accounting credit inside escrow until the second replacement finishes. Then release the difference between reserved peak credit and final live allocations. This prevents a page between replacements from letting another task consume the released old-container space. Hard denial of this initial escrow leaves the private fork unmodified and returns typed Unknown; aggregate contention preserves the unallocated plan and retries using the refreshed floor. If neither order fits even at needed capacity under the stable caps, report typed Unknown. Do not impose a fixed path-length cutoff or repeatedly copy a long route on ordinary pages. The vector and set may be replaced independently to avoid unnecessary peak overlap. Each old-entry transfer charges actual `CopiedBytes`; legality has already charged `ReplayRouteCells` once per new cell, so retained commit uses a deadline/page checkpoint before each new-cell insertion without charging that category again. Do not precharge unprocessed entries. Reservations include the simultaneous old container, replacement, prepared vector, growth escrow and any other live fork state, with escrow credit counted only once; staged scratch is released or transferred exactly once. If a resource hard stop occurs during growth or commit, discard the private fork and all its live reservations, preserve typed Unknown and return the original source. A temporary page or aggregate-memory stop retains the cursor and allocations. Since no caller can inspect this fork during a command, its vector and set may be temporarily out of sync, but the next command and turn/revision cannot begin until both are complete. This is resource admission, not a runtime audit of module outputs. Bench the local fallback and one-shot caller here; Plan .10 and the broad distribution Plan 2026-09-26.08 account for integrated workflow and supported-distribution overhead before the final Plan 2026-09-26.07 gate. An atomic `reserve` or large set allocation is allowed only if its peak and measured upper-scale time bound fit the soft page; if a whole-container allocation cannot meet that bound, use a retained segmented representation or another bounded allocation path rather than silently exceeding the page.

The retained source and completing-layout builder need an explicit safe ownership shape. Use one pinned private replay future that owns `SourceOwner::Borrowed(&Session)` for an uninterrupted caller, `SourceOwner::Shared(Arc<Session>)` when the existing lower root already owns an `Arc`, or `SourceOwner::Owned(Session)` when a future network partial or repair draft moves its existing source into replay. All variants dereference to the same immutable source. Source field and hash-table iterators, and later `CompletedLayoutCursor` borrowing the now immutable completed fork, live *inside* that pinned future across admission yields. The future does not store a reference to a sibling field of `NativeReplayProgress`, use unsafe self-reference, or clone the whole source merely to obtain a lifetime. `NativeReplayProgress` returns an owned source with the validated child or recoverable rejection after the future completes; the caller keeps the original source reservation, while the replay cursor owns and releases only incremental fork/layout reservations. The borrowed one-shot entry drives the same future to completion without allocating a source snapshot. After command commit, freeze the fork behind a uniquely owned `Arc` while materialization runs; release the builder's reservation on any denial, cancellation or hard stop. Transfer the completed `Layout` into an `Arc` for the existing owned-input `ValidationCursor`; on successful validation, release layout/validator scratch, uniquely unwrap the frozen fork, install `metrics = Some(metrics)`, and only then return the validated child. On validation failure, convert the independent validator result to the existing `final-validation` diagnostic and reject the internal child while returning its original source; the public one-shot `Session::step` still records accepted command plus `final_failure`. The future communicates page visits, retryable memory requests, releases and typed hard stops through an admission request/response boundary. Work is charged only when actually consumed; a page yield does not precharge an unprocessed chunk. This boundary is resource control, not a routine module-output audit.

The progress owner must close every retained reservation explicitly: `advance` transfers fork reservation only with a completed child, `cancel(&mut RequestAllowance)` drops the pending future (including its owned source) and nested materializer/validator before releasing their exact live bytes, and every completed hard/invalid return releases fork bytes before handing the original source back. Plan .10's direct, network and repair owner states must call this cancellation path and release the separate source reservation when discarding a candidate, partial or attempt; task/node cleanup cannot just drop a pending cursor while the shared request allowance remains alive. Cancellation never promises to recover an `Owned(Session)` from a dropped pinned future. An interrupted process relies on the request allowance's own drop for aggregate memory cleanup, but that does not replace in-process cancellation. This is a resource ownership rule, not a repeated output check. Keep a typed admission-stop latch around completed-layout and independent-validation callbacks. If one of those cursors returns a `Diagnostic` caused by a hard work, deadline or memory refusal, return `RequestFailure::Stopped(original_allowance_stop)` as typed Unknown; only genuine native/layout invalidity maps to `RequestFailure::Invalid`. A soft refusal remains `Pending`, never a completed invalid result.

Network and repair owner transitions belong wholly to Plan .10, after the cost cursor exists. There, `Partial.session` and `RepairDraftState.draft` move into retained member progress; the primitive in this step must support that move and return without an extra source clone. Plan .10 retains source reservations and chosen pagers across yields, computes cost from the original and child, commits both child and priced member once, and releases all guards on cancellation. No partially integrated member path may be used in the later experiment until .10 passes review.
