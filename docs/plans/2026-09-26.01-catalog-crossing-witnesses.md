## Completion Criteria

- [ ] Candidate search derives bridge options from committed straight carrier axes (including shared same-item trunks), validated external catalog, transport, exact rates and excluded sites. It can propose a crossing even if ordinary same-item sharing is also legal; its crossing limit is explicit and reported, not hard-coded to zero or eight.
- [ ] A candidate witness names its bridge component/position/rotation and axis membership, reserves it before traversal, and replays it atomically through `Extend` and `Connect`. Stale/tampered bridges, turns inside a bridge, wrong transport, insufficient per-axis capacity and crossing through a terminal/body are rejected.
- [ ] A forced crossing case for belt and pipe returns a bridge-bearing candidate and completes through the independent validator; a case with no compatible bridge returns a local no-candidate/unknown distinction without false infeasibility.
- [ ] Learning observations and candidate summaries expose installed bridge axes and component use with a documented checkpoint/input-schema decision, so later decisions can see the committed resource.

## Proposed Changes

Adapt `aic-routing::crossing_options` and `PathResult.crossings`, plan 00's axis-owned physical `Bridge` DTO/validator and production channel tests. Build carriers by aggregate existing straight axis, not by assuming exactly one route at a site. Exclude bodies, terminals, junctions and incompatible components. In the exact graph, distinguish ordinary same-item sharing from a bridge crossing even when both transitions enter the same occupied point; preserving a crossing choice requires a separate search state and witness marker. Replace the router's blanket `crossing_limit > 8` rejection with a checked resource guard and explicit work-limited `unknown` result, since eight is not a game rule.

Encode each selected crossing as an explicit command before the `Extend` segment that enters it. Keep active bridge reservations separate from committed bridges; `Extend` may traverse an otherwise incompatible occupied cell only with a matching reservation and must leave straight on the other side. `Connect` confirms both axes, catalog pose, exact per-axis rate and declared connection membership, then commits the bridge with the route. Aborting or rejecting a route clears reservations without modifying the existing carrier. Replay occurs on a clone; final independent validation remains authoritative. Update route/network candidate metadata, hashing, features and schema versions where the new command changes serialized identities.
