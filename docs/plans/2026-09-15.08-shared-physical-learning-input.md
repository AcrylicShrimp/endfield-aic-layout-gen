# Plan: Share the physical learning input

## Current Status

- State: Completed
- Last Updated: 2026-09-15 22:08:59 KST

## Goal and Scope

Move the existing factory-only numerical feature construction and action-domain
projection onto the compiled physical problem/draft boundary, then expose the same
owned observation contract from factory and procedural sessions. For a
source-equivalent compiled problem, draft, budgets, counters and metric context,
both admissions must produce byte-equal numerical arrays, equivalent port domains
and the same selected common edit. The factory path must retain its current
features, ordering, masks, caching behavior and batched-model compatibility.

This step does not collect an outcome dataset, add supervised heads, change PPO,
or run pretraining. It does not change external procedural or factory interchange,
editor semantics, feature widths, model settings, action-family priors or learned
checkpoint version.

## Proposed Changes

Introduce a crate-private recipe-independent learning module beside the common editor.
It receives validated `CompiledProblemV1` and `PhysicalDraftV1` references plus a
small explicit context containing the initial/best three-component scores,
attempt and route-work counters, action/routing limits and search padding. These
are the only factory-session values used by the current global features. The
builder precomputes static graph tables once from the embedded used catalog and
compiled incidence, retains the existing physical frame and mutable-input cache,
and uses `PhysicalCandidateAuthority` as the sole root/domain/selection owner.

Move the current numerical `Input`, schema constants, frame math and graph-table
logic without changing column meanings or widths. Replace source-local lookup by
dense compiled block/node/component indices. Preserve canonical candidate order;
source names may remain lookup keys during admission but may not enter numerical
features. Extend procedural compilation's embedded used-definition catalog to
include the validated catalog definitions for both fixed schema kinds, `Belt`
and `Pipe`, before adding any definitions referenced by networks, components or
facility ports. This intentionally preserves both capacity feature slots even
when the published layout and every embedded facility use only one transport
kind; no default capacity is fabricated in code. Test that case explicitly.
Represent factory `Options` as the existing external configuration
and convert it once to `PhysicalCandidateOptions` at runtime construction.

`PhysicalLearning` owns an `Arc<CompiledProblemV1>` that was validated with the
session's initial draft at admission. Observation accepts only a draft, revision
and context, so fixed tables cannot be reused with another problem. It performs
no per-observation source hashing or compiled validation. The session remains the
authority that prevents its fixed problem from changing. Add a crate-internal
candidate enumeration path over the session-owned validated problem and draft.
The shared `aic-layout` extent helper remains safe for arbitrary input: it checks
every length, definition lookup and index needed by extent calculation and returns
a diagnostic rather than indexing or unwrapping malformed values, while omitting
unrelated static-catalog and full-path validation. The public standalone
enumerator keeps its complete validation for untrusted callers.

The common observation contains `Arc<Input>`, an `Arc` port-domain view, the
retained handle, source binding, revision, attempts and done flag. Keep the public
factory `Observation` shape used by `aic-learning`, either through a type alias or
a thin ownership wrapper with no numerical conversion. The wrapper retains the
existing `blueprint_sha256` field name for current `aic-learning` diagnostics and
maps the common `source_sha256` binding into it. Add procedural observation and
selection methods directly to `ProceduralSession`; they reuse its resident
compiled problem, draft and counters. Adapt procedural metrics explicitly as
`[area, transport_cells, turns]`, and test equality with the factory score meaning.
Initial/best metrics are already resident, and completion state supplies the same
pending/conflict feature inputs.

`ProceduralSession` has one candidate authority, owned by its common learning
runtime. Existing `observe_actions` and `step_candidate` delegate to that same
authority. One `prepare_domain(draft, revision, attempts, options)` method returns
a `PreparedDomain` containing both contracts: the public `PhysicalActionDomain`
envelope and the fixed numerical `Arc<Domain>` port-prefix metadata. Revision or
options changes enumerate once, clear the numerical cache and rebuild action
arrays. When only attempts changes, it calls `refresh_context`, republishes the
public envelope with the new handle/attempts and refreshes budget globals without
rebuilding geometry/action arrays. `observe_learning` uses both prepared values;
`observe_actions` returns only `prepared.actions`. No second authority or
source-specific domain remains.

Retain the existing factory exact-reference artifact from plan 07 as the
before-state. Run its identical release command after the cutover. Add focused
matched-source tests instead of a second per-step validator. A source-equivalent
test must compare all arrays, domains, chosen port assignments and selected
`PhysicalEdit`, rather than comparing dimensions or aggregate hashes alone.

## Execution Result

Implemented the recipe-independent numerical builder under `physical_editor`,
including the preserved schema, frame, canonical ordering, fixed graph tables,
mutable draft features, root/port features, budget globals and revision/options
cache. Factory learning is now a thin adapter over this builder; the old duplicate
factory input, ordering, schema and view modules were removed. Procedural sessions
own the same builder and candidate authority, expose `observe_learning` and
`step_learning`, and route their existing public candidate methods through the
same retained domain. Procedural admission now embeds both Belt and Pipe
transport definitions. The extent-only candidate path performs its own bounded,
non-panicking shape, lookup and index checks without repeating full compiled
validation.

Focused tests cover malformed extent inputs, both fixed transport capacity slots,
translation and opaque-relabel numerical invariance, public/numerical domain
identity, attempts-only handle/global refresh, options invalidation and charged
stale selection. The retained factory release harness produced 512 byte-identical
semantic rows with SHA-256
`81672a244f622b927c46c544d825f5a992da7a097d2446eb8574e0cf7fcc62e3`
and the unchanged 47,008,640 numerical bytes. The final warm measurement was
0.505133709 seconds, 10,077,370,222 instructions and 15,908,864 bytes maximum
RSS. Relative to the plan-07 baseline this is about +3.7% time, +0.47%
instructions and +0.83% RSS, within every predeclared threshold.

`cargo fmt --all`, `cargo check --workspace`, `cargo test --workspace`, the
tracked-file worktree check, and the remote LibTorch-enabled
`cargo test -p aic-pilot-native -p aic-learning --all-features --
--test-threads=1` all passed. The planned `rsync` transfer was unavailable because
the remote host has no `rsync`; an equivalent fresh dedicated-directory tar
transfer was used before the same exact remote Cargo command.
