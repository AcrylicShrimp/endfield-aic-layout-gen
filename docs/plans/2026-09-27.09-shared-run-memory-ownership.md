# Plan: Shared live-memory ownership across the run

## Current Status

- State: Ready
- Last Updated: 2026-09-27 KST
- Blocker: Execution waits for node-lower widening and fair first-turn scheduler dependencies.

## Goal and Scope

Use one run-level live-memory counter for native candidate generation, node/tree actions, beam, MCTS, selected-root commit, retained reports and training collection. Reserve before each material allocation and transfer guards with the object they own. An aggregate refusal is typed resource exhaustion and can retry an unchanged legal candidate after capacity is released.

## Completion Criteria

- [ ] One counter charges original root, native pager, pending/edge witness copies, child peak, beam and MCTS retained states, root commit, state hashing, reports, outer inference, serialization and training collection/optimizer coexistence. Construct it before the panel-lifetime `Factory` and pass it through every case. It owns both retained outer compiled modules (`module` and `page_module`) through `Factory` drop and exposes the same retained-cache guard interface for Plan .16's lower-guidance modules. No second ledger resets available capacity between phases or cases; this step does not wait for Plan .16's lower-module size/admission implementation.
- [ ] Each separately retained material copy is covered by one guard from before allocation until drop or ownership transfer; bounded local scratch is covered by its owning operation's admitted peak rather than a per-item guard. Collection growth is reserved before allocation for the old and new storage overlap, including serialization buffers. No release/re-reserve gap, double charge or cap hit after allocating the object. Hard impossible requests differ from temporary aggregate refusal.
- [ ] Scoring and collection stream one child at a time where possible. A candidate held by the native pager remains retryable when tree admission waits for memory; prior complete results are retained on a typed stop.
- [ ] Local near-cap cases cover root hash/commit, completing child, beam-to-MCTS handoff, two retained case reports and collection groups. Measured RSS and integrated runtime include storage and final validation; the [broad-distribution plan](2026-09-26.08-broad-training-distribution.md) covers final factory bands.

## Proposed Changes

Complete the WIP native `RequestAllowance` and outer `TreeMemoryLedger` transfer into one shared run owner. Construct the ledger before the panel's `Factory`, and pass that same owner through every beam/MCTS case and collection phase. At material ownership or growth boundaries, calculate an action-aware peak from actual source/geometry/catalog shape and reserve it before cloning a child, action batch, observation, root hash or report. Cover bounded feature-row and similar local scratch within that operation's peak; reserve growing retained collections in batches or at capacity changes before growth, including the old/new allocation overlap. Keep the guard through replay, completed-layout validation, feature extraction and publication, then shrink to retained size. Native and tree candidate copies are distinct and charged separately; move the tree guard from pending action to edge. Beam and MCTS use the same counter even though they execute sequentially because root/reports can coexist. The panel-lifetime outer compiled model owns both its regular-forward and page-head module guards in this ledger from insertion through `Factory` destruction; measure and admit their actual retained bytes and first-trace peak at their respective call boundaries. A later case starts with earlier cached modules still charged. Expose the same retained-cache guard interface to the lower guidance model, but Plan .16 owns lower-module trace/forward sizing, insertion and cross-case validation after this ledger is complete; do not make that later implementation a prerequisite for this step. Collection streams child replay and reserves lower/outer examples and optimizer inputs. Validate bounds offline at local representative scale; normal runs emit compact usage summaries rather than per-item memory audits.
