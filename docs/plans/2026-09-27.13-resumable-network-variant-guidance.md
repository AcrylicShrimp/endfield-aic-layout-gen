# Plan: Resumable network variant and member guidance preparation

## Current Status

- State: Ready
- Last Updated: 2026-09-27 KST
- Blocker: Native fork and shared route search dependencies remain

## Goal and Scope

Prepare each network variant's native partial session and batched member guidance once, retaining inputs, predictions and ownership through admission of the member route pager. A temporary page or aggregate refusal cannot discard an earlier prepared variant or cause repeated model inference. This step ends at a retained member route pager; network publication is separate.

## Completion Criteria

- [ ] Variant `Session` forks advance with the reviewed retained fork cursor and transfer their live reservation once. A temporary stop retains the exact variant index and previously prepared variants.
- [ ] Every member guidance input retains progress through its data-dependent endpoint/raster/graph work, indexed batch slot and reservation. Finalization uses the existing retained cursor only where measured physical-input work or memory can cross a page; otherwise it runs as a bounded direct phase after soft admission within the same owner. Existing batched inference runs once after measured soft-time and memory admission for all participants; predictions stay paired with their original member/variant identity.
- [ ] Predicted guides and their reservations remain owned while `RouteCandidatePager::new_unpublished` prepares the member route; a stop there retains the partial route preparation rather than discarding the guide or repeating inference. Invalid guidance fallback remains typed and does not hide a resource stop.
- [ ] A multi-member, multi-variant local fixture yields during variant fork, input preparation, batch admission and guide-to-route transfer, then matches uninterrupted candidate identities, inference calls, work and peak memory. Upper-scale batch time and variant coexistence are measured.
- [ ] The implementation review records which guidance-input phases require retained inner state at the actual first-turn credit. Bounded finalization and ID handling must not keep their own cursor merely for uniformity; the top-level variant/member owner still retains prepared inputs and predictions through a stop.
- [ ] Keep every partial `Session` at one stable address while its `RouteGuidancePreparation` is live. Finish the batch of variant insertions before starting any guidance input, then forbid moves/removals of live sources; if incremental insertion is required, give each source stable ownership. The reused preparation checks source address on advance, so verify this at the implementation review.

## Proposed Changes

Replace `NetworkPager::start_batch` and `prepare_guidance` local vectors with `NetworkPreparationProgress` in `aic-learning`. Use the `SessionForkCursor` for each variant and the existing WIP native `GuidanceInputPreparation` for each member; measure its finalization phase and execute it directly after sound admission if it is bounded, retaining an inner cursor only for work that actually crosses a page. Retain prepared inputs with keyed `(variant, member, source_revision)` slots. Reserve temporary tensor/model capacity before calling the existing batched predictor and admit the measured uncancellable batch time against every participant's page. Keep predictions and reservations until the matching `RouteCandidatePager` has accepted the guide and unfinished route preparation. Transfer one owner guard at each transition; release only after the route pager owns the input/guide or the variant is durably rejected. Do not run a second guide/model pass to confirm the output; check identity at batch admission, not per edge.
