# Plan: Admit learned route-guidance batches by actual resources

## Current Status

- State: Ready
- Last Updated: 2026-09-27 KST
- Blocker: Shared run-memory, native route-candidate API and constructive learning spatial admission dependencies remain.

## Goal and Scope

Remove learned route-guidance inference's separate 250,000-cell grid cutoff and preserve resource failures as typed unknowns through every hierarchical and research caller. Keep model input shape, finite-value and identity checks at the input boundary. This step owns the existing native raster preparation, constructive graph batch, route raster batch, prediction extraction and their immediate error-propagation contract as one inference-input module; it does not change routing search or model architecture.

## Completion Criteria

- [ ] Native `guidance_preparation::RasterCursor::new` checks positive dimensions and exact channel/area/scratch byte products, fallibly allocates `grid`, bridge and occupied-cell vectors after the existing allowance reservation, and refunds exactly on any host allocation refusal. Its bridge rows use the established `try_clone_bridge` pattern for the nested strings and channel-owner vectors, with one retained reservation through transfer or release. No saturated size is treated as an accurate byte claim. `route_guidance::Batch::from_inputs` no longer rejects solely because area exceeds 250,000. It checks positive/representable dimensions, channel count and exact product/length with checked arithmetic, then allocates host raster and tensors fallibly at batch admission. `constructive::InputBatch::from_inputs` likewise calculates checked feature/edge/offset capacities, fallibly grows its existing host vectors and uses fallible tensor construction; this is the graph encoder input for the same prediction. Remove both existing `inputs.len() <= 262_144` graph/batch limits in favor of checked backend tensor shapes and actual memory admission; a tensor dimension that cannot fit `i64` remains an invalid shape, while insufficient memory is resource unknown. Normal-size batch behavior and throughput remain comparable. No per-cell model-output audit beyond the established finite prediction check is added.
- [ ] `route_guidance::prediction_to_native` checks output shape products/offsets, admits the CPU transfer/output footprint, classifies tensor transfer/conversion failures and grows `Vec<Guidance>` plus each directed-cost vector fallibly. Its `heads × 4 × area` output cannot panic, abort from an avoidable host allocation, or be mislabeled invalid solely because of size. The existing finite-value contract remains at the output conversion boundary, not in routing's successor loop.
- [ ] Eager graph/raster forward and compiled inference use checked shape products and measured, shape-dependent peak admission for their tensor intermediates, including the first-shape trace, eager parity run, compiled run, packed predictions and retained compiled module. Use fallible `tch` operations where exposed and classify returned allocation/device failures as resource unknown. For any tensor operation without a fallible API, measure its simultaneous footprint and admit it before invocation; document the remaining backend failure behavior instead of promising that host `try_reserve` controls LibTorch allocations. The compiled cache keeps its useful reuse but charges retained modules to Plan .09's run-level owner from insertion until eviction or `Factory` destruction; a later case sees every earlier cached module alongside its own active tree. No arbitrary grid or batch-count limit substitutes for this admission.
- [ ] Distinguish invalid input/model diagnostics from resource-censored inference. Host/Torch allocation refusal and insufficient existing hierarchical search memory yield typed resource unknown with exact ownership release; an uncertain runtime allocation failure is conservatively unknown, never `None`, anchor-only success or proof of no route. Research/evaluation callers retain the same distinction and cannot relabel a censored case as a normal evaluation.
- [ ] The five current hierarchical prediction owners in `hierarchical_search.rs` (direct root and later route path), `hierarchical_search/negotiated.rs`, `network_pager.rs`, `lower_pager.rs` and `repair_pager.rs` stop or retain their in-progress owner on resource unknown, preserve already published candidates, allowances and source identity, and expose that cause to the scheduler/report once. Valid nonresource model errors follow an explicit diagnostic path rather than an unrecorded fallback. No repeated state/input audit is placed in an inference hot loop.
- [ ] Guided research and hierarchical inference complete a sparse above-250,000-cell admitted-input case with bounded actual work and memory, or return typed resource unknown when their explicit memory cannot fit. A forced allocation refusal is visible at each owner and cannot silently become a candidate-count change. Compare old/current normal-size inference time and peak memory before adoption.
- [ ] Guided research collection checks native `Report.termination` and `allowance_stop` before judging a case to have too few candidates; evaluation checks them before adding a case to any success/sample count. Their shared `continuation` checks **every later route report** before treating an empty candidate list as a completed route failure or applying an earlier published candidate; a partial later report cannot become a low quality training label or full-survival statistic. A partial root or later route report stops the whole research run with a typed censored diagnostic containing case ID, `termination` and `allowance_stop`; it never publishes a complete checkpoint or report. Guidance training admits `Batch::from_inputs`, graph/raster forward, loss, backward, gradient clipping and Adam first/subsequent steps at its batch boundary, including retained optimizer state and foreach temporaries. Its separate before/after `evaluate` path also admits the full CPU prediction transfer, checked offset products and fallible per-case candidate-energy storage; resource refusal in either evaluation stops the run as censored before publishing a completed result. No training sample is silently skipped.

## Proposed Changes

Keep native `RasterCursor` plus the existing constructive graph `InputBatch` and route `Batch` as the inputs of one guidance inference operation. After Plan .21 opens the learning bounds, replace `area <= 250_000` and both `inputs.len() <= 262_144` checks with checked shape and capacity calculations plus resource admission. Native raster construction must admit exact bytes before each fallible growth and release prior reservations once on refusal. Build both model host batches with `try_reserve` or equivalent fallible paths and use fallible tensor APIs where available. At `prediction_to_native`, check and reserve the output vectors before copying tensor data to CPU; classify recoverable Torch transfer/conversion/resource errors rather than allowing them to become an absent prediction. The hierarchical caller uses Plan .09's shared run-memory owner: admit measured graph/raster/CPU-output live peaks against it once at inference boundaries, count transferred/released buffers once, and avoid a new independent area cap. Research evaluation has no tree owner; its fallible batch and output allocation reports a typed resource failure rather than declaring malformed input. Keep actual model tensor/resource errors distinguishable from malformed input and programming/model errors. If a backend operation can abort the process rather than return an allocation error, use its measured footprint for boundary admission and record that limitation; do not claim `try_reserve` alone makes backend allocation fallible.

The inference boundary covers the eager encoder and raster decoder's intermediate tensors, not only input and output conversion. For a new compiled `(batch, width, height)` shape, include tracing, the eager reference, compiled parity invocation, packed tensors and retained module in the peak before inserting the cache entry; subsequent calls reuse the admitted cached module. Size these operations from checked shapes and measured simultaneous lifetimes, including graph rows and model width, rather than a conservative fixed factory-size veto. Use fallible tensor calls when the `tch` API exposes them and translate backend resource errors to the same typed Unknown; where it does not, keep the calibrated peak admission and record the backend failure limitation. `Factory` and its compiled cache live across panel cases, so Plan .09 creates the shared ledger before `Factory` construction and passes that same ledger to every case search. Each module retains a guard there until eviction or `Factory` destruction; a per-case `SearchMemoryBudget` cannot own this guard. A cache hit does not re-trace or revalidate the model, but its retained bytes still reduce capacity available to every later case. Training uses the same batch/forward admission and also accounts for retained activations, loss, backward, gradient clipping, persistent Adam mean/square state allocated at the first step and temporary denominator tensors in first and later foreach steps. Reserve the simultaneous peak before each allocation boundary, retain the optimizer-state charge through the run, and release it on completion or abort; a batch resource stop ends that run with a resource classification rather than dropping cases. Reuse Plan .21's fallible deep-bridge-copy method in native raster preparation and charge/release each nested copy once.

Remove `Err(_) => anchor/None` handling for resource failures at all five direct/network/repair/negotiated/lower owners. Each owns its source, pending page and allowance until a typed unknown is committed; previously published candidates remain visible. Do not introduce resumable inference merely for uniformity: a batch is admitted as one bounded operation, and the scheduler's existing first-turn admission determines whether it can run now or yield. If representative upper-scale inference cannot meet that time boundary, Plan .08 must revise its batch scheduling; do not fabricate a fixed area cap.

At research boundaries, inspect Plan .15's typed partial route report before consuming its candidate array. `collect_case` distinguishes a valid completed case with fewer than two candidates from a partial root report; `evaluate_guided` checks every root report before accumulating success or sample counts. The shared `continuation` checks every later report, whether it has zero candidates or an earlier published candidate. Any partial root or later report returns one typed censored-run stop carrying case ID, `termination` and `allowance_stop` through `collect_case`/`evaluate_guided` to the CLI; the run ends without publishing a complete checkpoint, report or changed evaluation denominator. Candidate quality/later-completed labels and full-survival counters receive only complete route reports. Checkpoint/resume must not mark a resource-stopped training run complete.

The before/after `route_guidance_training::evaluate` is a separate dense research output conversion, not `prediction_to_native`. Check `batch × heads × 4 × area` and every candidate base/offset before indexing, admit the whole prediction CPU transfer and concurrent retained tensors at that call boundary, and grow each candidate-energy vector fallibly. A transfer or host allocation failure is typed resource censoring of the run; neither before nor after score is published as a complete comparison if either side stops. Preserve the existing successful-case scoring and denominator.

## Verification Plan

Run focused native raster, graph/raster batch shape and allocation, output conversion, and owner propagation tests, then `cargo fmt --all`, `cargo check --workspace`, `cargo test --workspace`, bounded guided research CLI and tracked-file check. Test one sparse grid just above 250,000 cells and a normal small grid with exact predictions before/after; force resource refusal in native raster growth, nested bridge copy, graph host growth, model raster host growth, eager/compiled tensor admission, first-shape trace/cache insertion and output vector admission without allocating an enormous fixture. Check that both former 262,144 graph/batch caps are absent and oversized actual shapes fail by checked representation or typed resource admission. At each direct, negotiated, network, lower and repair owner, verify typed unknown or retained pending, once-only allowance release and preservation of prior candidates. Run two panel cases with different compiled shapes: retain the first module while the second tree is active, verify both charges share one run counter, and verify eviction/`Factory` drop releases each guard once. Feed typed partial native reports with and without a published candidate through root collection, guided evaluation and later-route `continuation`; assert each returns a case-ID/termination/allowance-stop censored run failure, publishes no complete checkpoint/report and creates no ordinary low-quality label, too-few-candidates error or completed success statistic. Force training resource refusal at first and later Adam steps and separately at both before/after `evaluate` CPU transfer and energy allocation; check retained optimizer-state release and that no stopped run publishes completed scores. Confirm invalid input and model diagnostics remain distinguishable. Measure normal and representative upper eager and compiled batch elapsed/RSS/admitted peak, including first-shape trace and cached reuse, against the first-turn credit; no blanket runtime distribution scan is needed. Request independent implementation review.
