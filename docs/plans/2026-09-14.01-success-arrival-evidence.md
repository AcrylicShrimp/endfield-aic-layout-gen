## Goal and Scope

Produce one complete chronological corpus containing a starting replay pool and
all subsequent successful terminal admission attempts, including duplicates and
experiences the baseline immediately evicts. This resolves the survivor-only
limitation of the update-1410 export. Capture is an explicit bounded diagnostic;
normal training must not start retaining full trajectories or new audit journals.

## Proposed Changes

Add `diagnostics/declarative_success_arrivals.py` with `inspect` and `capture`
subcommands and focused tests. First inspect existing retained evidence. A complete
historical interval can be reused only if every attempted terminal segment and
its policy rows are present; update JSON events plus surviving rows are insufficient.
Do not repeat complete native rollouts solely to reconstruct missing old history.

If the interval is incomplete, collect a new explicitly labeled isolated baseline
continuation. Require an already immutable complete-wave checkpoint bundle with
its actual input/source dependencies and a noncompeting execution allocation.
Use existing parent binding, `Learner`, persistent `pool`, `Evidence`,
`publish`/`retain`, and diagnostic source/input initialization from
`declarative_execution_migrate` / `diagnostics/declarative_execution_cycle.py`.
Adapt their bounded diagnostic setup; do not create a second training engine.
The existing migration requires a paused parent: an actively running directory
must not be relabeled paused or passed through by weakening the check. Missing
eligible input/allocation is an execution blocker; do not pause main training,
regenerate its inputs, or run competing server work to clear it.

The only additional buffer seam is an optional diagnostic admission observer,
disabled by default and absent from checkpoint state. After terminal labels and
stable identity are calculated but before active-duplicate handling or eviction,
it receives the candidate and its evidence references. Batch extraction by source
chunk, reuse already hydrated policy rows and the scorer's capture conversion,
and store each required row once. Preserve actual identity and duplicate order;
do not require IDs to be globally unique across re-admission after eviction.
Persist complete terminal credit, not a shortened segment-only return.

Schema `declarative-success-arrivals-v1` contains parent binding, initial pool,
ordered update records, attempted entries, actual baseline observations/events,
and declared completeness/stop reason. At each publication boundary record the
actual SIL minibatch-call count and actor-epoch/KL-stop schedule; live active-credit
references; retained-checkpoint identities and their referenced row sets; and
which roots the normal post-publication pruning preserves. Capture these compact
metadata while they exist; do not infer earlier roots from the final run state.

Maintain two separately bound source tables: baseline published chunk references,
retained row coverage and compressed bytes; and diagnostic union chunk references,
complete row coverage and compressed bytes. The union includes initial and all
attempted-entry rows, including same-update evictions, plus rows needed by recorded
mandatory roots. Preserve a source-ordinal mapping between representations. A
baseline chunk may lack an attempted row; its size cannot price a complete chunk
containing that row. The later screen prices complete diagnostic union chunks
for every arm and labels this a conservative common-representation estimate.
Actual production bytes are separately recorded, then measured in plan 04.
An attempt key is `(update, terminal_order, segment_order)`; entry ID retains its
existing semantic identity. A diagnostic row union may outlive a baseline eviction,
but is not added to the normal replay store or normal retention roots.

Bound a new capture to at most 128 updates, 1,800 wall seconds and 2 GiB of added
diagnostic evidence, without raising the parent's RSS/free-space/native limits.
Persist compact rows at normal update publication, not per action. Finish a
complete wave only within the existing bounded grace; interrupted active credit
is retained in the existing checkpoint and the corpus marks the incomplete tail.
Do not create a second recovery journal. The comparison will censor late arrivals
and require minimum coverage separately; a capture does not need to manufacture
enough rare cases. Keep the original generator/curriculum and tracking disabled
for this isolated run; preserve normal no-construction-report behavior.

## Verification Plan

- Run `inspect --parent <immutable-run> --output <fresh-directory>` and inspect
  exact missing coverage instead of silently treating survivors as all arrivals.
- A bounded fixture covers cross-update preparation, multiple successes at one
  terminal, active duplicate, re-admission, and an entry evicted in its admission
  update. Captured attempts must reconstruct all baseline admission events. After
  later baseline pruning, the corpus must still resolve the immediately evicted
  row through its diagnostic union and reproduce earlier mandatory-root unions.
- Compare observer enabled/disabled on the same two recorded updates: identical
  model, both optimizers, RNGs, buffer, ordered events and forward counts. Measure
  added compact write bytes/time separately; no observer work when disabled.
- Execute the bounded capture CLI only when the explicit parent/allocation
  prerequisites exist. Inspect complete-wave stopping, cleanup and source coverage.
  Preserve a blocked receipt if they do not; do not mark this plan Completed
  without an actual complete corpus interval usable by the dependent screen.
- Required code verification: `cargo check --workspace`, `cargo test --workspace`,
  affected Python tests, CLI output, and worktree/index hygiene. Rust formatting
  is required if Rust changes. Keep raw corpus ignored and commit its compact
  provenance, reproduction command, and findings under `docs/reports/`.
