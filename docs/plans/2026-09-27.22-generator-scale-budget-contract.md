- State: Completed

## Goal and Scope

Make the procedural layout generator's scale intent produce a valid configuration across its declared 2–256 facility range, including spacious 256-facility requests. Remove the hidden 250,000-cell canvas clamp and the inconsistent one-million-expansion per-call validation ceiling where they reject a potentially feasible requested band. Keep explicit finite attempts, work, time and memory controls, and determine their values from bounded production-scale evidence rather than shrinking the factory or silently changing effort. This step owns generator intent/config/placement budget admission; route search behavior and final stop classification are Plans .14 and .18.

## Completion Criteria

- [x] Every semantically feasible `Intent` combination in the declared facility range constructs a `Config` that passes its own validation. An acyclic two-facility light-cycles/branching request or three-facility branching request exceeds the directed-pair capacity; reject it explicitly with the requested target and permitted maximum, before sampling, rather than silently reducing its topology target. In particular, Standard 256-facility Spacious currently computes `256² × 40 = 2,621,440` per-call route work, exceeding `Config::validate`'s 1,000,000 ceiling; Thorough currently clamps twice that budget back to 1,000,000. Remove both inconsistencies without reducing computed work to an arbitrary smaller value. Thorough receives at least Standard's per-call and per-attempt work for every supported size/packing combination. Keep checked arithmetic and clear diagnostics for unrepresentable requests.
- [x] `Config.max_cells` and `Intent` canvas selection no longer silently clamp a 256-facility geometry to 250,000 cells. Preserve the caller's finite requested canvas budget; validate it against representable placement and actual resource admission. The lower-level placement request already accepts up to 250,000,000 cells, which is an implementation bound to review against memory rather than a reason to allocate a dense canvas. Check `packing.rs` width/height products and `intent::conservative_workspace_bytes`'s work/canvas multiplications and sum as the canvas range widens, returning a typed invalid/resource result on overflow rather than wrapping. A sparse legal above-250,000-cell placement can proceed with bounded actual work.
- [x] The route work per call/attempt, pair-trial and attempt budgets remain finite and their upper-band defaults are calibrated on predetermined compact/balanced/spacious, branching and crossing-forbidden seeds. A budget stop remains typed search-incomplete after Plan .18, never proof that the target size is impossible. Any infeasible upper-band preset reports the actual missing resource and observed success/attempt rate; it is not replaced by a smaller layout or a lucky seed.
- [x] Batch publication and later layout loading admit the actual serialized upper-band outputs. Measure representative 256-facility compact/balanced/spacious JSON sizes offline; if the 16 MiB `batch::run`/`io::bytes` guard excludes a required legal layout, adjust one shared finite file-size admission limit with bounded reading and preserve atomic publication. A generated complete layout must not fail only at serialization, and later reading must accept what the producer writes. No per-sample distribution audit is added.
- [x] Bounded CLI generation covers a normal small control and upper-scale compact, balanced and spacious requests. An offline lower-level packing/placement regression must admit a legal sparse canvas above 250,000 cells; the semantic public profiles need not be distorted solely to create that test case. Compare accepted layout size/pattern, yield, route work, wall time and RSS with the old default where comparable. The generated cases feed Plan .20's shared materialization and Plan .08's offline distribution checks without a runtime per-sample audit.

## Proposed Changes

Keep the existing `Intent -> Config -> placement` path. Preserve the checked `n² × 16` canvas formula and 65,536-cell floor while removing its 250,000-cell ceiling; at 256 facilities this requests 1,048,576 cells, still a finite budget. Make `Config::validate` accept a positive per-call work budget above one million; remove Thorough's per-call truncation and preserve its checked twice-Standard calculation. The first fixed-seed sweep proved that the previous 8,192 pair and 250-million route-work stops cut off 256-facility completions. An intermediate one-billion/two-billion attempt cap also stopped three of three 256-facility branching Spacious requests and came within 0.6% of cutting off a successful tree Spacious request. Therefore use the original checked `2*per_call*target_connections` attempt formula without an extra policy cap, while retaining a portable 32-bit unsigned bound in the low-level config validator and the survey's finite wall deadline. A same-seed 65,536-pair probe completed one 256-facility branching Compact case that the 64-times-target policy missed; use factors 32/192/288 for Fast/Standard/Thorough, with a 131,072 low-level validator ceiling above the derived 110,304 maximum. Verify the revised policy on the same seeds and identify remaining pair-exhausted cases. Document residual failures as work stops, pair exhaustion or deadline interruptions, not infeasibility. Add an explicit CLI aggregate-workspace admission budget with the old 2-GiB default and a report field so a machine with ample memory can run Thorough without changing factory intent. Check the producer/reader 16 MiB JSON guard against measured upper-band output, then keep or raise one shared bounded allowance consistently. Publish complete layout JSON atomically through a temporary file. Use checked width/height/area arithmetic in the packer/placement code and checked workspace estimate multiplication/addition rather than unchecked products. Do not add a dense grid allocation, a per-sample scale audit or an unreviewed fallback to smaller facility counts.

## Verification Plan

Enumerate the bounded Intent cross-product offline with acyclic and cyclic modes; ensure each feasible built Config validates, and assert an explicit target/capacity diagnostic for the three impossible small-DAG combinations. Include 256 Spacious Standard and Thorough; assert Thorough per-call/attempt work is never below Standard. Compare a predetermined same-seed upper-scale sweep under the old and revised work/pair limits. For failures with pair work remaining, repeat the exact seeds with a separately identified higher-pair probe; do not infer structural impossibility merely from the old stop label. Run a small CLI baseline and predetermined upper-scale compact, balanced, spacious, branching and crossing-forbidden requests; the latter is a 256-facility Tree Balanced case at seed 43000. Exercise a legal sparse >250,000-cell canvas through the existing lower-level packing/placement API offline; measured public Spacious 256-facility packings under the current catalog are smaller, so do not enlarge profile gaps merely to make a CLI test cross this number. Record accepted facility/connection counts, physical area, belt/pipe/crossing patterns, serialized JSON bytes, attempt/work stops, elapsed/RSS and disk use. Test that the default 2-GiB workspace admission gives a concrete error for an upper Thorough request, an explicit larger CLI budget admits the same intent, and the report retains that budget. Read back upper-scale outputs through `io::read_layout` and check that complete layout files appear only after the temporary file is flushed and renamed. Check representability of packing area and workspace estimates without allocating a huge grid. Do not run an unbounded campaign or redefine failed requested sizes. Then `cargo fmt --all`, `cargo check --workspace`, `cargo test --workspace`, relevant generator CLI output and tracked-file check. Request independent implementation review of the full intent/config/placement path and the actual size distribution.
