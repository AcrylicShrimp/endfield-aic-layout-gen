# Plan: Incremental lower candidate coverage and exact costs

## Current Status

- State: Ready
- Last Updated: 2026-09-26 14:53 KST
- Blocker: None

## Goal and Scope

Make lower route/network candidate generation incremental at a stable outer node, with diverse anchor coverage, a shared prepared exact-graph scheduler, exact physical cost/resource metadata and bounded reusable work. Ordinary MCTS revisits must not rerun generation. Gumbel root action identities, noise, visits and training targets must remain bound to the original witness when placement or lower pages are appended and sorted.

## Completion Criteria

- [ ] A new node receives a small stratified lower page; additional visits can expose more distinct ports, corridors, topology and repair candidates within explicit work limits while keeping a non-learned anchor.
- [ ] A first page with zero legal actions tries authorized later pages before declaring no macro action. Anchor and learned queues share prepared legal transitions, successor expansion work and found candidate identities under one scheduler, while cost-mode-specific path values remain separate so learned penalties cannot corrupt anchor correctness.
- [ ] Gumbel root selection binds its shortlist and sampled noise to immutable semantic action IDs at the start of sequential halving, resolves IDs after any action-vector change, and freezes shortlist membership for that root budget. PUCT and nonroot visits may add pages; new Gumbel root candidates enter only at the next reroot. The root cap and pending-page count are reported.
- [ ] Semantic deduplication preserves best exact cost and provenance; stable request/state/model/config identity controls a bounded cache or retained node workspace, with no stale candidate reuse after commit or version change.
- [ ] Every candidate reports exact length, turns, occupied cells, component IDs/costs, capacity use, congestion price, learned cost, overlap and charged work. Outer action encoding uses the actual candidate metadata.
- [ ] A local coverage fixture exposes a useful later candidate only after widening, and instrumentation shows no additional lower search on an ordinary revisit.

## Proposed Changes

Split `Factory::action_batch` into first-page enumeration and a stateful lower pager held on each expanded node. The pager carries request identity, per-task cursor, dedup set, charged work and a prepared exact-graph workspace; it generates a new batch only when visit schedule authorizes it. One scheduler interleaves anchor and guided queues, caches legal successors and candidate discoveries, but maintains separate path costs for modes with different edge penalties. Keep the existing CPU pool and batched model inference, and avoid reinitialization or full-state copying on each revisit. New route costs derive from exact committed geometry and catalog components, while guidance and congestion are separate reported terms. Score only newly exposed actions where possible and preserve existing visits/Q values when appending.

Replace root Gumbel's stored vector indices with stable semantic action IDs plus sampled noise/initial rank. Any placement/lower page sorting resolves IDs to current edges; a late candidate cannot inherit another candidate's noise or forced visits. Freeze the sequential-halving shortlist once a root search begins and expose this cap in diagnostics. A root with no legal action in its first page asks for later bounded pages before terminating. Root records retain exact exposed candidates and normalized priors for distillation.
