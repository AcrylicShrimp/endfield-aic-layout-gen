## Goal and Scope

Give each expanded outer node a retained lower pager that exposes route, network and repair candidates in scheduled pages. An ordinary revisit does no new lower search; a zero-action first page continues authorized pages before reporting no macro action. The selected first page also reaches the learned-guided route phase when guidance, candidate slots and the existing hard allowance permit it, before a Gumbel root freezes eligible actions. Stable source/model/config identity controls reuse. This step does not change Gumbel root selection, physical feature schema or first-turn fairness.

## Completion Criteria

- [ ] Each node retains exactly one identity-bound pager and completed native-accepted candidates across revisits; only the visit schedule authorizes new pages.
- [ ] Initial pages stratify anchors, ports, corridors and topology; later pages can expose distinct route, network and repair witnesses without restarting their preparation.
- [ ] Semantic dedup keeps the same immutable physical witness ID while accumulating provenance and best exact cost. No candidate is visible before its native publication gate completes.
- [ ] A useful later candidate appears in each route/network/repair fixture, while ordinary revisits show zero added lower work and source/model/config changes invalidate stale pages.
- [ ] MCTS expansion, widening and simulation drain a live Plan .10 replay growth-escrow owner before any competing scoring, action append or child reservation. The exact direct/network/repair stage advances through bounded pages despite pending actions, updates, native IDs or exhausted desired-page visits; returned actions/updates remain owned and append exactly once after drain. A hard stop restores ordinary selection while preserving prior complete candidates.
- [ ] Initially selected ready route tasks with at least two direct candidate slots and usable guidance attempt both anchor and guided phases before Gumbel freezes eligibility. A soft direct stop retains its exact progress, gives repair its reserved first turn, then continues under the unchanged hard allowance; a hard stop is typed Unknown. Genuine exhaustion of a guided phase is distinguishable from stopping after the first anchor. There is no new fixed connection-count or per-task work cutoff.
- [ ] On the retained legal placed 100-block case with 99 connections and 19–20 completed route prefixes, measure initial and late anchor/guided witnesses, pending tasks, first-page time/work, RSS and a full 128-simulation collection under the reviewed allowance and resource limits. The completed collection contains at least one usable guided lower example, and generation from that collection completes a `train_lower=true` optimizer update. Merely entering a guided phase or finishing with anchor-only witnesses does not pass. If lawful exhaustion or a resource stop prevents this result, record the exact cause and keep this gate and [streamed root-target training](2026-09-28.04-streamed-root-target-training.md) blocked for an evidence-based decision; a resource-stopped collection publishes no partial target. Broader size and pattern coverage stays in the separate distribution plan.

## Proposed Changes

Complete the WIP `LowerPager`, `NetworkPager` and `RepairPager` ownership in `aic-learning`. Keep task allowances, prepared inputs, native route/repair progress and candidate reservations with the pager. At node expansion, use the existing evenly spread first task batch. Its direct route page currently requests one candidate, so the native pager's anchor-first phase stops before guided search; use enough available direct slots to cross that phase boundary. If its soft first turn stops first, let repair take its reserved turn and continue the same direct pager under the unchanged hard allowance before freezing the initial page. Only the selected tasks get this initial continuation; later tasks still use the documented visit schedule, with no fixed legal connection cutoff. Return initial-page completion or a typed stop alongside published actions, so callers cannot confuse a pending lower phase with a complete candidate set. Transfer accepted candidates by immutable physical ID to pending tree state; preserve the native copy until its pager is released. Continue zero-action first pages through authorized later pages. Publication delegates legality, repair finish and exact costs to reviewed lower primitives; this step owns node scheduling and semantic admission.

Use Plan .10's owner-targeted escrow drain API at the three MCTS boundaries. First expansion drains before scoring even when placement actions already exist, and before the empty-action/all-pending-memory exit. `simulate` drains before pending-action processing, placement widening, edge selection or child reservation. `maybe_widen_lower` drains before ordinary pending-action/update and visit gates, then checks again immediately after `next_actions` because that call can create escrow; hold returned actions and updates across the second drain and append them once afterward. Keep each page bounded; do not classify temporary escrow competition as a permanent `ResourceStopped` or edge `blocked_value`. A hard replay stop releases escrow and then ordinary scheduling resumes. This step verifies all node call sites against Plan .10's direct drain contract.

The production Gumbel caller is `root_catalog/collector.rs`. In `CollectPhase::InitialLower`, drain a live replay escrow before scoring or freezing the initial catalog, retain accepted actions and updates across the drain, and continue an incomplete mixed-provenance initial page even if placement actions already exist. A hard lower stop ends collection as resource Unknown and discards the uncommitted catalog regardless of `placement_count`; only an exhausted or completed first page may enter `RawFinish`. In `InitialRootCatalog::advance_late_lower`, drain before invoking the pager and before publishing late actions or route provenance updates. Keep a stopped late page and its exact action IDs until it can resume or report typed Unknown. Apply the same source identity and memory ownership rules as the dense MCTS caller rather than creating a separate lower search policy. If the retained placed 100-block case still produces anchor-only witnesses, trace native phase completion, candidate admission and collector freeze to the first missing guided witness; correct that path within this module and repeat the same case before claiming completion.
