## Proposed Changes

Add `operations/declarative_quality_branch.py` and an explicit readiness command.
Reuse `declarative_execution_migrate.initialize`, the experiment source-linker,
`Learner`, normal `run`, Buffer observer and retained restoration helpers. Add only
`gain_only` to the existing score-mixture profile allowlist; its score is native
validated gain and all other mixture constants remain unchanged. Default sampler
behavior is unchanged.

A branch accepts either the newly paused main parent or a completed, bound study
endpoint. Declare exactly success.retention/sampling, source/protocol and private
input/output locators, diagnostic stop/evaluation/tracking and second-replicate
sampler/shuffle resets as permitted differences. Reject optimizer, reward, model,
native, generator, capacity or curriculum changes. Evaluation panels are explicitly
bound study inputs and old evaluation/best-selection records must not be relabeled
as new-panel evidence. Reset only diagnostic evaluation accounting where needed.
Validate sources before publishing a child; retain parent data on all failures.

Initial main-to-study forks fill missing native-quality metadata once from actual
source rows. Initialize priority metadata with one packed parent-model pass only
when initially enabling a priority profile from a parent without that state. A
same-profile study continuation or live restore preserves all existing utility,
priority values and observed-update fields exactly; it does not refresh them at
the fork. Reject missing required priority state on such continuations. Do not
borrow old-study frozen caches or invent unobserved critic measurements.

The terminal observer fills missing quality metadata once for newly admitted
uniform/priority successes as well as score/category successes, reusing existing
features where available. Retain it with the entry for later allocation measurement
and restoration. It does not affect native reward, identity or the default
sampling/replacement behavior. Use cached metadata for per-update quality
aggregates and record every terminal attempt before eviction.
The observer is installed only by the study runner and is absent on normal main
runs. Measure draw-weighted actual native gain and raw/corrected SIL contributions
by stratum/category; preserve admission population and report zero/tied quantiles.

Readiness: one score-8 branch runs four normal updates, retaining its first live
checkpoint and exact dependencies before pruning. Restore that checkpoint into
an isolated branch and execute one additional update, comparing to uninterrupted
update two. Permit the normal runner to stop this diagnostic after one update
at its complete-wave boundary; do not force normal production update limits odd.
Compare all learner/optimizer/RNG/buffer/events and native state with existing
elapsed-bookkeeping exclusions. Exercise count/reference and category settings
with focused actual-kernel tests, not additional learned candidate runs. Reuse
shared native correctness tests and run meaningful new profile/measurement tests.
Enforce 600 seconds/five updates and current parent resource limits.

Explicitly bind the operations entrypoints, imported diagnostics helpers and fixed
experiment JSON in addition to `sources()`'s existing top-level file set. Preserve
these execution bindings throughout downstream study preparation. If plan 08
changes the verified execution path, reassess and repeat affected readiness checks
before study execution; adding orchestration/reporting alone does not change a
passed learner-transition proof.
