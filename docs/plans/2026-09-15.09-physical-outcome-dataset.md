# Plan: Collect the bounded physical outcome dataset

## Current Status

- State: Completed
- Last Updated: 2026-09-15 23:31:00 KST
- Blocker: None

## Goal and Scope

Add one bounded, reproducible collection command that generates the fixed
96-root procedural screen, assigns every root to training, development or
confirmation before any action is taken, enforces structural-identity and
ancestry separation, executes one sequential trajectory of at most 32 common
physical edits per admitted root, and publishes compact owned pre-action inputs,
complete selected actions and observed native outcomes. Execute that registered
screen and retain its local dataset plus a compact tracked collection report.

This step does not train a predictor, inspect confirmation labels for model
selection, change PPO, add predicted feasibility masks, generate descendant
copies, or claim that the collected source represents player layouts. It does
not substitute a smaller layout when a configured root fails generation.

## Proposed Changes

Extract the scheduling mechanics of `learning::pool` into a crate-private fixed
worker dispatcher: fixed stream ownership, one bounded command batch per worker,
ordered replies, panic/failure capture, cold evidence access and joined shutdown.
Its constructor accepts a worker-state factory and an executor that maps one
`(&mut state, stream, command)` to a typed reply, allowing factory and procedural
wrappers to retain their own catalogs and session maps without type erasure.
Keep the existing factory `Pool`, `Command` and `Reply` API as a wrapper over that
dispatcher. Add a procedural wrapper beside `physical_editor` whose four workers
retain at most one `ProceduralSession` per stream and accept typed open, observe,
step, snapshot/evidence and close commands. The procedural wrapper receives the
already compiled admission object and one shared validated physical catalog; it does not
serialize observations through the worker channel or initialize a worker per
action. This preserves the optimized factory path while giving the new collector
the same bounded persistent-worker behavior.

Extend `PhysicalSessionOutcome` with optional observations of the actual current
draft after a changed edit: pending count, conflict count and current `Metrics`
when the candidate completes and independently exports. These fields describe
the candidate even when it is worse than the retained best. Rejected, unchanged,
stale, deadline and internal-error paths leave post-state fields absent unless a
new draft was actually retained. Retain `best_metrics` for its existing purpose.
Expose enough typed procedural pool data for the collector to classify censoring
from native diagnostic codes without parsing display strings.

Add a compact, non-neural current-port view to the common physical observation:
one `Arc<Vec<Option<String>>>` aligned to compiled nodes. It borrows no draft and
passes through the typed worker reply, so retain-compatible sampling can map the
current selections into the already published compatible `PortGroup` rows. The
collector never writes this name view into an action record; it persists only the
selected terminal indices and numerical port feature rows. The existing factory
observation wrapper may ignore the view, leaving its public API stable.

Create `aic-learning::outcomes` behind the learning build. Its strict config has
one explicit `RootSlot` per root (`root_id`, `ancestry`, split, blocks, generation seed and
action seed), an embedded generator config, physical candidate/session/identity
limits and command/output ceilings. Validation requires the exact 96-slot matrix,
unique IDs and seeds, fixed 8/16 sizes, four workers, 32 decisions, 50,000
per-action expansions, a cumulative allowance no smaller than the full horizon,
and permits time/output values only up to the stated 15-minute/4-GiB maxima. The
registered study config fixes those values at the maxima; tests may lower them
without changing the 96-slot allocation or generator/action contracts. Every fresh root has one distinct ancestry
key; any later descendant must reuse that key and therefore its split. The tracked study config uses generator
defaults verbatim except that collection constructs a fresh generator with
`blocks = [slot.blocks, slot.blocks]`; later config drift is therefore explicit.

Collection has two phases governed by one deadline anchored at command entry.
Admission first loads and hashes catalogs once,
generates every configured seed, serializes exactly one validated layout source,
compiles it once through `ProceduralAdmission`, and calls a guarded compiled-
identity API with the configured individualization allowance. Generation checks
the same cancellation guard between attempts, pair trials and bounded route calls;
identity checks it at individualization visits. A call already in a bounded route
or refinement unit may finish, but its result is censored when the deadline has
passed and is not admitted. Unstarted, interrupted and late slots retain their
configured identity, split and seeds in the incomplete manifest. The collector
builds the complete root manifest before dispatching actions, rejects a root whose
structural key or explicit ancestry is already assigned to another split, and
records exact-problem and canonical-draft keys separately. Identity exhaustion or
an unresolved cross-split collision prevents action dispatch for the affected
root and remains visible; it does not prove independence.

Move each already compiled `ProceduralAdmission`, including its initial source
metrics, into the procedural worker's session constructor. The action phase does
not decode, validate or compile source bytes again. It schedules admitted roots
across four persistent streams. Each stream receives one root, keeps that session live through its sequence and is
reused only after the root bundle is returned. For each observation, partition
valid roots by the existing `root_meta` family, draw a nonempty family uniformly,
then draw one root uniformly. A placement draw flips an unbiased recorded mode
coin. Retain mode finds each terminal's current selected port in its compatible
domain and uses it only if the complete assignment has no repeated port; random
mode samples compatible ports sequentially without replacement. If retain mode
is unavailable, record that fact and use the random complete assignment. Persist
the chosen terminal index and physical port feature row with the root index, so a
later learner never needs the full conditional domain to reconstruct the action.

The admission and action phases use the same command deadline. The command derives
every newly opened session's elapsed allowance from its remaining duration.
Workers test cancellation between decisions; a routing
call remains bounded by 50,000 expansions, and a result finishing after its
derived allowance is retained as censored evidence without committing a late
candidate. A coordinator stops opening roots when the deadline is reached. A
bounded result channel limits retained completed bundles. The configured metadata
reserve is withheld while the writer accounts sources and framed Postcard rows;
final manifest/report bytes must fit inside that reserve. Thus aggregate staged
directory bytes are checked before rename, and the writer can publish a partial
root without crossing 4 GiB. Fatal failures preserve the
already verified sources/chunks and a failure manifest instead of inventing a
resumable complete boundary.

Add `aic learning collect-outcomes --config ... --catalog-root ... --output ...`.
The output path must not exist. Write into a sibling staging directory, fsync the
small manifest/report and rename once into the requested path for complete or
explicit incomplete publication. The manifest binds schema, config/source/catalog
hashes, identities, ancestry, chunk hashes, row counts and status. A loader checks
those bindings and Postcard framing before exposing rows. Normal output contains
no per-action JSON and no duplicate draft/session snapshots.

Register the fixed experiment config as a benchmark source asset. Run a small
temporary fixture command locally for CLI/error/resource behavior, then run the
fixed 96-root release command in `artifacts/physical-outcomes-v1`. Commit only the
configuration, compact summary report and reproduction command; retain the
regenerable multi-gigabyte source/chunk directory outside Git.

commands, cancellable procedural generation and exact identity resolution, the
compact graph-aligned current-port view, actual candidate outcome fields and a
typed procedural pool over the extracted fixed worker dispatcher. The existing
factory pool now uses the same dispatcher while retaining its public command and
reply API. Collection admits and compiles every source before dispatch, keeps one
live sequential session per stream, writes one source plus one framed Postcard
chunk per root, and publishes explicit complete or bounded-incomplete metadata
under one command deadline and aggregate byte ceiling.
