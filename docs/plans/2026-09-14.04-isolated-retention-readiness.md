## Proposed Changes

Add `operations/verify_declarative_retention.py` and focused tests. Reuse existing
source-bound parent validation, compact loader, indexed buffer, normal
`declarative_duration.py run`, and restoration/retention test helpers. Keep the
existing execution-only migration strict: add an explicit policy-experiment
transition validator, not an exception that permits arbitrary learning changes.

Require an immutable complete-wave parent with all actual checkpoint/input/source
dependencies and noncompeting execution resources. Metadata backfill uses batched
source decoding once and the exact shared feature extractor from plan 02 when
required. For positive-advantage sampling initialize priorities with one packed
parent-model pass, reusing the same loaded rows. Uniform/v1 volume-only changes
need no feature/priority backfill. Reject
missing features/sources or ambiguous identities before publishing a child.
Maintain semantic IDs, all label returns and existing utility/admission/usage;
no historical replay, regenerated inputs or weakened source authentication.

The transition allowlist is only the shortlisted `success.retention` and
`success.sampling` settings (including draw count, priority and correction),
new source/protocol identity and independent diagnostic output/input locators.
The receipt must bind this parent/model and the selected code/configuration;
a shortlist from an unrelated parent is not accepted.
Diagnostic stop/evaluation schedule/tracking changes are explicit harness bounds,
not changes to the parent's learning or remaining duration. Preserve model, both
optimizers, all RNGs, gamma, SIL coefficient, product-stratum sampler contract,
native limits, generator,
curriculum start plans and evaluation panel. Initial checkpoints have no live
drafts by prerequisite; subsequent ordinary v2 restore must preserve live drafts.
Write a receipt identifying every retention/sampling/objective-distribution change;
do not call this an
execution-only or numerically identical learning continuation.

Use one candidate and one v1 control from the same parent. Each arm executes four
new normal updates (two waves), with a live snapshot after its first update. The
candidate's restored branch continues exactly one additional update from that
snapshot for comparison with its own uninterrupted second update. Before later
pruning, retain this one diagnostic snapshot and its exact source/input dependencies
in the isolated output, or execute the restored branch first. Do not alter the
normal checkpoint cadence. Compare model,
both Adam states, RNGs, replay content, ordered events, native drafts and next
start plans at that boundary; elapsed wall/native bookkeeping may differ and
must remain monotonic/budget-valid. Do not demand candidate/v1 model equality
after their sampling or retained experiences diverge. Pair their actual input slots where
possible; inherited parents may diverge and must be disclosed in timing analysis.

Use existing hand-controlled native/capacity tests to force both sequence-limit
and label-limit eviction and a grace expiry; do not alter the normal four-update
arm's capacity or synthesize successes into its learning buffer. If the real arm
never evicts, report the missing integrated coverage as BLOCK rather than extend
the run. Reuse prior CUDA/action/native equivalence evidence when code is unchanged.
At least one normal publication followed by source pruning must retain both
latest recovery states, selected best checkpoints and active credit sources.

Continuity gates: exact declared transition fields; within-candidate restoration
agreement; all hard resource limits; unchanged baseline mode; no normal audit
hooks, full trajectories or construction JSON/HTML/stdout dumps; all required
references load through normal restore; and no unresolved end-to-end regression.
For the latter, compare cached admission/index/feature time and source loads on
the same ordered terminal corpus, then report normal four-update collection,
learner, publication, peak RSS and retained allocated bytes separately. A median
normal update increase above 10% or retained bytes above 125% of control blocks
readiness pending explanation and a separately reviewed bounded follow-up; the
small sample cannot establish a general speed guarantee. Report one-off migration
time/bytes separately and preserve the existing checkpoint cadence.

Limit the complete verification to 600 wall seconds, nine newly executed updates
across the two arms/restored branch, parent resource ceilings and 2 GiB added
artifacts. If required inputs, device, coverage or bounds fail, retain a BLOCK
receipt. Stop all workers/diagnostics. Keep immutable parent data and nonreplayable
checkpoints; remove only regenerable intermediates after preserving the findings.
Update the relevant design to label v2 experimental and record its evidence,
without claiming the currently running launch was changed.
