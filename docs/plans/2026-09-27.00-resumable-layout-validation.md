# Plan: Resumable independent layout validation

## Current Status

- State: Completed
- Last Updated: 2026-09-27 KST
- Blocker: None

## Goal and Scope

Make completed-layout materialization, the existing independent validator and its catalog junction enumeration resumable at bounded visit boundaries. A pause must retain partially built layout vectors, maps, indices, selected component/rotation and charged work, then return the same metrics or diagnostic as uninterrupted validation. This enables first-page route and repair continuation without publishing before final validation. Preserve validation of external layouts and the public `validate` / `validate_with_visit` behavior. This step does not implement native command replay or alter game legality.

## Completion Criteria

- [x] Native completed-layout materialization, facility-port projection, and the independent validator and junction catalog enumeration own every data-dependent visit cursor; a temporary stop retains state without repeating copies or visits, losing diagnostics, or accepting an unvalidated layout.
- [x] The ordinary one-shot APIs drive the same implementation to completion and retain their existing result and diagnostic contracts for external layouts.
- [x] Retained validation memory is reserved before growth, transferred or released once, and a truly impossible hard reservation is distinct from a temporary aggregate refusal.
- [x] Small and representative upper-scale local fixtures compare uninterrupted and repeatedly resumed metrics, diagnostics, visit counts, and live memory; an actual completing layout is checked through the CLI. The integrated upper-scale measurement includes materialization and validation cost.

## Proposed Changes

Refactor `crates/aic-layout/src/validation.rs` into owned validation phases over one immutable completed `Layout`. The cursor owns aggregate maps and exact positions in poses, terminals, routes, cells, junctions, bridges, catalog definitions and allowed rotations. It also owns the work currently outside visit hooks: route-turn windows, owner-set construction, final junction/terminal scans, unique transport and weak-component metric accumulation. Admit these one item at a time, or use a measured, sound soft-time and work bound for a truly small indivisible operation; a conservative bound never becomes a hard rejection if actual work might fit. Factor `junction_options_with_visit` into a reusable cursor so both independent validation and native Connect can resume its catalog loop. Each bounded visit is admitted before mutation, charges once, and may return `Pending`; errors remain typed `Diagnostic`. The cursor borrows a stable immutable layout under its owner, so identity is checked at admission rather than hashing or rescanning every page. Normal `validate` and `validate_with_visit` drive this same validator to completion, with no second validator or routine audit.

In `crates/aic-pilot-native/src/constructive.rs`, extract the existing `complete_layout_bounded` copies into an owned `CompletedLayoutCursor` that retains the partially built `Problem`/`Solution`, source indices, route-cell offset, deterministic bridge/junction order and memory reservation. It charges each copied record/cell once and keeps the finished `Layout` alive through `ValidationCursor`. The ordinary `complete_layout` and bounded wrapper drive this same builder to completion with their established behavior; repair's completing-layout path uses it too. Sorting and allocation are either incremental or admitted under measured soft bounds. Avoid duplicate materialization and release the owned layout only after its metrics are consumed.

At each facility pose, project catalog ports through a per-port cursor using the existing `projection::project_port` rule rather than calling all-at-once `projection::rotate`. Reserve the growing projected-port vector and retain its index. The facility data contract has no fixed port-count cap, so this operation cannot be assumed small. The ordinary projection API remains a drive-to-completion wrapper over the same rule.

## Execution Result

Implemented after round 3 scoped design PASS. Local only; no server. Added per-port projection and catalog junction cursors. `CompletedLayoutCursor` retains a route-cell offset and copies admitted chunks of up to 256 cells into a route-sized allocation, preserving bulk-copy throughput. A 400-cell fixture compares single-visit pages and reservation retries with uninterrupted copying and a direct expected layout, including visit charges, retained bytes and cancellation release. The independent validator runs through one retained future cursor for borrowed external or owned replay inputs; its existing rule body is shared by the one-shot API. Port projection, catalog enumeration, stable-ID chunks, route turns, owner scans and final metrics yield without revisiting accepted work. Major hash-map/set and vector growth requests memory before mutation and releases temporary route/site state. A valid completed layout and an invalid route match uninterrupted metrics/diagnostics and exact visit count under single-visit pages and aggregate reservation retries; cancellation returns the held reservation. The existing native ReplayMeter caller still grants layout-builder memory unconditionally, and the builder cursor borrows its source session. Plan 01 owns the retained replay caller and aggregate memory admission; these are outside this scoped primitive step.

The read-only interim implementation review `/root/review_validation_cursor_interim` blocked integration because large validation tables were not reserved, route cells had regressed from 256-cell copying, and pending cursor reservations had no cancellation path. The table-growth helper, retained chunk copy, explicit cancellation and ownership transfer address those local issues. The final scoped review `/root/review_plan00_impl_after_calibration` found and verified fixes for unmetered junction users, false duplicate-key growth reservations, builder denial cleanup, ordering-allocation accounting and long union-find chains; its verdict was PASS. It assigned the current native caller's aggregate memory integration to Plan 01.

Local release calibration used the ignored `completed_layout_upper_scale_calibration` test with 110 valid, disjoint facility pairs, 220 facilities and 1,000 or 18,000 straight cells per route. After the resource fixes, the current checkout at 1.98 million total route cells materialized in about 3 ms and validated in about 638 ms uninterrupted or 624 ms across 1,934 pages of 4,096 visits. It charged 7,925,500 validation visits; peak measured live reservation, including the completed layout, was 471,156,818 bytes. The one-shot baseline at `cd1a8428`, using the same geometry in a disposable local worktree, materialized in about 3 ms and validated in about 448 ms with 3,962,640 previously metered visits. At 110,000 cells, current one-shot validation took about 33 ms versus baseline 21 ms. The new visit accounting covers previously unmetered route-turn and final metric scans; it adds a measured 0.19 second at this near-guard size, so the final integrated performance review must decide whether to reduce this overhead before adoption. The straight-route fixture establishes one upper-size memory/work data point, not generator distribution coverage or a proof that the 10-million-visit request cap fits every accepted factory. No runtime output or distribution audit was added. The port projection cursor now allocates its known final vector length once, avoiding an unreserved transient growth peak.

The completed-layout builder reserves the full replacement vector before growth and releases the old allocation after copying, rather than reserving only the capacity delta. It reserves a known-size binary heap for bridge/junction ordering, then pushes and pops one entry per admitted visit; this removes an unmetered sort and B-tree node allocation uncertainty. Its focused retry, transfer, denial-release and component-order tests pass. The validator admits junction users and avoids reserving hash-table growth for duplicate keys; union by size bounds long-chain root traversal within the validation work cap. The final `cargo test --workspace --quiet` passed, including 39 `aic-layout` tests and 90 `aic-pilot-native` tests with 9 intentionally ignored. `cargo check --workspace --quiet`, formatting, the tracked-file worktree check and `git diff --check` passed locally. For a CLI workflow, `cargo run --quiet -p aic-layout-gen -- generate --config target/local-validation/config.json --catalog-dir data/game/normalized --seed 27 --count 1 --workers 1 --output target/local-validation/output` produced one complete layout, and `aic-layout-gen validate` on its `layout-00000.json` returned `physical_validated: true` with 805 transport cells and 23 bridges. The config was generated from `aic-layout-gen config`; the disposable outputs can be regenerated locally. The existing `complete_layout_bounded` wrapper has a ReplayMeter work/deadline contract but no aggregate memory allowance; Plan 01 owns its replacement with a retained, memory-admitted native replay caller. These checks do not close the native replay integration or distribution-readiness gates.
