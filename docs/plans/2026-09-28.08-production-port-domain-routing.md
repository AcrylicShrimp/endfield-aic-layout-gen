# Plan: Preserve all compatible production port domains through routing

## Current Status

- State: Completed
- Last Updated: 2026-09-28 KST
- Blocker: None.

## Goal and Scope

Remove the demonstrated eager port-choice truncation in the existing full-factory constructive production module. A new facility's compatible ports are a domain of routing alternatives until a real network connection chooses a port. This applies to the seed, added facilities, internal connections and final external connections. Keep the existing four growth strategies, placement proposals, finite A* and placement budgets, work interruption and committed-output contract; these other candidate bounds remain subject to Plan .07's upper-scale calibration. This step does not promise a globally exhaustive layout search or model exposure to upper-scale factories.

## Proposed Changes

Stop using a growth variant as a port-assignment index. `construct_facility_node` already projects every compatible port and `network::attachments` already filters ports occupied by actual physical networks. Preserve these domains in `Constructor::fresh`, including the initial seed, while keeping fixed orientation from the existing flow-direction policy. Run the existing `analyze_constructive_port_demands` at the seed and normal acceptance boundaries so a multi-requirement facility with too little distinct capacity is refused. Do not introduce a new port-option cap or an eager Cartesian enumeration.

In `network::first`, `network::external` and `production/placement`, reserve the short outward corridor only for a different boundary whose sole remaining `NewPort` attachment is a concrete commitment. This includes `pending_corridors` used by nearby shortlisting and by the coarse fallback's `future_corridors_clear`. A multi-option boundary is a choice domain: reserving every candidate would make all choices block one another or reject a legal pose. Existing `attachments` filtering, post-route `refresh`, `network::validate`, port-demand analysis and production boundary screening remain the acceptance contract. Keep these checks at their present search boundaries; add no routine per-sample audit or persistence. Keep `connect_nearest` behavior for its existing fixed-factory caller.

The counterexample's four occupied connection cells eliminate ports 0–3 before A*, while ports 4–5 remain valid and one routes in a single call. Convert the ignored diagnostic to an active module regression asserting the revised constructor's `fresh` plus `connect_external` result; it is a fixed-placement witness, not by itself a complete `construct_production` run. Add a separate compact actual-constructor seed case because `construct_production` currently calls `fresh(target, 0)` before growth. Test the nearby/coarse proposal treatment of multi-option and singleton boundaries, add a capacity competition fixture, then run actual source controls and an independent implementation review before closing this step.

## Execution Result

Implementation started after the second independent plan review passed. `Constructor::fresh` now preserves all projected compatible ports and runs the existing demand analysis before accepting the seed or added facility. Internal/external routing and nearby/coarse corridor proposals reserve only a boundary's sole stored attachment, not every member of a choice domain. Internal first-feasible routing tries residual existing-network attachment pairs before claiming new ports, preserving network reuse when the domain is widened.

The historical ignored diagnostic was replaced with an active fixed-geometry regression: the four blocked output ports are skipped, output 4 or 5 connects in one A* call and the physical network validates. A separate actual `construct_production` case returns a seed with all six alternatives after a deliberate one-call external budget; two competing sale requirements demanding eight belt lanes are rejected against six distinct ports. The same test compares nearby shortlist treatment of a multi-option versus singleton boundary and invokes the shared `future_corridors_clear` helper used by the nearby-enabled coarse fallback. Existing separated-moss assertions were changed from counting duplicate attachment-list entries to counting unique physical ports; an existing-capacity test now observes one 2/5-rate reused attachment rather than two 1/5-rate branches, with no new source port.

The full `production::tests` subset passed 36/36 and `network::tests` passed 9 with one ignored. `cargo fmt --all`, `cargo check --workspace`, and `cargo test --workspace --quiet` passed after the main code edits.
