# Plan: Admit upper-scale held-out input files consistently

## Current Status

- State: Ready
- Last Updated: 2026-09-27 KST
- Blocker: Implementation awaits native input-file admission in Plan .24.

## Goal and Scope

Ensure the full-factory pilot's fixed held-out panel can load every Generated input in its declared distribution. Evaluation and migration currently impose independent 16 MiB per-case guards after the native source publisher and reader. This step owns that evaluation panel's file boundary and exact case identity. The hierarchical curriculum uses a different panel and loader, owned by Plans .26 and .08.

## Completion Criteria

- [ ] Panel::load and explicit migrate admit the measured upper-band Generated input bytes permitted by Plan .24, including an intended 256-facility held-out case. Keep the existing aggregate max_input_bytes allowance and a finite per-case bound; derive or share its value with native generated-input admission rather than leaving an independent, smaller 16 MiB guard. A size refusal names case/path, actual bytes and applicable limit as input/resource failure, not missing physical eligibility.
- [ ] A loaded case's manifest SHA-256 is computed from the exact bounded buffer deserialized into Generated, including during migration; a file change between separate hash and parse operations cannot bind the wrong case. Preserve disjoint train/held-out identity, structural admission, reservation checks and immutable evaluation model behavior.
- [ ] A bounded fixed held-out panel with small and upper-band legal inputs loads and completes one evaluation setup under this evaluator's currently supported shared limits. Record input byte sizes, aggregate bytes, wall time and RSS; independent implementation review checks the per-case and aggregate admissions and identity binding. No periodic reread, runtime distribution audit or duplicate input buffer is added.

## Proposed Changes

Use the native generated-input allowance from Plan .24 or a directly checked equivalent at the evaluation loader. Read the panel manifest once under its separate metadata cap, parse and hash that same buffer for `Panel::identity`, which is used as the run/resume identity. Read each case once under both its per-case and remaining aggregate limits, hash those bytes, then parse the same bytes and run existing admission. Apply the same per-case rule to the one-time migration path. Migration publication may reread one source through a bounded copy, but must enforce the same byte limit and verify the copied bytes against the previously admitted hash before publishing the panel. Preserve the ordinary panel's immutable case IDs and source hashes.
