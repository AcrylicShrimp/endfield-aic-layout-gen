# Plan: Score placement actions from one prepared source state

## Current Status

- State: Completed
- Last Updated: 2026-09-28 04:19 KST
- Blocker: None

## Goal and Scope

Provide one reusable, source-bound placement scorer that returns the existing 49-value action feature row, entity reference, anchor score and child state value for every native `Place` and `PlaceTerminal` action without cloning and stepping a `Session` per ordinary pose. Preserve the complete native legal domain, action order and exact anchor rounding. Final-placement transitions may use an admitted native child application when analytic completion metrics are unavailable. This module does not score route/network/repair witnesses or choose Gumbel actions.

## Completion Criteria

- [x] A prepared scorer owns one process-local `Session` instance ID **and** revision, bounds, compact per-connection terms and incident indices. Native exposes a read-only process-local ID for this boundary; preparation and each new page owner check it once, while per-action scoring does not clone a `Session`, rescan entity IDs or add distribution checks. Persistent replay uses the separate state/`Limits`/config digests from Plan .03, never this process-local ID.
- [x] Native `Place` and `PlaceTerminal` rows, entity indices, anchor scores and child values agree with the current `MacroAction::apply` + `features` + `prior_score` + `state_value` path across rotations, occupied holes, placed/unplaced peers and final-placement transitions. Ordinary anchors preserve source connection summation order and bitwise `f64` results; completion fallback keeps native errors typed.
- [x] The root can stream the maximum child `state_value` over all legal actions without holding children. Bounded release measurements report actual full-page throughput and peak RSS on the retained legal 100-block partial physical state and sparse 320 × 320 fixture, with terminal/completion cases separately identified.
- [x] Local feature-enabled tests, workspace checks and changed CLI-visible workflow checks pass. An independent implementation review finds no missing scorer contract.

## Proposed Changes

Add a small `PlacementActionScorer` module beside hierarchical search. Expose the already-present private native session instance counter through a read-only process-local accessor, without serializing it. Build an ordered fixed contribution array and per-entity incident list from that immutable source once. Derive ordinary placement progress and feature fields directly. Keep the old arithmetic grouping and iterate connection terms in original order to preserve anchor bits and stable sort ties. Apply a native child only for transitions that can create final metrics or require native completion semantics; account for its memory/time in the caller's existing root admission. Reject a stale source at scorer preparation and page-entry boundaries, not per pose. Keep the ignored research probe as comparative evidence until the production implementation and parity checks replace it.

## Execution Result

Implementation started locally after the proposal's round-two PASS. Native now exposes a read-only, process-local `Session` instance ID; `placement_scoring.rs` prepares ordered connection terms, source-bound page scoring, and an admitted native completion fallback. `apply_scoring_children` consumes the production scorer for placement commands while leaving route/network/repair witnesses on their original path. The scorer does not clone children for ordinary poses; the current caller still owns dense actions and rows until later catalog plans.

Local release production score-only traversals: all 5,715,346 native Place commands on the legal 100-block partial physical state in 1.789 s, `/usr/bin/time -l` maximum RSS 102,203,392 bytes; all 808,992 native Place commands on a separate sparse 320 × 320 fixture in 0.248 s, maximum RSS 99,680,256 bytes and 4,304 retained scorer-budget bytes. These measurements include native paging and scoring but exclude model inference, global sorting and training. The research-only 1,024-action parity sample and 1.782-second complete analytic traversal remain comparative evidence. Separate release fixture measurements: 16 ordinary `PlaceTerminal` scores took less than 1 microsecond on the 2-block/1-connection source; the isolated test process reached 98,451,456 bytes maximum RSS. Sixteen final `PlaceTerminal` scores each ran native completion and independent validation, totaling 164 microseconds of scoring time, with 99,401,728 bytes maximum RSS and all 16 publishing metrics. Those small completion measurements establish this fallback's local cost only; they do not project it to a fully routed upper factory. Reproduce the two named feature-enabled release test binaries with `AIC_PLAN01_MEASURE=1` and local LibTorch runtime; retained logs are in ignored `artifacts/plan01-terminal-release.log` and `artifacts/plan01-completion-release.log`.

Feature-enabled tests compare all 49 values, entity index, exact `f64` anchor bits and child value against the existing native child path. Cases include multiple ordinary offsets, a partially placed connected peer with occupied cells, ordinary terminal poses, and native final-terminal completion. The completion fallback propagates a native `Diagnostic` as a typed error; page entry rejects a distinct instance at the same revision and a stale revision. An existing caller-level test now compares `apply_scoring_children` output to native children. `cargo fmt --all`, `cargo check --workspace`, `cargo test --workspace`, all 85 active feature-enabled library tests, the CLI harness help command, the documentation checker and `git diff --check` passed. A complete CLI harness run needs model artifact outputs unavailable in the local checkout; the changed scorer caller is exercised directly by the feature-enabled test.

Independent implementation review round one (`/root/review_plan01_impl_r1`) returned BLOCK: no analytic fixture with a placed peer/occupied cells, and completion errors were flattened through `MacroAction::apply`. Both findings were verified and fixed. Round two (`/root/review_plan01_impl_r2`) returned BLOCK on missing separate terminal/completion release time and RSS evidence; that evidence is now recorded above. Round three (`/root/review_plan01_impl_r3`) returned PASS_WITH_NOTES. Its sole note is that the final-placement fallback charges a conservative child reservation while native completion materialization and independent validation do not directly charge their allocations to `SearchMemoryBudget`; the 16-pose fixture does not establish upper physical completion cost. The later integrated upper physical resource gate retains this risk. No scorer-contract blocker remains.
