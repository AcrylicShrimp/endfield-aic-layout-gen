## Goal and Scope

Give the existing constructive production module two complete result contracts: its current full, valid step-history report for the CLI report/visualization path, and a typed compact result for normal full-factory `Source::generate` and the CLI's final-only JSON path. These final-only consumers need the final validated physical node and compact failure/progress diagnostics, but currently retain cloned full nodes for every accepted growth and external step until construction returns. Remove that unused normal-path history and decision trace without changing candidate search, budget accounting, source identity, committed-input structure or the full CLI report schema. This is one constructor-result ownership stage; Plan .07 still owns 240–256-facility construction policy, time/RSS and publication gates.

## Proposed Changes

Keep `ConstructiveProductionRequest` and the existing full-report API and schema stable. In the current `production` module, share one constructor engine and choose its result ownership at entry. A full-report caller retains the existing step and diagnostic history. Source generation and final-only CLI callers receive a distinct public typed `ConstructiveProductionCompactResult` with only the final accepted node, scalar accepted-step counters, compact reasons/diagnostics and the exact effective bounds needed by the existing failure summary. Reexport that type and constructor through the existing `constructive` and `layouts` facades; do not return a full `ConstructiveProductionReport` containing empty or fake steps as a compact result. The engine updates accepted counters at the same commit points as the current `steps.push`, and indexes external steps from the counter rather than from history length. It records costly placement, growth, orientation and obstruction traces only for full-report callers; internal search and acceptance logic remains identical. Resource stops and work interruption still leave only the last valid accepted node.

In `full_factory/generation/source.rs`, consume the typed compact result and compute the same deterministic `construction_failure_summary` fields from its counters and final node. On success take the final node directly into randomized setup; on failure keep the existing top reasons and actual stop category. In `aic-cli`, select the compact path for `--final-json` before construction; keep report and HTML modes on the full path. No per-sample validation, replay, checksum or new runtime limit is added. The normal source path remains responsible for the existing input admission and publication boundaries.

This reuses the current constructor, report type, validation, Source work control and publication path. The intended simplification is one normal-path node owner instead of a vector of historical full-node copies and traces that Source immediately discards. The CLI's historical visualization remains an explicit separate consumer.
